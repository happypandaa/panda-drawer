# agent 应用

## 工作方式与识别

agent 负责做事，应用负责展示、长期保存结果和收集用户反馈。应用根目录就是 agent 的工作目录：根目录的 `AGENTS.md` 说明日常流程，表结构和列的含义以应用的 `docs/database.md` 为准。`panda.json` 用 `"agent": {"instructions":"AGENTS.md"}` 标记；若声明了其他规则路径，也须阅读它。

agent 与应用通过同一份 `data/main.sqlite` 交流，配图等文件放在 `data/attachments/`。agent 不在线时，应用照常使用，反馈留在数据库等下次读取。平台不调起 agent、不读会话、不做定时调度、不监听外部文件变化，也不在双方之间转发消息。定时任务由用户自己的 AI 工具负责。

agent 是工作方式，`runtime` 仍为 `web` 或 `node`。网页使用 SDK 时照常声明 `platform.sdkApiVersion: 1`；agent 标记不会改变 Node 的运行契约或为其启用网页 SDK。平台项目元数据中的 `isAgent` 只是标识和提醒，不能代替清单及路径检查。

## 日常任务和修改应用

- **更新内容、处理请求等日常任务：** 按应用规则读取设置和反馈，仅写入应用允许 agent 写的表和列。不改程序、`panda.json`、`AGENTS.md`、声明的规则文件、`docs/` 或表结构。
- **用户明确要求修改界面、增加功能：** 按主 skill 的“用法一”保存代码版本、关窗并修改。需要改表结构时，同时修改程序的建表升级逻辑和 `docs/database.md`；只加列、加表，保留已有数据。任何删除或清空数据的操作先说明影响并取得用户同意。

数据库或所需表不存在时，不要自行建库建表，也不要先运行会创建空库的连接命令。请用户先在熊猫小抽屉里打开一次应用，由应用程序初始化；仍缺失时报告问题。

## 命令行读写数据库

以下流程面向 macOS 已有数据库，工作目录为应用根目录。每次连接先设置锁等待：

```sh
sqlite3 -cmd ".timeout 5000" data/main.sqlite
```

写入分三步，使用应用自己定义的运行记录和字段，不自行创建通用表：

1. **开始状态单独提交。** 如有运行记录表，先写入“进行中”并立即提交，让界面可以看到。
2. **事务外完成耗时工作。** 读取设置和反馈、搜索、处理请求、下载和缩图时，不持有写事务；先准备好要写的数据和附件路径。
3. **用一个短事务提交结果。** `BEGIN IMMEDIATE; ... COMMIT;` 内只执行数据库写入，将内容、请求结果、偏好和最终运行状态一起提交，几秒内完成。写入失败先确认回滚，再单独标记失败并记录原因。

平台连接的锁等待为 5 秒，外部持锁过久会使界面上的保存报 `SQL_BUSY`。macOS 一次性项目的真实窗口实测中，短事务与 SDK 持续读写可以共存；外部持有写事务超过 5 秒时，SDK 写入等待后失败，释放锁后可继续写入。这是锁等待上限，不是所有 SQL 的执行时限。

还须遵守：

- 新增内容使用应用约定的 `INSERT` 或 `INSERT OR IGNORE`。禁止 `INSERT OR REPLACE` 和 `REPLACE`，它们会先删除旧行，可能丢失用户的收藏、备注等数据。
- 严格遵守列的写入分工，不覆盖用户写的列。不要因内容重复而删除旧数据。
- 不执行 `PRAGMA journal_mode`、`VACUUM`，不删除 `main.sqlite-wal`、`main.sqlite-shm`，不替换数据库文件。
- 遇到“被锁”时等待后重试，不删除任何文件。结果不明时先检查实际结果，不盲目重放写入。
- SQL 值使用参数绑定或可靠的 SQL 值编码，不把用户输入、网页文字直接拼接成可执行 SQL。

## 附件、刷新和统计

agent 可把普通文件直接写入 `data/attachments/`，例如 `images/YYYY-MM/<链接哈希>.jpg`。应用使用相对附件根的路径调用：

```js
const files = await panda.files.list('images/');
const imageUrl = await panda.files.url('images/2026-11/1.jpg');
const image = await panda.files.get('images/2026-11/1.jpg');
await panda.files.remove('images/2026-11/1.jpg');
```

这些接口无需先通过 `put` 登记文件；现有路径边界、符号链接、硬链接和文件类型检查保持适用。直接文件写入与 SQL 提交不是同一个事务，失败后须按应用规则核对结果。

外部写库、写附件不产生 SDK 的 `data.changed` 事件。应用应提供刷新按钮，并可在窗口获得焦点、页面重新可见时重新查询；不要依赖文件监听或平台推送。业务数据更新不需要重新构建网页。

平台空间统计是扫描快照。外部写入不会自动使缓存失效，即使显示 `stale: false` 也可能尚未包含这些变化；需要最新占用时显式重新扫描。

## 给用户的路径和定时提示

网页可通过 `const { projectRoot } = await panda.context.get()` 取得当前应用根目录的绝对路径，放进“粘贴给你的 AI”的提示词，并请 AI 先读 `AGENTS.md` 和声明的规则文件。返回路径使用系统原生格式；不要从网址猜项目位置，也不要把展示路径当作其他应用的访问许可。

当前推荐和链接下载仍使用平台当前工作区的位置，没有 agent 专用的位置选择。需要使用自己习惯的目录时，可先自行下载，再用“本机文件夹”添加。目录选定后请保持原位置；移走或删除后平台会提示找不到文件夹，不负责自动找回。

删除以平台登记的目录归属为准：用户目录保留代码、Git 和 `data/`，平台所有目录整根删除；平台私有配置和浏览器数据均清除。即使文件夹保留，用户仍须在 AI 工具中关闭为它设置的定时任务。平台不代为操作 AI 工具。

## 开发建议和验证边界

- 为每张表、每一列写清谁能写；应用反馈列与 agent 内容列分开，避免互相覆盖。
- 在应用自己的运行记录表记录开始、完成、结果和失败原因，让界面能显示“上次更新”。当前没有平台强制的通用运行记录表，平台首页不读取业务表。
- `.gitignore` 包含 `data/`，代码版本不包含用户内容、附件和数据库。
- 用户的 AI 工具能否为定时任务指定工作目录，需要由该工具的实际结果确认；不要仅凭复制了提示词就显示已连接或已设置成功。
- 当前数据库并发和外部附件实测来自 macOS 真实应用窗口。Windows 的原生路径返回、编译及既有功能按平台检查要求保持；Windows agent 运行和定时流程尚未验收，不声称已支持或已实测。
