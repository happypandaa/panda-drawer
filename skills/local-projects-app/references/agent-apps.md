# agent 应用：写给应用作者

这份说明写给做 agent 应用的人（或 AI）。agent 应用的日常任务由应用自己的 `AGENTS.md` 规定，那份规则要自成一体：用户的 AI 做日常任务时只读 `AGENTS.md`，不会读平台说明。所以下面「底线」里的每一条，都要写进你的 `AGENTS.md`。

## 工作方式与识别

agent 负责做事，应用负责展示、长期保存结果和收集用户反馈。应用根目录就是 agent 的工作目录：根目录的 `AGENTS.md` 说明日常流程，表结构和列的含义写在应用的 `docs/database.md`。`panda.json` 用 `"agent": {"instructions":"AGENTS.md"}` 标记；声明了其他规则路径时，以那份为准。

agent 与应用通过同一份 `data/main.sqlite` 交流，配图等文件放在 `data/attachments/`。agent 不在线时，应用照常使用，反馈留在数据库等下次读取。平台不调起 agent、不读会话、不做定时调度、不监听外部文件变化，也不在双方之间转发消息。用户想看新内容时，自己在 AI 对话里叫 agent 做。

agent 是工作方式，与是否有后台独立。清单采用 `manifestVersion: 2`，不写 `runtime`；声明 `backend` 即有后台。无论有无后台，使用 SDK 都声明 `platform.sdkApiVersion: 1`。平台元数据中的 `isAgent` 只是标识和提醒，不能代替清单及路径检查。

## 底线：每个 AGENTS.md 都要写进去

1. **分清日常任务和修改应用。** 日常任务只写应用允许 agent 写的表和列，不改程序、`panda.json`、`AGENTS.md`、`docs/` 或表结构。用户要改界面或加功能时，请用户在熊猫小抽屉里点「按你的想法改」重新交给 AI，由平台说明接管。
2. **不自己建库建表。** 数据库或所需表不存在时，不要自行创建，也不要先运行会创建空库的连接命令（先用 `test -f data/main.sqlite` 检查，再用只读连接）。请用户先在熊猫小抽屉里打开一次应用，由应用程序初始化；仍缺失时报告问题。
3. **短事务写库。** 每次连接先设置 `.timeout 5000`。写入分三步：开始状态单独提交；读取、搜索、下载、缩图等耗时工作在事务外完成；最后用一个 `BEGIN IMMEDIATE; ... COMMIT;` 短事务提交全部结果，几秒内完成。写入失败先确认回滚，再单独标记失败并记录原因。
4. **不覆盖用户的数据。** 新增内容用 `INSERT` 或 `INSERT OR IGNORE`，禁止 `INSERT OR REPLACE` 和 `REPLACE`（它们会先删除旧行，丢掉用户的收藏、备注）。严格遵守列的写入分工，不覆盖用户写的列；不要因内容重复而删除旧数据。
5. **不动数据库文件本身。** 不执行 `PRAGMA journal_mode`、`VACUUM`，不删除 `main.sqlite-wal`、`main.sqlite-shm`，不替换数据库文件。遇到“被锁”时等几秒重试，不删除任何文件；结果不明时先检查实际结果，不盲目重放写入。
6. **SQL 值要编码。** 使用参数绑定或可靠的 SQL 值编码，不把用户输入、网页文字直接拼接成可执行 SQL。
7. **按数据库现状继续。** 同一句开场白可能因为换了 AI 工具或对话丢失而再次发来。每次都先读数据库，按现状继续，不要假设这是第一次。

平台连接的锁等待为 5 秒，外部持锁过久会使界面上的保存报 `SQL_BUSY`。macOS 一次性项目的真实窗口实测中，短事务与 SDK 持续读写可以共存；外部持有写事务超过 5 秒时，SDK 写入等待后失败，释放锁后可继续写入。这是锁等待上限，不是所有 SQL 的执行时限。

## 写法建议

- **列的分工写清楚。** 为每张表、每一列写清谁能写；应用反馈列与 agent 内容列分开，避免互相覆盖。
- **运行记录表。** 在应用自己的运行记录表记录开始、完成、结果和失败原因，让界面能显示「上次更新」和失败原因。当前没有平台强制的通用运行记录表，平台首页不读取业务表。
- **刷新。** 外部写库、写附件不产生 SDK 的 `data.changed` 事件。应用应提供刷新按钮，并在窗口获得焦点、页面重新可见时重新查询；不要依赖文件监听或平台推送。业务数据更新不需要重新构建网页。
- **空状态和上次更新。** 应用第一次打开、还没有数据时，用一句话告诉用户内容由他的 AI 收集，并直接给出要发给 AI 的那句话。平台支持时（`panda.context.get()` 的 `capabilities` 含 `ai.open`），在用户点击时调用 `panda.ai.open(text)`，主按钮叫「交给我的 AI」，「复制」作为后备；不支持时只给「复制」。有数据后显示上次更新时间，并说明想看新内容就在 AI 对话里说一句。
- **日常提示词的句式。** 写绝对路径，点名 `AGENTS.md` 和其中的段落名，可以重复发送；末尾加一句「如果你读写不了这个文件夹，先告诉我」。不带平台说明路径，保持简短。路径用 `const { projectRoot } = await panda.context.get()` 取得，返回系统原生格式；不要从网址猜项目位置。
- **打不开时显示原因。** 建表或升级失败时，把真实出错信息显示出来，附「复制」按钮，引导用户发给自己的 AI；应用不自己修数据。
- **表结构升级。** 建表和升级逻辑放在应用程序里，打开时执行；只加列、加表，并在 `docs/database.md` 写明当前版本。
- `.gitignore` 包含 `data/`，代码版本不包含用户内容、附件和数据库。

## 附件

agent 可把普通文件直接写入 `data/attachments/`，例如 `images/YYYY-MM/<链接哈希>.jpg`。应用使用相对附件根的路径调用：

```js
const files = await panda.files.list('images/');
const imageUrl = await panda.files.url('images/2026-11/1.jpg');
const image = await panda.files.get('images/2026-11/1.jpg');
await panda.files.remove('images/2026-11/1.jpg');
```

这些接口无需先通过 `put` 登记文件；现有路径边界、符号链接、硬链接和文件类型检查保持适用。直接文件写入与 SQL 提交不是同一个事务，失败后须按应用规则核对结果。

平台空间统计是扫描快照。外部写入不会自动使缓存失效，即使显示 `stale: false` 也可能尚未包含这些变化；需要最新占用时显式重新扫描。

## 放在哪里、删除

macOS 添加标有 agent 的应用时，先选择放在哪里：默认使用当前工作区，归平台所有；也可以选择或新建一个空文件夹，下载后的应用根就是这个文件夹，不另套子目录，归用户所有。空文件夹只忽略明确允许的系统元数据（如 `.DS_Store`），`.git`、`.env` 等仍算非空。目录选定后请保持原位置；移走或删除后平台会提示找不到文件夹。

删除以平台登记的目录归属为准：用户目录保留代码、Git 和 `data/`，平台所有目录整根删除；平台私有配置和浏览器数据均清除。

## 验证边界

当前数据库并发和外部附件实测来自 macOS 真实应用窗口。Windows agent 运行流程尚未验收，不声称已支持或已实测。
