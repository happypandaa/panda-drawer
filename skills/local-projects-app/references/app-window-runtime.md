# 给应用开发 AI 的环境、窗口与后端约束

2026-10-29 同步 Node 单目录运行规则。本文随平台 skill 分发，是仓库 `docs/app-development-environment.md` 与 `docs/app-window-runtime-contract.md` 的应用开发执行摘要；可独立读取，不要求访问平台源码。只说明当前实际入口，不将历史方案当作可调用能力。

## 平台环境与交付

第一版应用兼容范围以 Radio 类为基线：静态网页、一个受管 Node、同进程 SDK 与外部 HTTP 服务。网页／SQL 优先；不要主动扩成通用 CLI、多服务或现场原生编译。Mac 配套 Node/npm 供 project-v1 构建和 Git 项目依赖准备使用；Node 修改、构建和 Git 版本由外部 AI 完成。平台保留 Git 工具选择／诊断、公开 HTTPS 仓库 HEAD 检查，以及 project-v1 的状态、历史和明确源码／数据取回。私有仓库认证未接入；Radio 本机试用不代表标准安装、目标系统、可选 TTS 或账号登录已验收。

- 默认用前端 + 平台 SDK + SQL／附件完成业务，不为表单、列表和数据管理增加独立 Node 服务。已有 project-v1 的 SQL 由平台原生 SQLite 提供；React/Vite 的构建依赖不等于用户运行依赖。业务持久数据不以浏览器缓存替代。
- 确需后端 SDK、私密 Key 或服务端 API 时再选 Node，尽量一个受管服务，SDK 作为库放在服务内。AI 优先使用在线 HTTP API 并适配真实协议，不默认依赖 Claude Code。前端直连仍受 CSP/CORS 限制，不得在前端暴露私人 Key 来省掉后端。
- 普通用户应配置后直接打开。前端包含构建好的 HTML、JavaScript、CSS 及完整资源，不能只交 TSX 或让用户开 Vite。后端可交能直接执行的 `.js` / `.mjs` 源码或打包产物；需要转换的源码先构建，完整运行依赖及其动态加载资源须准备好，不能首次运行再安装。
- 应用运行使用固定私有 Node，当前 Mac arm64 内部版为 `24.22.0`，不因构建环境选择而改变。Mac 配套 npm 现供已有 project-v1 构建入口使用，支持 Node `^22.12.0 || ^24.0.0`；`env doctor` 返回桌面实际工具路径、版本与检测结果。已有显式本机路径优先；无显式选择时，有受管资源位置的环境默认使用配套私有工具，没有该位置的开发服务仍可自动探测。显式路径失效或受管资源缺失／损坏时不自动回退，需修正选择或修复平台；“恢复默认工具”／`env node clear` 清除显式路径，受管位置本身不证明可用。
- 不附 pnpm、yarn 或通用原生编译器。从 Git 添加在项目文件夹执行 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`，使用隔离配置和缓存；项目根与后端根去重后须恰好一组有效 `package.json` 和 npm v2/v3 锁文件。无包的零依赖项目跳过；缺锁、双依赖根、项目 `.npmrc` 等不支持材料返回需要修改。Git／file／workspace／别名依赖和第三方 `.node` 原生扩展不在此准备子集。平台不运行仓库构建或生命周期脚本；`development.build.kind = npm` 时也须已提交清单声明的运行文件，否则让 AI 构建后添加本地项目。本地登记不准备依赖，启动不执行 npm。
- Mac 私有 Git 固定为 2.56.0，官方完整源码、许可证与构建 recipe 随工具资源保留。`env git doctor/set/clear` 只诊断／选择工具，独立 `git-toolchain.json` 不改变 Node 设置。默认受管、显式路径优先，失效不自动换工具；`unresolved` 表示选择设置无法读取／解析。系统 SSH 仅执行 `-V`，认证为 `not-checked`。源码保存、分支和 Node 版本取回由外部 AI 使用项目自己的 Git 完成；project-v1 的平台源码／数据取回另有明确流程。不读取／复制 SSH 私钥或修改全局配置，应用运行不依赖 Git／SSH。
- 公开仓库访问检查使用 `env git check --url https://github.com/owner/repository.git --json`，仅支持标准 GitHub/Gitee HTTPS 仓库地址。20 秒执行预算内匿名读取 HEAD，不读取账号凭据、不克隆或下载仓库、不推送、不写项目；不将远端检查加入普通工具诊断。结果只说明本次公开读取情况，缺少 HEAD 不表示空仓库，也不改变 `doctor` 的认证未验证状态。实际接入从平台“从 Git 添加”发起后端统一任务，不提供独立源码获取／捕获／安装候选入口。
- 优先打包 JavaScript 或携带完整纯 JS 运行依赖树。原生扩展、额外二进制／服务没有相应契约和目标系统实测前，不声称标准兼容；不能把作者机器的 `node_modules` 默认当作跨系统产物。程序启动无需联网装依赖，不表示 AI／TTS／音乐功能无需网络。
- 尽量不要求用户另装软件。若确需 Claude Code、Python、Docker、数据库服务器或其他 CLI，在选方案时提前说明，并在用户／开发说明中列名称、版本与系统、用途、安装认证准备、缺失影响和替代方式。在线服务账号、API 地址、Key、费用及离线影响另列；无要求明确写“无”。声明并不会授予平台尚无的外部 CLI 或多服务运行能力。
- 不依赖宿主 PATH、全局包、作者机器绝对路径、开发服务器或未声明环境变量。配置由清单和平台表单管理。用户／开发说明写明平台提供什么、应用自带什么、用户还需准备什么，使用现有声明字段，不发明自动安装或 shell 字段。
- 所有受支持 Node 项目直接运行登记的项目文件夹。Git 下载和平台生成的文件夹由平台管理，删除项目时一起删除；用户选择的外部原始目录保留。关闭应用窗口后，由 AI 在该目录修改代码、准备依赖或构建，重新进入生效；平台不另存运行副本，也不提供 Node 构建更新或 Git 面板。旧 version 2 项目仍可在列表和详情查看不可用原因，不能启动；完整删除后重新添加，不自动迁移。Node 未获得 project-v1 SQL 或整项目 ZIP 等接口，固定 Node 与原生窗口也不是系统权限沙箱。

已有 project-v1 构建每次复制 `sourceDir` 内普通源码，在独立候选执行锁定 `npm ci` 和构建，原源码的 `node_modules` 不复用也不修改。构建脚本仍须接受绝对 `--outDir`；只支持源码目录内 file/workspace 依赖，拒绝源码符号链接和外部依赖。候选不包含项目根清单、Git、活库或附件；不要依赖这些位置。失败不发布，正常结束清理候选，崩溃现场保留。它不是系统权限沙箱，脚本绝对路径访问和上级依赖查找未被系统隔离。

## 应用运行

1. 所有应用统一从“我的项目”启动台进入。卡片只常显图标和单行名称，超宽省略，悬停显示完整名称，Node 保留绿色六边形角标；不设置三点按钮。右键或聚焦后使用 Shift+F10／ContextMenu 键打开详情菜单。运行类型中文以及配置、运行、维护和异常状态保留在菜单、详情与读屏说明中，不另占首页卡片文本行，也不放宽进入门禁。应用在平台提供的一个原生窗口里运行；再次打开只聚焦原窗口，保留已有页面与草稿，不创建第二个窗口或偷偷刷新。列表统一不合并 Node 内部源码槽与 project-v1 身份。
2. 不使用 `window.open`、`target="_blank"`、外部浏览器、额外 WebView 或独立原生窗口扩展运行界面。业务表单、帮助与确认放在当前窗口内；不要调用脚本 `alert`、`confirm`、`prompt`。受控的文件选择、保存位置与系统权限仍按平台实际能力和用户操作使用。
3. 网页类型不启动 Node 后端。Node 类型由平台在打开应用时后台启动受管后端，关闭应用窗口须收尾本应用全部受管 Node、普通子进程及连接；不能只看主进程退出就报告清理完成。应用不要自建常驻、脱离进程组或要求用户手动开终端服务。
4. 启动尚未完成时重复打开复用同一次启动；取消／关闭后不得因迟到响应重新弹窗。后端异常显示原因和明确重试，不无限拉起、不猜旧 PID、不影响其他应用。
5. 保存配置不启动或自动重启。运行中明确重启才使用新快照；关闭业务窗口后再次打开使用当前保存配置。macOS 管理窗口 X 只隐藏并保留 Dock、已开的业务窗口和受管服务；点击 Dock、Reopen 或重复启动恢复同一个管理窗口和页面状态，不新建第二套窗口或平台服务。菜单退出／Cmd+Q 才安全关闭全部业务窗口并收尾全部受管 Node，非 macOS 管理窗口 X 维持正常退出。不终止用户独立启动的其他 Node 服务，也不能把管理窗口隐藏视为应用或服务已经停止。当前要求覆盖旧“管理窗口 X 退出”的说明，实际验证须按当前安装版本分别记录。
6. 项目详情、说明与配置集中在平台页面内带 tabs 的 modal，沿用静态项目详情习惯，不新建管理页或原生窗口。缺必填时“进入／打开应用”仍可点击，先开配置 tab 指出缺项与获取步骤；保存后还需明确打开。后端就绪或网页入口失败显示真实原因，不以空白页冒充正常运行。
7. 收尾失败或进程归属不明时记录真实异常／未完成状态，保留现场，不能显示全部已停止。硬崩溃、被强制杀死或逃离受管进程组的后代不作全部自动清理保证；单元测试与正常关窗成功不替代这些场景验收。

## 应用窗口尺寸

业务应用可在 `project.json` 的可选顶层 `window`，或 Node 项目的 `local-app.json.window` 中提供初始内容区逻辑尺寸。不要把字段嵌套在 JSON 的 `extra` 中；Rust 的 `extra.window` 是 project-v1 的内部透传表示。可选片段如下，须保留所在清单的其他合法内容：

```json
{
  "window": { "width": 960, "height": 640, "rememberSize": true }
}
```

省略整个 `window` 默认 1080×780、记忆尺寸；提供对象时宽高都必填，为 1..32768 的整数，`rememberSize` 可选且默认为 `true`。实际内容区最小 640×480，并按显示器可用区收敛。之后新开默认优先使用该应用上次普通窗口的本机逻辑尺寸；设为 `false` 则每次新开使用声明值，不读写记忆值。重复打开已有窗口仍只聚焦，不重设尺寸或重载；最小化、最大化和全屏尺寸不作为普通尺寸保存。

本机记忆由宿主管理，分别存于固定数据根 `web-project-ownership/<项目ID>/window-size.json` 和 `node-project-ownership/<实例UUID>/window-size.json`，与 `settings.json`、项目业务数据和分享包分开。网页项目按稳定 ID、Node 按注册 UUID 隔离，公开工作区迁移不改变该尺寸身份；已有窗口仍只聚焦。当前仅 macOS 在尺寸变化后的正常业务关窗／明确退出时原子保存，正常成功保存不积累旧副本；非 macOS 未因此新增持久发布支持。

单个坏缓存只让该项目回退默认并停止写入，不拖住其他项目；临时／冲突材料只在本项目控制目录内。项目删除同步撤销尺寸写许可、清除磁盘缓存和内存绑定，旧回调及迟到 flush 不得重新创建已删除归属目录。AI 不自行修改尺寸控制文件。此新格式不读取或迁移旧全局缓存与 preserved 副本，也不自动清理这些旧材料；用户另行重置数据根。

可以在关闭应用窗口后修改有效 Node 清单，包括 `app.id`、版本、入口、配置和 `window`。平台在下次真正启动前重新读取、检查并接受新摘要；实例 UUID、原数据和删除归属不变。已有窗口仍只聚焦，不重置尺寸；本机记忆尺寸继续按前述规则优先。清单无效或入口缺失时不启动，不能改平台控制文件绕过检查。维护源为平台 `docs/app-window-runtime-contract.md` 的“应用窗口尺寸”节；尺寸逻辑回归不替代真实原生拖动、重开、屏幕／DPI 变化及全屏等行为验收。

## 配置与项目边界

- 作者在当前支持的结构化清单中声明运行类型、启动入口及配置。每项写清中文名称、用途、必填／可选、默认值及获取方法；用户不应编辑 `.env`。
- API Key 由平台配置入口保存并只注入目标后端。不要写进源文件、前端、作者清单、日志、交接说明或截图，也不从其他应用、宿主环境和旧 `.env` 借用。
- 用户最新选择将 Node Key 保存在各自本机受管槽的 `configuration/credentials/`，目录 `0700`、秘密文件 `0600`；它是当前用户文件权限保护的明文文件，不是 macOS Keychain 或系统加密库。这个目录不是作者源码、分享包或 Git；AI 不读取／复制秘密文件，不迁移或删除旧系统凭据，保存与注入由平台处理。
- 先核对交接身份。含 `project.json` 并经当前 CLI 确认的是既有 project-v1；只有 `local-app.json` 的本机 Node 源码槽不是这种项目，不得套用 SQLite／备份／导出／迁移命令或伪造项目 ID。
- 受管源码和其依赖仍要可信；内置 Node 与原生窗口不是权限沙箱。普通编辑保全原项目源码、固定 SDK、数据库、附件和恢复现场；用户明确删除项目时按项目独占归属清除全部平台管理材料，外部原始目录和已完成外部交付保留。
- 固定开发标识为 `dev.happypandaa.pandadrawer`。2026-10-25 的旧开发环境清空是用户针对平台维护的一次独立授权，不适用于普通业务项目操作；接手时不自行修改身份、清空资料或改数据目录。普通工作区移动使用平台已开放的迁移流程。

## 验证与交接

从平台原生应用窗口验证首次打开、重复打开只聚焦、关闭后端退出、重开数据保留，以及必要的配置生效和异常提示。浏览器／HTTP 诊断只能作补充，不能代替原生窗口验收。只记录实际验证过的动作和环境；没有能力操作原生窗口时明确留下未完成项，不能以浏览器截图表示通过。

更新本应用自己的用户使用／配置说明和 AI 开发说明；旧项目的 skill 和 SDK 不随平台升级改写。需要平台新能力时先核对当前安装版本、真实接口和交接信息，不为满足文档自行修改平台控制文件或已有用户数据。


项目原生窗口按稳定项目身份使用独立 WebKit store，管理器使用另外的全局 store。复制／导入生成新身份；正常迁移保留身份。项目删除须等实际写入结束和窗口 Destroyed，再等系统清空所有网站数据、删除 store 并确认标识不存在；失败保留当前清理凭据，不能把关闭窗口或端口变化当作存储已删除。Node 后端和代理使用动态端口，Cookie 不按端口隔离，不能借端口随机化混用项目存储；localStorage／IndexedDB 仍受 origin（含端口）划分。
