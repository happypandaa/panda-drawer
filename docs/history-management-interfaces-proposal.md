# 历史备份与迁移旧目录管理接口建议

状态：v0.1，讨论稿，路由、输入输出和新增保护规则待用户确认，尚未实现  
更新日期：2026-10-15

后续范围更新（2026-10-16）：用户确认了旧工作区、已完成恢复现场与回收站的显式范围清理入口，实施接口见[历史清理补充](history-cleanup.md)。这不代表本文备份另存、备份删除及全部建议接口已获确认。

本文补充三个已经进入产品范围、但尚未定稿精确接口的入口：另存指定历史备份、删除可清理备份、清理迁移后的旧工作区。既定范围见[备份维护](backup-and-maintenance.md)、[项目生命周期](project-lifecycle-and-workspace.md)与[空间管理](project-storage-and-assets.md)。下面是建议，不将它们直接加入已确认 API 表。

## 1 共同规则

- 桌面管理窗口和原生 CLI 调用相同 Rust 模块；HTTP 使用管理凭据。普通项目 SDK 不新增管理历史备份或删除目录的权限。
- 不需要 Node，不运行项目脚本，不改业务数据库或当前网页。历史读取及清理不要求进入项目维护，但必须遵守保护引用与任务互斥。
- 变更操作返回 HTTP 202、任务 ID，沿用 `queued → running → succeeded | failed | interrupted`。CLI 退出码 0 仅说明调用成功，最终结果仍查任务。
- 删除必须有明确对象，不能默认“最新备份”“全部备份”或“某个旧路径”；首版不提供批量清空或 `force`。
- 操作不自动重放。删除后登记未完成等崩溃情况按日志核对真实结果；核对不等于重新执行一遍删除。
- 字节按逻辑文件大小报告，不称作保证释放的磁盘空间。资源并发和空间预检采用[资源限额建议](resource-limits-proposal.md)。

历史备份按 `projectId + backupId` 定位，不先要求项目仍是活跃项目。项目在回收站或已永久清除，但历史备份仍保留时，以上两个备份入口继续可用；`projectId` 在这些路由中标识历史归属。

## 2 建议接口总览

| 动作 | CLI（`platform` 仍为占位名） | 管理 HTTP |
| --- | --- | --- |
| 另存指定历史备份 | `platform backup save-as --project ID --backup ID --input request.json --json` | `POST /api/v1/projects/{id}/backups/{backupId}/exports` |
| 删除指定备份 | `platform backup delete --project ID --backup ID --input request.json --json` | `POST /api/v1/projects/{id}/backups/{backupId}/deletions` |
| 查看已登记旧根列表 | `platform workspace retired list --json` | `GET /api/v1/workspace/retired-roots` |
| 查看一个旧根 | `platform workspace retired info --retired ID --json` | `GET /api/v1/workspace/retired-roots/{retiredRootId}` |
| 生成旧根清理预检 | `platform workspace retired cleanup-plan --retired ID --json` | `POST /api/v1/workspace/retired-roots/{retiredRootId}/cleanup-plans` |
| 清理该旧根 | `platform workspace retired cleanup --retired ID --input request.json --json` | `POST /api/v1/workspace/retired-roots/{retiredRootId}/cleanups` |

后四个端点共同服务一个“清理迁移旧目录”入口；引入列表和预检是为了让用户及 AI 选择明确对象，不是新增通用文件管理器。查询返回 HTTP 200，预检耗时操作也返回 202 任务。

既有 `backup list/info` 增加：`backupId`、`projectId`、`snapshotAt`、`kind`、`archiveBytes`、已验证时的 `sha256`、`validationState`、`revision`、`canDelete`、`protectedReasons`。详情同时给出历史项目名称；`validationState` 区分已验证、损坏、缺失和待检查，不把不存在的 ZIP 当零字节有效备份。

## 3 另存指定历史备份

### 3.1 用户看到的动作

在备份列表选定一份备份，选择“另存到其他位置”。界面显示原快照时间，默认不覆盖已有文件。它复制已有 ZIP，不生成新的当前项目快照，也不更新原备份的创建时间。

建议请求：

```json
{
  "destinationPath": "/Volumes/BackupDisk/english-2026-10-15.zip",
  "overwrite": false
}
```

`destinationPath` 为本机绝对路径，必须指向具体 ZIP 文件，父目录已存在且可写；不隐式新建一串未知目录。源由路由里的 ID 决定，不能提供另一个任意 `sourcePath`。

### 3.2 检查和执行

1. 查找归档登记，核对源文件身份、状态和已登记 SHA-256。损坏、缺失或不能验证时失败，不将文件包装成健康备份。
2. 对归档建立使用引用，防止手动或自动清理；不冻结当前项目，不要求维护 ID。正在恢复所需的归档也可只读另存，但共享资源与迁移调度仍需排队。
3. 解析目标真实路径，拒绝源自身、工作区内部、已登记迁移旧根、恢复现场、固定设置／运行／迁移记录目录和 `.app` 内部，避免覆盖平台管理文件或使新外部副本被后续清理误删。相同文件的路径别名也视为冲突。
4. 目标已存在且未明确覆盖时返回 `DESTINATION_EXISTS`。允许覆盖时记住原目标身份，源 ZIP 流式复制到目标旁的任务临时文件，不先删除旧目标。
5. 校验新副本与源归档摘要一致；发布前再次核对目标未被外部替换。完整发布后记录成功，保留原 ZIP 不变。

临时创建与最终发布必须绑定已核对的卷、父目录及目标身份，使用目录句柄相对操作或等效方式检查，不仅在预检做一次路径解析后就按字符串盲写。父目录被替换、变成链接或磁盘挂载改变时停止；这些检查仍依赖外部工具按约定协作，不承诺对任意并发文件篡改形成安全沙箱。

已登记的可验证历史归档可以原样另存，不执行解包、npm 或数据库打开。另存不受附件上传 256 MB 限制，也不因为默认 ZIP 展开预算而拒绝复制已经存在的有效大归档；仍按实际源尺寸做空间预检。

成功任务结果建议：

```json
{
  "projectId": "prj_english_01",
  "backupId": "bak_example",
  "snapshotAt": "2026-10-15T02:00:00Z",
  "destinationPath": "/Volumes/BackupDisk/english-2026-10-15.zip",
  "archiveBytes": 125000000,
  "sha256": "[实际归档摘要]",
  "savedAt": "2026-10-15T03:00:00Z"
}
```

`savedAt` 是另存时间，不是快照时间；示例值不对应真实文件。大整数继续沿用已有明确字节字段的无损编码。

### 3.3 失败与重启

未发布时失败只清理本次可识别临时文件，源归档和原目标保留；目标磁盘断开则记录残留待处理，不能追着一个后来同名的新目录清理。新文件已发布、结果未写完时，重启按目标身份及摘要核对是否完成，不能盲目再次覆盖。

任务返回 `sourceUnchanged`、`destinationPublished`、残留位置及原因等实际结果；失去访问时无法确认发布状态就标记未知，不能谎称旧目标一定仍在。外部另存完成不自动删除本机归档或取消其保护引用。

## 4 删除可清理备份

### 4.1 建议产品边界

首版一次只删除一份明确备份。先查看详情中的可删除性和保护原因，再提交带版本的请求：

```json
{
  "expectedRevision": "rev_example"
}
```

`revision` 是服务提供的不透明版本，涵盖登记内容、保护状态及详情核对时文件身份和内容指纹；不能只依赖修改时间，也不是管理凭据。原位重写仍须能被识别；大归档需要重新核对时先返回待检查及关联任务，校验完成才提供可提交版本。损坏归档绑定已经展示的现状指纹，不要求先恢复健康才能删。状态或文件变化后旧版本不继续代表刚才看到的对象，执行时仍重新检查所有引用。

### 4.2 哪些备份不删

| 条件 | 建议处理 |
| --- | --- |
| 当前维护基线，包括回收站中项目保留的基线 | `BACKUP_PROTECTED`，返回引用原因 |
| 正在恢复、另存或被未解决恢复操作引用 | 正在使用返回 `BACKUP_IN_USE`，恢复保护继续保留 |
| 同项目最后一份已验证且可访问的本机有效备份 | 建议手动删除也保护，先建立另一份有效本机备份 |
| 没有其他保护的手动备份 | 允许明确删除；“不自动清理”不等于永远不可删除 |
| 已损坏的归档 | 无其他保护时可以明确删除；不计入有效备份数量 |
| 文件已缺失的登记 | 报告缺失并按恢复核对流程处理，不冒充删除了一份真实 ZIP |

**“最后一份有效备份也不能手动删除”是本轮新增建议。** 既有规则只明确它不参与自动清理。本稿建议首版手动入口也不提供绕过；外部另存不自动算作另一份受平台持续验证的本机备份。其代价是清除项目后至少仍保留一份有效备份；“彻底移除该项目所有历史”若确有需要，应另定一个明确范围的入口，不暗藏在这里。

删除和自动保留清理共用按历史 `projectId` 管理的归档索引锁。保护引用的新增／解除也在同一协调机制下完成，防止两个删除任务各自看见“还有另一份”后删光。`canDelete` 只是展示，实际执行必须复核。

删除有效归档前，至少核实一份将保留的有效归档当前仍与登记摘要一致，并在删除期间持有保护引用；不能把仅仅“曾经验证过且文件还在”的另一 ZIP 当作有效替代。所需大文件校验进入重 IO 调度，不绕过资源限额。未知或失联不算有效替代，也不自动删除来替用户试错。

### 4.3 执行与结果

取得对象排他访问后，持久记录删除意图，核对源文件身份，删除这一归档并更新索引。操作不删除当前项目、回收站、恢复现场或其他归档。普通持久维护本身不阻止删除无保护旧归档；引用不清或 `recoveryRequired` 影响该归档时拒绝，不能猜测安全。

成功任务结果建议包含 `deletedBackupId`、`projectId`、`removedLogicalBytes`、`deletedAt` 和 `completed: true`。若 ZIP 已删除但索引尚未更新，重启核对并补齐登记，任务可以按既有中断协议返回实际 `deleted` 结果；不能再报告一份可恢复备份。文件仍在则保留登记并报告失败，结果不明则先核对。

没有通用跨重启请求去重承诺。重复提交已删除 ID 返回明确 `BACKUP_NOT_FOUND`，不选择另一份备份替代；响应丢失时优先查原任务和备份登记。

## 5 清理迁移后的旧工作区

### 5.1 选择记录，而不是任意路径

建议迁移成功时新增 `retiredRootId`，绑定一次已停用的源目录实例。固定迁移记录保存：

- `retiredRootId`、`migrationId`、迁移提交及完成时间。
- `oldRootPath`、磁盘卷身份、目录文件身份，及迁移目标／后续迁移链的提交依据。
- 迁移时源目录的持久文件清单和内容摘要，已识别可重建目录清单；未知文件也必须归入保留范围。
- 原迁移保护引用已经完整迁出的校验记录，以及当前清理状态、关联任务和残留位置。

记录及清理日志位于固定 `appLocalDataDir/migrations/` 中，不能放进待删除旧根。路径后来被用户换成另一份目录，不继承旧根清理资格。既有旧根缺少身份或清单依据时显示“无法自动确认”，不猜路径后递归删除。

多次迁移分别登记旧根。清理较早的旧根时，须能核对其目标到当前工作区的已提交迁移链及保护材料；原中间目标也已迁走不等于可以忽略验证。无法核对时先阻断，不能仅凭“不是当前位置”放行。

### 5.2 先预检，再执行

用户在工作区空间页选定旧目录，点击“检查可清理内容”。预检不修改文件，返回任务；完成后结果包含 `planId`、`retiredRootId`、旧位置、检查时间、逻辑字节数、文件数、警告和不可清理原因。通过时建议有效期 10 分钟，自预检完成起计算。

用户明确清理时，提交：

```json
{
  "planId": "cleanup_plan_example"
}
```

客户端不能改写计划里的路径、磁盘或文件清单。CLI 也执行同样两步；这是对明确对象的检查流程，不意味着平台必须让用户为每个文件逐次批准。

预检与执行共同检查：

1. 迁移已经完成，当前位置可访问且确属已提交的目标或后继工作区；没有会依赖旧副本的未解决切换、回退或恢复问题。
2. 实际目标是登记的卷和目录实例，不是当前工作区、与其重叠的父子目录、固定控制目录、迁移日志目录或 `.app`。不跟随符号链接穿出目标树，发现不能安全解释的特殊文件或嵌套挂载时拒绝自动清理。
3. 原有基线、回收站和受保护恢复现场已完整迁出，当前保护引用仍可解析到可访问的新副本；旧根不能是它们唯一可用的依据。
4. 旧根的持久文件与迁移时清单一致，没有新增、修改或缺失；已识别可重建区域按原归属处理，不把未知文件改分类为缓存。发现旧 AI 仍在写源码或数据时返回 `OLD_WORKSPACE_MODIFIED`，先找回改动，不提供 `force`。
5. 外部 AI、编辑器和数据库工具停止使用旧目录。平台检查不能代替系统级写锁，不能承诺任意外部并发写入下无损删除。

执行开始时验证计划未过期、未被其他任务消费且对象未变化，再重做关键检查；到期发生在已经接受的任务运行中不直接中断删除。变化、失联或身份不符时失效计划并要求重新检查。

只为同一 `planId` 提供有限去重：计划被接受时持久绑定任务 ID；响应丢失后再次提交同一个计划，返回原任务，不开始第二次清理。它不扩展成其他 SQL 或管理操作的通用幂等机制；服务重启后未消费计划失效，已消费计划仍可查询原任务。

### 5.3 删除范围和中断

建议首版在原位置按已核对清单删除，不先把整个目录改名到新位置，减少额外目录切换状态。开始前持久记录计划与操作进度；逐项核对身份，不跟随链接，不使用吞掉新文件的兜底递归删除。发现内容变化或未在清单中的文件时停止并保留剩余内容。

实际逐项删除绑定已验证的卷、根目录与父目录身份，使用句柄相对操作或等效核对；发现目录、链接或挂载变化即停止，不能只在预检做一次 `realpath` 后继续按旧字符串操作。已损坏归档的删除同样只针对详情与版本绑定的文件现状。

迁移后的旧根包含完整历史，清理意味着删除这份迁移时点副本，即使其中有后来已从当前工作区主动删除的历史文件。界面应清楚显示这一范围，不只写“清理缓存”。它不影响当前工作区内的备份和恢复现场。

部分清理后失败不能保证旧副本还能完整恢复。任务记录实际已删条目、未删条目、原因和残留路径，状态为 `failed` 或 `interrupted`，`completed: false`；重启不自动继续删除，也不激活旧根为当前工作区。再次清理先基于原清单与已完成记录生成新计划，已由该任务删除的文件允许缺失，其他变化仍拒绝；不能把新增文件悄悄扩进清理范围。

成功结果至少包含 `retiredRootId`、`oldRootPath`、`removedLogicalBytes`、`removedFileCount`、`completedAt`、`completed: true`。部分失败另带残留摘要；大量条目通过受控分页查看，不将几十万个路径塞进一个 JSON 响应。删除根目录并确认清单完成后才报告完成，固定清理记录保留以免同路径后来出现的新目录被误认。

### 5.4 与当前工作并行

旧根清理与新迁移、其他旧根清理互斥，并占用一个大型文件任务槽位；预检只读且低优先级。它不冻结当前项目的正常查询与保存，也不改变维护模式。开始时保留相关迁移记录和保护引用的读取资格，期间涉及同一保护材料的变更操作暂缓或返回忙碌，不能一边证明备份存在一边允许另一个清理器删掉它。

## 6 错误与保护信息

沿用统一错误体；`details` 给明确对象、触发条件、是否已经发生删除及下一步，不暴露到普通项目会话。

| 建议错误 | 含义 |
| --- | --- |
| `BACKUP_NOT_FOUND`／`BACKUP_INVALID` | 无对应登记或归档无法作为有效来源 |
| `BACKUP_PROTECTED`／`BACKUP_IN_USE` | 存在基线、最后有效份或活动读取等保护 |
| `DESTINATION_EXISTS` | 另存目标已存在且未明确覆盖 |
| `TARGET_CHANGED` | 详情版本、文件、目录或磁盘身份已改变 |
| `CLEANUP_PLAN_EXPIRED` | 旧根预检已过期，需要重新检查 |
| `OLD_WORKSPACE_MODIFIED` | 迁移后旧持久内容变化，可能存在未搬走的资料 |
| `WORKSPACE_IN_USE`／`RECOVERY_REQUIRED` | 当前身份或恢复链不允许清理 |
| `CLEANUP_INCOMPLETE` | 已部分删除，保留结果与残留，不能保证旧副本完整 |
| `SPACE_INSUFFICIENT`／`RESOURCE_BUSY` | 空间不足或资源／操作冲突，沿用现有语义 |

两个备份动作使用同项目归档索引与对象引用锁，不需要占用活跃业务 SQL 队列。工作区迁移等待它们安全结束；从回收站到重新登记的项目身份变化不能绕过这些历史引用。

## 7 建议取舍与验收

建议首版采用：历史 ZIP 原样另存；单份明确删除且保护最后有效本机备份；旧工作区通过登记身份、预检计划与明确执行清理，不开放任意路径删除。

最需要用户确认的新增取舍是“最后一份有效本机备份是否也保护手动删除”。本稿推荐保护，以保留恢复入口；代价和未来彻底清除入口已在第 4 节明确。

未来验收覆盖：项目已删除仍可另存历史备份、最后有效份保护、并发另存与删除、两份备份并发删除、目标被替换、外置盘断开、ZIP 已删但索引未写完、多次迁移、旧路径复用、旧 AI 继续写入、过期计划、重复提交同计划、清理中断及残余重试。本文没有执行这些删除或运行测试。
