# 最小静态应用包示例

状态：拟议包格式 v1 的规范样例；外部应用包检测、安装与更新尚未实现。此目录不能作为当前“导入完整项目备份”的输入。

专用 `local-app.json` 已按[项目与应用包格式 v1](../../../project-and-app-format-v1.md)整理为目标清单，尚未实现。`empty/seed` 初始化、`user_version` 关联及更新细则仍沿用[应用包设计候选](../../../web-app-package-design.md)，待确认和实施。整理规范不等于批准全部旧草案，也不代表新增安装入口或完成真实验收。

目录如下：

```text
minimal-app/
├── local-app.json
├── README.md                 仓库规范示例说明，未声明进入安装范围
├── docs/
│   ├── USER_GUIDE.md          给用户的使用/配置说明
│   └── DEVELOPMENT.md         给AI的技术/开发说明
└── dist/
    └── index.html
```

清单中的网页根为 `dist`，入口 `index.html` 相对网页根，使用实际文件导航 `files`。此页面没有 JavaScript、内联事件、外部资源、SDK 调用或数据保存；网络与设备需求为空。候选 `empty` 模式的数据版本为 0，不携带业务库、种子附件或建表脚本。此处只展示声明，不执行初始化。

`documentation.readme` 指向[用户使用说明](docs/USER_GUIDE.md)，`documentation.development` 指向[AI / 开发说明](docs/DEVELOPMENT.md)。它们都明确进入目标安装资料范围，且不成为网页根。本根 README 仅用于在仓库解释规范示例，未声明进入包复制范围；规范链接只供本仓库查阅，不假设安装后仍能访问仓库相对路径。分工见[两类应用说明](../../../application-documentation.md)。

[local-app.schema.json](../../local-app.schema.json) 使用 JSON Schema Draft 2020-12，文件自身包含全部定义。验证前须按严格 UTF-8 JSON 解析，拒绝重复键、注释、尾逗号、非有限数字和不合法的 Unicode。Schema 只检查结构与部分字符串规则，不修改或补齐清单。

后续实际检测还必须分别完成：

- 将版本段按数值比较，核对目标平台版本、API 主版本及实报的接口能力；Schema 通过不证明兼容。
- 检查声明内容存在、相对范围不重叠、路径/大小写/Unicode 名称无冲突；拒绝链接、特殊文件、嵌套挂载及禁止分发的控制资料。按当次真实运行限制检查字节长度，不能把 JSON 字符数当文件路径字节数。
- 按当前 URL 与浏览器策略验证 origin、保留域、端口、规范化和同组重复来源；声明不授予系统设备权限，也不证明 DNS、CORS、网络或外部服务可用。
- 对真实 HTML 和资源执行语法、UTF-8、入口、MIME、子路径和 CSP 检查；本轮未运行安装器或浏览器，不把此静态文件作为已安装或真实运行证据。
- 若另行制作 seed 包，按候选规则准备一致性 SQLite 快照和数据说明，验证完整性、外键、`user_version` 以及伴随文件；本例没有种子，也不代表该初始化方案已获批准。

检测预算、计划有效期、正式错误码、安装更新和备份兼容实现须按主方案另行定稿。本例不写死旧草案的体积、文件数、深度或时间建议，也不改变现有开发项目和备份。
