# 工作区持久身份与离线兼容修复

状态：实现、自动化检查、当前工作区公开离线修复、新包真实启动及样本应用重启验证已完成，详见[实际验收记录](workspace-identity-repair-verification.md)。未额外重启整台 Mac。

更新日期：2026-10-19

## 1 问题与身份规则

旧版将文件系统 `device + inode` 持久保存为目录/数据库身份。2026-10-19 本机重启后，当前工作区 `inode=124141598` 不变，设备号从 `16777231` 变为 `16777233`；路径、迁移任务和标记均匹配，但启动校验错误阻断。

macOS 新写入的持久身份包含 `device`、`inode`、`volumeUuid`。跨重启匹配使用卷 UUID 和 inode；卷 UUID 通过已打开文件描述符的系统属性取得，不调用外部命令，不以路径存在或单独 inode 相同作为同卷证据。UUID 缺失、格式错误、换卷、换目录或符号链接不自动放行。

运行期间的 fd、设备号、inode、父链、清理预览及扫描缓存绑定继续严格校验当前对象；设备号并未从所有检查中删除。项目/数据库登记、迁移、恢复、回收站和历史清理中的持久引用使用新身份；旧数组与旧对象仍可读取。

## 2 旧记录兼容边界

旧记录没有卷 UUID，不能自动猜测重启后的设备号属于原卷。新增离线公开入口只处理设置中已经选定、日志完整提交/完成/解决、代次应用完成且目录 inode 未变的旧版迁移目标；不创建新工作区、不移动数据、不改设置指向、不回退旧根。

修复先预检，再以精确计划 ID、当前工作区和卷 UUID 显式确认。修复在固定实例锁下执行；应用服务运行时拒绝写入。预检不启动应用、不初始化缺失环境，也不读取管理令牌或打开业务数据库。

修复写入：

- 当前工作区 `.platform/identity-binding.json`：限定该目录、稳定卷/目录身份与被核对的旧设备号。
- 固定数据根 `identity-repairs/<planId>/`：保存原 settings、迁移 journal、选择 marker 的字节副本及 SHA-256、完整预检计划和绑定收据。

原 settings、迁移日志、选择标记、项目登记和业务文件不由修复改写。收据与绑定采用私有权限及不覆盖的原子发布；中断后只接受内容完全一致的准备记录，不删除冲突证据。收据缺失、篡改或计划摘要不匹配时拒绝兼容。

读取旧引用时，只有该已绑定范围内、实际卷 UUID 相同且具体对象 inode 仍匹配，才可兼容旧设备号。范围外的旧保留根不会被顺带授权；无迁移依据的默认旧工作区、未完成迁移、真实换卷/根替换或稳定 UUID 已不匹配均不在此入口自动修复。

## 3 离线命令

命令由安装包内的实际 CLI 路径执行，使用固定开发身份和数据根，没有任意根目录覆盖参数。

| 命令 | 行为 |
| --- | --- |
| `workspace identity-repair-plan --json` | 返回只读预检、`planId`、`workspaceRoot`、`volumeUuid`、原件摘要与预计写入范围 |
| `workspace identity-repair --input <JSON文件或-> --json` | 输入精确 `planId`、`workspaceRoot`、`volumeUuid` 与 `confirm: true`，离线绑定或返回已绑定 |

确认前核对实际目录、迁移标记与已有保护证据，并保留项目、源码、固定 SDK、数据库、附件、备份、维护、回收站和恢复现场基线。陈旧计划、改变的路径/卷、未确认输入或实例锁冲突均拒绝。未知结果时先重新预检，不盲目重发其他写入。

绑定完成后正常启动新版，CLI 重新发现服务；不沿用旧端口或旧凭据。正常启动仍可更新运行发现和原子保存本机设置，需与“离线修复本身没有改原件”分别审计。

## 4 迁移、清理与版本兼容

绑定是本机兼容证据，不进入项目 ZIP。公开迁移不把绑定文件原样复制到新根；新根和经验证重绑的活跃项目、回收项使用新的稳定身份，原绑定与固定收据保留在原范围作为证据。

历史清理仍需要新实例的新预览和明确选择，旧预览不跨实例执行。持久根身份只帮助验证历史已接受的部分删除进度；fd/父链/条目与实际删除回执仍逐项核验。混合新旧历史迁移链缺少可核对对象时保守阻断，不按单独 inode 放行。

新身份写入后，不承诺旧程序能够读取新控制格式；软件降级不是数据恢复方式。固定 SDK、项目源码、锁文件及用户文档不因本次平台修复自动升级。Windows 按其稳定优先工作线继续推进；离线身份修复也受平台运行门禁约束，本次 macOS 修复不构成 Windows 运行时开放或验收。

## 5 验收要求

自动化覆盖稳定身份的设备号变化、不同卷和 inode 拒绝、旧数组/对象、符号链接与祖先替换、离线实例锁、确认/陈旧计划、收据篡改、准备中断与幂等、项目/数据库替换、恢复、回收站、迁移链和部分清理进度。

实际验证使用明确可丢弃项目完成保存、备份、删除恢复及应用重启；原开发资料按修复前基线比对。当前机器已发生的真实重启场景、新记录设备号变化模拟和另一次系统重启必须分别记录，不用进程重启宣称完成系统重启测试。安装包检查签名、架构、包内 CLI/SDK、DMG 内容及摘要，再交付具体文件。
