# 内置 Node 与首批运行连接器（历史讨论）

更新日期：2026-10-19

## 1 已确认的方向与当前边界

用户希望普通使用者无需配置 Node，同时支持 Claude Code 和网易云 SDK，并明确选择内置 Node。平台继续采用 Tauri + Rust + SQLite，项目页面继续通过平台 SDK 使用能力。

- 平台携带私有 Node 运行环境，用于当前所需的 SDK 适配；不依赖用户安装的系统 Node 来运行该适配器。
- Claude Code 由 Rust 桥接本机 CLI；内置 Node 不等于已经安装、分发或登录 Claude Code。其发现、安装引导、认证和兼容版本需要单独落实。
- 网易云优先沿用 radio-bob 使用的社区 SDK，当前包支持函数调用；不必因该 SDK 采用 Node 而托管每个应用的 HTTP 后端。
- 本次选择不开放任意项目脚本、任意 shell、通用 Node/Rust 后端、SSR、Docker 或外部包自带可执行程序。
- 现有系统 Node/npm 的项目构建机制继续按原约定执行。私有运行时不自动接管构建、不更改系统工具链，也不改写已有项目的源码、SDK、锁文件或清单。
- Fish TTS、通用密钥连接器及项目任意联网代理不因内置 Node 自动成为已确认交付；此前的保密 API key 后置约定继续有效。

当前程序没有携带这份 Node，也没有对应连接器 SDK、CLI 或 HTTP 接口。外部应用包仍按 `static-web` 目标规划；不能在 `local-app.json` 中新增自定义字段来获得执行权限。

## 2 稳定性优先的实施建议

以下是围绕已确认方向的实现建议；精确补丁版本、文件布局、协议、默认限额和凭据生命周期尚未定稿。

1. **固定配套资源。** 从受维护的 Node LTS 分支选择版本，在目标系统验证后锁定精确版本；Node、网易云 SDK、完整运行依赖和适配器随同一平台版本发布，保留来源、校验摘要和许可证。运行时不执行 `npm install`，不从项目目录或系统 PATH 任意选择替代程序。
2. **独立辅助进程。** Rust 按需启动网易云适配器，通过有长度限制的结构化输入输出通信，不调用 SDK 的 HTTP 启动入口。限制并发、时间、日志和输出，处理退出与取消；进程复用和空闲退出规则在验证后确定，不预先承诺每个请求启动一次或永久常驻。
3. **限制故障影响。** 适配器缺失、崩溃或超时，应使相关音乐操作明确失败，平台管理、已有网页、SQLite 和附件仍应可用。需要通过故障注入验证，不把独立进程描述成系统沙箱或绝对隔离。
4. **持久状态独立。** Cookie、登录状态、用户数据和 SDK 临时状态不能只放在进程内，也不能写回安装资源。每项目身份、可写目录、权限、归档/复制/恢复时的凭据处理，以及维护/迁移开始后的任务协调，须在开放真实登录前确定。SDK 的默认系统临时目录不能直接作为共享项目会话存储。
5. **请求结果可核对。** 两个连接器均检查项目会话与文档代次；任务结果提交前再次检查维护、删除和根身份。平台退出应回收辅助进程与 Claude 子进程。未知结果不自动重放；重启适配器不表示可以无条件重试登录或其他已发出的操作。
6. **资源随程序更新。** 建议将只读运行时及固定依赖作为程序资源，共享磁盘上的运行时不等于跨项目共享登录会话。Mac 嵌套程序签名、公证、实际启动和 Windows 两版目标系统分别验证。安装体积和补丁更新成本由实测记录，不预先给出数值或承诺稳定性已经通过。

Node 的受维护分支与独立程序来源见 [Node 发布政策](https://nodejs.org/en/about/previous-releases)和[官方下载](https://nodejs.org/en/download)。选择 LTS 和锁定版本减少环境差异，但网易云社区接口变化、网络、账号权限及 Claude 认证/额度仍是另外的失败来源。

## 3 分步验证顺序

| 步骤 | 范围与通过条件 | 当前状态 |
| --- | --- | --- |
| N0 资源与协议 | 确定目标 Node/SDK 版本、完整依赖与许可证；设计项目范围、输入输出及凭据规则，不增加现有清单必填字段 | 未开始；已有下述离线探测 |
| N1 私有运行时 | 内部包从 Finder/系统入口使用自身 Node，在无系统 Node 的受控环境完成无网络辅助任务；错误资源不阻止平台核心启动 | 未开始 |
| N2 网易云适配 | 只开放搜索、扫码登录、状态及播放地址；验证无需本地 HTTP 端口、项目会话区分、临时目录和取消；真实登录/歌曲权限单独记录 | 未开始 |
| N3 Claude 桥接 | 固定生成参数，禁用电台不需要的工具；验证 CLI 探测、真实结构化结果、未登录、超时、取消、退出和版本不兼容 | 未开始 |
| N4 平台接入 | 明确项目能力与任务接口，复用现有 SQLite/附件；通过旧页面、维护/恢复/删除/迁移和晚到结果验证后再开放样本 | 未开始 |
| N5 实际交付 | 用可丢弃 radio-bob 副本分别验证桌面/浏览器、重启、辅助进程故障与真实播放；Mac 签名包及 Windows 实机各自验收 | 未开始 |

既有任务记录不等于已具备外部 CLI 的取消与进程回收。运行连接器也不能通过现有构建脚本偷偷启动；项目构建与运行任务分别管理。

## 4 2026-10-19 已完成的只读与离线探测

- 检查 radio-bob 源码：Claude 调用为 stdin 输入和 JSON 输出，当前电台调用关闭工具、MCP 和会话持久化；Node 并非这条 CLI 桥接的必需运行时。
- 检查其安装的 `@neteasecloudmusicapienhanced/api 4.41.1`：自带说明提供直接引入调用方式，`main.js` 导出功能函数；监听端口发生在单独的 `serveNcmApi` 调用中。
- 使用现有系统 Node `24.14.1`，在独立可丢弃临时目录中加载 SDK，并核对 `cloudsearch`、`song_url_v1`、`login_qr_key`、`login_qr_create`、`login_qr_check`、`login_status` 为函数。
- 以人工测试 key 调用本地二维码生成；主动阻止网络连接和端口监听，结果为成功生成图片、网络连接尝试 0、监听尝试 0。临时目录与最小环境避免读取 radio-bob 的 `.env` 或使用原项目的 SDK 临时状态。

这仅证明该版本 SDK 可脱离 HTTP 服务加载并执行本地二维码生成，不证明真实扫码、登录、搜索、播放或上游兼容。没有执行真实 Claude、网易云账号或 TTS 请求，没有内置 Node、构建新安装包或完成故障测试；没有修改原项目、业务数据、平台开发身份或数据根。
