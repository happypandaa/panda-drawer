## 1. 设计目标

普通用户在任何时刻都知道三件事：

1. **现在到哪一步**：同一个弹窗里显示步骤条和当前状态。
2. **文件在哪里**：每个结果页都有一行“文件在哪里”，写明完整路径或“没有留下文件”。
3. **接下来做什么**：每个状态只有一个主按钮。

尽量减少：重复选目录、重复粘贴地址、手动整理信息给 AI、理解技术概念。

---

## 2. 两类项目（核心模型）

| | 托管项目 | 外部项目 |
|---|---|---|
| 来源 | 从 Git 添加、新建项目 | 添加本地项目（包括 AI 帮忙改好的 Git 项目） |
| 位置 | 熊猫小抽屉的**项目目录**（软件创建） | 用户自己选的文件夹，原地不动 |
| 谁能修改源码 | 用户和外部 AI | 用户和外部 AI |
| 运行的是 | 平台准备／构建好的版本 | **直接运行原文件夹里的代码** |
| AI 改坏后表现 | **更新失败**，旧版本照常用 | **启动失败** |
| 卸载前清理 | 删除整个项目目录 | 不删除 |
| 删除应用 | 按现有删除契约 | 只移除平台登记及平台私有的配置、数据、缓存，原文件夹保留 |

**项目目录的不变量：只放添加成功的项目，不放半成品。** 不承诺“项目目录里的源码一定能运行”——外部 AI 随时可能改坏，运行稳定性由“托管项目运行的是平台准备的版本”保证。

**应用数据**（记录、附件、设置）单独保存在平台位置，不放进源码。第一版**不做数据备份、不做旧数据迁移**，由用户自己保证。

## 3. 已确定的规则

1. 任何失败（下载、检查、准备、构建、添加、启动、更新）都表现为：**报错 + 一份可复制给外部 AI 的说明**。
2. Git 项目在检查、准备、构建任一步失败：**本次下载的文件直接删除**，不进项目目录，不保留待处理记录。错误信息保留在弹窗里，直到用户关闭；复制给 AI 的说明自动带上 Git 地址和失败原因。
3. AI 改好 Git 项目后，把项目放在本机某个文件夹并告诉用户路径；**用户自己用“添加本地项目”添加**。平台不追踪这个过程。
4. 本地项目识别不了或不符合要求：复制带本地路径的说明给外部 AI；AI 在原文件夹修改；**用户改完后自己重新添加**。
5. **同一个文件夹不能重复添加**：检查前发现该路径已登记，直接提示并提供跳转到已添加的应用。
6. 不做“待接入”分组。进行中的任务看右上角“任务”；本地弹窗提供“最近选过的文件夹”减少重复查找。
7. 说明里**不强制禁止删除数据**：要求 AI 在执行任何会删除或清空应用数据、数据库、上传文件的操作前，先向用户说明影响并取得明确同意。
8. 卸载前清理：确认页列出将被删除的托管项目（名称 + 路径），并说明外部项目文件夹不会被删除；不需要列出“未保存修改”清单。
9. 第一版不做数据备份与迁移。
10. 外部项目继续“直接运行外部代码”，不要求先分离出运行副本。

## 4. 对用户使用的词

只用：**项目目录**、**你的文件夹**（外部项目）、**应用**、**应用数据**、**添加**、**检查**、**准备**。

不对用户使用：导入、安装候选、来源记录、外部引用、发布代、运行副本、受管、清单（技术细节放进“检查详情”）。

原则：
- 原因用普通话写“结果和影响”，技术原文放进可展开的“检查详情”，复制给 AI 时自动附带。
- 不承诺没发生的事：检查通过 ≠ 能运行；添加成功 ≠ 已打开；复制说明 ≠ AI 已修改。
- 关闭弹窗时只说“在后台继续”，从不说“已取消”，除非任务确实停止。

## 6. 从 Git 添加

### 6.1 表单

- 标题：**从 Git 添加项目**
- 说明：粘贴仓库地址。熊猫小抽屉会下载源码，检查能否使用，再添加到你的项目列表。
- 字段“Git 仓库地址”，输入时即时校验：
  - 通过：`GitHub 公开仓库 · 将使用默认分支`
  - 不通过：`这不像仓库地址。请复制浏览器地址栏里以 https://github.com/ 或 https://gitee.com/ 开头的地址。`
- 只读信息“添加成功后，源码放在”：`<项目目录>/<仓库名>`
  - 说明：这是熊猫小抽屉的项目目录，你和 AI 都可以修改里面的源码。检查不通过时，下载的文件会自动删除，不留半成品。要换位置，在 设置 › 存储位置 修改项目目录。
  - 同名文件夹已存在时自动用 `<仓库名>-2`，不覆盖。
- 三个位置说明（小卡片）：源码在项目目录里，卸载前清理会删除它；应用是平台准备的运行版本；应用数据单独保存，重要数据请自行备份。
- 高级选项（折叠）：分支（留空用默认分支）、显示名称（留空用仓库名）。
- 开始前说明：接下来会依次：下载源码 → 检查项目 → 准备应用 → 添加应用 → 清理临时文件。需要运行构建脚本时会先问你；任何一步不通过，都会给你一份可以复制给 AI 的说明。
- 按钮：`开始添加`（主）、`取消`。
- 上次因失败或“稍后再试”关闭时，再次打开表单，地址栏预填上次的地址。

### 6.2 同一仓库已添加过（开始下载前检查）

- 标题：**这个仓库已经添加过：「{名称}」**
- 按钮：`打开已添加的`（主）、`仍然另外添加一份`（新的一份从空数据开始，两份互不影响）、`取消`。
- “更新已有应用并保留数据”走应用详情里的现有更新流程，不在这里做。

### 6.3 进度

同一个弹窗内，步骤条五步：**下载源码 → 检查项目 → 准备应用 → 添加应用 → 清理临时文件**。无法准确计算时只显示已下载量和用时，不伪造百分比。

| 阶段 | 标题与说明 | 操作 |
|---|---|---|
| 下载 | 正在下载源码 · 已下载 {大小} · 用时 {时长}。全部通过并添加成功后，源码才会放进 {项目目录路径}；在这之前都在临时位置。 | `在后台继续`、`取消下载` |
| 检查 | 正在检查项目… 只读取文件，不会修改。 | — |
| 准备 | 正在准备应用… 正在安装依赖，可能需要几分钟。 | `在后台继续`、`取消` |
| 添加 | 正在添加应用… 这一步很快，完成前不能取消。 | 关闭按钮禁用 |
| 清理 | 正在清理本次临时文件… | 关闭按钮禁用 |

- 进行中关闭弹窗：任务继续，显示提示条“添加会在后台继续。可以在右上角“任务”里查看进度。”，带 `查看任务`。需要用户确认或出错时，任务中心提醒；点开回到同一个弹窗的对应状态。
- 软件退出导致中断：重开后“任务”里显示为“需要查看”，临时文件自动清理，提供 `重新下载`、`关闭`。
- 取消下载确认：`停止下载？已下载的部分会被清理。` 按钮 `停止下载`、`继续下载`（主）。

### 6.4 需要构建（准备阶段暂停）

- 标题：**这个项目需要先构建一次**
- 说明：项目说明要求运行构建脚本 `{脚本名}`，生成可以运行的网页和程序。需要你同意后才会运行。
- 要点：在单独的临时位置运行，不改动源码；只运行这一条脚本，不执行依赖包自带的安装脚本；不读取或注入应用设置和密钥。
- 警示：脚本来自仓库作者，会以你的身份在这台电脑上运行。只在你信任这个项目时继续。
- 可展开“查看脚本内容”。
- 按钮：`同意并继续`（主）、`不构建，关闭`。选后者等同失败处理：删除下载的文件，关闭。

### 6.5 下载失败

源码还没进入项目目录，只说明没有留下文件。

| 情况 | 文案 | 按钮 |
|---|---|---|
| 超时／网络错误 | **下载没有完成** 连接 {网站} 超时。请检查网络后重试。文件在哪里：你的电脑上没有留下文件。 | `重试下载`（主）、`修改地址`、`稍后再试` |
| 仓库不存在或私有 | 找不到这个仓库，或它是私有的。请确认地址能在浏览器里打开。目前只支持公开仓库；私有项目可以先下载到电脑，再用“添加本地项目”。 | `修改地址`、`改用本地添加` |
| 不支持的网站 | 暂不支持这个网站。目前支持 GitHub 和 Gitee 的公开 HTTPS 地址。 | `改用本地添加` |
| 磁盘空间不足 | 磁盘空间不足，还需要大约 {大小}。可以先到“空间”释放可重新生成的文件。 | `打开空间`、`重试` |
| 位置不能写入 | 不能写入 {路径}。请在 设置 › 存储位置 换一个项目目录，或在系统设置里允许访问。 | `打开设置` |

### 6.6 检查、准备或构建不通过

- 步骤条在失败的那一步标为需要注意。
- 标签：`需要修改` 或 `当前不适合`（判定见第 7.3 节）。
- 标题：**这个项目暂时不能添加**
- 原因：最多 3 条，每条“普通话标题 + 一句影响”（对照表见第 10 节）。
- 文件在哪里：**下载的文件已经删除，项目目录里没有留下东西。**
- 引导：可以把下面的说明复制给原来帮你开发的 AI（或能读写本机文件夹的 AI）。它会下载这个仓库、在你电脑上的文件夹里改好，并告诉你文件夹位置。改好后，用“添加本地项目”添加那个文件夹。
- 按钮：`复制说明给 AI`（主，复制第 8.2 节“添加失败”说明，带 Git 地址）、`关闭`。
- 检查详情（折叠）：技术原文，已包含在复制内容里。
- 准备或构建失败的标题改为 **准备应用时出错** 或 **构建没有成功**，其余相同。

### 6.7 添加成功

- 步骤条全部完成。
- 标题：**已添加「{名称}」**
- 说明：临时文件已清理。还差 {n} 项设置就可以使用。（或：可以直接使用。）
- 位置清单：
  - 源码：`{项目目录}/{名称}`，带 `在 Finder 中显示`；想改功能时，交给 AI 修改这里。
  - 应用：在“我的项目”里打开。
  - 应用数据：单独保存在熊猫小抽屉里。
- 按钮：有必填设置时 `去设置`（主）；否则 `打开应用`（主）。另有 `完成`。“去设置”只进入设置，保存设置不自动打开应用。
- 完成、进入设置／应用或关闭成功页后结束本次添加会话，再次打开显示新表单，保留上次提交的仓库地址。旧任务仍可查看，但不会打开后来的新添加会话。
- 提示：以后想改功能：应用详情 › 开发与更新 › 交给 AI。
- 已添加但清理失败：标题 **应用已添加，临时文件还没清理完**，说明“不影响使用。剩余 {大小}。”，按钮 `重试清理`（主）、`稍后`。
- 添加结果不确定：**还不能确定应用是否已经添加。正在核对，请不要重复添加。** 按钮 `重新核对`。不得自动重复写入。

## 7. 添加本地项目

### 7.1 选择文件夹

- 标题：**添加本地项目**；说明：选择电脑上已有的项目文件夹，检查它能否在熊猫小抽屉里使用。
- 步骤条：**选择文件夹 → 检查项目 → 添加应用**。外部项目不复制、不准备，所以没有准备和清理步骤。
- 拖放区 + `选择文件夹…`；选中后显示路径和 `换一个`。
- 三条保证：
  - 检查只读取文件，不修改、不移动这个文件夹。
  - 添加后应用直接运行这个文件夹里的代码，你和 AI 继续在这里修改。
  - 应用数据另外保存；原项目里的数据不会自动带过来。
- **最近选过的文件夹**：最多 5 条，每条显示路径和上次结果（上次未通过／已添加）；点一下直接开始检查。按路径记住上次的检查原因，重新检查时可显示“和上次相比：已解决 2 项，还剩 1 项”。
- 按钮：`开始检查`（主）、`取消`。

### 7.2 同一文件夹已添加过（检查前判断）

- 标题：**这个文件夹已经添加过了**
- 说明：「{名称}」使用的就是 {路径}。同一个文件夹不能添加两次。
- 按钮：`打开「{名称}」`（主）、`查看应用详情`、`换一个文件夹`。

### 7.3 四种检查结果

每种结果页结构一致：标签 + 标题 + 最多 3 条原因 + “文件在哪里” + 一个主按钮 + 检查详情（折叠）。

| 结果 | 判定 | 标题 | 按钮 |
|---|---|---|---|
| **可以添加** | 声明与必要文件满足当前 Node 入口，依赖与运行材料齐全 | 「{名称}」可以添加 | `添加`（主）、`取消` |
| **需要修改** | 缺平台声明、端口／协议不符、只能用开发服务器运行、数据写在项目目录、**缺依赖、缺构建结果**等，可以通过修改解决 | 「{名称}」需要修改后才能添加 | `复制说明给 AI`（主）、`关闭` |
| **当前不适合** | 主要功能依赖 Python／Java／Docker／多服务／本机编译组件等平台不支持的能力，改造约等于重写 | 这个项目目前没法在熊猫小抽屉里运行 | `复制说明问 AI 有没有替代办法`（主）、`关闭` |
| **信息不足** | 无法确定要运行什么 | 见下表 | 见下表 |

“可以添加”页展示：名称与版本、源码（原地运行，不移动不修改）、应用数据（新建，从空白开始）、需要填写的设置数量，以及提示“原项目里的数据不会自动带过来，需要的话请自己处理”。

“需要修改”“当前不适合”页的“文件在哪里”：**你的文件夹保持原样，没有添加任何内容。** 底部提示：AI 改完后，重新点“添加本地项目”选择这个文件夹（它会出现在“最近选过”里）。

“信息不足”的细分：

| 情况 | 文案 | 按钮 |
|---|---|---|
| 一个文件夹里有多个应用 | 这个文件夹里有 {n} 个应用，要添加哪一个？（单选列出子目录和简述） | `检查所选目录`（主）、`复制说明给 AI` |
| 没有读取权限 | 系统没有允许熊猫小抽屉读取这个文件夹。 | `重新选择并授权` |
| 空文件夹 | 可以直接生成一个起始项目并添加。（沿用现有空目录流程） | `生成并添加项目` |
| 平台导出的完整项目（含 project.json） | 这是熊猫小抽屉导出的完整项目，应该用导入完整项目的方式添加。 | `改用导入完整项目` |
| 只有安装包或压缩包 | 里面没有源码，无法检查。请找到项目源码文件夹，或问原作者要 Git 地址。 | `复制说明给 AI` |
| 文件太多，检查没有完成 | 可能选到了上层文件夹。请选择项目本身所在的文件夹。 | `重新选择` |

“选择子目录”只在平台能支持该子目录作为应用根时提供；否则只给“复制说明给 AI”（见第 12 节）。

### 7.4 检查后文件夹被改动

确认添加时，发现文件夹在检查后有改动：**检查完成后文件夹有新改动，需要重新检查一次再添加。** 按钮 `重新检查`。（沿用现有 `expectedRevision` 核对。）

### 7.5 添加成功

- 标题：**已添加「{名称}」**；说明：应用现在使用全新的空数据。
- 位置：源码 `{路径}`（原位置，未改动）；应用数据新建，保存在熊猫小抽屉里。
- 按钮：`打开应用` 或 `去设置`（主）、`完成`。
- 不做旧数据识别与迁移。

## 8. 交给外部 AI 的说明

平台不自动发送、不上传目录。用户复制后自行粘贴给 AI。检测到已验证的 Codex 时，额外提供 `在 Codex 中打开草稿`（只打开未发送的草稿）。

### 8.1 三种说明

所有说明共用同一份正文和同一份平台要求，只是附带的信息不同：

| 说明 | 入口 | 自动附带 |
|---|---|---|
| **评估** | 两个添加弹窗底部链接，添加前即可使用 | 可选：Git 地址或本地路径（弹窗里已填就自动带上；不填则评估“当前对话里正在开发的项目”） |
| **添加失败** | Git 检查／准备／构建失败；本地“需要修改／不适合／信息不足” | Git 地址（含分支、提交）或本地路径；检查时间与原因（普通话 + 技术原文）；日志尾部；平台版本 |
| **启动／更新失败** | 第 9 节两个报错页 | 源码路径；应用名称与版本；运行或构建日志尾部；平台版本 |

评估弹窗内容：
- 标题：**先让 AI 看看能不能用**
- 说明：复制一份说明，发给原来帮你开发项目的 AI。不用先添加，也不用等失败。
- 字段：评估哪个项目（可不填，可选文件夹）。
- AI 类型二选一：
  - **能读取项目文件夹的 AI（推荐）**：Codex、Claude Code、Cursor 等编程工具，可以直接看文件，之后也能直接修改。
  - **网页聊天 AI**：读不到你电脑上的文件，结论只能作参考。
- 按钮：`复制评估说明`（主）、`预览全文`。
- 复制后提示：已复制。粘贴给 AI，看它的一句话结论：可以接入就回来添加；需要修改就让它改好再添加；当前不适合就不用继续。

### 8.2 说明正文要求

以现有 `docs/project-compatibility-review-prompt.md` 的可复制 prompt 为基础，平台要求随安装版本打包，复制时写入平台版本号，不依赖对方读取本机文档或仓库链接。在此基础上调整：

1. **开头**：请帮我判断这个项目能否在“熊猫小抽屉”中使用，以及我接下来怎样做最省事。我不懂代码，请用普通话回答，先给结论。
2. **【项目信息】由平台自动填写**：路径或 Git 地址、分支、提交、检查时间与结果、原因列表、日志尾部、平台版本。
3. **【先确认你能看到什么】**：说明实际读到了哪个文件夹或版本。读不到时，第一句就告诉用户，并建议换成能读写本机文件夹的 AI；不要凭聊天记忆或 README 猜测；不要让用户上传整个项目、.env、数据库或账号信息。
4. **【先回答】**：A 一句话结论（可以接入／需要修改／当前不推荐／信息不足）；B 用户现在只需做的一件事；C 主要功能能保留哪些、会失去什么；D 简短表格：文件依据 → 问题 → 处理；E 推荐的一条路线；F 之后需要实测什么。
5. **【修改时的边界】**（添加失败、启动／更新失败两种说明使用）：
   - 先回答，等用户同意再修改。
   - 只修改指定的项目文件夹；保留主要功能；不读取或输出 .env、密钥。
   - **任何会删除或清空应用数据、数据库、上传文件的操作，先说明影响并取得用户明确同意。**
   - 建议修改前用 Git 保存一个版本（项目是 Git 仓库时）。
   - 改完列出改了哪些文件。
6. **【交付方式】**：
   - 来自 Git 的项目：请把仓库下载到用户电脑上的一个文件夹里修改；完成后告诉用户该文件夹的完整路径，并提醒用户在熊猫小抽屉里用“添加本地项目”添加它。
   - 本地项目：在原文件夹修改；完成后提醒用户在熊猫小抽屉里重新点“添加本地项目”选择这个文件夹。
   - 托管项目更新失败：在项目目录中的源码上修改；完成后提醒用户在应用详情里重新“构建并更新”。
   - 外部项目启动失败：优先用 Git 撤回到上一次能运行的版本，或修复后提醒用户重新打开应用。
7. **【平台要求】**：同源、随版本附带的当前实现摘要。

### 8.3 网页 AI 与读不到文件夹

- 选择“网页聊天 AI”时，默认附带公开材料摘录：目录结构（3 层，排除 node_modules、.git、数据目录）、`local-app.json`、`package.json`、主要入口文件开头、README 前 200 行、`.env.example`；约 20 KB 以内；展示文件清单，可取消。永远不附带 .env、密钥、数据库、上传文件。摘录要标明“这是摘录，不是完整工程”。
- 弹窗内链接“AI 说读不到文件夹？”，打开说明页：
  - 推荐：换一个能读取文件夹的 AI，把同一份说明粘贴进去。按钮：`在 Codex 中打开草稿`（可用时）、`在 Finder 中显示文件夹`、`复制文件夹路径`。
  - 继续用网页 AI：`复制附带材料的说明`，并注明判断只能作参考。
  - 警示：不要把整个项目压缩上传，也不要发送 .env、数据库或账号信息。

## 9. 添加后的报错

### 9.1 外部项目启动失败

- 触发：打开外部项目时进程启动失败、协议握手失败或健康检查失败。
- 标题：**「{名称}」没能打开**
- 说明：这个应用直接运行你文件夹里的代码，最近的修改可能让它启动不了。你的应用数据没有被改动。
- 文件在哪里：`{源码路径}`，带 `在 Finder 中显示`。
- 按钮：`复制说明给 AI`（主，启动失败说明，带路径和当前错误摘要）、`再试一次`、`关闭`。
- 检查详情：当前任务错误码与简短原因（配置值脱敏，不保存构建／npm输出）。

### 9.2 托管项目更新失败

- 触发：在应用详情“构建并更新”时检查、构建或核验失败。
- 标题：**更新没有成功，请核对处理结果**
- 说明：检查或构建阶段失败时，明确说明当前程序是否仍为原登记版本；提交结果未知时显示待核对，不能承诺正在使用的版本不受影响。
- 文件在哪里：`{项目目录}/{名称}`。
- 按钮：`复制说明给 AI`（主，更新失败说明）、`关闭`。

### 9.3 托管项目新版本启动失败

- 更新成功后首次启动失败，按 9.1 处理。
- 平台不提供程序退回按钮或上版索引。用户将说明交给外部 AI，在作者源码中检查或取回可用版本，再按现行“构建并更新”流程交付；源码 Git 不恢复数据库、附件或配置。

## 10. 技术原因 → 用户文案对照

| 检查发现 | 标题 · 影响 | 结果归类 |
|---|---|---|
| 缺少 local-app.json | 缺少熊猫小抽屉的应用说明文件 · 平台不知道它叫什么、从哪里启动。 | 需要修改 |
| 固定端口／未实现启动协议 | 程序固定使用 {端口} 端口 · 需要改成由平台分配，否则可能和其他应用冲突。 | 需要修改 |
| 数据写在项目目录 | 数据写在项目文件夹的 {目录} 里 · 需要改为写到平台提供的数据位置，以后更新才不会丢。 | 需要修改 |
| 只能用开发服务器／SSR 运行 | 网页只能用开发模式运行（npm run dev）· 需要改成先构建好的网页。 | 需要修改 |
| 未处理 shutdown | 收到“关闭”通知后没有退出 · 关窗时程序需要先保存再结束，否则可能丢失未保存的数据。 | 需要修改 |
| 密钥写在前端代码 | 密钥写在网页代码里 · 需要移到应用设置里，由程序在后台使用，避免泄露。 | 需要修改 |
| 外部项目缺依赖或构建结果 | 依赖还没有安装／还没有可运行的构建结果 · 需要在这个文件夹里准备好。 | 需要修改 |
| 缺锁文件或依赖写法不支持 | 缺少依赖版本记录／依赖的写法平台暂不支持 · 平台无法确定该装哪个版本。 | 需要修改 |
| 原生扩展（.node） | 用到了需要在本机编译的组件 · 平台暂时无法准备。 | 当前不适合（或问 AI 替代） |
| Python／Java／Docker／多服务 | 主要功能依赖 {运行环境}／需要同时运行 {n} 个服务 · 熊猫小抽屉目前只运行“网页 + 一个 Node 服务”的应用。 | 当前不适合 |
| project.json | 这是熊猫小抽屉导出的完整项目 · 应该用导入完整项目的方式添加。 | 信息不足（改入口） |

Git 项目缺依赖、需要构建，由平台在“准备应用”阶段处理，不算失败；准备或构建本身失败才走 6.6。

## 12. 与现有契约的差异，以及实现前需确认的点

1. **Git 源码的位置与可编辑性。** 现状：来源记录和源码副本在工作区 `.platform/sources/src_<UUID>/`，安装程序在固定数据根 `node-apps/<UUID>/generations/`，用户不直接修改。新要求：添加成功后，源码以可编辑形式放在项目目录 `<项目目录>/<名称>`，并作为该托管应用的开发源码（复用 `docs/node-development-workflow.md` 中“受管应用绑定同应用标识的源码目录”的能力）。需要确定项目目录的具体位置：建议即现有工作区下一个用户可见、可被 AI 打开的子目录。是否改为 `~/熊猫小抽屉项目` 这类更显眼的默认位置，待定。
2. **Git 失败即删除。** 与 `docs/git-app-import.md` 中“不支持、失败、取消后清理”方向一致。去掉其中引导到“源码检查与 AI 适配”、保留来源的分支。“源码记录与恢复”高级入口是否保留，待定。
3. **外部项目交给 AI 不再要求先分离。** `docs/node-development-workflow.md` 写有“旧式应用先完成这次分离，才能通过平台交给 AI 编辑源码”。按本页，外部项目的“交给 AI”就是复制带本地路径的说明，不要求分离；分离只在用户主动“构建并更新”时发生。
4. **本地检查结果从三态改为四种。** 现有 `node_app_directory_inspect` 返回 `empty`、`ready`、`needs-review`。界面需要把 `needs-review` 细分为“需要修改／当前不适合／信息不足”及其子情况：可在检查结果中增加分类字段，或由界面根据问题代码映射。空目录仍走现有“生成并添加项目”。
5. **重复添加判断。** 检查前按规范化路径（及目录身份）比对已有外部登记；命中则显示 7.2，不进入检查。
6. **多应用仓库选择子目录。** 当前开发声明要求 `development.sourceDir = "."`；外部引用能否以子目录为应用根需要技术确认。不支持时，信息不足页只提供“复制说明给 AI”。
7. **最近选过的文件夹。** 保存在平台设置中（路径、上次时间、上次结果摘要），最多 5 条；路径不存在时显示“已移动或删除”并可移除。
8. **构建同意的记忆。** 建议按“项目 + 脚本内容摘要”记住同意，脚本变化后重新询问（可后定）。
9. **说明正文同源。** 评估、添加失败、启动／更新失败三种说明与现有 `local-folder-review` skill、`docs/project-compatibility-review-prompt.md` 使用同一份平台要求正文，随版本打包，避免各自过时。

## 14. 验收场景

实现方按以下场景逐条验证。界面模拟与真实原生操作分开记录。

1. Git 公开仓库可直接使用：五步自动完成，源码出现在项目目录，`打开应用`可用。
2. Git 仓库需要构建：出现构建确认；同意后完成；拒绝后下载文件被删除。
3. Git 仓库检查不通过：显示原因；项目目录无残留；复制内容包含 Git 地址、提交、原因、平台版本和交付方式说明。
4. Git 准备或构建失败：同上，复制内容包含本次有界错误摘录和实际退出状态。
5. 下载超时、私有仓库、不支持的网站、磁盘不足：文案与按钮符合 6.5；无残留文件。
6. 下载中关闭弹窗：任务后台继续；“任务”可回到弹窗；完成或出错有提醒。
   添加成功后点“完成”、进入应用设置或关闭结果页，结束本次会话；再次点“从Git添加”打开新表单，只记住上次提交的仓库地址，不复用成功页或自动执行。删除已添加项目后也遵守此规则。后台执行、安装结果未知、源码整理或清理未完成时保留原会话和核对／重试入口。
7. 下载中退出软件：重开后“任务”显示需要查看；临时文件已清理。
8. 同一仓库再次添加：先提示，可打开已有的或另加一份。
9. 本地项目可以添加：原文件夹逐文件不变；应用直接运行该文件夹代码。
10. 本地项目缺 local-app.json、缺依赖、只能 dev 运行：归为“需要修改”；复制内容含本地路径和原因；文件夹不变。
11. 本地 Python／Docker 项目：归为“当前不适合”。
12. 多应用目录、无权限、空目录、project.json、文件过多：分别命中 7.3 的细分情况。
13. 同一文件夹再次添加：显示 7.2，不进入检查，不产生重复登记。
14. AI 修改后从“最近选过”重新检查：显示与上次的差异；通过后可以添加。
15. 外部项目被改坏后打开：显示 9.1；复制内容含路径和脱敏日志；应用数据未被改动。
16. 托管项目“构建并更新”失败：显示 9.2；旧版本仍可打开。
17. 网页 AI 模式：附带摘录不含 .env、数据库、上传文件；文件清单可见可取消。
18. 卸载前清理：确认页列出托管项目及路径；外部文件夹未被删除。
