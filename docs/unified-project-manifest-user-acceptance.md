# panda.json 用户验收方案

状态：待用户执行。本文不是通过记录。对应[统一方案](unified-project-manifest-proposal.md)的三批实现；自动检查结果另记在[实施记录](unified-project-manifest-implementation.md)。

按 2026-11-01 的补充安排，原生窗口与模拟用户操作由用户验收。macOS 和 Windows 分别执行并记录；一个平台通过不代表另一个平台通过。

## 准备

1. 使用本次修改后的开发版。保留已有开发项目，只操作名字以「可丢弃验收」开头的项目。旧格式项目不用于本次验收。
2. 在一个已有的用户文件夹中生成测试源码，例如在仓库终端执行：

   ```sh
   node scripts/create-panda-acceptance-fixtures.mjs --output /你选择的现有文件夹
   ```

   Windows 使用自己的完整文件夹路径。脚本创建一个新的 `panda-acceptance-时间/`，打印完整路径；不打开平台、不登记应用、不安装依赖、不执行项目脚本、不改现有项目。后文的测试根指这次输出路径。
3. 保存本次开发包版本／提交号、系统版本，Windows 另记 WebView2 版本。表格中填「通过／失败／未测」；失败记录在哪一步、实际提示、截图和可丢弃项目的路径。不要附真实密钥或业务数据库。

## 第一组：本地接入与普通网页

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| L1 | 添加本地 `web-no-sdk`，从卡片打开，再点一次同一卡片 | 直接使用原文件夹，只有一个原生窗口；再次点击聚焦原窗口，输入框中的未保存文字保留 |
| L2 | 看网页上的绝对资源、内联脚本、CDN 三个状态，点击各按钮 | 绝对资源和内联脚本成功；按钮的 `onclick` 正常；CDN 在网络可用时成功，网络失败单独记录 |
| L3 | 在 `web-no-sdk` 点击「写数据库和附件」 | 显示「这个应用没有启用平台 SDK」；项目中没有新增 `data/main.sqlite` 或附件 |
| L4 | 在同一个无 SDK 项目点击「读取配置」 | 成功返回空对象，而非 SDK 未启用错误；不创建数据库 |
| L5 | 点击「进入路由并刷新」 | 地址进入 `/route/deep`，刷新后仍为同一页面，绝对资源正常；不存在的 `.js`、私有路径和平台未知接口不能得到首页 |
| L6 | 点击「测试系统对话框」；分别试确认、取消、输入文字 | alert、confirm、prompt 显示系统对话框；确定／取消的结果正确，prompt 取消为 null；平台仍可正常操作 |
| L7 | 点击外部链接和 `window.open` | 外部 HTTPS 页面交给系统浏览器，平台不增加第二个业务窗口，当前业务页面保留 |
| L8 | 添加 `web-entry-missing`，尝试进入 | 显示「入口文件缺失」和可供 AI 修复的说明，不打开空白应用 |

`web-no-sdk` 的源码无 `platform` 声明，仍可用平台提供的脚本读取普通配置；数据库和附件调用必须拒绝。

## 第二组：配置、数据和真正关闭

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| D1 | 添加 `web-sdk` 并点击打开 | 显示「需要配置」，直接进入配置表单；不会先打开应用窗口 |
| D2 | 在表单中填验收文字、整数 23、开关关闭、选项「乙」，选填文字留空；保存 | 保存后返回详情；没有自动打开或重新构建 |
| D3 | 打开并点击「读取配置」 | LABEL 是字符串、COUNT 是数字、ENABLED 是布尔值，MODE 是字符串 beta，OPTIONAL 不出现在结果中 |
| D4 | 应用开着时在平台修改配置并保存，回到应用刷新，再读取 | 新配置生效，无需构建；保存没有主动刷新页面或丢弃其草稿 |
| D5 | 点击「写数据库和附件」，然后「读取数据库和附件」 | 与输入框一致；文件分别出现在原文件夹 `data/main.sqlite`、`data/attachments/acceptance.txt` |
| D6 | 点击「检查私有文件保护」 | 四个私有路径全部拒绝，不显示测试私有正文；不得把它们作为 SPA 路由返回首页 |
| D7 | 保存浏览器测试文字，记下网页显示的完整 origin；关闭应用窗口，等平台显示「应用已关闭」，重新打开 | origin 完全相同，浏览器文字仍能读取；SQL 和附件数据也仍在 |
| D8 | 通过菜单完整退出平台，再启动并重新打开该应用 | 没有自动恢复业务窗口；用户打开后 origin 和浏览器文字仍相同 |
| D9 | 写入数据库后关闭应用，等待「应用已关闭」，用 SQLite 工具在原目录打开、修改并关闭数据库，然后重开应用读取 | 工具能操作数据库，不被平台的遗留连接锁住；重开读取到修改。不要在应用打开时直接改数据库文件 |
| D10 | 应用关闭后，用 CLI 连续执行两次 `db schema`，随后直接用 SQLite 工具打开数据库 | 每次 CLI 用完即关，不留下常驻数据库连接；命令未知结果不盲目重复写入 |
| D11 | 只在该可丢弃项目上，关闭后移走 `data/main.sqlite` 和匹配 WAL/SHM，再打开并调用 SDK | 创建空库；没有旧业务表是预期行为。不要对真实项目这样操作 |
| D12 | 只在可丢弃项目上，关闭后把数据库替换为普通错误文本，再调用 SDK | 返回数据库真实错误，错误文件不被自动删除、修复或重置 |

关闭过程中若显示「正在关闭」或异常，不把窗口消失当成通过。记录提示，并检查详情中的重试关闭入口。数据库工具操作前须确认应用确实已关闭。

D10 的 CLI 路径可从「复制 AI 接手说明」取得，实例 ID 在详情的详细运行信息中。例如：`"<CLI完整路径>" db schema --project <实例ID> --json`；PowerShell 在完整路径前加 `&`。这里只查询 schema，不执行业务写入。

## 第三组：原地构建与声明变更

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| B1 | 添加本地 `web-build` | 显示「需要构建」，保留原文件夹，没有额外风险确认 |
| B2 | 在详情点「构建」，等任务终态，再打开 | 实际执行 `bundle:web`，生成原目录的 `site/`。故意会失败的 `build` 脚本没有被执行；页面显示 BUILD_A |
| B3 | 应用开着时点构建 | 明确要求先关闭应用窗口，没有启动第二次构建 |
| B4 | 关闭应用，将 `page.html` 中 BUILD_A 改成 BUILD_B，用自己终端执行声明的 `bundle:web` 脚本，再打开 | 页面显示 BUILD_B；无需经过平台发布或同步，不出现额外产物代次 |
| B5 | 修改构建脚本：先写一个测试产物，再以非零退出；平台点构建 | 任务失败并提供错误／AI 求助说明；脚本已经修改的文件保留，平台不假装回滚 |
| B6 | 临时移走该测试工程的 package-lock，点构建 | 明确提示缺 npm v2/v3 锁文件，没有执行构建脚本；恢复文件后可重试 |
| B7 | 关闭项目后改 `app.name`、version、图标、window，重新打开 | 新名称／版本／窗口声明生效，平台没有把修改写回作者文件；无改名／改图标面板 |
| B8 | 只改测试清单：未知字段、错误 entry、runtime 改成另一类，分别尝试打开并恢复 | 每种有明确字段／原因；改变 runtime 提示删除后重新添加，不擅自转换登记 |
| B9 | 在配置声明加一个没有默认值的必填项，再重新打开 | 进入配置表单，新字段缺值标明；旧字段按变量名保留 |
| B10 | 查看测试项目根和 Git 状态 | 平台没有生成项目 `.platform/`、构建副本、版本目录或改写 `.git`；声明构建产生的依赖／网页产物及 SDK data 属于预期 |

## 第四组：Node 与空文件夹

1. 添加 `node` 并打开。点「检查数据目录」，结果应为这个用户源文件夹下的 `data/`，目录自动创建。点保存浏览器数据，关窗并完整退出平台后重开，地址和浏览器数据应保持。
2. 再次打开只聚焦已有窗口。关闭窗口后，后台受管 Node 停止；其他应用继续运行。修改 Node 的名称、版本和有效配置声明后，下次打开生效。
3. 添加 `empty-node`，按界面生成起始项目。生成位置仍是用户选的空文件夹；删除确认明确说明保留该文件夹及 `data/`，浏览器数据清除。
4. 删除这个生成的实例，核对源文件夹和文件数据仍在。把同一文件夹重新添加，应得到新实例，不能读到之前的浏览器存储。

## 第五组：Git 添加及完整删除

需要三个你能公开访问的专用测试仓库。不要用真实业务仓库做失败／删除试验。可把生成的测试源码推到自己专门的测试仓库；不要提交 `data/`、依赖或真实配置。

| 编号 | 仓库内容及操作 | 预期结果 |
| --- | --- | --- |
| G1 | `web-no-sdk`，入口已经提交；从 Git 添加 | 不安装 npm 依赖、不运行任何脚本，直接登记并打开 |
| G2 | `web-build`，不提交 site；从 Git 添加 | 停在「需要确认」，确认框显示仓库和构建风险；点「构建并添加」后执行 bundle:web，成功才登记 |
| G3 | 同上，等待确认时点取消 | 不登记；下载目录、临时任务／控制材料与归属清除 |
| G4 | 同上，等待确认时完整退出再启动 | 登记前任务回滚，不自动运行仓库脚本、不出现半个应用 |
| G5 | 构建脚本故意失败的专用仓库 | 明确失败及 AI 修复入口，未登记源和临时材料清除 |
| G6 | `web-entry-missing`，无入口且无构建声明 | 「需要修改」失败，不安装依赖或执行脚本 |
| G7 | 同一正常仓库添加两次，在两份应用写不同浏览器数据 | 两个独立文件夹、实例和 origin，彼此数据隔离 |
| G8 | 删除其中一个 Git 实例 | 确认框分别说明整个源文件夹及 data 删除、浏览器数据清除；完成后其代码、Git、data、私有材料全部清除，另一实例和远端原仓库保留 |
| G9 | 删除一个本地 web-sdk 实例 | 确认框说明源文件夹和 data 保留，浏览器数据清除；重新添加后 SQL／附件还在，浏览器文字为空 |

Git 收尾故障后的归属与精确删除主要由自动故障注入覆盖；不要求你手工改平台私有登记或制造磁盘故障。

## 第六组：地址占用与路径边界（可选进阶）

- 记住一个测试实例的端口，关闭应用。用一个临时本机 HTTP 服务占住该端口，再从平台打开。必须明确提示原地址被占用及关闭占用程序后重试，不能悄悄换端口。停止临时服务后重开，地址保持原值。只操作本次测试实例的端口。
- macOS 可在测试网页根内创建符号链接，分别指向根内普通资源、项目 data、项目外文件；仅第一种可读取。指向 data／隐藏目录的 `web.root` 应在检查时拒绝。创建一个指向普通文件的硬链接，该文件应拒绝提供。
- Windows 在支持的 NTFS 测试目录验证相同边界。若创建符号链接需要额外系统设置，记录「未测」即可；不要为验收修改全机安全策略。
- 用 SDK 发起一个较长 SQL 或较大附件上传后关窗。关闭状态应经过真实排空，不出现数据库未释放却显示「应用已关闭」。可中途点开另一个应用，确认不会被该项目的关闭锁阻塞。
