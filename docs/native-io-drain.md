# 原生与下载 I/O 排空登记（第一步）

本步建立关闭接纳入口和等待实际资源释放的基础。它没有开放自动更新安装，也没有提供“已安全退出”凭据。开发版身份、数据根、项目和业务数据均不变化。

## 接纳与资源寿命

`IoLifetime` 由整个 `RuntimeSwitch` 持有；迁移工作区后的新旧 HTTP 状态共用同一登记。接纳检查和登记计数在同一把锁内完成。`close()` 拒绝普通原生操作和新 HTTP 请求；仅明确列出的停止、取消和状态查询保留 cleanup 接纳。`RuntimeService::shutdown` 开始时 `seal()`，随后停止 HTTP/上传，等待活动请求与真实 I/O，再关闭存储及业务管理器。关闭和等待期间不持接纳锁。

`IoLease::run` 启动拥有工作本身的任务，调用方只等待结果。关闭页面、丢失请求或取消前端等待不会取消该工作。`TrackedIo` 先析构实际资源，再归还登记，包含正常返回、错误及 panic。它不是 updater 许可。

原生命令、Node 窗口关闭/销毁回调、后台监测的实际工作阶段、权限声明读取和窗口偏好写入均使用登记。监测睡眠和未选择路径的原生对话框不算正在 I/O。路径/附件保存框返回后重新检查接纳；停止后的迟到选择不能开始复制。Finder/Codex 的短子进程在超时后执行 kill、wait，并等待输出读取结束；外部编辑器后续编辑不属于平台拥有的进程。

HTTP 处理器同样由拥有工作的任务运行。响应文件不再把描述符藏在未消费的 Body 中：独立阻塞生产者拥有实际文件、项目读门和登记，最多排队两块 64 KiB。停止或客户端断开会结束生产；如果底层读仍未返回，登记仍保持忙碌。服务等待的是这些资源的释放，不是单独等待返回响应头或中止 Axum 父任务。

## 浏览器下载的两个阶段

WebKit 请求下载时，私有暂存与登记一起创建。收到 `Finished` 后才能把暂存交给等待保存选择的可撤销槽。停止会释放未选保存的槽并清理自己的暂存；保存 claim 与停止使用同一接纳锁。已经 claim 的复制保留原登记，直到实际文件/暂存清理完毕。

目前 Tauri/Wry 没有本实现可核验的 WebKit 取消完成接口。如果回调在收到 `Finished` 前被销毁，本实现保留该暂存和忙碌登记，不删除可能仍由引擎写入的路径、不宣称已排空。因此该异常情况下普通退出可能继续等待，需要后续引擎取消完成方案或明确的人工退出流程；本步未把它描述成完整原生下载关闭验收。原生 GUI 尚未验证。

## 验证

在固定开发数据根之外的独立源码副本、独立 target 中验证；测试使用 TempDir、人工本地文件、回环 HTTP 和 `/bin/sleep`、`/usr/bin/printf` 人工子进程。没有读取真实项目、数据库或下载真实业务内容，也没有运行原生 GUI。

- `cargo test --locked -p platform-core --lib io_lifetime`：11 项通过，包含丢失原生/HTTP 请求后仍等待阻塞文件工作、Body 不消费/丢弃、停止与保存选择同时发生、错误/panic 的资源析构顺序。
- `cargo test --locked -p platform-desktop --bin local-projects-desktop-dev`：18 项通过，包含旧下载路径保护及新增的选择前撤销、已选择复制、短进程超时回收。
- `cargo clippy --locked -p platform-core -p platform-desktop --all-targets -- -D warnings`：通过。
- 完整核心回归首轮 619 通过、1 失败、39 忽略。既有 `manager_shutdown_cancels_git_guard_before_waiting_for_build_runner` 在立即探测进程组消失时失败；该模块没有改动，单项重跑通过。无并行桌面编译的第二轮完整回归 620 通过、0 失败、39 忽略（81.42 秒）。保留两轮日志，不将首轮失败抹去。随后 `-- --test-threads=1` 完整串行核心回归同样 620 通过、0 失败、39 忽略（208.21 秒），桌面完整串行回归 18 通过。

桌面编译只在副本放置了编译所需的现有开发 CLI、图标及 README 资源；这不等于新包、真实 Finder/Codex 打开、物理权限或 WebKit 引擎已验收。

集成到包含数据恢复保护与正式包元信息基础的开发分支后，核心 I/O 专项 11 项、桌面 18 项再次通过；全工作区全目标严格 Clippy、格式及差异空白检查通过。本轮实际正在运行的 `82247eb` 原生验收包尚未包含该 I/O 变更，不将其窗口结果作为本步原生证明。

## 自动安装前仍必须闭合

`RuntimeService::shutdown(self)` 当前仍消费服务，部分失败会提前返回，管理器/数据库的 Join 错误仍未统一汇总。桌面 `request_safe_shutdown` 仍可能记录错误后设置 `exit_ready`。本步没有将这些行为称为成功排空。

下一步需要可重试、明确 Result 的关闭协调器，先关闭所有接纳并发出所有管理器/Node 停止信号，再等待全部拥有工作的 runner/连接/数据库线程，保留失败阶段和实例锁；重复退出、更新与调用方丢失共用同一个关闭任务。Node 的进程组、后代与代理连接需要保留明确关闭证据，WebView 也需要完成关闭。仅后端证明成功关闭后才可调用 updater 原有签名/版本校验与安装流程；不能用 `runtime=None`、日志、超时或父任务 abort 代替证明。
