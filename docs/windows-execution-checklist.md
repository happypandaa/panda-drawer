# Windows 接续执行与验收清单

更新日期：2026-10-19

本清单把[已确认的 Windows 20 小步](windows-support-plan.md#4-与-m0m6-的关系)拆成接下来可执行的工作，不修改支持范围、SDK/API v1、数据格式或既有退出条件。W1、W2.1 **仍未整体通过**；已有本机结果只覆盖记录中的 Win11 x64、内部 exe 与本轮可丢弃项目。

## 1 执行与证据规则

- 继续 `codex/windows-compatibility`，按[分支规则](windows-support-plan.md#51-分支与主线关系)核对状态、fetch；主线有变化则合并 `origin/main` 并重跑受影响检查，不 rebase、强推或自行合回 `main`。
- 一次完成一个可审查片段，针对性测试和适用的实机检查通过后记录实际结果、检查 diff、commit 并 push。尚未完成的并行实现不混入提交；文档片段完成不等于其中列出的能力通过。
- 只新建名称明确的可丢弃项目做写入验证。保留已有四个样本和全部源码、SDK、数据库、附件、控制状态、备份、回收及恢复证据；不手改控制文件、覆盖数据库、自动接管历史或清理未知目录。
- 固定身份 `dev.localprojects.platform.m0` 与系统 API 解析的固定根不变；本机为 `C:\Users\g\AppData\Local\dev.localprojects.platform.m0`。工作区变更只走公开迁移。生成 exe、应用、DMG、项目数据、密钥和 `.test-artifacts` 不提交。
- 每项证据注明代码/包身份、系统与运行环境、项目 ID、操作、预期/实际及局限；区分纯模块、DOM 合成 IPC、真实回环、GUI 和物理设备。拒绝且夹具不变证明门禁，不证明操作成功；受控中断不证明硬件断电。
- 同一片段的检查失败先修复或收窄到完整可验收范围。缺少 Win10、Mac 或硬件证据保留为待验，继续不依赖该条件的工作，不扩大开放或验收结论。

契约依据：[平台与 SQL/事务](platform-development-contract.md)、[项目生命周期与迁移](project-lifecycle-and-workspace.md)、[备份维护恢复](backup-and-maintenance.md)、[历史清理](history-cleanup.md)、[发行与更新](release-and-updates.md)。安装器与 WebView2 分发的待定选项沿用原状态，不因列入清单而被确认。

## 3 W2.2：受控持久 SQL 与事务

W2.2 分四个实现片段顺序推进；这不是新增阶段或对外协议。a、b1 原语及 b2 私有实验连接已完成，继续 b3，**公开 SQL、事务和管理写入仍关闭**。计算器仅内存计算，不能作为本步持久数据证据。

| 片段与状态 | 依赖与实施内容 | 本片验收与开放边界 |
| --- | --- | --- |
| a 数据库对象 lease 安全原语：已实现并通过本机原生检查 | 只打开调用方提供可信预期身份的既有 main/WAL/SHM，保留目录链与对象句柄；核对 ID128、卷、私有 ACL、普通文件及实际原生句柄。项目登记和 data 归属由后续调用方检查 | 新 disposable 文件夹具的 8 项原生测试通过，覆盖身份不符、缺失、路径/对象变化、硬链接、重解析点、占用和权限变化；不是 SQLite 连接或 SQL 通过，公开入口仍关。见 [W2.2a 记录](windows-w2-verification.md#9-w22a数据库对象-lease-安全原语) |
| b 受限 VFS、WAL/SHM 与 worker：进行中，b1/b2 已完成私有实验检查 | b1：完整登记文件集合；b2：受限非默认 VFS、相对 HANDLE 的 SHM 映射/锁、保守 WAL 预检及关闭错误；b3 待实现：受保护的 WAL 初始化、合法 stale/中断尾部的现场策略、静止准入、每项目线程/串行队列/排空、诊断前完整证据留存与有界 checkpoint | b1 的 4 项及 b2 新增 22 项通过；b2 使用真实 SQLite 3.51.3 验证提交/回滚、重开、同/跨进程 stock SQLite 互锁、坏库和坏 WAL、关闭失败。不是通用历史接管或运行期 SQL，严格尾部拒绝可能阻断合法 WAL 复用；完整范围见 [W2 记录](windows-w2-verification.md#11-w22b2受限-vfs与私有-wal-连接)。公开 API 继续门禁 |
| c API/SSE 与新版样本：待实现 | 依赖 b；沿用 `db.execute`、`db.transaction`、schema、无损 SQL 值、会话/Origin/代次契约；接入新命名的持久小程序及匹配预编译资源，不改旧样本或固定 SDK | 真实回环验证参数绑定、单语句、事务失败全回滚、int64/bytes、接收及执行前身份/代次检查；仅成功提交通知变化，回滚不发成功通知；未知结果不自动重放。后置接口继续拒绝 |
| d 实机 CRUD、事务与重启：待验证 | 依赖 a–c 及可运行包；创建两个新的明确命名样本 | GUI/真实服务实际建表、参数化新增/查询/修改/删除、事务成功与失败回滚；跨项目隔离、旧代次/身份拒绝；独立坏库夹具诊断且原现场保留；正常退出重启后 schema/记录一致、旧会话失效；旧四样本保留。记录浏览器/Win10 未完成分支 |

本步不得用内存数据库、伪造空库、直接覆盖 `main.sqlite` 或清除 WAL/SHM 替代持久执行。数据库目标、事务控制、外键/日志/同步/忙等待设置保持平台约束；业务 DDL/DML 不缩成固定 CRUD。API 返回成功前完成提交，错误后清理事务状态再归还连接。a–c 的模块/回环结果不单独构成 d 的实机通过。
