# 旧备份退役：封闭新建与解除 ZIP 基线依赖

日期：2026-10-24（Asia/Shanghai）。接续[停止自动裁剪](backup-retirement-preservation-step.md)。本步实现新建入口退役和新实例安装边界，不删除旧资料，也不宣称旧归档所有状态均可安装为新实例。

## 生产行为

- `MaintenanceManager::submit` 对 `backup`、`maintenanceBegin` 始终先返回 `BACKUP_WORKFLOW_RETIRED`、`operationOutcome: not_started`；不会创建任务、预留项目租约、加载或写入控制状态。测试构建也执行同一拒绝规则。
- 普通源码、SQL、构建与 Git 保存不需要 ZIP 基线。已有旧维护、`recoveryRequired`、基线引用和待构建要求继续生效，不因退役自动解除。
- 旧 ZIP 仍可列表、校验和显式同实例恢复。恢复使用所选已有归档作为旧维护依据，不再创建 `preRestore` ZIP；原来的冻结、业务写锁、数据库关闭、完整原目录保留、目录身份校验、持久 journal、替换和重启核对继续保留。成功恢复后仍须检查并显式结束旧维护。
- 新实例导入／复制不再复制或生成维护基线 ZIP。只有明确 `ready`、没有待构建要求且数据库外键检查通过的快照可以继续登记。维护、未知、仍需构建和外键异常返回 `LEGACY_ARCHIVE_REQUIRES_REVIEW`，保留来源归档、候选路径、具体原因及待构建信息，在实例登记前拒绝；不把这些输入改为正常状态。现有同实例恢复不经过这项新实例准入限制。
- 显式项目导出的 ZIP 编解码和复制用临时候选继续保留。这些操作不建立独立备份历史，不代表分享路径已完成。

## 引导与旧项目

新分发 skill、新项目数据库说明、动态 AI 接手文字和开始使用指南改为先核对、保存 Git 版本，再做候选构建与必要的操作协调。源码版本与数据版本分别核对，不能将仅源码提交称为数据版本；数据进入 Git、源码取回与活库的边界见[数据版本说明](project-data-git.md)。

旧兼容面板不再提供新建备份、进入维护或重试基线；保留旧归档读取、明确恢复与检查结束旧维护。业务运行提示把通用忙碌状态称为“正在准备项目操作”，不再把所有停写解释为备份。已有项目自己的 skill、源码、SDK 和文档不覆盖；动态交接说明当前规则优先于其中已退役的新基线步骤。

## 隔离验证

旧测试使用明确命名的 `maintenance_legacy_test_fixtures` 工厂构造临时历史归档、任务和控制状态；工厂不调用已退役的生产 `submit`，没有测试模式生产放行开关。原维护、重启、历史清理与生命周期证据仍通过真实临时文件和 SQLite 验证。

本步定向检查结果：

- 维护 24 项：包含退役拒绝前后文件树及控制状态不变、无任务租约、未完成恢复保留、旧 ZIP 恢复不新建归档、完整原库和附件保留、所选旧归档可作为维护依据、正常 SQL 无需基线，以及已有重启恢复兼容。
- 补充服务层回归 7 项（M3 3 项、M5 4 项）通过：遗留维护由显式隔离 fixture 生成，继续通过真实 HTTP 验证管理身份、结束维护、共享新 Cookie 下旧页面 SQL／附件拒绝和新页面可用；退役入口在已有读门期间立即拒绝，不冻结、创建任务或推进页面身份。设备声明门禁继续核验已有维护状态，不代表实际设备或系统权限验收。
- 生命周期 37 项：完全可用归档的正常导入／复制继续通过；维护、未知、外键异常和 `ready + pendingBuild` 均拒绝新实例并保全来源及候选；迁移、直接删除及旧回收兼容仍通过。
- 历史清理 18 项、源码恢复守卫 14 项、资源／交接 7 项、候选构建 4 项通过。Git 默认专项 16 项通过、2 项真实工具测试按原 opt-in 条件忽略；此处不把默认忽略记为真实 Git 验证。
- 原管理交互脚本 70 项、运行提示脚本全部检查及 TypeScript／Vite 构建通过；前端仍有既有的大包体提示。
- core 全目标 Clippy（`-D warnings`）通过；改动文件的格式和差异检查通过。

旧备份生产入口没有提供替代 ZIP 或私有 Git 恢复仓库。没有操作真实开发项目或旧归档，没有执行带真实工作区副作用的历史 M3／M4 live 脚本，没有生成安装包或完成原生界面验收。旧维护缺失基线、未知归档的新实例转换及数据库版本取回到活库仍是明确未提供的后续能力；不能将本步写成完整旧备份系统移除或所有旧资料无缝迁移。
