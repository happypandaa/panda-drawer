# 从 Git 添加项目

更新：2026-11-01，统一清单批次 3。接受 GitHub／Gitee 公开 HTTPS 仓库，以根 `panda.json` 识别网页或 Node。项目使用唯一可编辑源码文件夹，不创建安装候选、程序副本或网页代次。字段见[项目格式](panda-project-format.md)。

## 流程

填写仓库地址和可选分支，默认仓库分支。名称来自 `app.name`，界面不覆盖作者名称。平台下载、检查、准备、登记、清理临时材料，在同一弹窗显示真实阶段；成功后明确打开或进入 Node 配置，不自动启动。

网页入口已存在时直接添加，不安装依赖、不执行构建。入口缺失且有有效 `development.build` 时进入 `waitingConfirmation`，显示仓库、原目录、源码目录和具体脚本，说明依赖安装及构建会执行仓库代码并修改本次下载文件；用户选择“构建并添加”或“取消”。明确同意后才执行 `npm ci` 与 `npm run <development.build.script>`。无入口且无构建声明不能直接添加。

确认绑定当前修订；来源、清单或确认信息变化后须重新查看。关闭弹窗仅转后台，等待确认保留在任务入口，不当作取消或成功。等待状态可取消，并继续观察至真实进程收尾和清理结束。构建失败不承诺撤销脚本已写入的外部内容；未登记的受管源码按任务归属收尾。

Node 前后端入口必须已经存在，不执行构建脚本。有 npm 材料时，从项目及后端根去重选择恰好一组有效 `package.json` 和 npm v2/v3 锁文件，执行 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`。零依赖且没有包声明时跳过。平台受管 npm 契约与本机开发安装使用 pnpm 的偏好分开。

## 提交与中断

一次导入始终绑定同一请求 UUID、来源和任务。网页预登记后获得真实 `prj_` ID；只有明确绑定的 `webProjectId` 和任务项目 ID 相符时，界面才接受这次身份交接。不能用任意新 ID 替换当前导入。

持久登记是提交点。确定未登记时，先等待下载／构建进程和写入者结束，再按精确身份回滚本次平台源码及临时材料；确定已登记则只清理临时材料，保留正式源码。结果未知先核对登记和 journal，不重复添加或根据裸路径删除。清理失败显示未完成范围并允许重试，不能提前显示正常成功。

正常退出等待已接受操作；重启不自动执行仓库脚本。未提交的中断任务按日志核对并收尾，已提交的恢复到已有实例。任务暂时读不到、回复丢失或窗口关闭不等于失败，不自动重放写入。恢复提示仅用于当前导入，不恢复已退役的平台源码／数据版本工具。

## 归属和数据

Git 下载源码归平台独占，删除应用时连同代码、Git、依赖和项目 `data/` 全部删除。私有配置、秘密、缓存、任务、日志及浏览器数据也清除。用户选择的本地原目录不属于 Git 清理范围。

文件数据在项目 `data/`；浏览器 localStorage、IndexedDB、Cookie 在平台窗口存储。两者的删除范围分开说明。应用真实配置值不从下载源码或作者 `.env` 采纳，Node 秘密由平台表单注入。

## 当前边界和验证

不支持私有仓库登录、SSH、任意 Git 主机、额外运行时或自动适配任意工程。网页在独立固定端口的根路径打开，HTML 加载 `/_platform/sdk.js`；SDK／配置路径见[当前项目格式](panda-project-format.md)。平台不提供 ZIP 导入导出、复制、版本取回或旧格式兼容。

批次验证见[实施记录](unified-project-manifest-implementation.md)。覆盖直接网页、等待与过期确认、Node 依赖准备、取消、提交不明、重启及清理；模拟响应不证明真实网络、任意仓库、原生窗口或系统权限已经通过。
