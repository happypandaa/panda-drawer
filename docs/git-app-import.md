## 用户流程

1. 在“添加”的下箭头选择“从 Git 导入应用”，填写标准 GitHub 或 Gitee 公开 HTTPS 仓库地址。分支和备注名称放入高级选项，默认使用仓库默认分支。不提供私有仓库登录、SSH 或任意 Git 服务地址。
2. 点击“导入应用”。开始前说明这会下载源码、准备依赖并添加一个新的独立应用实例；不自动启动应用。界面依次显示下载源码、检查兼容性、准备应用、安装应用、清理临时文件，系统自动衔接，无需用户重新选择刚下载的来源或手动核验安装候选。
3. 仅当清单要求执行 npm 构建脚本时，展示一次具体构建提示并等待明确同意。未经这次同意不执行该脚本。已经具有可信构建产物的来源不重复构建。
4. 安装提交和应用登记确认后，继续在同一进度中清理本次临时文件；清理完成才显示“导入成功”。清理进行中不提前显示成功或点亮全部步骤。如果缺少必填配置，主按钮进入配置；可直接使用时，主按钮明确打开应用。导入成功表示登记和本次清理完成，不表示已经实际启动或验证全部业务功能。
5. 仓库格式不支持、下载失败、构建或安装失败、用户取消分别给出明确结果及下一步。“已获取，待接入”不再作为普通导入的最终成功状态。需适配的项目说明原因，可以转到源码检查与 AI 适配，不承诺自动适配任意仓库。

进度只展示真实阶段及活动状态；无法准确计算时不伪造百分比。下载和准备阶段允许请求取消，必须等所属任务及进程实际停止后才显示已取消。最终安装提交不提供伪装的取消或撤销。

## 导入结果

| 情况 | 结果与操作 |
| --- | --- |
| 应用登记且临时文件清理完成、配置完整 | 导入成功；可以打开应用 |
| 应用登记且临时文件清理完成、配置缺项 | 导入成功；进入必填配置，保存不自动启动 |
| 不符合当前可安装子集 | 明确不能直接导入及原因；可以清理并关闭或检查源码 |
| 下载、依赖、构建或确定未提交的安装失败 | 显示失败阶段和错误；可以重试或清理并关闭 |
| 用户取消且任务实际停止 | 导入已取消；可以清理并关闭或重新导入 |
| 安装是否提交尚不能确认 | 显示结果需要核对；先核对原候选，不重复安装或删除依据 |
| 应用已安装但临时材料未清完 | 显示“应用已添加，清理未完成”；停在清理阶段，重试清理后再进入正常成功页 |

来源、准备任务、安装候选和最终应用须始终绑定本次导入身份。迟到响应、界面重新打开或平台实例切换不能触发另一次安装。暂时读不到任务不等于任务失败；先恢复查询，不能自动重发写入。

## 本次材料清理

用户已经确认导入后的临时材料清理。该授权只覆盖本次导入产生、归属可核对且任务已经停止的材料，不构成对历史目录、已有应用或任意来源的删除许可。

- 应用登记后自动进入“清理临时文件”阶段，处理下载中间文件、安装准备材料及其缓存；保留已登记程序、正式源码及其版本信息，供运行、修改和 Git 管理使用。清理完成后才显示正常成功结果。
- 失败、不支持或取消后，明确“清理并关闭”会删除本次下载及未被引用的准备材料。重试先处理上次可安全清理的材料，不要求用户到 Finder 找目录。
- 最小任务、错误和清理结果记录继续保留，避免把“关闭结果”当作已完成物理删除。清理失败要显示真实残留和原因，并提供重试入口。
- 活动任务、尚未停止的受管进程、结果不确定的安装，以及被已有应用或其他安装引用的来源受保护。清理不能删除当前运行程序、业务数据库、附件、配置和密钥，也不能追踪来源记录中的外部作者目录。
- 清理应按本次任务身份重复核对范围，允许失败后幂等重试，不能扩大成遍历所有旧来源和旧安装。

这调整了新导入流程中“失败现场整份默认保留”的旧规则。既有历史来源和未解决恢复依据仍按原契约保护，通过“源码记录与恢复”及“空间 → 历史资料”核对；不得用新规则批量清掉旧证据。

## 恢复与高级入口

“源码记录与恢复”保留本机源码检查、独立副本接入、旧来源查看、已有安装候选核对和更新材料等操作。它服务源码处理及恢复，普通公开 Git 导入无需进入这里。

关闭或退出不能把未结束任务当作取消；正常退出按现有受管任务收尾规则处理。重开后可以查看保留的来源及候选，明确继续或核对，不能在后台自动安装。如果原候选已经提交，只显示其已有安装结果，不再创建新实例。

CLI `source acquire`、`source capture` 和管理 HTTP 来源接口仍只执行其各自的源码操作，不因为界面流程简化就隐式安装或运行应用。安装提交继续由原生管理窗口的操作锁及服务门禁控制。

## 验收要求与当前限制

本轮需分别验证：可直接安装、需要构建并同意／拒绝、缺配置、格式不支持、下载失败、准备失败、活动下载／准备取消、结果读取暂时失败、提交结果不明、成功与失败清理、清理失败后重试、旧候选恢复及平台实例切换。重复点击和迟到结果不应多装一个实例；成功后在列表找到应用，失败不出现半成品。
