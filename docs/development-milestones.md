# 开发里程碑与验收计划

状态：v0.7，执行计划已确认；M0 至 M3 已完成本机内部验证，M4 已交付实现及 CLI/API、迁移/进程重启验证，GUI 全流程未完成；M5/M6 尚未开始  
更新日期：2026-10-16

现有架构足够开始工程搭建和第一条完整使用流程的开发。本文安排实现顺序、交付物和验收条件，不重选已确认的 Tauri 2、Rust、SQLite、系统 Node 和 Mac 首发方案，也不把尚未确认的讨论稿升级为正式契约。

技术依据为[主约定](platform-development-contract.md)及其配套文档；决定状态统一见[技术决策与实施清单](remaining-technical-decisions.md)。用户已确认按本计划从 M0 开始实施。仅有明确验收记录的阶段视为完成；未做工作量实测前不承诺日历日期。

## 1 目标与第一条验证流程

首版目标：用户安装平台后拥有本地项目工作区；外部 AI 可以编辑项目文件、操作数据库并构建网页；用户在 AI 关闭后仍能通过桌面窗口或浏览器使用项目，数据长期保存在本机。

第一条验证流程使用“孩子英语学习”，只包含单词列表、增加或修改单词、记录一次练习、查看历史，以及一个附件保存场景。所有内容使用可丢弃测试数据，业务示例不成为平台内置的固定表结构或正式功能模板。

M2 必须完成：创建项目并直接打开初始应用 → 复制交接说明 → 外部 AI 阅读 skill 与 README → 编辑页面与数据 → 调用平台构建并等待成功 → 桌面及浏览器打开 → 保存记录 → 关闭 AI 和重启平台 → 数据仍可读取。至少由一个具备本地文件、命令执行及浏览器工具权限的外部 AI 客户端实际完成，不能只由开发者手动操作来代替。初始应用在平台打包时预编译，创建和首次打开不依赖用户的 Node/npm 或网络。

后续阶段持续复用这条流程；新增备份、迁移、媒体等能力时扩展验证，不反复创建互不关联的演示项目。

## 3 M0：开发工程与环境

**交付内容**

- 建立平台工程、Rust 核心、管理界面、原生 CLI、浏览器 SDK 和模板的清晰边界；目录与依赖版本在建立工程时记录，业务项目另放测试工作区。
- 配置从源码启动的开发命令、日志和调试入口，使用系统 Node 与平台开发所需的 Rust/macOS 工具链。用户安装成品时仍无需这些平台开发工具。
- 建立默认黑白灰界面基础，沿用 shadcn/ui 的组件建议；此时只需要能运行和定位问题，不要求完成所有管理页面。
- 为开发实例设计独立的应用标识、设置、工作区、服务发现、凭据、CLI 目标和单实例占用规则。M0 已按 `dev.localprojects.platform.m0` 落实，具体字段和命令见[开发说明](development.md)；不把该临时身份当作正式品牌。
- 尽早产生最小内部测试 `.app` / DMG，检查从 Finder 启动和包内资源读取；查看签名、公证及 macOS 15 测试设备的准备情况。内部探测包不当作已签名、公证或可对外发行的产物。

**验收条件**

1. 一条记录在开发说明中的命令可以启动真实 Tauri 窗口，错误能在日志中定位；修改界面和 Rust 后分别验证更新或重启行为。
2. 开发实例创建的文件全部落在明确的测试范围；开发 CLI 不会误连正式实例，开发服务不会默认收养已有正式工作区。
3. 能生成并打开最小内部测试包，已记录开发运行与打包运行的实际差异；缺少发行签名资质可记录为后续门槛，不阻塞小样本开发。

平台 UI 可以使用开发热更新；这不改变业务项目首版“构建后加载、没有项目 HMR 服务”的约定。开发模式额外的前端服务端口不属于正式平台运行时的共享 HTTP 端口。

## 4 M1：本地服务、数据与窗口

**交付内容**

- 管理窗口、项目登记和基础列表；生成符合清单和 README 约定的测试项目目录，显示未构建、缺失和错误状态。
- Tauri 主进程内的 Rust 服务、仅回环地址监听、端口冲突处理、实例与凭据发现、原生 CLI 的服务状态和项目查询。
- CLI 管理身份、项目浏览器会话、Host/Origin 检查、受控静态文件与附件路径；从第一版 SDK 请求起包含文档代次，不先开放无身份的临时管理接口。
- 每项目 SQLite 连接和串行队列、SQL 与托管事务、类型传输、附件读写、基础通知；建立共享任务协议和同项目操作协调入口，供后续构建、备份和迁移复用。
- 独立项目窗口、同项目重复打开复用、浏览器入口、关闭窗口与明确退出的不同处理。用受控测试产物先验证运行，不宣称已支持 AI 构建。

**验收条件**

1. 两个项目分别写入测试记录和附件，桌面与普通浏览器重新查询得到同一项目的数据；重启后数据仍在，接口目标错误不会写到另一个项目。
2. 没有有效管理身份、错误项目会话、过期实例或旧文档代次时按契约拒绝请求；项目窗口无法调用平台管理原生命令。
3. 查询和事务失败、附件写入失败不会破坏已有内容；数据库缺失不会被静默替换成空库。
4. 重复打开复用窗口、不丢页面表单；明确退出关闭服务，重新启动后旧会话不能直接继续操作。

SQL、上传和队列限额在对应模块完整验收前按第 10 节落实。未确认的数值只能作为有标记的内部实验配置，不冻结为公开 SDK 默认值或在小样本通过后宣称模块已完整验收。

## 5 M2：构建、SDK 与真实 AI 操作

**交付内容**

- 固定版本 SDK 包、标准 React/TypeScript/Vite 项目模板、依赖锁文件，以及写入实际路径和命令的 README、数据库说明与平台说明。平台打包时构建并核对匹配的初始网页，新建项目直接复制后可打开；独立空库不预置业务表。
- 随项目保存的 `.agents/skills/local-projects-app/SKILL.md`；README、AGENTS.md 和 CLAUDE.md 指向同一套接管流程，“复制给 AI”提供绝对路径，不假定各工具自动发现 skill。旧项目缺少 skill 时只读引用安装包后备文件。
- 系统 Node/npm 检测与环境诊断，遵守最低 22.12.0、推荐 24 LTS 及已定支持分支；系统 Node 只参与项目构建。
- 构建任务、日志与等待、临时输出、输入变化检测、产物检查与切换、持久构建来源；失败保留旧产物及已保存数据。
- 创建项目、查看 schema、执行 SQL、构建、查询任务和获取浏览器入口的完整 CLI 交接；AI 按文档调用，不依赖猜测包内路径或固定端口。
- 桌面和普通浏览器联调；打包后的实际 `.app` 中验证 CLI、SDK、模板资源，以及 Finder 启动时的 Node 环境发现。

**验收条件**

1. 完成第 1 节规定的外部 AI 全流程，并保存客户端、工具版本、项目 ID、构建结果和问题记录；AI 关闭后业务功能仍可用。
2. 换一个没有原对话上下文的 AI 会话，仅凭项目文件及说明完成一次小修改；这是文档交接验收，不要求绑定特定 AI 厂商。
3. 构建故意失败、构建期间输入变化时不发布新产物；旧网页和原数据库、附件保留。只改名称、图标、README 或业务数据不误触发构建。
4. 移除构建环境可用性后，已有产物仍能打开和读写；发起新构建明确提示环境问题。无 Node 测试通过受控环境完成，不要求删除开发机的系统 Node。
5. SDK 随项目保存，平台升级模拟不替换旧项目 SDK、锁文件或源码；浏览器与桌面分别验证。
6. 在无可用 Node 的受控环境创建新项目，桌面和浏览器立即能打开欢迎应用；记录 `bundledTemplate` 来源和模板版本，源码为 `matched`，没有虚构的成功构建任务。创建不安装依赖、不联网；后续首次用户构建失败保留欢迎应用，成功发布后旧初始页资源仍可访问。
7. 检查项目 skill 及三个文档入口，独立 AI 可以只凭交接信息定位项目、读取实际 schema 并继续修改；旧项目读取 handoff 不写入 skill、源码或其他文档。平台数据身份继续为独立开发环境。

此阶段仅使用测试数据。构建产物与来源的中断切换检查属于 M2，不能等到 M3 才保证已保存文件不被失败构建覆盖。尚未实现的管理功能不显示为可操作，也不以成功空响应代替。

**当前实施状态**

M2 已实现固定 `@local-projects/sdk 0.1.0`、项目真实 README/CLI 路径、系统 Node/npm 探测与显式选择、持久构建任务和分段日志、输入和产物摘要、带来源的发布及中断核对。当前模板为 `react-ts-vite-0.1.1`，本轮增补配套初始网页和 AI 接管 skill。管理界面接入构建、日志、复制给 AI 和明确重载；网页资源按不可变构建代提供，初始模板来源与用户构建来源分别记录。

当前开发身份仍为 `dev.localprojects.platform.m0`，不重用正式数据位置；已有项目不会自动补写初始网页、模板、SDK、锁文件、README、skill 或 AI 工具入口文件。无构建来源的旧网页显示 `unknown`，合法的无产物旧项目仍可为 `unbuilt`，不因升级平台而被强制重建。

上述为代码交付范围，原独立外部 AI、桌面与普通浏览器、重启结果保留在 [M2 验证记录](m2-verification.md)；本轮新增场景单独写入[初始应用与 skill 验证记录](starter-skill-verification.md)，不借用历史结果预先宣称通过。资源限额仍是内部测试参数；各代产物和任务暂不自动过期清理，保留期限未定。构建脚本不是沙盒，必须遵守不写业务数据、不启动后台或脱离进程组子进程的约定；平台负责普通构建进程组的收尾。

## 6 M3：完整备份、维护与恢复

**交付内容**

- 整项目 ZIP、数据库一致性副本、文件校验清单、可移植构建来源和维护提示；完整携带清单、`meta/`、源码、SDK、网页产物及附件。
- 普通备份的短暂冻结、持久维护、成功基线后允许修改、结束检查与文档代次推进；重启不会自动解除维护。
- 恢复候选校验、完整原现场保留、持久操作日志、根切换与中断识别；正常备份保留策略与保护引用。
- 基础备份列表、详情、创建与恢复界面和 CLI；完整历史管理入口按已定稿范围逐步补齐，不提前承诺讨论稿中的删除规则。

**验收条件**

1. 修改源码、数据、图标与附件后恢复到指定快照，所有相关内容一致恢复；可复用产物的恢复不要求 Node。
2. 在备份、维护基线和恢复关键阶段模拟失败与重启，得到可解释的完成、回退或待处理状态；不损坏原现场、不伪报成功。
3. 旧页面在维护结束或恢复后不能继续用旧代码写数据，用户明确重载后取得新入口。
4. 损坏归档、坏库、磁盘写入失败、已有待构建要求和维护中的操作冲突按契约处理；项目状态与文件实况一致。

M3 通过后，才进入受控真实数据验收；对外试用还须满足 M6 的分发与身份条件。这是数据和恢复能力的验收，不以新增默认测试表代替实际项目快照。

## 7 M4：导入导出、复制、删除与迁移

**交付内容**

- 完整快照导出、原 ID 导入、新 ID 副本、重复 ID 检查；复制保留业务主键，图标、附件和数据库独立保存。
- 删除进入回收站、原 ID 恢复、明确永久清除；历史备份和未完成恢复现场按各自保护规则处理。
- 同机 APFS 工作区迁移、工作区外的持久迁移日志、复制校验、提交新位置后不自动回源、旧目录占用展示。
- 历史备份另存、可删除备份清理和迁移旧目录清理的精确接口仍待讨论稿定稿；本轮只显示保留旧根，不提供删除旧根命令，也不将未确认的接口作为本轮必交项。

**验收条件**

1. 原项目和副本的修改互不影响，名称与图标随文件传递；新身份、维护状态和构建来源符合契约。
2. 删除、恢复和导入后的同 ID 项目拒绝旧页面；恢复后的统计缓存不沿用旧根结果。
3. 在迁移复制、校验、提交前后模拟中断及目标不可用，不能误开旧副本或丢失受保护状态。
4. 核对回收站永久清除只影响明确选择的对象；历史备份、外部导出和受保护原现场继续保留，保留旧根不被普通清理误删。

“卸载软件时清除所有本机数据”是另一项尚未确认的建议，不隐含在项目删除、回收站清除或本阶段历史管理中；不把它当作 M4 必交功能。

## 8 M5：统一管理页面、空间与浏览器能力

**交付内容**

- 首次启动、创建与打开项目、交给 AI、错误诊断及环境检查的连贯流程；细化默认工作区与可选位置的实际交互。
- 完整项目卡片与概览、名称简介和图标编辑、编辑冲突检测、运行需求展示、关于页面；未构建、坏图标与坏库仍能查看可用资料。
- 空间分类和占比、明确的缓存位置与时效、平台程序和工作区去重、附件分页浏览与基本预览、白名单缓存清理及相关历史入口。
- 运行需求与 CSP、本地文件选择/拖入/下载、播放、主动剪贴板、短录音和拍照；公开接口失败的处理，不加入密钥连接器或通用网络代理。
- 在明确的签名测试构建中提前验证 macOS 设备权限，不能只等 M6 才发现桌面媒体能力不可用。

**验收条件**

1. 用户无需终端即可找到项目、位置、当前状态、空间占用和 AI 交接说明；每个入口反映真实任务与错误，不把未统计显示为零。
2. 元数据改名不改 ID、不重建、不重载业务表单；UI 与 AI 编辑冲突不会静默覆盖，复制和恢复显示正确图标。
3. 空间分类、占比、未知范围、默认工作区父子目录去重和根切换缓存失效正确；清理不影响用户资料和受保护记录。
4. 签名桌面构建、Safari 和 Chrome 分别验证拍照、录音、回放、保存、拒绝权限及设备释放；附真实系统与浏览器版本。
5. 断网后本地功能继续工作；外网声明与实际请求策略一致，附件保存和业务记录写入的失败不会被显示为完整成功。

媒体组件及上传限制采用正式定稿参数，首版不增加长期后台录音、自动转写、AI 评分或视频处理等功能。

## 9 M6：发行、更新与外部试用

**交付内容**

- 正式品牌、固定应用标识、CLI/SDK 名称、版本及平台图标，统一写入发行元数据；身份在首批携带持久用户数据的外部分发前冻结。
- macOS 15+、Apple Silicon 原生 arm64 的签名、公证 DMG；验证包内 CLI、SDK 和模板资源，提供真实下载和版本说明入口。
- 检查更新、完整退出后手动覆盖安装；更新时保留项目、控制状态、维护记录和恢复现场。
- 完整用户流程、环境诊断和验收记录；普通卸载默认保留数据。若额外采纳清除全部数据功能，必须另有已确认范围和失败恢复规则，再纳入验收。

**验收条件**

1. 使用下载得到的真实 DMG，在最低支持 macOS 与发布目标系统的 Apple Silicon 设备上完成首次安装、启动与离线启动检查。
2. 在没有平台开发工具和没有 Node 的运行环境使用已有项目；需要构建时按约定检测和引导环境，不能依赖开发机 PATH 掩盖问题。
3. 覆盖更新后 SDK、源码、数据库、附件、持久维护和恢复状态正确保留；当前安装版本和程序占用显示正确。
4. 非开发用户完成安装、创建项目、交给外部 AI、日常使用、备份和恢复；记录实际卡点，修复阻塞问题后才进入发布候选。
5. 普通卸载保留工作区，重新安装可按原位置找到项目；有未完成任务、不可用外盘或未知控制格式时行为与契约一致。

M6 之前的内部包只能用于受控验证。不能用“开发模式通过”代替签名安装、权限、覆盖更新和卸载验收，也不能把生成出 DMG 当作已完成全部发布检查。

## 11 测试方式与完成记录

日常从源码启动平台，在测试工作区使用真实 Rust 服务和 SQLite。平台管理原生能力在 Tauri 窗口验证；项目网页同时在桌面和普通浏览器验证。自动测试优先覆盖路径边界、事务与失败状态、构建输入一致性、快照校验、恢复和迁移提交等重要逻辑；媒体、系统权限与安装流程保留真实设备验收。

每个里程碑完成时记录：代码版本、实际交付内容、复现步骤、测试环境、验证结果、尚未实现的范围和未解决问题。代码或包不能运行、只有静态截图、关键步骤靠未记录手工修改、或未完成的数据操作被标为成功，都不能作为阶段完成证据。

进入真实数据与外部试用前，检查相应恢复能力及发行门槛；不把测试资料混入用户工作区。本计划不要求为普通文案、样式等低影响修改堆砌测试，验证重点是实际功能和数据保留。
