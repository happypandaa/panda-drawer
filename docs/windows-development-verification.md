# Windows 开发工具与源码候选验证

## 2026-10-23：开发工具、本机目录与执行基础

本步继续 `codex/windows-compatibility`，开发身份与系统默认数据根保持原样。验证全部使用明确命名的新可丢弃目录，没有修改既有开发项目、SDK、数据库、附件、备份或恢复现场。

Windows 独立开发载荷为官方 Node 24.22.1／npm 11.19.1 与 MinGit 2.56.0.windows.2。开发 Node 使用 [2026-10-21 安全发行](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)对应补丁；业务 Node 24.22.0 仍是独立载荷。本步不把开发工具当作业务应用运行时。Git 来自 [Git for Windows 官方发行](https://github.com/git-for-windows/git/releases/tag/v2.56.0.windows.2)。固定归档摘要、逐文件清单、完整树摘要、许可证与 PE 架构记录分别见 `scripts/windows-development-{node,git}-release.json`；MinGit 内的托管 .NET PE32 资料按固定清单保留，主 Git、HTTPS helper 和 Node 入口要求 Windows x64。

本机设置中可按需检查工具、明确选择本地开发 Node 或 Git、明确恢复内置选择。选择先生成草稿，确认后完成文件树和实际版本检查再保存；无效选择不覆盖旧记录。显式选择失效、设置损坏、目录或文件变化均拒绝使用，不寻找系统 PATH 中的替代工具。资源核验保留已知目录链与叶文件 HANDLE，并在使用边界重核目录清单；这不是限制同一用户其他进程的安全沙箱，也未验证在不同机器上的交互延迟。

Windows 现在复用本机目录三态流程：检查普通目录、明确确认初始化真正空目录、再次预览后登记。已有有效 Node 目录只登记外部引用；其他目录显示 AI 检查说明。检查不运行代码、不安装依赖、不自动发送 AI。外部创建使用原目录 HANDLE 的 create-new，不改变外部 ACL、不覆盖已有对象。预览修订绑定目录与条目身份；部分创建保留已建路径，关闭平台时阻止新操作并等待已接受初始化结束。

协议无关执行器共享已有 Job 所有权实现。进程第一条指令前进入非继承 Job；stdin 与两个二进制输出通道独立处理，输出有界并标注截断。取消、超时、先退出的 leader、future 被中止及宿主异常退出均只处理所持有的 Job／进程 HANDLE，不枚举并终止无关进程。Node 业务协议与既有错误类别保持兼容。

开发设置与任务证据只在已准入工作区 `.platform/` 下按需创建，根证明绑定固定数据根与目录的卷／ID128。未识别目录不按名字接管。任务记录按主线 `task_` 标识和响应字段保存追加事件；中断任务只分类、保留，不自动重放。源码标识沿用主线 `src_`。读取空列表不创建任务根。
