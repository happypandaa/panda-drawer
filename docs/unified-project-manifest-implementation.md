# panda.json 分批实施记录

依据 [已确认方案](unified-project-manifest-proposal.md)，2026-11-01 开始。仅记录实际实现和验证；旧验证记录不代表本次结果。

## 批次 1：清单、Node 与功能删除

### 已实现

- 新增 Rust `PandaManifest`，统一声明结构、严格字段和版本检查、递归重复键拒绝、相对路径与真实链接边界检查。声明检查只读；图标无效时回退默认。Node 读取项目根 `panda.json`，不读取旧文件或迁移旧登记。
- Rust 声明生成 `schemas/panda.schema.json`，再生成前端类型。Rust 与 Ajv 使用同一组公开样例，生成脚本支持 `--check`；Schema 随桌面资源分发，交接说明提供实际资源路径。删除旧的独立配置 Schema，避免两份规则。
- Node 数据使用项目 `data/`；缓存、临时文件、日志、实际配置和密钥仍在平台私有目录。检查预览不创建数据目录，启动时才创建。已有用户目录权限不被平台重写。
- 用户选择的空文件夹生成新清单和 `.gitignore`。登记完成后撤销初始化临时归属，文件夹属于用户。删除本地应用保留代码、Git 和文件数据；Git 获取的受管源随项目删除。两者均清除平台登记、私有配置和浏览器存储。
- 启动前重新读取声明。名称、版本、图标、配置项和入口修改下次打开生效；类型改变明确拒绝并提示删除后重新添加。实例身份不从作者清单获得。
- Node 网页文件读取同时检查声明路径与解析后的真实路径，拒绝隐藏目录、`data`、`node_modules`、清单以及链接数大于 1 的文件。内部安全符号链接可使用，外部或指向受保护路径的链接拒绝。项目根 `data/` 与普通网页资源 `assets/data/` 分别判断，后者可正常提供。保留原有文件句柄绑定和读取排空。
- 修复 Git 获取时的预算监测竞态：运行中的临时软／硬链接只观察自身元数据，不跟随；全部 Git 写入与读取排空后，发布前再严格拒绝持久链接及特殊文件。两平台使用各自的原生目录绑定。
- 修改 Node 交接、求助提示词、表单类型、详情和删除文案；文件数据与浏览器数据分别说明。标注退役文档，更新当前配置、数据和 Windows 适配表。

## 批次 2：网页单目录与接入

### 已实现

- 网页只读取 `panda.json`；实例 ID、源目录身份、用户／平台归属和 Git 来源保存在固定数据根 `web-apps/<实例>/registration.json`，不从作者清单或目录名获得身份。同一个可写源目录继续保持独占登记。
- 网页直接提供当前源目录中的 `web.root/web.entry`，不复制源码或网页产物。运行中的清单使用打开时快照，重新打开才采用新声明。静态文件仍通过真实路径、原生文件句柄和读取排空检查。
- 数据库固定为 `data/main.sqlite`，附件固定为 `data/attachments/`，均首次使用时创建。数据库不存在就新建，损坏时返回真实错误，不删除、修复、迁移或重置。没有 SDK 声明时，SDK 调用明确拒绝且不创建数据。CLI 的数据库操作在无应用窗口时用完即关。
- 平台构建在原项目的 `development.sourceDir` 中执行受管 Node/npm 的 `npm ci` 和 `npm run <声明的脚本>`，检查声明入口；不增加输出参数，不回滚用户文件。应用窗口存在时拒绝构建。
- 起始网页模板改为根目录源码布局；新建时实际构建。批次 2 仍保留共用服务路径和 Vite `base: './'`，SDK tarball 的移除属于批次 3。
- 本地网页直接登记为用户所有。已有入口可打开；缺入口并声明构建时显示需要构建，否则显示入口缺失。删除保留用户文件夹及 `data/`，仍清除浏览器数据和平台登记。源目录被移动或替换后，删除旧本地登记也不取得删除该目录的权限。
- Git 网页已有入口时不执行安装或构建；需要构建时持久等待用户确认，使用声明脚本。取消、失败和登记前退出均回滚未登记的受管材料。登记后只清临时材料，不回滚已登记应用。导入收尾中断可重试，或直接删除应用；临时控制目录按原始文件身份纳入完整删除，成功后不留成功日志。
- 详情只读展示作者名称、图标和版本，按声明显示构建入口。删除确认及添加完成页分别说明文件数据与浏览器数据。交接说明只写平台私有目录，列出实际可用的 Schema 和说明文件路径。

### 控制材料去向与删除清单

| 原项目内材料 | 当前处理 |
| --- | --- |
| 项目状态、登记、配置 | 固定数据根的 `web-apps/<实例>/`；不写回项目 |
| 构建状态与日志、npm 缓存、最新构建指针 | 同一实例私有目录中的 `builds/`、`npm-cache/`、`latest-build.json` 等 |
| 上传暂存与跨卷附件发布凭据 | 实例私有 `uploads/`；目标卷临时文件在写入前登记精确归属，完成或删除时清除 |
| 交接说明与当前交接指针 | 实例私有 `handoff/` |
| 任务索引、任务日志、操作协调 | 工作区平台控制目录的集中任务／操作表；按实例归属清理 |
| 构建源码副本、不可变产物、代次占用、发布恢复 | 删除，不再生成 |
| 元数据修改、源码摘要和构建新旧状态 | 删除；名称和图标只来自清单，平台不判断产物新旧 |

集中任务／操作表的物理位置与方案 3.3「按实例存放」不同。它们已全部位于项目文件夹以外，保留现有统一调度；实例删除按归属清除其条目及日志，无跨项目共享内容或引用计数。此处是内部存放方式差异，不改变项目文件、删除范围或用户操作。

删除 `metadata`、`metadata_file_io`、旧项目目录映射模块及其命令；保留并拆出有界 PNG 解码与独立文件读取。删除 `build_admission`、`build_candidate`、`build_artifacts`、`build_copy_io`、`build_digest_path_io`、`build_directory_exchange`、`build_publication_io`、`build_source_io`、`build_window_views` 及对应旧测试；保留任务调度、受管进程、构建输入检查和取消／退出收尾，重写为原地构建。

网页独立服务、固定地址、配置表单、SDK 新路径和实际关窗后数据库释放在批次 3 实施，本批不提前宣称完成。

## 批次 3：固定地址、独立服务与网页配置

### 实现选择与范围

- 固定地址选 A：网页和 Node 各实例保存固定 `127.0.0.1` 端口。Web/Node 共用分配锁和私有地址预留，排除已关闭和登记中的实例；登记与预留必须一致，缺失或损坏不分配替代地址。端口冲突报原地址与释放占用后重试的办法，不换端口。Unix 允许地址重新绑定而不允许共享监听；Windows 使用 exclusive-address-use，避免接管现有监听。
- 网页每次真正打开启动进程内独立服务；管理服务不再提供共用项目路由。每实例独立认证、一次性 bootstrap、停止信号和 I/O 生命周期，SQL／附件处理仍复用共享实现，浏览器配置接口不提供管理能力。
- 真实窗口销毁触发有归属的关闭任务；显式关闭、删除、迁移、平台退出均加入同一收尾。先停监听、会话与活动流，再排空请求／上传／SQL并关闭 SQLite，持写门禁直到释放打开租约，最后报告 closed。调用者取消不丢弃任务，失败保留资源及重试状态。无窗口时 CLI 数据库命令用完即关。
- 绝对资源、无扩展名页面路由回退与统一放宽 CSP；保护路径、越界／硬链接、资源缺失和未知平台接口不回退。Node 使用同一安全策略定义，connect 仍仅 self。
- `/_platform/sdk.js` 为唯一普通 IIFE 实现，提供 `window.panda`；固定 `/_platform/api/v1/`，配置单独读 `config.json`。可选 npm 包只做全局薄封装，类型以一份 `panda.d.ts` 为源，随资源安装及复制到模板。删除 SDK tarball、模板 vendor 依赖和 Vite base。
- 网页配置复用 Node 的声明、版本锁、类型校验和表单；网页不提供密钥。保存只写实例私有目录，文本／整数／布尔／选择值保留 JSON 类型，选填空值省略。配置值刷新生效，声明使用本次打开快照；新增必填项在下次真正打开前拦截并进入表单。服务切换保留未保存草稿并阻止旧会话写入新目标。
- 已运行窗口重复进入先安全聚焦，再次打开时不因作者刚改声明而丢弃草稿；真正重开／明确重载才应用新声明和配置门禁。两平台先创建不可见空白页，完成存储及原生对话框适配后再导航显示。启用原生 alert／confirm／prompt；外链和 window.open 交系统浏览器。
- 更新当前提示词、技能、格式和窗口契约、SDK／模板资源准备及人工探针。增加[用户验收方案](unified-project-manifest-user-acceptance.md)和只生成可丢弃测试源码的脚本；不替用户执行原生操作或重置现有开发项目。
