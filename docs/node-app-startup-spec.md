## 1 哪个文件负责什么

| 文件 | 职责 |
| --- | --- |
| 外部包 `local-app.json` | 机器读取的应用类型、版本、前后端入口及兼容要求；声明配置字段、中文用途和获取步骤，不含用户秘密值 |
| 平台受管项目清单 | 安装后记录真实类型、程序来源、数据归属；由新版本契约明确映射，不伪造现有构建来源 |
| 后端 `package.json` 与锁文件 | 描述作者构建和依赖来源；不是平台自动执行 npm scripts 的授权 |
| 用户使用说明 | 功能、首次配置、从平台打开／关闭应用、联网、数据与常见问题 |
| AI / 开发说明 | 入口、依赖交付、启动协议、数据和故障处理，供维护者核对 |

机器启动规则放在版本化清单中；Markdown 供人和 AI 阅读，平台不从说明文字提取并执行 shell 命令。两份说明继续按[应用文档分工](application-documentation.md)分别提供。

现有外部包 v1 固定 `static-web`，project v1 的未知字段也没有后端执行语义。Node 类型必须采用旧平台会明确拒绝的新包版本及受管项目/归档版本，不用 `extensions`、`runtimeRequirements` 或旧清单的未知字段偷渡启动能力。具体版本号和迁移方式在 NR0.1 冻结；保留现有 v1 Schema 和示例。

### 1.1 两种运行类型与识别

这里区分的是应用日常运行是否带自己的 Node 服务：不带的显示为“网页项目”，带的显示为“Node 服务项目”。项目源码构建曾使用 Node/npm，不会使网页项目变成 Node 服务项目。两类都依赖平台现有 Rust 服务；类型也不表示是否附源码、能否离线、是否调用 AI，或此刻后端是否正在运行。

| 运行声明 | `backend` | Node 环境配置 `configuration` | 平台类型显示 |
| --- | --- | --- | --- |
| `static-web` | 禁止出现，包括空对象或 `null` | 禁止出现；不借静态类型获得启动环境注入 | 网页项目 |
| `node-service`（新格式候选枚举） | 必需且有效，入口与完整运行依赖须通过检查 | 有需用户填写的启动变量时按[配置草案](node-app-configuration.md)声明；不改变既有候选字段规则 | Node 服务项目 |

新外部包或新受管格式必须有明确且被支持的运行类型；缺失、未知、格式版本不支持或声明矛盾均拒绝，不根据 `package.json`、依赖目录、构建工具或文件名猜测，也不静默当作网页项目。仅对已知合法的历史 project v1 按原静态语义识别，不补写清单或取得新执行权。新 Node 类型的包、项目和归档版本必须使旧平台明确拒绝。

类型图标由平台按有效运行类型生成，规则见[项目类型显示](project-metadata-and-overview.md)；作者不另填 `needsNode` 布尔或指定类型图标。它与项目自己的 `icon`、是否有源码和运行状态分别显示；Node 服务已停止、缺少配置或启动失败时，仍显示 Node 服务项目。清单无效时展示识别问题，不猜成网页类型。

## 2 两类最小声明片段

下面分别展示网页项目与 Node 服务项目的运行声明，均省略应用基本信息、文档和数据等完整包要求，不是可直接安装的完整清单。网页片段沿用静态 v1；Node 片段的 `formatVersion: 2`、`node-service` 和 Node `24` 均为设计示例，未成为现行格式。Node 配置声明另见[变量示例](node-app-configuration.md#2-声明与实际值分开)，本片段省略它；`backend.protocolVersion` 与包及配置声明版本分别演进。

网页项目：

```json
{
  "packageFormat": "local-web-app",
  "formatVersion": 1,
  "runtime": "static-web",
  "web": {
    "root": "web",
    "entry": "index.html",
    "routing": "files"
  }
}
```

Node 服务项目：

```json
{
  "packageFormat": "local-web-app",
  "formatVersion": 2,
  "runtime": "node-service",
  "web": {
    "root": "web",
    "entry": "index.html",
    "routing": "files"
  },
  "backend": {
    "protocolVersion": 1,
    "root": "backend",
    "entry": "start.mjs",
    "nodeMajor": 24
  }
}
```

| 字段 | 候选约束 |
| --- | --- |
| `runtime` | 按第 1.1 节显式声明运行类型；两类方向已确认，新 Node 枚举和格式待冻结 |
| `backend.root` | 相对包根的后端运行产物目录，包含完整运行依赖 |
| `backend.entry` | 相对后端根的实际 JavaScript 文件；不接受命令串 |
| `backend.nodeMajor` | 与平台私有运行时匹配的主版本；精确补丁由平台锁定 |
| `backend.protocolVersion` | 平台和启动适配入口共同支持的协议版本 |
| `web` | 前端由平台静态服务；不将包根、后端源码或数据目录公开 |

路径沿用并扩展现有包检查：拒绝绝对路径、目录逃逸、链接、路径别名和越界引用；核对真实文件身份、摘要、大小及目标系统。清单不允许任意 shell、自定义 npm 启动脚本、作者传入的 Node flags、固定端口、本机绝对路径或秘密值。

## 3 运行目录和依赖

候选发布结构如下；仅说明职责，最终受管目录布局由 NR0 定稿。

```text
application-package/
  local-app.json
  web/                       静态前端产物
  backend/
    start.mjs                统一启动入口
    dist/                    后端 JavaScript
    node_modules/            若未打包依赖，完整纯 JS 运行依赖放此处
    package.json
    package-lock.json
  docs/
    USER_GUIDE.md
    DEVELOPMENT.md
```

启动使用平台指定的私有 Node 绝对路径和入口绝对路径，工作目录固定为后端根。平台不调用 shell 或 `npm start`。后端程序目录视为不可变产物，运行写入必须使用注入的数据、缓存和临时目录；约定不能代替 OS 沙箱。

运行依赖是应用程序的一部分，不能从备份中当源码缓存排除。应用可以预先打成独立 JS 产物，也可以交付完整依赖树；必须离线可启动。带原生扩展、平台二进制或额外服务的包在目标类型尚未定义、实测前不接受。Node 自带模块的版本要求也需验证。现有源码依赖和系统 Node 构建流程另行保留。

## 4 平台注入的运行上下文

以下环境名称为协议候选，不是当前可用环境变量：

| 名称 | 内容与用途 |
| --- | --- |
| `APP_INSTANCE_ID` | 本次启动随机标识，不能用应用 ID 或 PID 代替 |
| `APP_HOST` | 固定回环监听地址，建议 `127.0.0.1` |
| `APP_PORT` | 建议为 `0`，由 OS 分配空闲端口，应用报告实际绑定结果 |
| `APP_DATA_DIR` | 本应用允许持久保存的独立目录，数据模式与生命周期须先确定 |
| `APP_CACHE_DIR` | 可重建缓存，清理前确认不是业务唯一副本 |
| `APP_TEMP_DIR` | 本应用本实例临时目录，同时正确设置目标系统临时目录变量 |

必要系统环境采用明确白名单，分别验证桌面与各操作系统；不把宿主完整环境复制给应用。平台管理令牌永不注入。另按[可视化配置规范](node-app-configuration.md)读取清单声明的业务变量，校验用户填写的普通值和秘密绑定，仅在创建目标 Node 子进程时注入。不得覆盖上述平台保留变量或系统加载选项，不从机器任意环境/文件映射秘密，也不把真实值写入清单。

启动前检查必填项、声明版本及配置修订，缺失或无法读取秘密时显示“需要配置”，不带空 Key 启动。运行实例保留所用配置修订；后续保存只影响下次启动，用户明确重启后再取新快照，不能在全局环境热修改或向网页返回保存的秘密。

控制认证及代理到后端的短期凭据由私有控制通道传递，不放命令行、公开配置或日志。应用 ID、数据目录等路径值不构成其他项目的访问权限。PID、端口、实例 ID 和短期令牌不进入可复用应用包或归档实例记录。

## 5 就绪、健康和控制通道

建议使用受限长度的 NDJSON 控制通道：平台写子进程 stdin，子进程 stdout 只输出协议消息，stderr 为受限应用日志。启动适配器负责将普通库日志留在 stderr，避免污染协议。编码、消息大小、速率、错误分级和超时在 NR0 冻结；无效或过期消息不能改变实例状态。

| 消息方向 | 候选消息 | 语义 |
| --- | --- | --- |
| 平台 → 后端 | `initialize` | 协议、本次实例、私有认证及必要启动配置 |
| 后端 → 平台 | `ready` | 当前实例已绑定指定回环地址及实际端口，必要本地初始化完成 |
| 平台 ↔ 后端 | `ping / pong` | 核对实例和控制通道活性；仅凭此不能证明 HTTP 事件循环与路由可用 |
| 平台 → 后端 | `shutdown` | 禁止继续接纳工作，排空、关闭资源并退出 |
| 后端 → 平台 | `stopping` | 正在收尾的提示；不代表已退出或数据已安全关闭 |

就绪后平台还需对**同一监听器**完成带本次实例认证的本地探测。固定健康路由及格式由协议统一规定，作者不任意配置探测命令；准确路径尚未定稿。探测只检查本地响应，不请求网易云、AI 或 TTS。实际进程存活、已验证 `ready` 和 HTTP 响应共同决定后端是否可用。

使用端口 `0` 避免“预选一个端口再启动”的竞争。平台核对报告的 host、实际端口、运行 ID、认证与进程归属，不能把其他程序在相同端口的成功响应当作本次启动成功。启动退出、控制通道关闭、初始化失败、协议不兼容或到期未就绪，均封闭入口并回收实例。

## 6 业务请求经平台代理

平台提供受项目会话约束的访问入口，实际 SDK 名称、HTTP 路径和管理 CLI 在后续接口契约定义，本文不预注册方法。网页不硬编码后端端口，不使用 `localhost:3000/8080`，也不把回环 HTTP 填进现有 `runtimeRequirements.network` 绕过规则。

平台代理检查项目、文档代次、运行实例和维护门禁，再携带实例私有认证访问后端。浏览器不能拿到该认证；后端本地端口只接受平台转发，需防止未经授权的直连。代理内部地址来自管理器的已验证实例，不接受页面提交任意目标 URL。

第一步先明确普通 JSON/HTTP 请求。开放音乐类应用前，另验收 SSE、取消、长请求、流式响应、GET/HEAD、音频 Range 和背压；WebSocket 等额外协议须单独定义。头部、Cookie、重定向、Origin/Host、CSP、路径前缀和错误映射按受控规则处理，不转发平台管理凭据或盲目改写任意页面。第一阶段不代理后端 HTML/SSR。

应用从平台代理提供的基址构造 API 路径，不能假定站点根目录就是自己的 `/api` 或 `/tts`。桌面 WebView 与普通浏览器分别验证。上游音乐地址和媒体来源仍需遵循网页运行声明与实际浏览器限制。

## 7 正常停机和强制终止

收到 `shutdown` 或控制通道失联后，应用停止接收新业务，结束或取消在途任务，提交/回滚事务，关闭数据库和文件、HTTP listener 及受管子任务，然后退出。必须提供有限时间内可完成的收尾路径；不能仅发 `stopping` 就继续无限等待。

平台先关闭业务入口，再发停机通知并等待。到期按目标系统机制强制结束归属本次实例的进程树，记录“异常终止”，核对退出；不按进程名批量终止，不仅凭归档 PID。应用不得脱离进程组、后台自启动或自行重启。准确宽限期与强制结束策略在 NR0 定稿，不能由包任意拖延管理操作。

正常退出、强制终止、未能确认退出分别记录。涉及快照、恢复、删除和迁移时，无法确认退出就拒绝后续操作；强制终止后还须通过所选数据模式的恢复与一致性检查，不能自动宣称保存成功。平台硬崩溃后的残留核对见[运行方案](node-app-runtime.md#5-故障子进程与平台退出)。

## 8 作者必须写进两份说明的内容

**用户指南**写实际操作：需要哪些账号或配置、网络用途、首次启动、运行状态含义、正常停止与强制结束差异、错误时怎样查看诊断、数据如何备份。普通使用不要求安装 Node、打开终端或手工输入端口；尚未交付的界面不能写成现成功能。

**AI / 开发说明**至少包含：

- 与清单一致的入口、兼容 Node 主版本、控制协议，以及可复现构建与完整运行依赖来源。
- 前端代理基址、路由、流式/媒体需求；不得固定本机端口或依赖原开发站点根路径。
- 数据、缓存、临时文件分别是什么；数据库由谁管理、干净关闭方式、异常恢复条件、归档与更新要求。
- AI、TTS、音乐 SDK 的版本、外部网络和凭据用途；每个变量的中文名、必填/默认、格式示例、用途、获取步骤及生效规则与清单一致，不附真实 key、Cookie 或本机私人路径。
- 正常停止、启动失败、上游不可用时的行为和验证结果；仅测试控制协议不能宣称真实账号和播放通过。

平台只读取文档，不执行文档中的指令。新类型的完整清单、数据规则和验收冻结前，上述规范用于准备适配方案，不允许直接登记真实项目并运行。
