# Node 启动途中退出的收尾

2026-10-25，E25 原生发现：点击进入后立即正常退出，第二次私有 Node 版本检查已被关闭接纳门禁拒绝，应用尚未创建实际运行目录，`active.json` 却始终保留。平台下一次启动因此把这个已结束的启动视为未知状态，阻止再次进入。该旧 E21 现场保留，没有根据空目录、PID 消失或人工删除标记解除保护。

本次修复只处理当前进程亲自拥有的启动。失败启动返回明确的清理回执：应用尚未生成且已经接纳的版本检查真实完成 driver、进程组和 I/O 收尾，或应用已收到正常停止回执并完成关闭，才允许收尾本次 intent。空 pending 句柄、普通错误或进程不存在均不构成回执。已经接纳的版本检查无法确认关闭、应用未正常停止或资源仍未知时，继续保留 intent 和可保留的真实运行句柄。

intent 创建时持有其打开文件和精确字节。收尾先持久化独占的 `.start-intent-cleanup-*` 私有槽，再用 macOS 的目录描述符与不覆盖原子移动捕获 `active.json` 候选；核对捕获对象的普通单链接文件、设备／inode 和内容后，才删除私有槽内的本次对象。不会对检查之后仍可被外部替换的公开 active 路径直接删除。若捕获到外部对象，只在目标空缺时不覆盖地归还；若新 active 已出现，则两份都保留。任何错误或崩溃留下的清理槽都是持久门禁，不能凭槽为空推断完成。

详情、列表和启动共用清理门禁：停止状态显示需要检查、`canStart:false`；真实后端仍运行时保留 running 状态并说明问题。安装目标、最终发布指针前检查、开发绑定／构建／源码取回以及删除入口也拒绝绕过门禁，原数据和证据保留。配置修改的原有规则不因该修复扩大。该原子清理目前仅在 Mac 开放，其他平台拒绝执行；未增加自动修复旧 intent 或跨宿主猜测进程归属的入口。

主工作区相关 Node 检查152项通过、0失败，2项原有真实 Node 条件测试按原入口忽略；全目标严格 Clippy、格式及差异空白检查通过。独立同源码回归另覆盖24项运行时、47项进程所有权检查，原有3项外部／显式条件测试未执行。生命周期测试使用隔离人工协议进程，不能当作包内真实 Node 或原生窗口证明。它们验证：intent 后接纳关闭、第二次真实检查被取消且完整 join、失败 ready 后正常停止、无正常停止时即使空句柄仍保留、标记替换／改写／变类型、检查后替换、捕获后新标记出现、残留清理槽的三种类型及修改入口拒绝。原生新包复验另行登记于[三场景验收](three-scenario-verification.md)，不回填为旧包已正确收尾。

同轮修正配置展示：`canStart` 同时包含运行、来源和关闭门禁，不能当作必填配置缺失。界面根据真实缺项、字段校验和密钥目标状态显示配置问题；普通配置完整而运行被阻挡时保留运行错误并进入运行状态，不再提示“缺少0项必填”。可选密钥 `missing` 不能区分从未填写和已保存文件丢失，阻挡时保守显示待核对，不据此允许启动。执行仍严格使用后端 `canStart`。主工作区全部界面433项和 TypeScript／Vite 通过；新增11项为模拟命令的DOM验证，未冒称真实密钥或原生重开已通过。
