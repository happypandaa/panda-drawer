# Node 项目单目录运行

更新：2026-11-01。现行格式和分批范围以[项目配置与网页接入方案](unified-project-manifest-proposal.md)为准。

2026-11-02 的健康检查 HTTP 兼容性修正、启动诊断和仍未覆盖的接入情况见[Node 后端兼容性记录](node-backend-compatibility.md)。该记录区分源码改动、验证结果和已安装应用，不能据源码修改推断本机安装包已经更新。

## 项目与清单

Node 直接运行登记的项目文件夹，不保存程序副本。根清单为 `panda.json`，`manifestVersion: 1`、`runtime: "node"`；`app.name` 必填，版本、简介和图标可选，没有作者应用 ID。前后端入口必须已经准备，后端使用固定 Node 24 和控制协议 1。Node 不接受 `development`、`platform`、`runtimeRequirements` 或其他未知字段。

每次打开重新读取有效清单；修改名称、版本、图标、入口和配置声明下次打开生效，运行中保持本次快照。新增必填配置未填写时先进入配置，保存不自动启动。改变 `runtime` 时拒绝启动，提示删除后重新添加；实例身份、配置和删除归属不能由作者清单修改。

JSON Schema 随应用放在 `schemas/panda.schema.json`，具体路径由交接说明提供。不支持旧清单，不迁移旧登记或业务数据，不清理开发机旧残留。

## 数据和归属

文件数据使用平台注入的 `APP_DATA_DIR`，指向项目的 `data/`；真正启动时才创建，检查和添加不创建业务目录，已有内容与权限保持。缓存、临时文件、日志、配置和密钥仍放在平台私有实例目录。秘密值只向目标后端注入，不写作者清单或前端。

localStorage、IndexedDB、Cookie 等浏览器数据由平台窗口存储保存，与实例绑定。删除实例始终清除，重新添加同一文件夹也不能读取原浏览器数据。

用户选择的本地文件夹，包括在用户选择的空文件夹中生成的 Node 起始项目，归用户所有；删除应用保留代码、Git 和 `data/`。Git 下载的项目归平台所有，删除时连同文件夹和 `data/` 全部删除。两者的私有配置、密钥、日志、缓存、任务和浏览器存储均清除。初始化期间只临时记录本次创建文件和 UUID，不取得递归删除用户目录的权限。

## 从 Git 添加

接受 GitHub/Gitee 公开 HTTPS 仓库。已声明运行入口须已提交，不执行仓库构建脚本。依赖根从项目根和后端根去重后选择：有 npm 材料时须恰好一组有效 `package.json` 与 npm v2/v3 `package-lock.json`；零依赖且没有包声明时跳过。受管命令仍为 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`，与本机开发依赖使用 pnpm 的偏好分开。

Git 添加沿用单 UUID、真实进度、提交点核对及中断收尾。登记确定未提交才回滚；登记已提交只清临时材料；结果未知时先核对，不能重新添加或借裸路径删除。用户本地文件夹不安装依赖。

## 修改和收尾

代码与 Git 版本由外部 AI 管理。修改前关闭应用窗口，修改后重新打开。平台不提供源码／数据版本取回、Node 构建更新、ZIP 导入导出或复制；不会因停止这些功能而清理既有业务文件。

关窗、平台退出、项目删除和现有工作区操作继续等待代理、真实后端及受管后代进程结束。平台目录归属、原生窗口存储和实际写入者核对仍保留。用户原件位于待删除旧工作区内时，工作区迁移拒绝收养或删除它，未完成初始化的用户目录也受保护。

网页也已使用同一份 `panda.json` 并直接服务原目录；其构建及本地／Git 接入见[当前项目格式](panda-project-format.md)。网页独立地址、全局 SDK 和公开配置路径见同页；Node 配置仍只通过后端环境变量注入，秘密不向网页开放。
