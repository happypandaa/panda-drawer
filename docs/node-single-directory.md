# Node 项目单目录运行

确认日期：2026-10-29。依据用户确认的实施说明 v2.1，第一批代码已实现；实际检查、验收边界和已知间歇测试问题见[实施与验证记录](node-single-directory-verification.md)。本页覆盖旧 Node 安装副本、程序代次、构建更新、平台源码取回和 Git 面板契约。

Node 项目直接运行登记的项目文件夹。Git 添加将源码发布到工作区 `project-sources/`，在该目录准备生产依赖后登记；不另存程序副本，不执行仓库脚本。用户选择的本地原始目录不安装依赖，明确删除项目时保留；平台下载和生成的源码随项目完整删除。

稳定身份是平台实例 UUID、项目路径和目录身份。清单中的 `app.id`、名称、版本、入口和配置声明可变化：每次真正启动读取有效清单并接受，实例 UUID、数据、配置、密钥、日志和删除归属不变。运行中的窗口使用本次启动的清单和配置快照，重新进入后采用声明修改；项目文件本身没有副本隔离，编辑前应关闭应用窗口。无效清单或缺失入口拒绝启动。`development` 仅在 Git 导入判断构建要求；`dataContract` 不参与运行或兼容判定。

Git 来源地址和用户请求的分支保存在当前登记里，重复提示按地址与分支匹配，不依赖已退役的安装候选 `sourceId`。用户明确另外添加时建立独立实例。

Git 导入是单一后端任务，下载、发布、依赖、登记和清理沿用同一 UUID。登记确定未提交才回滚；确定已提交只清临时材料；未知时保留并显示待核对，禁止重复添加。取消、异常和启动恢复先确认实际写入者结束。最少待清理状态包含归属、阶段和目录身份，不以任意裸路径授权删除，成功收尾不保留失败副本。

依赖根从项目根和后端根去重后选择，须恰好一组有效 `package.json` 与 npm v2/v3 锁文件。无包的零依赖项目跳过；缺锁、双依赖根、无效格式和需构建却缺少已提交运行文件均返回“需要修改”。唯一安装命令是 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`，沿用隔离配置、缓存、工具选择、超时、空间预算和有界错误诊断。项目 `.npmrc` 不能改变脚本禁用或受管写入边界。

旧 version 2 不迁移、不启动，提示删除后重新添加。删除仍完整覆盖实例 generations、安装候选、平台源码、配置／数据／日志、任务和归属；删除不依赖旧程序或清单完整。

本批保持既有公开迁移可用并重绑直接运行路径，不增加迁移旧目录自动删除（第三批）。不修改固定开发身份，不自动清空旧备份，不清现有开发项目。外部完成交付和原始导入归档按现有契约保留。
