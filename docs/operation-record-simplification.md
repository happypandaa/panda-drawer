- 平台继续提供 Git 获取、源码检查、受管安装、构建、发布、显式更新、ZIP 导入／导出和删除。构建候选、产物、当前版本指针、来源摘要、发布中状态及安装登记继续按原流程核对。

## 删除与清理

Node 单项目删除不再创建 `.deletions` 总回执或逐文件 NDJSON，不依赖旧删除记录隐藏登记。遇到旧版本已存在的删除标记且登记仍在时，只读识别并禁止误启动，不续写旧回执。删除开始后只在现有当前登记中标记不可运行／待清理，部分失败后继续禁止启动和保存配置；该标记不含文件清单、历史阶段或审计明细，明确重试仍重新核对当前目录。成功结果以本次实际清理及登记移除为准，部分失败明确报告实际剩余范围，重新处理先核对当前目录；不自动重放删除。

导入收尾、历史清理、空间缓存清理和卸载前全量清理不再保存专用 plan／selection／result／receipt 或逐文件日志。预览和本次范围归属在内存保存，执行重新核对；重启后重新扫描、确认，不使用旧计划恢复删除。用户未选的通用任务状态仍保留阶段、最终结果小摘要和错误，不将完整文件清单移入任务结果代替旧日志。

Git 添加的清理响应包含 `completed`、`sourceId`、`sourceRetained`、`removedPaths` 和 `failures`。界面核对这些本次结果及源码身份，不再要求已经取消的 `receiptPath`。准备依赖失败后，清理完成仍保留原来的依赖错误，并明确告知临时文件已删除；不把清理成功显示为添加成功。

受保护删除继续核对调用者确定的根、目录身份、父链、文件类型和挂载边界，按目录描述符处理，不跟随链接越界。删除不为每个文件写两条日志或逐文件强制同步日志。源码、数据库和附件的实际持久化及一致性约束不因删日志而取消。

## 日志与导入导出

平台不再保存构建／npm stdout、stderr 的头尾日志或 npm debug 日志，不提供任务日志查询命令、HTTP／原生接口和界面。进程输出继续排空并保留已有资源／输出上限；失败通过当前任务的错误码和简短原因表达。外部 AI 可在作者源码目录自行复现构建，不能把平台已无详细日志误写成运行成功。

导入／导出的中间归属和清理重试在本次服务内管理，不创建持久 lifecycle 操作历史。当前项目登记、目录名预留、数据库／附件一致性快照、归档校验、明确保存目标及最终发布继续保留；通用任务仍可查询最终状态。程序重开不自动恢复或继续旧的导入导出流程，需重新发起并核对当前目录及目标。
