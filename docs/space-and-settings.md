# 单主页、应用详情与设置（2026-10-30）

本文记录 2026-10-30 经用户确认的结构调整，取代此前“我的项目 | 空间”双页、空间三个页签和设置旧分类。只调整布局和信息组织，沿用已有主题变量与组件样式；历史验证记录仍描述当时版本。

## 我的应用

整个管理软件只有“我的应用”主页。顶栏左侧为品牌，右侧为按需显示的任务入口和设置；没有页面导航。任务入口仅在进行中或需要处理时显示，文案说明任务内容。浮层按进行中、需要处理、最近完成组织；完成任务不单独维持入口。移除首页重复的管理任务提示条。

标题行显示“我的应用”、总数与运行数；下方筛选为全部、运行中、需要处理。右侧为从 Git 添加、本机文件夹、新建。删除搜索、手动刷新和首页平台说明入口，列表及运行状态复用现有刷新机制。测试项目保持列表末尾分组。

Git 获取与安装任务直接在网格显示进度阶段，失败可查看原因并移除；关闭导入弹窗仍可查看。当前接口不提供可靠下载总量，因此本轮使用“下载中”“安装中”等阶段文案，不编造百分比。

页脚显示实际项目文件夹路径和“在访达中打开”，调用现有本地目录命令。

## 应用详情

网页与 Node 应用使用约 600px 的居中弹窗，依次为图标/名称/状态和类型、主操作、交给 AI 的提示与复制、信息行及底部删除入口。配置在弹窗内进入表单并可保存返回，不再依赖多个 tab。

应用空间来自既有空间统计；Node 日志可复制路径。运行恢复提示继续保留。网页“构建更新”本轮保留，版本与相关高级入口暂收进“更多”，其最终去留留待后续确认。

## 设置

分类为通用、存储与清理、运行环境、给 AI 的平台说明、关于与更新，分隔线后为红色“卸载前清除数据”。

- 通用：原有外观、使用指南与开发版说明。指南跳转到设置内部的运行环境和存储与清理。
- 运行环境：原 Node 构建环境、Git 工具与诊断信息；保留路径选择、检测、复制诊断及错误处理。
- 给 AI 的平台说明：原首页的 `PlatformAiIntroButton` 与使用说明，不在首页或关于页重复展示。
- 关于与更新：原程序信息、体积和更新状态。
- 卸载前清除数据：继续使用独立的[全量清理流程](local-data-cleanup.md)；终止锁保持面板同一实例。

### 存储与清理

1. 项目文件夹：当前实际路径、在访达中打开、更换位置。更换位置仍走公开工作区迁移；原目录自动收尾、失败重试及技术记录保留。软件数据目录收进折叠信息。
2. 三个数字：应用共占用、可以清理、磁盘剩余。应用总量按当前网页项目与 Node 应用逐项统计相加，不使用含软件程序和全局记录的 `knownLocalTotal` 冒充应用占用。未知或不完整结果明确标出；可清理数字为估计。
3. 临时文件和旧资料：一个清理入口。首次点击只读扫描并弹出候选明细，不默认勾选。每项展示应用/项目、来源或类别、目录与大小；临时文件标估计，取回原件使用服务返回的计划。用户选择后在同一个弹窗核对最终范围、勾选不可恢复并确认。
4. 各应用占用：网页与 Node 应用混排，按大小降序，显示图标、名称、长条与大小。默认前五个，可查看全部。软件本身与记录不在这里展示。

临时文件仅沿用网页项目 `dependencies / buildCache / logs` 白名单，Node 项目文件夹不增加依赖清理。旧资料仅沿用现役 `restoreOriginal` 候选；迁移原目录、旧安装现场与来源副本不成为通用清理对象。

统一确认后先执行历史清理，等待持久任务最终成功，再逐个执行网页临时清理并等待最终结果。两类接口保留各自门禁，并非一个原子事务。失败或未知响应停止后续提交，展示实际结果并要求重新扫描，不自动重放。执行期间禁止关闭设置或切换分类，避免未提交的后续步骤随卸载组件丢失；任务本身继续在任务中心跟踪。

历史计划过期、工作区、选择或刷新版本变化均撤销确认；保护原因与保留范围继续展示。最近统计的缓存大小可能含受保护内容，实际删除以最终结果为准。统计使用文件逻辑字节，不等于物理磁盘释放量。

## 接口与验证边界

本轮不修改后端接口。应用行复用 `workspace_storage.workspace.projects` 和 `nodeApps`；网页分类复用已有项目统计。整个工作区扫描仅在存储设置激活/相关结果变化时读取，不跟随每秒运行状态轮询反复扫描。

自动化测试使用可丢弃 DOM 数据与模拟命令，覆盖新结构、明细确认、逐步等待、失败停止、保护项和状态失效；编译检查及完整测试的实际结果见本轮交付报告。模拟 UI 通过不代表原生访达、真实磁盘释放或 macOS WebKit 已实测。
