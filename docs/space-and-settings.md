# 空间页、任务与设置（2026-10-26）

本文记录 2026-10-26 经用户确认线框后落地的管理界面结构。它取代此前“空间与工作区”四个页签、设置内“管理任务”及齿轮内长列表的说明；历史验证记录中的旧名称保留原样，只描述当时状态。

## 顶栏

- 主导航为“我的项目 | 空间”。
- 右侧为“任务”按钮和设置齿轮。任务按钮显示进行中与需要查看的数量，点开为浮层：进行中、需要查看（失败或中断）、最近完成。每项可展开查看原有任务详情与日志。浮层可用 Esc 或点击外部关闭；切换页面不会中断任务。
- 首页仍保留紧凑的“N 项管理任务正在进行 · 查看任务”提示，点击打开同一浮层，不再打开设置。
- 浅色／深色切换移入“设置 › 通用”。

## 空间

三个页签：概览、按项目、历史资料。

### 概览

- 顶部三个数字：共占用（已知范围合计）、可释放（可重新生成 + 最近一次历史扫描中可清理的部分，标“约”）、磁盘剩余（工作区所在磁盘）。
- 占用分布横条与四组：
  - 我的项目：网页项目目录与已登记 Node 应用目录，扣除下面两组中已计入的部分。
  - 可重新生成：各网页项目最近一次统计中的开发依赖 + 缓存与日志；尚未统计的项目单独提示。按钮“释放 …”转到“按项目”并直接打开一次性确认。
  - 历史资料：只取本次会话最近一次历史扫描的结果。概览本身不触发扫描；未扫描时显示“尚未扫描”，大小留在“软件本身与记录”内，避免重复计数。Node 旧程序版本位于应用目录内，从“我的项目”中扣出。
  - 软件本身与记录：程序、软件设置、运行记录、共享缓存等其余部分；“卸载时处理”打开设置中的卸载前清除。
- “占用最多的项目”列出前三个（网页项目与 Node 应用混排）。
- “统计说明与各位置明细”折叠区保留原有的范围卡片和“为什么删除项目后仍有占用”。

### 按项目

- 网页项目与 Node 应用同表，可搜索、按类型筛选、按占用／可释放／名称排序，默认显示 20 个。
- 每行：总占用、可重新生成、统计时间及操作：详情、清理（网页项目且有可重新生成内容时）、统计（未统计或已过期时）、删除…（打开原有删除确认）。
- “统计全部项目”逐个提交 `storage_scan`；“清理全部可重新生成文件”列出各项目及预计大小，一次确认后逐个提交 `storage_cleanup`（开发依赖、构建缓存、可清理日志），保留源码、数据库、文件和当前应用。
- Node 应用的大小来自 `workspace_storage` 新增的 `nodeApps` 行（每个已登记 `node-apps/<uuid>` 目录一行，`referenceOnly`，已包含在应用数据范围内，不另行相加）。Node 应用没有“可重新生成”清理入口。

### 历史资料

- 首次打开且没有可用结果时自动扫描（只读）；之后可“重新扫描”。
- 按类别分组：迁移前的旧工作区、取回前的原件、Node 旧程序版本、Node 安装现场、未被使用的源码副本。每组可全选（跳过受保护项），每项显示名称、项目 ID、文件数、目录、大小和复制路径；受保护项显示原因且不可勾选。已清理的迁移原目录记录以完成状态列在旧工作区组内。
- 底部固定栏显示已选数量与合计，“清理所选…”打开确认弹窗：逐项列出、合计、勾选“我理解这些内容将永久删除，无法恢复”后提交。服务要求的固定确认短语由界面在用户勾选后附带发送；计划编号、目录和保留范围在“技术详情”。
- 结果区沿用逐项结果、下限说明与回执路径。

## 设置

左侧分区：通用、存储位置、开发工具、诊断信息、关于，分隔线后为“卸载前清除数据”。

- 通用：外观主题、使用指南、开发版说明。
- 存储位置：项目工作区与软件数据目录（可复制路径）、迁移工作区（原表单与确认，移自空间页）、未清理旧工作区提示（“去清理”跳到空间 › 历史资料）、技术信息与迁移记录。
- 开发工具：Node 构建环境与 Git 工具。
- 诊断信息：服务、SQLite、包内资源、目录与实例信息，“复制全部诊断信息”。
- 关于：版本、程序信息、程序体积统计与更新状态。
- 卸载前清除数据：原 [本机内容清理](local-data-cleanup.md) 面板。清理进入终止锁定后只显示该面板，面板保持同一实例。
