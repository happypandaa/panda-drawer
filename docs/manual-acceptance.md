## 8 失败与取消

三种失败分别记录，不把一次失败后的成功当作另一种取消的重试通过。

1. **语法错误**：只在第3项新便笺项目中，让AI故意制造一个业务源码语法错误。通过平台构建，应明确失败，旧程序和已保存内容仍可用。再恢复源码并明确重新构建，直到成功。
2. **依赖获取失败**：通过“从 Git 导入应用 → 源码记录与恢复”接入 `06-node-dependency-failure`，准备安装材料。应显示真实依赖错误，不登记半成品，已有A／B可继续使用。该人工包没有联网复核当前状态，记录实际错误，不预填404。选择03的正常材料完成新实例安装，只能记作更换材料后的新一次成功；原失败任务继续保留。
3. **取消与重试**：先让 `07-node-cancel-large` 的源码接入完成，截图当前项目列表，再点“准备安装材料”或“构建并准备安装材料”，在复制或构建仍进行时点“取消准备”。等该任务明确终态，取消后应无新增实例；再明确重新准备，完成新候选并确认安装，核对最后只新增一个实例。取消源码获取另行记录，不能代替准备取消；也不重复提交已经安装的候选。这覆盖大材料复制／构建中的取消；若操作已完成或显示不可取消，记“未覆盖”。
4. **统一导入的清理与重试**：对本轮新建、明确归属的公开失败导入，记录来源任务和材料位置。错误结果点击重试时，应先处理上次临时材料且只创建一个新实例；点击“清理并关闭”后，核对该任务临时下载及未引用准备材料已删除，最小记录保留，A／B和其他来源保持。若安装提交结果不明，必须先核对原候选，不能开放重复导入或清理依据。清理部分失败只能显示实际结果，重新处理限原任务范围。

## 11 删除边界

1. 先正常关闭目标业务窗口并等待停止。对外部引用实例和独立安装实例分别打开“删除项目”，核对名称、实际路径和范围；先取消，检查卡片、文件和数据仍在。
2. 重新打开，勾选确认并提交，等删除操作明确成功；只有此后卡片才应移除。
3. 外部引用应保留整个原目录，核对资料夹中的原源码和人工文件；平台中该实例的私有配置、数据和缓存按预览删除。
4. 独立安装实例应按预览删除受管程序与私有数据，保留作者源码、独立来源及必要历史证据。
5. 核对系统废纸篓和平台旧回收站没有新增该实例。不要为了“测删除”操作原Radio、旧项目、旧备份或未解决恢复现场。

## 12 平台升级与重装

正式签名包和更新整链尚未交付，本次不做覆盖升级或卸载程序的结论。准备好正式版后，再用同一正式身份依次测试：旧版保存数据、正常退出、覆盖新版、核对实际新版本号和全部数据；只移除程序再重新安装，核对仍能找到原数据。

开发版与正式版身份及数据根分开，不能用开发数据自动出现于正式版作为预期，也不能私自搬迁数据目录。
