# 旧平台回收站退役

2026-10-22，用户明确要求先清理旧回收区文件，再移除该功能。本变更覆盖原生命周期、空间及历史清理合同中旧回收站的发起入口；新删除继续使用 macOS 系统废纸篓。

## 本机实际清理

在固定开发身份和公开迁移流程选定的当前工作区中，通过原有公开 `trash purge` 与持久任务逐项处理7个旧回收项目，均返回最终 `purged`。移除项目文件的逻辑字节合计69,307,092（约66.1 MiB），该数值不等于文件系统立即释放的物理空间。

清理前确认旧项目 ID 与5个当前网页项目不重叠，并核对登记目录。清理后，公开旧列表为空，所有旧回收项目的 `project/` 目录均不存在；当前网页项目列表、目录身份保持，52个独立备份文件的内容哈希全部相同。系统废纸篓和 Node 应用目录未作为清理对象。

保留42份旧回收记录，共35,000字节，以及既有操作、注销和清理回执。这些是历史身份与迁移核对证据，不是可恢复的项目副本。本次没有删除整个 `.platform/trash`、清空系统废纸篓或连带清除历史备份。实际清理摘要、每个任务最终结果与目录核对存于忽略的 `.test-artifacts/legacy-trash-retirement/`，不提交用户现场资料。

## 产品能力

- 移除“空间与工作区”的旧回收页签、列表、探测及恢复和永久清除按钮，工作区只保留空间总览、工作区位置和清理历史。
- 移除旧 `trash_*` 原生命令、RuntimeHandle方法、`/api/v1/trash...` 管理路由及 CLI `trash` 子命令。正常 `project delete` 和 `/api/v1/projects/{id}/trash` 继续调用系统废纸篓，不能与旧入口混淆。
- 新历史清理计划不生成旧回收项，尚未消费的旧计划不能再发起该类删除；已消费计划仍能读取原任务和回执，不重放文件删除。
- 空间统计继续计入“历史删除资料与记录”，避免遗漏旧工作区可能保留的字节，不再提供旧回收站操作。

## 兼容边界

旧生命周期日志解码与恢复核对、身份占用与注销、迁移后的目录身份绑定、保留旧工作区的所有权检查继续存在。它们保护旧未完成现场和历史资料，不能因为移除界面而跳过。保留的代码不能从新公开入口发起旧删除、恢复或清除。

新接口不自动擦除其他旧工作区或安装的遗留内容。只有本次已核对并获用户授权的7个旧项目实际执行了清理；一般升级不把遗留数据视为可自动删除的缓存。

## 验证

Rust工作区回归568项通过、16项按原条件忽略；所有目标编译检查和格式检查通过。220项界面检查、TypeScript/Vite构建、运行时删除提醒检查、4份现场脚本语法检查及9份文档的233个本地链接检查通过。

覆盖旧HTTP入口返回404且遗留样本字节不变、CLI不再接受旧命令、正常项目删除仍走系统废纸篓、旧清理计划拒绝新提交、旧已消费任务可读取且不重放、空工作区不新建内部回收目录、迁移所有权核对继续依赖已提交清理证据。界面用独立样本检查三个工作区页签，不连接真实业务服务。

本轮真实数据操作只有上述7个已获授权的旧回收项目清理。没有再次执行整套真实迁移或新系统废纸篓烟测；旧系统废纸篓样本、现有项目和备份继续保留。
