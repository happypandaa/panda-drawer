## 1 已确认的基础，不再重复选型

- 桌面使用 Tauri 2 + Rust；每项目一个 SQLite 文件，rusqlite 内置数据库引擎。
- Axum + Tokio 运行在 Tauri 主进程；HTTP JSON + SSE；项目网页与普通浏览器共用同一服务。
- 每个活跃项目一个数据库工作线程、连接和串行队列。
- 服务仅监听本机；固定位置发现服务；管理凭据与项目浏览器会话分开。
- 原生 Rust CLI 随安装包分发，MCP 后置；异步构建通过任务 ID、最终状态和日志交接。
- 项目构建使用系统 Node，最低 22.12.0，推荐 24 LTS；新增已确认的私有 Node 用于用户应用后端，由平台统一启停和状态管理，精确版本与运行实现尚未落实，见第 27 节。
- Node 应用所需环境变量由清单声明，平台提供可视化填写及普通用户可理解的说明、获取指引；含秘密配置的设计范围已纳入 Node 路线，具体存储和注入接口见第 27 节草案，不表示已实现。
- 项目源码、构建产物和数据分开；第一版不集成 Git、自动数据库迁移或多版本发布。当前静态项目不自带后端；用户另确认的 Node 后端类型按第 27 节单独规划，不能通过旧清单扩展字段取得执行语义。
- 默认提供 React + TypeScript + Vite 模板，建议 shadcn/ui 与黑白灰风格；组件建议不变成强制限制。
- 每项目同一时间一个构建；AI 在构建期间停止修改相关源码。
- 依赖准备前记录输入摘要，执行构建前及发布前复核；变化则失败并保留旧产物，来源信息随归档携带。
- 管理窗口与独立项目窗口分开；同项目重复打开只聚焦复用，关闭窗口与退出软件分别处理。
- 整项目备份和恢复已经确定；恢复包含同一时点的源码、文档、网页产物、数据库和附件。
- SDK 由安装包提供固定版本发布包，复制到项目 `app/vendor/`，使用相对依赖并随项目保存。
- API v1 内向后兼容；平台升级不自动改写旧项目的源码、SDK、锁文件和文档，新增可选能力通过能力列表检测。
- 完整 ZIP 备份、短期冻结、10 份普通自动备份保留、坏库恢复现场、持久维护及旧文档代次检查已确认。
- 首发 macOS 15+、Apple Silicon 原生 arm64；签名公证的 DMG，首版检查更新后手动退出并覆盖安装。
- Windows 10 22H2 x64、Windows 11 x64 支持目标已确认；Mac 与 Windows 分别验收，不承诺同日发行；Windows 初期限定本机内置 NTFS、固定默认工作区，安装方式及扩展磁盘/迁移范围仍待定。
- 默认工作区为 `appLocalDataDir/workspace`，程序和数据分离；固定的本机设置与服务发现位置不随工作区迁移。
- 导入导出复用完整 ZIP，复制生成新 ID，维护提示及构建要求不因导入消失；删除先进回收站且不自动过期。
- 同机工作区迁移采用整体冻结、复制校验和提交新位置；保留旧目录，提交后不自动回退。APFS 是 Mac 支持条件，Windows 文件系统及对应实现待落实。
- 原静态应用支持本地功能与公开接口，不因新增 Node 自动获得浏览器密钥代理或固定业务连接器。用户新确认的 Node 可视化配置及其中秘密凭据按第 27 节设计，不能继续将这项整体标为后置。
- 本地短录音、拍照、文件、播放和用户主动剪贴板能力已确认；运行格式探测，签名桌面包和 Safari/Chrome 分别验收。
- 可选运行需求声明、HTTP CSP、HTTPS 公开接口及 CORS 边界已确认，项目路径不构成系统级权限隔离。
- 平台统一空间页、逻辑字节分类、附件分页浏览与基础预览、关联历史及白名单清理已确认；用户素材、数据库与受保护现场不归入缓存。
- 项目名称、简介、图标以清单与 `meta/` 为准，统一概览无需业务数据库；UI 和 AI 修改同一份文件，统计由平台扫描缓存。
- 平台自身名称、图标和版本随包发布；关于页读取当前安装版，程序占用与工作区、其他本机数据分别展示并排除重叠范围。

## 6 D4：备份、移植与项目生命周期，已确认

完整规则见[生命周期契约](project-lifecycle-and-workspace.md)与[备份维护契约](backup-and-maintenance.md)。当前快照导出与历史备份另存分开；导入原项目保留 ID，复制生成新 ID，不改业务主键。同 ID 在活跃项目、回收站或未完成操作中被占用时拒绝覆盖。

归档包含可移植维护提示和已知待构建信息；导入维护项目建立新本机维护和匹配目标 ID 的基线，不能借复制消除未完成构建要求。原有可复用产物不因位置变化而强制重建。

删除进入回收站，保留原 ID、维护状态及基线，第一版不自动过期；永久清除单独进行，不连带删除历史备份。相同 ID 恢复或重新登记时推进代次，旧网页不能继续操作。

迁移限同机，Mac 支持本地 APFS；Windows 文件系统范围及对应实现待落实。迁移完整保留项目、备份、回收站、维护记录和受保护现场。固定迁移日志在工作区外；目标校验完成并安置后持久提交 `workspaceRoot`，提交后不自动回源。旧目录另行清理，跨电脑先用项目导入导出。既有 CLI 与管理路由的确定状态不表示已在 Windows 实现。

## 7 D5：项目维护状态与操作协调，已确认

维护入口、备份恢复任务、互斥、恢复现场与崩溃处理，以及相关命令、请求字段和状态事件均已同步为确定项；维护状态不等于 Git、自动迁移或外部文件编辑锁。

## 8 D6：项目的联网与设备能力，已确认

完整规则见[运行能力契约](project-capabilities-and-secrets.md)。`project.json.runtimeRequirements` 可选，声明 HTTPS 来源、用途、发送内容及麦克风/摄像头用途；默认本地。平台 HTTP CSP 与服务方 CORS 分别处理，声明、平台能力和系统授权分别展示，不把同 origin 的路径当成项目权限隔离。

首版提供本地短录音、拍照、播放、文件选择/拖入/下载及用户主动复制粘贴。格式运行时探测，附件与业务记录都保存成功后才显示完整业务保存成功。设备释放是标准组件和项目实现要求，平台服务端仍以维护与文档代次拒绝不允许的写入。桌面签名包、最低 macOS、Safari 与 Chrome 分别验收。

原静态应用不提供带密钥连接器或通用浏览器代理。2026-10-20 用户明确要求 Node 应用变量可视化配置，其中秘密凭据按第 27 节及[配置草案](node-app-configuration.md)纳入设计；具体存储、绑定、注入和权限仍待冻结，不能继续用原“密钥能力全部后置”排除这项新需求。屏幕捕获、后台长录音、自动语音识别和转码不因配置需求自动进入首版。

## 9 D7：构建输入一致性，已确认

每项目一个构建、构建期间 AI 暂停编辑、失败保留旧产物、首次失败仍未构建，不自动回滚源码和数据库。首版采用单编辑者协作，不增加源码快照、多 AI 文件锁或分支管理。

输入按相对路径、内容及规范化构建配置计算版本化 SHA-256。依赖准备前记录基准，执行脚本前及发布前复核；变化以既有 `failed` 结束，返回 `BUILD_INPUT_CHANGED`，不发布临时产物、不改旧来源记录。读取失败也不能当相同。纳入源码、固定素材、依赖声明、锁文件、vendor 和构建配置；排除数据库、附件、产物、已识别依赖/缓存，以及不参与构建的身份、展示名和根文档。具体范围及脚本要求见主约定第 7.4 节。

管理窗口与 `project info` 显示最近成功构建、检查时间及 `unbuilt`／`matched`／`modified`／`unknown`。发现源码差异时提示“源码有修改，当前网页仍为上次成功构建”；这些不替代任务状态或维护模式。正常模式可继续用旧网页；维护中已知待构建要求则必须保留，不因导入、复制或新基线清除。

成功构建记录和产物一致提交；可选 `buildProvenance` 随 `backup.json` 传播，恢复不依赖旧任务日志。复制新 ID、改名、迁移不引起无意义重建。旧归档缺少摘要表示来源未知，不自动认定完整网页不可用；维护快照的不明状态仍按维护契约检查。

摘要不是原子快照或可重复构建保证，不能识别所有改动后还原、外部环境或最后检查后的写入。AI 仍须停止编辑，跨项目并发数量等属于实施参数。

## 10 D8：项目空间与素材管理，已确认

完整规则见[空间管理契约](project-storage-and-assets.md)。项目卡片显示当前体积，统一详情页展示源码、网页产物、用户素材、数据库、开发依赖、缓存与其他文件，关联备份和恢复现场另列。分类互斥，固定素材作为源码子项；所有扫描显示统计时间、完整性及过期状态。

历史照片、录音和文档保存在附件目录，区别于源码里的固定界面素材。统计由平台读取文件系统，按逻辑字节、互斥路径分类并标注更新时间，不让 AI 手写尺寸。附件页浏览、筛选、预览和下载；缓存清理只操作明确可重建内容，不自动删除素材、数据库或受保护现场。物理占块估算、自动去重、附件引用分析、数据库自动压缩和强制配额后置。

分类、页面、CLI 与管理 HTTP 接口均已同步。统计不冻结业务、不要求打开数据库；清理仅接受白名单类别并沿用项目互斥、维护与恢复保护。后台扫描、附件分页、部分失败处理均不新增任务状态。

## 11 D9：独立项目窗口，已确认

首版采用“平台管理窗口 + 独立项目 WebView 窗口”。管理窗口承载项目列表、空间、备份、维护和设置；项目以顶层本地页面加载到 `WebviewWindow`。同项目 ID 的桌面打开请求去重，重复打开只聚焦复用，不刷新；不同项目可同时打开。普通浏览器直接打开项目顶层页面，允许多个标签，不提供浏览器管理后台。

最新要求覆盖原隐藏托盘方案：关闭业务窗口释放页面／设备并收尾本应用 Node 与普通后代；管理主窗口 X 与明确退出均安全结束任务、关闭全部业务窗口和受管进程／服务，独立 Node 不动。未确认清理不得显示成功，硬崩溃与脱组边界如实记录。恢复或迁移后的旧窗口即使复用，也必须检查会话、模式与代次；由用户明确重新加载，不能让旧脚本静默继续写入。

项目窗口与管理窗口使用独立标签及原生权限配置，自定义命令和插件同样执行宿主权限校验。项目不得获得管理命令，用户主动打开的外部 HTTP(S) 链接与弹窗交给系统浏览器，禁止任意原生协议跳转；项目无需 Tauri IPC。参见 [Tauri capabilities](https://v2.tauri.app/security/capabilities/)与 [WebviewWindow API](https://v2.tauri.app/reference/javascript/api/namespacewebviewwindow/)。同 origin 路径仍不是恶意代码安全沙箱。

项目负责未保存内容提示、录音拍照停止及主动重载协作；窗口失焦不等于关闭，页面不可见或明确切换按媒体约定处理。首版不做多项目标签系统、自动恢复所有窗口或任意表单的自动保存。完整规则已同步到主约定与服务生命周期。

## 12 已定流程的体验收口，不再单列架构选型
