## 2 新样本安全存储与受限服务

增加独立的 W2.1 后端；Windows 完整 core/CLI 门禁继续关闭。仅显式创建才初始化系统 KnownFolder 下的固定新根；读取不会创建根。已有目录须完整匹配本阶段标记、设置、空历史目录及登记，否则保留并阻断。没有接入恢复、维护、构建、迁移或清理管理器。

业务操作使用 `NtCreateFile` 的父 HANDLE 相对路径、显式私有 ACL、真实卷序号及完整文件 ID128。根与祖先句柄保留且不共享删除；子目录允许无覆盖原子发布，发布前核对准备阶段的源身份。跨会话保护由根内独占打开的锁文件承担；Local mutex 仅辅助缺根创建。系统卷检查核对 NTFS、盘符映射/卷 GUID、单磁盘布局、总线与不可移除/非热插拔属性；不凭 DRIVE_FIXED 推断物理内置，不支持的布局保守拒绝。

项目继续携带同一清单、固定 SDK、匹配源码、初始产物及来源格式。本机登记明确使用 Windows 身份，逐文件保存身份与摘要；重启检查根、祖先、项目和数据库，不自动补登记或重建库。平台资源重打包不会改写或因打包时间变化拒绝已有完整样本。源码/库被外部改动、未登记目录、创建残留、重复 JSON 键、未知历史均阻断。

回环服务只绑定 `127.0.0.1`，沿用 API v1、一次性短期票据、项目 Cookie、文档代次与 Host/Origin 检查。仅开放真实 context、SQLite 内存只读快照 schema、受保护静态资源和状态事件；没有任意 SQL、文件或管理写入。SQLite 快照来自安全句柄读取并检查过的登记空库，读取不打开库路径、不产生 WAL/SHM。正常关闭先停止接收，再等待已接受的存储操作结束并释放句柄。

限制：当前阶段只接受本轮完整样本及原登记空库；外部编辑先保持阻断，SQL、附件和构建另行开放。未做跨 Windows 登录会话、硬件断电/拔盘、Win10 或 Mac 原生验收。创建在强制终止或 I/O 失败时可保留未完成现场并阻断，不自动恢复或清理；这与正常退出等待完成分别记录。

## 3 启动上下文与固定目录诊断

实际 release 窗口创建验证发现：从当前 Codex 子进程启动时，Win32 新建的 LocalAppData 条目实际落在 Codex 包的 LocalCache 中，而父句柄仍绑定系统 KnownFolder 原目录。严格句柄相对路径检查以 `STATUS_REPARSE_POINT_ENCOUNTERED` 拒绝；固定业务根没有初始化，也没有创建半成品项目。没有关闭重解析点检查或改用包缓存作为业务根。

增加一个真实 KnownFolder 临时同级目录回归：实际绑定一致时要求严格创建、读写及身份检查成功；发生重定向时要求拒绝、夹具为空且 ACL 不变。后者只证明拒绝正确，不算该启动上下文受支持。另补充 NTSTATUS、失败祖先片段，以及缓存父目录所有者不符时的请求/实际路径和 SID 诊断；不修改任何权限或准入条件。

此步 host 55 项、共享格式 14 项、desktop 3 项及相关 all-targets Clippy `-D warnings` 通过。正常资源管理器启动的实际创建和开窗继续验收，不能用上述条件测试代替。

## 4 系统父目录与私有业务对象分开校验

从资源管理器启动旧包时，实际 LocalAppData 所有者为 Administrators，旧实现要求该系统父目录必须由当前用户所有，误拒绝启动。系统父目录现在允许当前用户、SYSTEM 或 Administrators 所有，同时检查实际 DACL：其他有效身份只允许列举、读取和遍历；写入、删除子项、改 ACL/所有者及未知权限均拒绝。只跳过已验证普通 ACE 的 inherit-only 授权，未知 ACE、坏 SID、null DACL 和查询失败继续拒绝。

这是对系统父目录准入的明确修正。新工作区、项目、文件和浏览器缓存仍须当前用户所有、受保护私有 ACL；没有修改系统父目录或任何已有路径的权限，也没有给未知 capability SID 加白名单。当前 Codex 进程视图中额外写 ACE 继续被拒绝，正常资源管理器启动已通过该检查。新测试父目录从 create-new 时显式使用私有权限，不继承仓库父目录的广泛写授权。

实际检查：host 60 项、共用格式 14 项、desktop 3 项通过，相关 all-targets Clippy `-D warnings` 通过。新增 3 项纯权限规则和 2 组真实 DACL 夹具验证允许读取、拒绝变更及原 ACL/字节保留；SYSTEM/Administrators 的所有者规则为纯规则测试，未通过提权修改夹具 owner。
