# 停止并删除：第二阶段第 2 批

本批接入持久删除任务、恢复和放弃机制，沿用[已确认设计](stop-and-delete-phase2-design.md)及第 1 批的实例准入。任务界面单独在第 3 批提交；旧同步删除命令仍等待实际终态，新 `node_app_delete_submit` 返回任务快照，避免后端批次独立提交时破坏旧调用方。

## 持久任务和范围

任务保存在固定开发数据根 `D/node-deletion-tasks/<任务UUID>/task.json`，位于被删实例目录外。记录实例／卷／目录身份、确认修订、原登记精确内容、各目标的改名意图和阶段。新任务先在私有 `.creating-<UUID>` 中完整落盘，再以不覆盖原子改名发布；未发布证据保留但不执行，不因一个空创建现场阻断所有应用。发布结果不明确时按原 task ID 核对，不能再创建第二任务。

实际删除目标仍限配置、数据、缓存、受管程序代次及最终登记。各目录先在原实例同卷的私有 `.pending-deletions/<任务UUID>/` 逐项改名并记录，然后递归清理。原卷、父目录或目标身份变化、挂载点及不确定移动结果都会保留现场并失败，不跨卷复制后删除。外部用户源码目录不改名、不删除；独立可编辑源码、运行和共享来源／安装恢复证据的既有保留边界没有扩大。

只有进程与平台资源收尾、所有目录实际清理以及精确登记清理和任务终态落盘成功，才返回 `deleted`。部分失败列出剩余目标；失败后的重试继续原任务，已移动目录不会重新成为可放弃状态。

## 放弃、恢复和协调

- 没有任何目标移动时允许请求放弃。存在未核实 rename intent 时先核对原位置和暂存位置；不能凭缺少完成日志猜测尚未移动。
- 放弃先记录请求，旧停止／窗口流程安全退场后才写 `abandoned` 并撤销删除门禁，不自动启动。旧 worker 不能在门禁解除后迟到停止新实例。
- 等待长 Git 等非窗口操作时，放弃不再受其桌面实例锁阻挡；先等已接纳的窗口创建／重启 owner 退场，再关闭原窗口和停止原运行。原开发任务仍按自己的 owner 和恢复协议收尾。
- 停止失败仍可放弃未移动的新删除任务，但原有进程身份未知、清理未完成等独立运行门禁不会被删除任务抹掉。旧版 `removalPending` 可能代表已经部分永久删除，按不可逆现场保留，不能假装是可撤销的新计划。
- 启动先加载任务门禁，再核对运行标记并恢复已确认任务；未完成实例不进入普通可运行列表。已请求放弃的任务不会进入文件删除阶段。
- 受理和重试前即注册共享工作区 lease，迁移能看见实际删除 owner。平台退出封住新请求、停止实例，并等待实际删除 worker，等待期间不持全局运行锁。
- 即使 worker 已结束而任务失败，仍保留独立的迁移／清理 barrier；先完成或安全放弃该任务再执行共享迁移，避免公共迁移改写登记后使原任务无法继续。该 barrier 不阻塞正常平台退出，退出只等待实际 worker。

最终登记的移除使用任务目录内的外部事务，主 journal 绑定原登记的精确字节、身份与摘要；同次开机在捕获后中断也能按原任务收尾。它不会在实例内创建运行标记的收尾门禁。无目录移动时申请放弃可安全恢复登记，不覆盖后来出现的替换对象。

## 验证边界

所有删除只发生在明确命名的临时项目中，外部源码及另一个实例均有哨兵。故障注入覆盖发布前／后中断、改名后未更新记录、部分递归清理、目录替换、卷身份不匹配、未知改名、终态落盘失败与放弃请求恢复。

另有真实进程中断回归：父测试保留真实 `Child`，终止运行测试管理器的子进程，在同一临时数据根加载原 task ID 并继续清理，核对外部源码及另一实例完整。这是测试管理器进程恢复，未冒称真实 Cocoa 应用或物理断电。

最终完整 Rust 工作区 978 项通过、55 项按专用环境条件忽略；其中 5 项固定版本真实 Node 测试额外显式执行通过。journal 23/23、任务／登记恢复 15 项、桌面 62/62、窗口准入 2/2 通过；专用子进程 helper 默认忽略，但已由真实强杀父测试显式启动。工作区严格 Clippy、格式与差异检查通过。最后界面集成回归及构建在第 3 批记录。

证据保留在 Git 忽略的 `.test-artifacts/phase2-final-*.log`、`phase2-batch2-*.log` 和 `stop-delete-phase2-*.log`。用户的 Radio Bob 重启验收可继续使用独立保留的第 1 批安装包；本批没有对真实项目执行删除，未验收真实挂载／实际跨卷删除、Cocoa 崩溃或物理断电。
