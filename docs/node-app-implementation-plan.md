## 先后顺序与保护门槛

每小步完成后只验证受影响内容，记录真实证据、限制并提交推送；不把后续未完成工作混入同一次提交。实现已获授权，仍使用明确命名的隔离样本；radio 源码可按本次授权适配并预先保全，不修改其真实数据、凭据或已有平台业务项目。

NR1–NR4 可先验证无持久业务数据的内部样本。NR5 的备份、维护和迁移保护，以及 AP 所需的新类型识别/校验基础完成前，不对真实项目开放 Node 运行。Windows 还受既有 W 工作线的安全文件与运行门禁约束，不能为测试 Node 绕开。

配置测试先使用人工普通值和可丢弃的测试凭据，不读取原应用 `.env` 或真实账号。首期建议将普通配置保存在受管数据中，秘密保存在操作系统凭据库；平台只向目标 Node 的创建环境注入配置，不生成 `.env`，目标原生 Node 必须能读到注入的秘密。管理页输入时存在瞬时明文，保存后只返回已设置状态，既有秘密不回显给业务网页、AI、日志或归档。清单只有声明、没有用户值；普通配置是未来私有完整归档的候选，分享包不带用户配置，任何项目 ZIP 不带秘密值或可用绑定。建议将保存后的配置与当前运行实例分开记录；保存不自动重启，用户明确重启后才生效。上述存储、绑定、备份及重启语义是本轮建议契约，不是用户逐项确认的规则；具体接口、存储实现及失败一致性在 NR0 冻结。下表的新增通过条件也按这一草案状态解释。
