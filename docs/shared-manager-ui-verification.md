## 1 共用组件与能力边界

按用户确认，Windows 与 macOS 复用 `ManagerView.tsx` 的导航、页面框架、操作按钮、项目卡片集合、搜索筛选和创建弹窗；卡片与弹窗仍使用同一 `ProjectCard`、`Modal`。两个前端入口均导入 `styles.css`，移除独立 `windows-host.css`。打包产物只有一份管理页 CSS，两入口使用共同组件 chunk；没有通过复制一份样式实现表面一致。

平台控制器保留真实请求差异。Mac 继续现有 bootstrap、项目、维护、任务与工作区流程；Windows 只调用既有 `project_status`、`project_create`、`project_open`、`project_open_browser`、`host_status` 五个 IPC。未虚构 bootstrap、维护 ready、任务或空历史来套用完整管理器。`manager-capabilities.ts` 的只读常量只控制界面能力，后端仍独立检查所有操作。

Windows 复用完整工作台布局，但资料修改、SQL、附件、构建、导入、删除、回收、迁移和清理仍受原门禁保护。导入、删除和构建显示禁用及原因；完整空间/关于导航禁用。运行环境只显示已取得的真实固定根和阶段状态，按需浅层诊断在根 ready 时不重复执行。详情只展示当前项目状态已有字段，不挂载会自动读取元数据、维护、空间或任务的 Mac 面板。

固定应用身份、数据根、项目格式、SDK、工作区与管理页来源不变。Windows 原生管理来源仍为 `/windows.html`；项目窗口没有取得管理权限。本轮不开放新数据能力，也不改变退出、缓存或文件权限策略。
