# 共用管理界面验证记录

日期：2026-10-19

状态：共用展示层与两端控制器接入完成，自动化检查及 Windows release 构建通过，实际窗口验证待补。Mac 原生启动、系统窗口及真实数据回归未在本机执行。

## 1 共用组件与能力边界

按用户确认，Windows 与 macOS 复用 `ManagerView.tsx` 的导航、页面框架、操作按钮、项目卡片集合、搜索筛选和创建弹窗；卡片与弹窗仍使用同一 `ProjectCard`、`Modal`。两个前端入口均导入 `styles.css`，移除独立 `windows-host.css`。打包产物只有一份管理页 CSS，两入口使用共同组件 chunk；没有通过复制一份样式实现表面一致。

平台控制器保留真实请求差异。Mac 继续现有 bootstrap、项目、维护、任务与工作区流程；Windows 只调用既有 `project_status`、`project_create`、`project_open`、`project_open_browser`、`host_status` 五个 IPC。未虚构 bootstrap、维护 ready、任务或空历史来套用完整管理器。`manager-capabilities.ts` 的只读常量只控制界面能力，后端仍独立检查所有操作。

Windows 复用完整工作台布局，但资料修改、SQL、附件、构建、导入、删除、回收、迁移和清理仍受原门禁保护。导入、删除和构建显示禁用及原因；完整空间/关于导航禁用。运行环境只显示已取得的真实固定根和阶段状态，按需浅层诊断在根 ready 时不重复执行。详情只展示当前项目状态已有字段，不挂载会自动读取元数据、维护、空间或任务的 Mac 面板。

固定应用身份、数据根、项目格式、SDK、工作区与管理页来源不变。Windows 原生管理来源仍为 `/windows.html`；项目窗口没有取得管理权限。本轮不开放新数据能力，也不改变退出、缓存或文件权限策略。

## 2 自动化检查

- TypeScript 与 Vite 两入口生产构建通过；共同 CSS 和组件产物已核对。
- Windows 管理页 18 项 DOM 回归通过，真实递归加载共同组件，Tauri IPC 为合成实现。覆盖根缺失/保留/过期、创建去重与未知结果不重放、草稿、公共弹窗焦点/inert、搜索筛选、只读详情、禁用操作、仅五 IPC 及 ready 根不诊断。
- 原管理页 34 项 DOM 回归通过，保留原 33 项弹窗、维护、清理、交接、创建与删除交互，补共同组件和本地搜索筛选检查。这不等同于 Mac 原生 GUI 或数据删除通过。
- 新增同轮事件检查：项目打开后立即刷新，以及诊断后立即重复诊断/刷新，在按钮尚未渲染成 disabled 时，仍由同步 pending 标记拒绝并发。创建真实响应确认后的内部刷新单独保留。
- Windows 原生 host 62 项、desktop 来源/导航 3 项，共 65 项通过；真实回环的关闭 CRUD 与生命周期请求继续拒绝且夹具不变。
- 公开开发构建入口实际完成 release exe；计算器模板版本和原产物摘要不变，没有生成安装器或运行用户项目脚本。

创建弹窗在请求期间保持打开，失败保留名称和简介；响应不明不自动重放。失败后的手动刷新放在弹窗内，避免 Modal 令背景 inert 后用户无法核对状态。共享组件不调用原生接口、不创建定时器、不触发管理写入。
