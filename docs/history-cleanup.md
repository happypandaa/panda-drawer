**2026-10-26 更新：** “旧版回收项”和“已完成恢复的原现场”两类候选随旧备份／回收站一起移除，见[旧版回收站、旧备份与维护的移除](legacy-backup-trash-removal.md)；同日新增 4 类由现役功能产生的历史资料，见下节。包含旧备份或回收站内容的旧工作区整体保留、不提供清理。

## 可清理的历史资料（2026-10-26）

扫描结果对每一项给出“可清理”或“保留原因”。只有标为可清理、且用户明确勾选并确认的项目才会删除；执行前按原有规则重新核对目录身份和文件清单，有变化即整体停止。

| 类别 | 位置 | 可以清理的条件 | 保留的情形 |
| --- | --- | --- | --- |
| 迁移前的旧工作区 | 迁移日志记录的原目录 | 沿用原有规则 | 内容有改动、迁移证明不完整、含旧备份或回收站内容、存放着迁移后已删除项目的唯一副本等 |
| 取回前的原件 | `.platform/project-state/data-restore/<项目>/<任务>/`、`source-restore/<项目>/<任务>/` | 该次 Git 数据或源码取回已经结束（已完成、已撤回或未应用），并且这个项目没有任何未完成或无法核对的取回、数据保存和生命周期操作 | 取回尚未结束（原件仍用于继续或撤回）；同一项目有任何待处理操作时，该项目的全部取回现场一起保留 |
| Node 安装现场 | 数据根 `node-apps/.installations/install_*/` | 安装记录处于已提交、失败或中断 | 正在准备、仍可继续安装（已准备）、提交中或需要核对、记录无法读取 |
| Node 旧程序版本 | 数据根 `node-apps/<应用>/generations/` 下非当前版本 | 当前登记指向的是另一个版本，且这个应用没有正在进行或需要处理的安装 | 当前版本从不列出；有未完成安装、登记无法读取或应用已进入删除流程时不列出或保留 |
| 未被使用的源码副本 | 工作区 `.platform/sources/src_*/` | 获取已结束，并且没有任何已安装应用的登记、开发源码绑定或未结束的安装引用它 | 正在获取；被已安装应用使用；有安装正在准备（其来源尚未记录）时所有副本一起保留 |

删除 Node 相关项目时，清理任务持有与安装提交相同的锁，避免与安装提交交错。新增的保留原因以中文直接显示给用户。

数据取回（data-restore）判定复用现有守卫的“已结束”识别，本次只用源码取回的测试夹具做了端到端验证；数据取回现场的完整夹具依赖真实 Git 与 macOS 文件身份，未在 Linux 上覆盖。

范围依据：用户于 2026-10-16 明确要求为迁移旧工作区、历史恢复现场和回收站增加可查看范围、确认后清理的入口。本补充只实施这些对象；历史备份删除、另存和自动保留期限仍不在本次范围内，不视为确认整份历史接口讨论稿。

2026-10-25 用户另行确认设置中的[卸载前全量清理](local-data-cleanup.md)。该入口至少两次确认后删除全部受管本机数据和代码，包括当前项目及历史备份、旧回收和恢复资料；外部原始源码保留。本页“清理历史”的选择范围、保护对象、原有接口和历史验收保持不变，不能由全量清理授权放宽普通历史清理。

## 查看与确认

“空间 → 历史资料”首次打开时自动扫描已登记历史对象（2026-10-26 前名为“空间与工作区 → 清理历史”，需手动扫描）。扫描不会删除资料；无默认勾选。结果按类别分组，确认弹窗以勾选确认代替手动输入短语，界面在勾选后发送服务要求的固定短语，见[空间页、任务与设置](space-and-settings.md)。结果逐项展示完整目录、类别、项目名称与 ID（适用时）、逻辑字节、文件数、保护原因和明确保留的范围。旧工作区是迁移时点的完整历史副本，可能包含后来已从当前工作区删除的项目，不能称为普通缓存。

用户选择对象后再次核对目录，输入“永久清理所选内容”，并确认外部 AI、编辑器和数据库工具已停止使用所选历史目录。修改选择、刷新范围、切换页签、工作区变化或预检过期会撤销确认。计划自生成起十分钟有效；客户端只提交服务生成的计划与对象 ID，不接受自定义删除路径或 force。

当前活跃项目、当前工作区内的历史备份、维护基线、未解决恢复现场、固定设置和迁移证明始终保留。一次可以显式选择多个已核对对象，不能默认“清空所有”。本轮实际操作额外只选择明确的历史平台测试残留，用户当前项目和用户命名的回收项不因名称类似测试而自动删除。

## 管理接口

| CLI | 管理 HTTP | 原生命令 |
| --- | --- | --- |
| `workspace cleanup-plan --json` | `POST /api/v1/workspace/cleanup-plans` | `workspace_cleanup_preview` |
| `workspace cleanup --input request.json --json` | `POST /api/v1/workspace/cleanups` | `workspace_cleanup` |

两步均返回持久任务，HTTP 为 202，复用 `task get/wait`；任务成功才表示该步完成。预览结果包含 `planId`、`expiresAt`（毫秒）、当前根、候选 `items`、`preserved` 和确认词。提交输入为：

```json
{
  "planId": "服务返回的计划 ID",
  "itemIds": ["服务返回的已选择对象 ID"],
  "confirmation": "永久清理所选内容"
}
```

计划绑定当前服务实例、工作区根身份与文件清单。未消费计划在重启后失效；同一已消费计划和相同选择只返回原任务，不能开始第二轮删除。响应未知时先查询原任务与回执，不能盲目重放。普通项目网页及 SDK 不获得清理能力；原生命令仍校验管理窗口，HTTP 仍需开发身份的管理授权。

## 对象保护

- 旧工作区须有已完成、已提交迁移、准确的源目录身份和退休标记，并能核对通往当前工作区的迁移证明。迁移时的持久文件清单必须一致，保护资料须有当前可访问的副本；旧目录存在新增或修改内容时阻止清理。
- 恢复现场只删除已提交且已解决恢复所保留的 `original/`，保留 journal、任务、备份和恢复元数据。迁移复制会改变 inode；不能直接把旧 inode 当作新的清理授权，必须通过已提交迁移清单与内容摘要证明其归属，再绑定当前预览的目录和文件身份。仍被维护或未解决操作引用的现场不提供清理许可。
- 回收站沿用生命周期的身份冲突和保护检查，清除所选项目 payload，保留回收记录、历史备份及操作证明。清理前登记 purge intent，部分删除即标记不再完整可恢复，重启仅核对元数据，不自动再删文件。
- 未登记路径、身份替换、路径重叠、嵌套挂载、特殊文件、不能核对的记录和未解决引用均阻止自动删除。源根不得是当前工作区、其父子目录、固定控制根或程序目录。

## 执行、失败与记录

提交时取得与迁移互斥的工作区管理操作门禁，检查活动任务并重新核对已选对象。执行使用预检清单逐项绑定目录和文件身份，不跟随符号链接或以兜底递归删除吞掉新增文件。当前项目不被重载，不清除业务草稿，不改业务 SQLite 或源码。管理写操作在清理期间暂时停用；遇到冲突先等待既有操作结束或重新检查范围。

本次计划在当前服务内存中保存，范围过期或软件重开后需重新扫描；不再创建专用计划、逐文件进度或清理回执。任务报告实际已删、失败和残留范围；逻辑字节不等于实际释放的物理磁盘块。部分失败和中断不会恢复已经删除的文件，也不自动继续删除；重新处理必须重新扫描和确认。成功清理旧根后保留原迁移登记，重新扫描只说明旧路径当前不存在，不保存删除历史，空间统计不再将该已清理目录计作未知占用，也不重建或激活旧根。

文件系统身份核对依赖外部工具按约定停止写入历史目录，不承诺把同一 macOS 用户的恶意并发篡改隔离成安全沙箱。真实服务验证、实际删除范围、保留资料核对、包摘要与未完成验证另记，不用模拟 UI 或编译通过替代实际删除证据。
