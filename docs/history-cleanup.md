# 历史副本的显式清理

范围依据：用户于 2026-10-16 明确要求为迁移旧工作区、历史恢复现场和回收站增加可查看范围、确认后清理的入口。本补充只实施这些对象；历史备份删除、另存和自动保留期限仍不在本次范围内，不视为确认整份历史接口讨论稿。

2026-10-22 更新：用户已授权清理本机旧回收项目并退役该功能。新计划只包含迁移旧工作区与已完成恢复的原现场；不再生成或接受旧回收项清理，已消费的旧计划仍能读取原任务与回执。旧记录和迁移所有权核对继续保留。见[旧回收站退役](legacy-trash-retirement.md)。

## 查看与确认

“空间与工作区 → 清理历史”先扫描已登记历史对象。扫描不会删除资料；无默认勾选。结果逐项展示完整目录、类别、项目名称与 ID（适用时）、逻辑字节、文件数、保护原因和明确保留的范围。旧工作区是迁移时点的完整历史副本，可能包含后来已从当前工作区删除的项目，不能称为普通缓存。

用户选择对象后再次核对目录，输入“永久清理所选内容”，并确认外部 AI、编辑器和数据库工具已停止使用所选历史目录。修改选择、刷新范围、切换页签、工作区变化或预检过期会撤销确认。计划自生成起十分钟有效；客户端只提交服务生成的计划与对象 ID，不接受自定义删除路径或 force。

当前活跃项目、当前工作区内的历史备份、维护基线、未解决恢复现场、固定设置和迁移证明始终保留。一次可以显式选择多个已核对对象，不能默认“清空所有”。本轮实际操作额外只选择明确的历史平台测试残留，用户当前项目和用户命名的回收项不因名称类似测试而自动删除。

## 管理接口

| CLI | 管理 HTTP | 原生命令 |
| --- | --- | --- |
| `workspace cleanup-plan --json` | `POST /api/v1/workspace/cleanup-plans` | `workspace_cleanup_preview` |
| `workspace cleanup --input request.json --json` | `POST /api/v1/workspace/cleanups` | `workspace_cleanup` |

两步均返回持久任务，HTTP 为 202，复用 `task get/wait/logs`；任务成功才表示该步完成。预览结果包含 `planId`、`expiresAt`（毫秒）、当前根、候选 `items`、`preserved` 和确认词。提交输入为：

```json
{
  "planId": "服务返回的计划 ID",
  "itemIds": ["服务返回的已选择对象 ID"],
  "confirmation": "永久清理所选内容"
}
```

计划绑定当前服务实例、工作区根身份与文件清单。未消费计划在重启后失效；同一已消费计划和相同选择只返回原任务，不能开始第二轮删除。响应未知时先查询原任务与回执，不能盲目重放。普通项目网页及 SDK 不获得清理能力；原生命令仍校验管理窗口，HTTP 仍需开发身份的管理授权。

## 对象保护

- 旧工作区须有已完成、已提交迁移、准确的源目录身份和退休标记，并能核对通往当前工作区的迁移证明。迁移时的持久文件清单必须一致，保护资料须有当前可访问的副本；旧目录存在新增或修改内容时阻止清理。
- 恢复现场只删除已提交且已解决恢复所保留的 `original/`，保留 journal、任务、备份和恢复元数据。迁移复制会改变 inode；不能直接把旧 inode 当作新的清理授权，必须通过已提交迁移清单与内容摘要证明其归属，再绑定当前预览的目录和文件身份。仍被维护或未解决操作引用的现场不提供清理许可。
- 历史兼容记录：旧回收清理曾沿用生命周期的身份冲突和保护检查，清除所选项目 payload，保留回收记录、历史备份及操作证明。清理前登记 purge intent，部分删除即标记不再完整可恢复，重启仅核对元数据，不自动再删文件。
- 未登记路径、身份替换、路径重叠、嵌套挂载、特殊文件、不能核对的记录和未解决引用均阻止自动删除。源根不得是当前工作区、其父子目录、固定控制根或程序目录。

## 执行、失败与记录

提交时取得与迁移互斥的工作区管理操作门禁，检查活动任务并重新核对已选对象。执行使用预检清单逐项绑定目录和文件身份，不跟随符号链接或以兜底递归删除吞掉新增文件。当前项目不被重载，不清除业务草稿，不改业务 SQLite 或源码。管理写操作在清理期间暂时停用；遇到冲突先等待既有操作结束或重新检查范围。

计划、逐项进度和回执保存在固定数据根的 `cleanup/`，不放进待删除树。任务报告实际已删、失败和残留范围；逻辑字节不等于实际释放的物理磁盘块。部分失败和中断不会恢复已经删除的文件，也不自动继续删除；重新处理必须重新扫描和确认。成功清理旧根后保留迁移与清理回执，空间统计不再将该已清理目录计作未知占用，也不重建或激活旧根。

文件系统身份核对依赖外部工具按约定停止写入历史目录，不承诺把同一 macOS 用户的恶意并发篡改隔离成安全沙箱。真实服务验证、实际删除范围、保留资料核对、包摘要与未完成验证另记，不用模拟 UI 或编译通过替代实际删除证据。
