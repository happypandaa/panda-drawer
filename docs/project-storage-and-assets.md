# 项目空间占用与素材管理

状态：v0.5，已确认契约；M5 已实现并通过真实分类、附件分页、白名单清理及坏库扫描验证，完整 GUI 交互未实测

更新日期：2026-10-16

2026-10-16 补充：用户确认了旧工作区、已完成恢复原现场和回收站的显式范围清理入口，独立规则及接口见[历史清理补充](history-cleanup.md)。项目缓存白名单与当前备份保护不因此放宽。

每个项目必须标注占用尺寸，包括源码、打包产物以及照片、文档等素材。平台统一提供“项目详情 → 空间与文件”，不要求每个 AI 生成的项目重新实现。本文的统计、页面、预览、清理边界及管理接口已确认；文件归属、备份、回收站及迁移按[主约定](platform-development-contract.md)和[生命周期契约](project-lifecycle-and-workspace.md)执行。

## 1 通用页面与入口

项目列表卡片显示图标、名称、简介、状态、“当前项目文件大小”和统计时间，分别提供打开项目与查看项目详情的入口。名称、简介、图标声明分别读取项目根目录的 `project.json.name`、`description`、可选的 `icon`；默认图标文件位置为 `meta/icon.png`。这些是项目持久资料，不能放进业务数据库，也不由某次空间缓存决定。未配置图标时正常使用默认图标；已声明图标缺失或无效时回退并提示，不能阻止查看项目资料。

打开项目使用独立项目窗口，同项目重复打开聚焦复用；详情始终在平台管理窗口内，提供“概览”“空间与文件”“备份与维护”。概览显示基本资料、项目 ID 与位置、运行／维护状态、最近构建及源码状态、空间摘要、联网与设备需求，并提供基本资料编辑入口。该页直接由平台读取清单和控制记录，不依赖项目构建成功、业务数据库可打开或执行项目脚本。元数据存储、编辑、图标读取和降级规则见[项目资料与概览契约](project-metadata-and-overview.md)，联网和设备需求见[运行能力契约](project-capabilities-and-secrets.md)。M5 管理页面与服务已实现，实测及尚未完成的 GUI 交互边界见 [M5 记录](m5-verification.md)。

空间页分为三块：

1. 当前项目：源码、网页产物、用户素材、数据库、依赖、缓存和其他文件，展示总量与比例。
2. 素材浏览：图片、音频、视频、文档、其他，各自数量和大小，可查找具体文件。
3. 关联历史：备份、恢复现场、暂存副本及对应任务，展示占用和保护原因，链接到已有管理入口。

工作区设置再提供空间总览，按项目大小排序；回收站、共享缓存和迁移旧副本在那里集中查看。平台程序本身、当前工作区和本机其他已知数据位置分别列出；“关于”页面的程序占用复用同一统计。主页面不只展示一个含糊的“项目 3 GB”，要让用户知道这些空间分别在哪里。

## 2 当前项目的分类口径

| 分类 | 实际范围 | 展示与处理 |
| --- | --- | --- |
| 源码与项目资料 | `sourceDir` 源文件、锁文件、固定 SDK，以及清单、README、docs、`meta/` 项目资料 | 持久内容，不进一键缓存清理；项目展示图标计入此项 |
| 固定素材〔源码子项〕 | 已明确的资源目录，如 `app/public/`、模板的 `app/src/assets/` | 属于源码合计，子项不再加一次 |
| 网页产物 | 当前 `outputDir`，通常 `dist/` 的全部文件 | 当前可运行版本，不当普通缓存删除 |
| 用户素材 | `attachmentsDir`，通常 `data/attachments/` | 图片、录音、视频、文档等持续积累的用户内容 |
| 数据库 | `main.sqlite` 及所属 WAL/SHM | 分列主库和伴随文件，合计显示 |
| 开发依赖 | 已识别的工程依赖根，标准为 `sourceDir/node_modules`，含其内部依赖树 | 可重装，但首次下载可能需要网络 |
| 缓存与日志 | 平台明确识别且可清理的构建缓存、临时材料和日志 | 必须核对任务和保护状态 |
| 其他文件 | 项目内不能归入以上类别的文件 | 保留并计入，未知不等于可删除 |

所有顶层类别互斥，每条路径只归入一个类别。固定素材是源码的展开项，不是额外顶层加数。同一图片从 `app/public/` 复制到 `dist/` 后确有两份文件，分别计入源码与产物，不按内容哈希去重后隐去实际文件体积。

`meta/icon.png` 属于项目资料，不属于网页固定素材子项，也不因平台展示图标而重复计数。项目名称、简介、图标及 `meta/` 资料变化使相关资料显示和空间缓存失效，但不触发构建；网页要使用同一图片时，由项目另行将资源纳入 `app/` 并构建，该实际副本按所在路径计数。

“打包体积”在本页表示当前 `dist/` 文件大小合计，页面标签统一写“网页产物”。导出 ZIP 的压缩后大小另标“导出包大小”，只有实际生成后才显示精确数，不能把网页产物大小或当前项目总量当 ZIP 大小。

分类按已校验的项目清单和实际路径识别，不把目录名恰好叫 cache 的用户文件直接视为缓存。第一版无需分析全部 JavaScript import 图；无法识别业务素材用途的源码文件仍计入源码。数据库里的照片 BLOB 只计数据库，不猜测任意表内容并拆成照片占用。

## 3 历史照片、文档怎样保存

固定按钮图标、游戏界面图片放源码资源目录。用户每次游戏、学习、录音或上传产生的历史内容放 `data/attachments/`，不随着构建重写。例如可以采用以下业务目录，名称仅为建议：

```text
data/attachments/
├── photos/2026-10/...
├── recordings/...
├── documents/...
└── videos/...
```

数据库保存逻辑路径、展示名称、时间、所属活动或业务记录；业务表由 AI 按项目需要设计，平台不强制所有项目用同一张素材表。SDK `FileInfo` 已有路径、大小、媒体类型与修改时间，可复用。实际录音格式按环境检测，不能单凭示例把所有文件都命名为 `.webm`。

归档、复制和恢复携带这些素材。清理 `node_modules` 或重新构建不影响历史照片和文档。用户删除一条业务记录是否同时删除附件、多个记录是否共享附件，应写入 `docs/database.md` 和项目 README；平台不能自行推断。

## 4 数字的含义与统计时效

主口径为**文件大小合计（逻辑字节）**，API 返回原始字节数，界面统一采用十进制 KB/MB/GB 并允许查看精确字节；不要和 KiB/MiB 混用。目录本身的文件系统元数据不纳入该主口径。

该数不是精确物理占块，也不保证等于删除后释放量。文件系统压缩、稀疏文件、共享块或链接会造成差别。第一版不做物理块去重或“保证可释放”估算；磁盘可用空间单独读取系统指标展示。

平台在后台低优先级扫描，进入页面先显示缓存结果和“上次统计”，再刷新；可以手动重新统计。构建、上传、导入、删除等已知操作使相关统计失效；外部 AI 直接编辑需要随后重扫。统计只是非原子的时点估算，不冻结业务、不做全盘内容哈希。

扫描结果至少有开始／完成时间、是否完整、是否过期、分类字节数和文件数。扫描期间文件变化、权限不足或路径无法访问时，显示不完整及原因，不能把未知报成零。完整仅表示本次扫描遍历了声明范围，不表示所有文件来自同一个原子时刻；未完成结果明确标记为部分值。迁移、删除、恢复或导入切换项目根目录时，正在进行的扫描作废或中断，不能把旧目录与新目录混成一个完整结果。

分类占比只能使用同一次扫描、同一范围内的分类字节数与总量。当前项目的比例不混入关联历史，也不使用另一轮缓存中的总量作分母。完整扫描且合计为零时显示“暂无文件”，不计算除零比例；部分扫描展示“已统计部分”及未知范围，不能将可见部分渲染为代表完整范围的 100%。显示四舍五入可能使各项百分比之和略有偏差，精确计算以字节数为准。

扫描遵守根目录边界，不跟随符号链接进入项目外。发现链接或其他特殊文件时列为异常／未统计对象，不隐形漏掉后宣称总量完整。文件浏览分页，不能把所有照片一次读入内存。

SQLite 删除记录后文件不一定缩小；库内空闲页可复用，不等于已经释放磁盘。统计只看文件大小，不顺便执行 checkpoint、VACUUM 或删除 WAL/SHM。高级的空闲页指标和数据库压缩后置，参见 [SQLite freelist_count](https://www.sqlite.org/pragma.html#pragma_freelist_count)与 [VACUUM](https://www.sqlite.org/lang_vacuum.html)。

## 5 当前体积、关联历史与工作区总量

项目卡片主数字只统计当前项目目录，关联历史另列。下面是页面信息示例，全部数字均为虚构值：

| 内容 | 示例大小 |
| --- | ---: |
| 源码与资料（含固定素材 15 MB） | 20 MB |
| 网页产物 | 35 MB |
| 用户素材（照片、录音、文档） | 800 MB |
| 数据库与伴随文件 | 10 MB |
| 开发依赖 | 300 MB |
| 缓存与日志 | 20 MB |
| 其他文件 | 5 MB |
| 当前项目合计 | 1.19 GB |
| 关联历史备份 | 2 GB，另列 |

工作区总览按实际路径归属汇总：活跃项目、备份、回收站、操作／恢复现场、共享缓存、平台控制记录及其他。项目详情里的“关联历史”只是对工作区项目的引用，不能再次加进工作区总量。回收站项目内容计回收站，仍保留的 ZIP 计备份。

恢复原现场、候选副本和活动操作暂存也占空间，要展示所属任务和是否受保护；可能正在增长的大小标明统计时间。不能为让数字好看排除这些目录。

未完成上传在平台暂存区单独计入对应临时占用，不列入正式附件列表；活动上传受保护，失败残留仅按平台已识别记录清理。构建来源记录属于工作区持久控制，不随日志或构建缓存清理丢弃。

### 5.1 平台自身与本机已知数据

统一空间总览分为三个并列范围：

| 范围 | 内容 | 排除项与归属 |
| --- | --- | --- |
| 平台程序 `platformProgram` | 当前正在运行的实际 `.app` 包内文件，包括随包分发的 UI、Rust 程序、CLI、SQLite、SDK、模板和图标等 | 只读扫描，不写入或清理安装包；不以固定 `/Applications/` 路径猜测当前位置 |
| 当前工作区 `workspace` | 活跃项目、备份、回收站、操作现场、共享缓存、控制记录及其他文件 | 保持上述互斥归属；项目的关联历史不二次加总 |
| 本机其他占用 `otherLocalLocations` | 固定应用数据目录中工作区之外的设置、运行记录、迁移日志、平台自身统计缓存，以及登记的迁移旧副本 | 当前工作区及已独立统计的其他根从父目录扫描中排除 |

默认工作区位于固定应用数据目录下，因此不能将整个 `appLocalDataDir` 的体积再加到工作区总量上。统计前解析实际根位置，将有包含或重叠关系的范围划分为互斥路径集合；同一路径只归属一次。无法确认根的身份或边界时标记不完整并说明，不能凭显示路径不同就重复相加。真实存在于不同路径的副本仍分别计入逻辑字节，不承诺识别文件系统共享块。

平台程序大小是已安装 `.app` 的文件大小合计，不是 DMG 下载包大小。系统 Node、外部 npm 缓存、系统 WebKit 和未登记的其他软件不计入平台程序；平台确实创建且能够定位的本机数据才计入相应已知位置。系统数据库、浏览器数据等无法划定归属的内容不估算成平台占用。磁盘剩余空间作为系统指标另列，不从上述合计反推。

扫描 `.app` 不跟随符号链接重复计入目标；根内普通文件按其实际路径计一次，链接项、根外目标或无法读取的内容明确记录。遇到无法统计的对象时按完整性规则报告，不通过链接遍历系统目录。扫描过程中应用被覆盖或运行安装根改变，旧扫描作废，更新后重新测量。安装包始终只读，统计缓存留在固定应用数据目录。

每个范围独立显示统计时间、完整性和过期状态。旧位置不可用时展示未知或明确注明的上次值，不当作零；不同时间的缓存只能组成带范围和时间说明的“本机已统计文件合计”，不能称为同一时刻的精确占用。若有未知范围，合计必须注明不完整；范围跨磁盘时不能给出一个虚假的统一剩余磁盘值。扫描不到的用户外部导出 ZIP、下载的 DMG 或未登记副本不纳入平台掌握的总量，不能声称覆盖用户电脑全部相关文件。

### 5.2 缓存位置、身份与失效

空间统计由平台扫描产生，采用以下固定缓存位置：

| 缓存 | 存储位置 | 生命周期 |
| --- | --- | --- |
| 当前项目及其关联历史摘要 | `workspace/.platform/cache/storage/projects/<projectId>.json` | 项目目录之外；不随单项目备份、导出或复制携带 |
| 当前工作区汇总 | `workspace/.platform/cache/storage/workspace.json` | 工作区缓存，可删除重建；迁移到新根后作废重扫 |
| 当前平台程序 | `appLocalDataDir/cache/storage/platform.json` | 固定应用数据目录，不随工作区迁移；按安装位置和当前程序版本重新验证 |

项目缓存单独放入 `storage/projects/`，避免合法项目 ID（例如 `workspace`）与工作区汇总文件重名。缓存路径中的项目 ID 仍须先通过清单 ID 校验，不能作为任意文件路径直接拼接。

这些缓存都不是项目资料、业务数据、保护状态或可删除对象的权威来源。丢失、损坏或格式不支持时，显示尚未统计并重新扫描；不能因此重新创建业务数据库或改写项目清单。缓存文件本身计入实际所在范围中的平台缓存，不再作为独立占用重复相加。扫描写回自身缓存可能使缓存目录大小随之变化，仍遵守非原子估算口径，不循环扫描直到数字不变。

每个缓存记录 `schemaVersion`、范围 `scope`、根目录身份、扫描结果与失效信息。项目及工作区缓存绑定 `workspaceRootIdentity`，项目缓存还绑定 `projectRootIdentity`；身份由当前规范化根路径及平台能够核对的目录身份组成，不能只比较路径字符串。`rootGeneration` 是当前服务实例对该统计根登记／切换的代次；同 ID 的恢复、重新导入、回收站恢复或迁移切换也使相应代次改变，旧扫描不能据此发布到新根。服务重启先重新核对根，旧结果先标记过期再重扫，不直接沿用旧实例的代次。该字段只用于缓存一致性，不引入新的工作区永久身份体系，也不与页面的 `documentEpoch` 混用。

缓存还记录本次分类使用的已校验目录映射；`sourceDir`、`outputDir`、`database`、`attachmentsDir` 等分类输入改变后必须失效。已知项目、备份、任务等被统计内容的变动使相关统计标记过期；统计缓存自己的写回按上述非原子估算处理，不触发无限失效重扫。导入、复制、恢复、回收站恢复及迁移后不能把携带的旧缓存当作新根结果，正在进行的旧根扫描也不能发布。平台程序缓存绑定安装根身份和已安装版本／构建标识，覆盖安装或移动后重新统计；平台启动重新核对这些绑定，不能只看缓存文件是否存在。外部修改未必被即时观察，界面始终保留上次统计时间和重新统计入口。

## 6 素材浏览与清理边界

### 6.1 通用页面以查看、定位为主

附件列表展示逻辑路径、可用时的原始名称、类型、大小、修改时间；支持按类型、路径前缀、名称搜索、大小／时间排序及分页。扩展名和 MIME 用于显示分类，不是可信代码判断或业务关系推断。平台不知道“这张照片属于哪次游戏”，除非项目提供明确业务信息。

图片、音频和视频按支持格式预览；其他文件可以下载。预览和下载仍遵守既定的项目读取门禁与文档代次校验；维护、恢复或快照冻结期间可以暂停内容读取，空间元数据不能成为绕过门禁的路径。未知 HTML、SVG 等不能作为平台管理页直接执行，不能把原始附件嵌入带管理权限的 DOM。PDF／Office 的完整预览可以后置，保存和下载不受影响。

首版通用页不做任意素材的批量删除，避免破坏数据库引用。用户通过项目业务页面删除记录与素材，或让 AI 根据数据说明操作。已有 `files.remove()` 和 AI 的文件能力仍保留；这个限制只针对平台通用清理器，不收回既定数据操作能力。

平台不能因扫描不到引用就把文件标为“无用”。第一版不做自动孤立文件删除、内容去重、自动压缩原照片或根据时间清理历史资料。

### 6.2 可清理项目明确列出

提供“清理开发依赖”“清理已结束构建缓存”“清理可删除日志”等具体动作，说明重建时是否需要下载；依赖清理仅使用已识别工程依赖根的白名单，附件、回收站或恢复现场中同名的 `node_modules` 不因此重分类或允许清理。清理前重新核对文件与任务状态，不以旧统计缓存作为删除依据。与同项目构建、备份、恢复和生命周期操作互斥；维护中使用当前维护 ID，且须已完成基线准备、允许修改。`recoveryRequired` 或未解决的恢复操作阻止清理。外部 AI 同时写目录时仍需协作暂停。

以下不进入普通缓存清理：源码、项目清单及 `meta/` 资料、固定 SDK、用户附件、当前 `dist/`、仍被切换或旧页面使用的保留产物、数据库及 WAL/SHM、维护基线、受保护备份、恢复原现场、未完成操作日志和未知文件。平台程序 `.app` 也不是空间页的缓存清理对象。

损坏或无法打开的数据库仍归数据库，不能因检查失败降为缓存。清理只处理白名单根内经重新确认可删除的对象，不跟随链接删除目标；发现边界不明、链接异常或保护状态无法判定时保留并报告。项目内或工作区内叫 `.platform`、`cache`、`logs` 的目录均不代表可以整目录递归清除。

备份清理、回收站永久清除、迁移旧目录删除继续使用已确定的独立入口与保护规则。清理结果显示实际删除了什么及剩余错误，不把预计文件大小等同于已释放磁盘空间。首版不做自动项目配额驱逐；磁盘不足显示明确失败，不擅自删用户素材腾空间。

## 7 统一服务与 AI 接口

由 Rust 平台扫描与汇总文件系统，UI 与 CLI 复用同一服务。统计不是 AI 自报数字，也不把某次统计结果硬编码到 `project.json`。统计缓存可重建、不放入项目备份；历史来源由已有备份及任务记录关联。旧项目无需升级 SDK 即可在平台页面查看空间。

| CLI 命令 | 管理 HTTP 接口 | 内容 |
| --- | --- | --- |
| `platform storage info --project ID --json` | `GET /api/v1/projects/{id}/storage` | 分类、字节数、数量、统计时间、完整性、关联历史和保护原因 |
| `platform storage scan --project ID --json` | `POST /api/v1/projects/{id}/storage/scans` | 提交后台重新统计任务，返回任务 ID |
| `platform storage files --project ID --input request.json --json` | `GET /api/v1/projects/{id}/storage/files` | 分页附件列表、筛选与排序；CLI 输入转换为查询参数 |
| `platform storage cleanup --project ID --input request.json --json` | `POST /api/v1/projects/{id}/storage/cleanups` | 指定允许清理的类别，不接收任意递归删除路径 |
| `platform workspace storage --json` | `GET /api/v1/workspace/storage` | 平台程序、工作区总览、本机其他占用及可访问的迁移旧副本 |

`platform` 仍为工具名占位，实际命令入口遵循主约定。以上路由均使用现有管理凭据；扫描和清理返回 HTTP 202 及任务 ID，状态、等待和日志沿用[本地服务接口](local-service-and-ai-tools.md)，不增加另一套任务协议。查询返回 HTTP 200；首次没有统计结果时返回“尚未统计”，不能以空结果或零代替。

最小请求与结果约定：

- 重新扫描请求体为空对象，范围由路由中的项目 ID 决定；只读统计不要求维护 ID，不冻结业务。同项目已有未完成扫描时返回该扫描任务，避免堆积重复任务。
- 附件列表支持 `type`（`image`、`audio`、`video`、`document`、`other`）、`prefix`、`query`、`sort`（`name`、`size`、`modifiedAt`）、`order`（`asc`、`desc`）、`limit` 和不透明 `cursor`；省略筛选表示全部附件。默认 `limit` 为 100，上限 500；相同排序值以逻辑路径排序。游标失效时明确要求重新获取，不能悄悄遗漏。列表也不承诺跨页期间文件不变。
- 附件列表仅限当前项目 `attachmentsDir`，返回已有 `FileInfo` 字段以及显示分类；不提供任意磁盘路径读取。`prefix` 与查询结果中的路径均为附件逻辑路径，仍执行越界和链接检查。平台管理页的预览与下载经宿主受控管理模块复用附件读取逻辑；项目网页使用既有项目会话文件接口，不向管理页面或图片 URL 泄露管理凭据，也不把现有项目接口改成免会话读取。不在管理页面执行附件脚本，读取继续遵守维护和冻结门禁。
- 清理请求包含非空 `categories`，仅允许 `dependencies`、`buildCache`、`logs`；维护中另带 `maintenanceId`。CLI 的 `--maintenance ID` 与 JSON 字段同时提供时必须相同。类别允许申请某类清理，不代表该类的所有文件均可删除；服务在执行前逐项核对保护和活动任务。
- 缓存使用的最小封装包含 `schemaVersion`、`scope`、根身份、`rootGeneration`（工作区／项目扫描）以及扫描结果。`scope` 明确范围种类和项目 ID（适用时）；工作区／项目根分别使用 `workspaceRootIdentity`、`projectRootIdentity`，平台程序使用 `installationRootIdentity` 及已安装版本／构建标识。管理接口返回相应范围、根位置及可读的缓存失效原因；不把根身份描述当作可执行文件路径参数或授权凭证。
- 扫描结果包含 `scanId`、`startedAt`、`completedAt`、`complete`、`stale`、`totalBytes`、`categories` 和 `issues`。未完成扫描的 `completedAt` 为空；每类提供字节数和文件数，固定素材以源码子项返回，不参与第二次加总。`totalBytes` 只合计本扫描范围中已统计的互斥顶层项，`complete=false` 时不是完整总量；尚未统计使用空值／明确状态，不以零占位。字节数沿用平台整数传输规则，超过 JavaScript 安全整数范围时使用 `$int64` 标记，不以浮点数静默舍入。`issues` 标注受影响的范围和原因，例如路径不可读、根已切换、链接未统计或分类清单无效。
- 项目空间结果把 `currentProject` 与 `relatedHistory` 分开；工作区接口返回并列的 `platformProgram`、`workspace`、`otherLocalLocations`。每一范围独立携带统计时间、完整性、过期状态和互斥归属；可展示的本机已统计合计仅对已排除重叠的范围求和，任何未知范围使合计不完整。不能把不同时间的缓存拼成“同一时刻的精确总量”，也不在该合计中重复加上项目详情里的关联历史。
- 清理任务结果返回已删除对象的类别、文件数与逻辑字节合计，以及跳过／失败原因；“逻辑字节合计”不是操作系统实际释放量。部分删除后遇到错误，任务为 `failed` 并保留实际完成结果；中断不自动重放清理，重新操作须重新核对当前状态。

普通项目网页仍使用现有文件 SDK，不获得跨项目空间、绝对路径或管理权限；如果将来增加本项目空间查询 SDK，再通过可选能力声明兼容加入。管理页无需为读取体积打开业务数据库、修改表或执行项目脚本；坏库不影响对其文件大小的扫描。

项目 README 必须明确项目名称／简介／图标的来源、固定素材与用户附件的位置、文件格式、业务引用与删除规则、可重建目录和预期持续增长的内容。`meta/` 是持久项目资料，不能列为可重建缓存；项目展示图标与网页运行素材的区别应明确。具体体积由平台动态测量，不要求 AI 每次手写数字。

## 8 首版范围与实施验证

第一版交付带基本资料的项目卡片／概览、平台统一空间页、互斥分类统计、附件列表与基本预览、关联历史占用和明确类别的缓存清理，并区分平台程序、当前工作区与本机其他已知占用；以上为已确认范围。项目元数据与平台“关于”页面细节分别见[项目资料契约](project-metadata-and-overview.md)和[发行契约](release-and-updates.md)。PDF／Office 完整预览、业务引用分析、孤立附件自动删除、内容去重、自动压缩、数据库压缩、精确物理块统计和自动配额驱逐后置。

实施时验证源码素材与 dist 的计数、`meta/` 计入资料且不触发构建、隐藏及未知文件、持续写入时统计过期、权限失败、WAL 增长、海量附件分页、维护与清理冲突、受保护现场不被清理、导入复制后的统计、回收站与迁移旧副本归属。补充验证坏库或未构建项目仍能展示概览、无效图标降级、缓存损坏／旧版本可重建、同 ID 根切换拒绝旧扫描、默认工作区与固定应用目录无重复计数、覆盖安装后程序缓存失效、符号链接不重复计目标，以及不完整统计／零文件／不同扫描时间下的比例与合计提示。文档示例不表示已有 UI 或已完成这些运行测试。
