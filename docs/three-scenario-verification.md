# 本轮三场景验收与样本登记

建立日期：2026-10-21。依据：[产品目标的本轮范围](product-goal.md#本轮三条场景范围)与[技术实施计划](technical-implementation-plan.md)。本轮补齐制作自用、获取项目、修改定制（包括 Codex 接手）三条链路；分享暂缓，四场景历史目标继续保留。

本文件初始仅登记验收要求与已知证据边界，**尚未记录本轮任何完整链路通过**。下表“待登记”不是实际项目 ID、路径、来源或测试结果；由主任务执行后填写真实值，不把历史子步、新增代码或模拟通过改写成原生验收通过。

## 1. 记录方式与完成条件

| 证据种类 | 可以证明什么 | 不能替代什么 |
| --- | --- | --- |
| 真实原生操作 | 指定构建和系统上，真实管理窗口／应用窗口中的操作、结果、重开与数据观察 | 其他系统、干净电脑、未执行的异常分支 |
| 后端故障注入 | 指定隔离样本的失败点、事务／进程收尾、已提交边界及数据不变断言 | 原生按钮、关闭事件、真实公网或外部 AI 操作 |
| DOM 模拟 | 人工接口结果下的点击、表单、草稿、重复提交与关闭保护 | 真实服务执行、下载、构建、认证、原生窗口或数据落盘 |
| 未验 | 缺少对应执行与证据，或能力尚未实现 | 不能用历史近似结果补成“通过” |

每次记录构建／提交、系统、样本代号与真实 ID、操作、预期、实际结果、证据位置和限制。失败、受阻和不适用须保留原因；修复后的通过作为新一次记录，不能删除失败现场。没有用户取消入口的操作不能标“用户取消通过”；停止等待不等于后端已停止。中断后的未完成状态必须真实可识别，不以重新提交或手工删除现场制造成功。

正常闭环须有真实原生使用和数据保存／重开证据。故障项可先用后端注入与 DOM 复验定位，但各自记录种类；涉及原生交互的项在实机完成前保留未验。Codex 接手须实际读取本轮指定项目与当前交接说明，完成可识别的业务修改，经平台构建并在原生窗口验证；仅复制交接文字或运行平台自身测试不算通过。分享、最低系统、Windows、干净电脑和正式发行没有本轮证据时继续未验。

## 5. 实际执行记录

当前无本轮执行记录。主任务每次执行后增加记录并关联第2节编号，至少包含：

- 时间、构建／提交、系统、证据种类，以及场景和样本代号。
- 真实项目 ID、源码／运行／数据／配置位置、来源和版本；不记录秘密内容或临时认证凭据。
- 操作步骤与注入点、预期、实际结果（通过／失败／受阻／未验）及证据位置。
- 前后业务记录／附件核对、进程与未完成状态、已知限制。
- 样本保留位置与最终处置；失败后的重试作为独立记录。

三条场景分别依据矩阵收尾。任一缺失路径保留未验或受阻，不用“全部通过”代替逐项结论；本轮完成不改变分享暂缓、其他系统及正式发行尚未验收的状态。
