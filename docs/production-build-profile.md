# 正式版构建身份基础

此步骤仅实现编译身份、统一有效版本和离线构建信息。首个正式版本为 0.1.0，正式身份为 `com.happypandaa.pandadrawer`，发行仓库为 `happypandaa/panda-drawer-releases`。它不表示已有正式安装包、签名、公证、下载资产或自动升级。

## 开发默认值

未启用 `production-profile` 时，版本继续来自 Cargo 工作区的 0.0.0，固定身份为 `dev.happypandaa.pandadrawer`，环境为 `development`。数据根由系统用户数据目录和固定编译身份派生，不接受环境变量、命令行参数或外部配置任意选择根目录。2026-10-25 用户最终选择[清空旧开发环境并重新开始](development-identity-reset.md)，不保留旧副本、校验清单或临时迁移证据，不交付身份迁移命令或旧身份兼容映射。实际清理与新环境验收另记，不沿用下方旧身份测试结果。正式身份、生产资源来源锚及运行门禁不因此变化。

## 固定生产配置

`build-profiles/production.json` 是首版生产元数据文件。core 的构建脚本只读取这一固定仓库路径，校验已确认的字段、目标架构与 schema，拒绝未知字段、缺字段及其他身份或版本。CLI 和桌面包通过同名 Cargo feature 转发给 core；core 在编译输出目录生成只读常量。

有效版本 `APP_VERSION` 同时用于平台基本信息、CLI 的版本与环境诊断、程序空间扫描缓存和旧备份的程序版本记录。桌面启动还检查实际 Tauri 包的 identifier/version 与编译常量一致。Cargo 包版本保留为开发默认 0.0.0，离线构建信息同时展示 `cargoPackageVersion`，供后续正式打包事务核对；本步骤不生成生产 Tauri 覆盖配置或安装包。

CLI `build-info --json` 完全离线，只返回编译身份、版本、目标、生产配置 SHA-256、资源锚状态和运行许可信息。它不查找数据根、不读取发现记录或凭据、不启动桌面、也不检测网络发行资产。开发版和正式候选版的 `releaseReady` 均为 false。

## 尚未配置签后资源锚

固定配置的 `resourceAnchors` 目前只接受 `unconfigured`，不在 profile 中接收任意替换摘要。普通 `production-profile` 允许编译与离线检查，但 `require_runtime` 返回 `PRODUCTION_RESOURCE_ANCHORS_UNCONFIGURED`。后续独立的 `production-resource-anchors` feature 只接收严格编译输入，见[签后资源协议](production-resource-anchors.md)；即使摘要锚已编译，也继续返回 `PRODUCTION_DISTRIBUTION_PROOF_UNCONFIGURED`。操作结果均为 `not_started`，不存在能打开正式运行的 JSON ready 字段或运行时覆盖。

桌面在创建 Tauri 插件和窗口前检查此门禁。CLI 在读取任何业务输入文件之前统一检查，所有业务命令都被拒绝；帮助、版本和 build-info 可离线使用。core 的初始化、发现、身份修复、已有根目录/凭据读取、服务启动与 Node 管理器构造也在目录或资源读取前拒绝。生产身份因此不会收养开发工作区，也不会建立未准备好的生产数据根。

签后资源清单的摘要/路径协议和编译、运行检查接点已经单独实现；真实签名转换与包装事务仍待后续步骤：先正式签署内嵌 Node/Git 叶子可执行文件，再生成覆盖运行 Node、完整开发 Node 树和完整开发 Git 树的摘要，绑定生产配置、目标和现有来源锚，经过严格构建校验后编译进只读二进制。生产运行时不得从邻近可写 JSON 接受替换摘要。缺失、旧 schema、错误目标、来源或字节不匹配必须拒绝；不能把本步骤的 `unconfigured` 改成 `ready` 来绕过它。开发资源的三处既有来源锚保持原规则。

Mac 正式分发仍须 Developer ID Application 签名、Apple 公证、票据和实际安装验收。主程序及 CLI 的最终签名属于后续外层签名事务，不能把它们自己的 hash 放入待编译清单形成循环。
