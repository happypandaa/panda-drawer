# 外部 Node 应用说明更新

日期：2026-10-23。

本轮为已登记的外部 Node 源码目录增加显式的“查看新版应用说明”入口。用户在原生管理窗口核对当前来源、后端入口和配置字段，明确重新信任后，平台更新同一实例的声明摘要。更新本身不启动、重启或执行应用代码，不创建第二个实例。

这补充了[本机配置与运行](node-native-configuration.md)中“来源声明改变时阻止启动”的旧边界。旧平台不提供此更新按钮，来源摘要不一致时仍会拒绝打开；使用原生入口需要构建并升级到包含本入口的平台版本。本轮已通过临时本地验证程序调用新核心方法，更新实际 Radio 的原实例声明，详情见末尾；这不是原生窗口点击验收，也不改写旧文档中当时的验证记录。

## 适用范围

| 登记或运行状态 | 处理方式 |
| --- | --- |
| 外部源码目录登记，`registration.json` 为 v1，应用已停止且无活动记录 | 可从原生管理窗口预览并显式更新声明。 |
| 正在启动、运行、关闭，或平台正在退出 | 先正常关闭应用并等待收尾；此路径拒绝更新。 |
| 存在 `active.json` 等未完成收尾的活动记录 | 拒绝更新并保留现场；不能删除活动记录来强行通过。 |
| v2 受管安装实例 | 使用[正常应用更新](node-managed-installation.md)流程；不能用本入口重新信任外部目录或绕过安装更新。 |
| 来源失联、声明无效、登记记录损坏，或新字段与已保存配置不兼容 | 显示错误并保留原登记、配置和数据，先修正对应问题。 |

这里的登记 v1/v2 指本机登记记录，不是 `local-app.json` 的 `formatVersion`。一个外部 v1 登记可以引用有效的 Node 应用新版格式说明。静态项目、工作区迁移、安装副本、备份恢复和来源目录迁移不由此入口处理。

## 用户操作

1. 正常关闭需要更新的 Node 应用，等待平台确认其服务已收尾。在“我的项目”找到原有实例，从卡片打开详情。
2. 点击“查看新版应用说明”。平台读取原登记指向的源码目录，不要求用户删除实例、重新登记或手工修改私有槽。
3. 核对预览中的源码路径、应用身份和版本、后端运行入口，以及完整配置字段。字段预览包含名称、类型、必填性、秘密属性、默认值、用途、获取步骤和帮助链接；秘密只显示“已设置”等状态，不显示保存的密钥。
4. 理解旧登记缺少历史声明、此次需要重新信任当前说明的提示后，显式确认更新。取消只关闭预览，不变更登记。存在配置草稿时，先按界面提示处理草稿，避免将未保存编辑误当成已经保存。
5. 更新成功后，在同一实例配置页查看新字段。原有值和密钥绑定保留，新增字段按清单提供默认值；需要新服务时再填写对应凭证并保存。保存或更新声明都不会启动应用，之后由用户明确点击“进入项目”。

旧外部登记只保存摘要和来源路径，没有历史完整声明可作比较。因此平台不能自动证明本次“只新增可选项”，也不能准确列出每一项相对旧版的增删变化。预览展示的是当前完整声明；确认表示用户重新信任当前来源中的应用说明。摘要校验只钉住说明文件，并不冻结源码或依赖，也不证明它们安全；外部源码接入仍要求来源可信。

## 保留与生效

更新沿用原实例 ID、原来源目录和私有槽，只提交新的声明摘要。普通显式配置、配置修订、秘密绑定及 `configuration/credentials/` 文件保持，业务 `data/`、缓存和运行历史不复制、不清空，也不从源码目录的 `.env` 借用配置。新默认值只参与未显式填写字段的配置求值，不把真实密钥写入清单。

保留绑定不等于无条件允许向新地址发送旧 Key。预览沿用配置校验；服务地址改变时，原有秘密仍按配置规则要求重新确认绑定、替换或移除。字段类型、秘密属性或已保存值不兼容时拒绝，不能为了接受新声明而静默丢弃旧配置。密钥缺失或新增必填项未完成时，配置页继续提示，启动仍受门禁约束。

当前秘密文件仍由本机用户文件权限保护，不是系统加密凭据库。本入口只检查秘密的绑定和文件元数据，不读取密钥明文，也不调用外部 AI/TTS 服务来“验证”凭证。

## 防止过期预览

预览和确认通过原生管理窗口命令 `node_app_declaration_update_preview`、`node_app_declaration_update_apply` 完成，业务网页不获得这两个管理入口。

预览返回三项并发校验依据：

| 字段 | 对应快照 |
| --- | --- |
| `expectedRegisteredDigest` | 当前 `registration.json` 原始内容的摘要，防止登记身份、来源或其他登记内容在预览后改变。 |
| `expectedManifestDigest` | 当前来源 `local-app.json` 原始字节的摘要，防止预览后替换或修改说明；不是重新序列化 JSON 后的摘要。 |
| `configurationRevision` | 当前已保存配置修订，防止预览后另一操作保存了新配置。 |

确认请求携带这些依据和 `confirmed: true`。提交时重新读取并校验登记、原始说明与配置修订，并再次检查停止状态和活动记录；任何一项改变都拒绝提交，提示重新预览。平台还在替换登记前复核这些条件，不接受把旧预览重复用于已改变的来源或配置。更新登记成功后返回同一实例的最新详情，状态保持停止。

这些摘要是公开元数据，不是 Key、凭证文件 ID 或启动授权。用户无需复制它们，也不应手工编辑登记文件绕过核对。失败时保留原登记和现场，不自动重试更新、不自动启动服务。

## Radio Bob 场景

Radio 的外部来源为 `/Users/ethan/dev/radio-bob`。原清单包含 6 个字段，新清单包含 14 个字段：

- AI 节目生成 3 项：`ANTHROPIC_BASE_URL`、`ANTHROPIC_API_KEY`、`CLAUDE_MODEL`。
- 语音服务选择 `TTS_PROVIDER`，显式选择 Fish、豆包、Gemini 或关闭，默认 Fish。
- 原 Fish 3 项：`FISH_API_KEY`、`FISH_REFERENCE_ID`、`FISH_MODEL`。
- 豆包 3 项：`DOUBAO_API_KEY`、`DOUBAO_RESOURCE_ID`、`DOUBAO_SPEAKER`。
- Gemini 4 项：`GEMINI_API_KEY`、`GEMINI_TTS_MODEL`、`GEMINI_TTS_VOICE`、`GEMINI_TTS_STYLE`。

14 个字段在现有配置上限内，沿用现有字段格式，没有条件显示或条件必填的新语法。语音项全部可选、秘密无默认值；未填写所选语音服务的 Key 时仍使用文字串词和音乐，不按已有密钥自动切换。更新声明应保留原 AI Key 的已设置状态及原业务数据；用户可以继续使用 Fish 默认值，再自行选择新服务。豆包和 Gemini 各自的凭证、音色、地区及额度说明由 Radio 清单和用户文档提供。

本轮已对实际 Radio 原实例完成声明预览与更新。操作由临时本地验证程序调用新核心方法，未通过原生窗口点击。返回同一实例 ID、14 个字段，配置修订仍为 `4`，AI Key 状态仍为 `set`，`configurationCanStart` 为 `true`。没有保存新语音 Key、启动 Radio 或请求真实语音合成。
