# 应用开发环境与交付要求

状态：2026-10-20 用户确认的应用开发原则。供应用作者、开发者和 AI 选型及交付时阅读；平台自身的 Tauri/Rust 开发环境另见[开发说明](development.md)。本文明确环境和交付责任，不新增清单字段、安装接口或构建能力。完整外部包安装仍待实现，当前 Node 接入范围见[本机配置与运行](node-native-configuration.md)。

## 1 默认使用前端与平台 SQL

优先采用 **构建好的前端 + 平台 SDK + 平台 SQLite / 附件**。表单、列表、搜索、统计和本地数据管理通常不需要应用自己的后端，不为这些功能额外引入 Node、数据库服务器或其他常驻服务。

平台以 Rust 提供本地服务和原生 SQLite；网页通过项目实际版本的 SDK 读写 SQL 和附件，不直接打开数据库文件，不用浏览器缓存替代业务主数据。React、TypeScript、Vite 是现有模板和构建工具，使用它们不意味着应用运行时需要自己的 Node 服务。

确需只能在后端使用的 SDK、私密 API Key 或服务端接口时，再选择 Node 服务类型。前端直连外部接口仍受平台声明、CSP 和服务方 CORS 限制；不能为了省掉后端把私人 Key 放进网页。应用调用 AI 优先采用服务商的 HTTP API，由适配代码处理实际协议，不默认要求用户安装 Claude Code 等开发工具，也不将不同服务商的接口一概当作兼容。

既有 project-v1 才有当前 SDK 的 SQL、附件和完整生命周期能力。独立 Node 源码槽没有自动获得同一套数据库接口；不能让 Node 直接打开平台 `main.sqlite` 或伪造 project ID。确需自有数据时使用该应用受管数据目录，并如实说明当前未接入完整备份、迁移等限制。

## 2 需要 Node 时，尽量只增加一个应用服务

首选 **静态前端 + 一个受管 Node 服务**，业务 SDK 尽量作为库放进这个服务。平台提供私有 Node，统一负责启动、停止、健康状态和窗口生命周期；作者实现业务、接口适配和完整依赖。不要把 Vite 开发服务器、`npm start`、自建守护程序或多服务启动脚本作为用户的运行入口。

应用不依赖终端的 PATH、全局 npm 包、作者机器路径、原开发服务或宿主未声明的环境变量。配置通过清单逐项声明，由平台表单保存并在启动时注入；用户不编辑 `.env`。每项写清中文名称、用途、必填／可选、默认值、填错影响及具体获取步骤。秘密值只交给平台配置入口，不随源码、网页或分享包交付。

尽量避免要求用户安装 Claude Code、Python、Rust 工具链、Docker、数据库服务器或额外 CLI。若业务确实离不开，必须在选方案时提前向用户说明，并在用户指南和开发说明中列出名称、版本／系统要求、用途、安装与认证准备、缺失影响和替代办法；不能等运行失败后才补充。

**提前声明不等于平台已经支持。** 当前没有通用外部 CLI、任意二进制或多服务编排的运行契约；不能仅因用户机器装了工具，就绕过受管入口调用它并声称标准兼容。外部在线 API、账号、Key、网络或付费额度属于使用前提，也要提前说明，但与本机软件安装要求分开写。

所有应用从“我的项目”进入同一种原生窗口。Node 在后台随窗口启动，关闭应用窗口收尾本应用受管进程，关闭平台则收尾全部受管应用；重复打开只聚焦。配置缺失先显示详情弹窗的配置 tab，保存不启动。具体约束见[窗口与后端契约](app-window-runtime-contract.md)。

## 3 作者准备完整运行文件

交付目标是用户配置后直接打开，不在首次运行时补装依赖或编译源码。

| 交付内容 | 作者需要准备 |
| --- | --- |
| 前端 | 构建完成的 HTML、JavaScript、CSS，以及实际引用的图片、字体等资源；不能只交 React/TSX 源码或要求用户启动 Vite |
| Node 入口 | 能被平台指定 Node 直接执行的 JavaScript，适配当前受管协议；可以是 `.js` / `.mjs` 源码或打包产物，TypeScript 等先转换为受支持的 JavaScript |
| Node 依赖 | 将运行依赖预先打入产物，或携带可独立运行的完整依赖树；动态加载文件、模板、静态资源及必要许可证也随程序保留 |
| 开发资料 | 提供实际源码、锁文件、构建方式和版本信息时如实标注；源码可以作为开发资料附带，不能替代运行文件。既有开发项目仍保留完整源码、固定 SDK 和资料 |
| 用户资料 | 独立的用户使用／配置说明、开发说明，内容与实际清单及平台能力一致；不附真实 Key、账号 Cookie 或作者本机数据 |

优先纯 JavaScript 运行依赖，运行不依赖联网执行 `npm install` / `npm ci`。这只要求本地程序已准备好；AI、TTS、音乐等在线业务仍需其声明的网络服务。

含原生扩展、额外二进制或安装时编译步骤的依赖，不能假定作者的 `node_modules` 可以跨系统／CPU 直接复制。当前标准接入范围不因本文扩大；未有相应类型和目标系统实测前不接受为标准兼容包。Node 自带模块也按平台指定版本核实，不能假定“任意 Node 包都能用”。

正式自包含应用包应脱离作者源码路径运行，包含所需程序和依赖；**这是交付要求，尚不是已实现的安装功能**。当前内部 Node 槽仍引用本机原源码目录及其已准备依赖，移动／删除源码会影响启动；登记成功不证明已经达到可分发交付要求。包结构和版本仍按[启动规范](node-app-startup-spec.md)及 AP / NR 前置契约推进，不手工搬登记目录来模拟安装。

## 4 内置 Node 不等于内置构建工具链

| 使用场景 | 当前实际能力 |
| --- | --- |
| 创建／打开已有起始网页及已构建 project-v1 | 不需要系统 Node、npm 或现场构建；本地数据能力由平台提供 |
| 启动已接入的 Node 服务 | 使用固定私有 Node，当前 macOS arm64 内部版为 `24.22.0`；不借系统 Node，应用依赖须已就绪 |
| 私有运行时附带内容 | Node 可执行文件、许可证与校验元数据；**不包含 npm、pnpm、yarn、编译器或自动安装器** |
| 修改 project-v1 源码后构建 | 仍使用桌面服务探测到的系统 Node/npm；支持 Node `^22.12.0 || ^24.0.0`，通过实际 `env doctor` 核对。平台构建任务可按锁文件执行 `npm ci`，这是开发构建流程 |
| 在用户端为 Node 应用安装依赖／构建源码 | 未提供这种流程；登记、恢复和启动不执行 npm 或作者安装脚本 |

因此，Node 后端可以交付能直接运行的 JavaScript 源码和依赖；前端仍需作者预构建。未来可以另做私有 npm 和受控构建，但还涉及依赖下载、锁文件、安装脚本、原生编译和失败恢复，不因内置 Node 就自动具备。本轮只明确要求，不新增这项能力。

以上私有运行时结果只针对当前实际验证的 Mac 内部版。Windows 是支持目标，尚未完成平台运行验收；不把 Mac 依赖或验证结果当作跨系统支持。内置 Node 也不是权限沙箱，只接入用户信任的代码。

## 5 应用说明中固定交代的环境信息

用户指南与开发说明分别按[文档分工](application-documentation.md)维护。推荐使用下表，按本应用实际情况填写；无要求写“无”，不能留空让用户猜测。

| 说明项 | 必须讲清楚 |
| --- | --- |
| 运行类型与理由 | 网页／Node；为什么平台前端与 SQL 已足够，或为什么确需 Node |
| 平台提供 | 实际可用的窗口、数据能力、私有 Node 及已验证平台版本；不将目标能力写成已支持 |
| 应用自带 | 前端产物、后端入口／依赖、资源；是否仍依赖原源码目录，源码是否可重构建 |
| 用户需另装软件 | 默认无；有则提前列名称、版本、用途、准备和缺失影响，说明平台是否已支持 |
| 在线服务与配置 | 服务名、账号／Key／地址等准备、用途、获取步骤、可能费用、离线影响；秘密只在平台表单填写 |
| 数据与验证 | 真实保存范围、已支持的备份／恢复方式，实测系统、首次启动、保存后重开及关窗退出结果和未验项 |

现有清单没有通用“外部软件自动安装”字段。当前先在两份说明中明确环境前提，网络／设备和配置只使用实际支持的结构化字段，不自行发明 `requiresNodeInstall`、shell 命令等字段期待平台执行。新增检测、安装预览或统一外部依赖检查需另按契约实现；写了说明不等于已有自动预检。
