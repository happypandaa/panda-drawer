# 应用开发环境与交付要求

状态：2026-10-20 用户确认的应用开发原则；2026-10-21 补充 Mac 内部版受管 Node/npm 接入现有 project-v1 构建的范围。供应用作者、开发者和 AI 选型及交付时阅读；平台自身的 Tauri/Rust 开发环境另见[开发说明](development.md)。本文区分环境、交付责任和当前已接入的构建子集，不增加清单字段或安装接口。完整外部包安装仍待实现，当前 Node 接入范围见[本机配置与运行](node-native-configuration.md)。

## 首版兼容基线：Radio 类应用

2026-10-20 用户确认第一版支持 Radio 这种程度即可。这里收敛的是**应用运行能力的兼容范围**，不是将 Radio 全部业务功能内置平台，也不是将尚未交付的安装、构建或系统验收标为完成。

- 网页类型继续优先使用前端与平台 SQL。需要 Node 时，以现成静态网页、一个受管 Node 服务、同进程 SDK 调用、外部 HTTP AI／TTS 等接口为基线；后端可以是可直接执行的 JavaScript 源文件或打包产物，运行依赖事先准备齐全。
- 不要求用户另装 Node、数据库服务器或 Claude Code。Radio 当前使用 Node 自带 `node:sqlite`，不是要求用户编译第三方 SQLite 扩展；库与内置模块都按实际 Node 版本和目标系统验证。
- 平台提供统一项目入口、类型标识、配置弹窗、Key 保存与注入、原生单窗口、随窗口启停、健康与故障状态；SDK 的业务适配仍由应用实现。
- 通用外部 CLI、任意后端语言、多服务编排、现场原生编译及任意 npm 包兼容，不作为这次首版基线的扩展目标。按实际业务运行路径核对 SDK；依赖树含未使用的其他平台组件，不等于这些组件被执行或已获支持，也不能据此宣称整棵依赖树跨平台可运行。
- 本轮 Mac 内部版已将配套私有 Node/npm 接入现有 project-v1 构建入口，减少单独安装构建工具的前提。后续私有 Git 已接工具选择与诊断，project-v1 已接候选源码与依赖准备；公开源码获取已提供，已接本机源码保存、历史列表与新建定制分支；另接显式源码取回；认证、已有分支切换及任意源码构建尚未实现；登记和启动 Node 应用仍不安装依赖。Radio 的网页与后端本身无需编译，可先围绕受管依赖准备／锁文件同步评估，不为这个样本引入通用源码编译器；依赖变更必须与 Node 启动／重启互斥。
- 自包含程序与依赖、标准包检测／安装、必要数据保护和目标系统实机验收仍按 AP／NR／Windows 原门槛推进。当前 Radio 是本机源码槽，真实 AI 与匿名音乐播放已有记录，Fish TTS、音乐账号登录和完整新电脑交接未验收；不将可选业务未验项或 Mac 结果扩张为完整首版通过。

首版交付验收应能在支持的干净电脑上，仅安装平台、取得符合约定的完整应用文件、填写必要配置后，从唯一原生窗口使用；正常关闭须确认所属受管业务进程已退出，不能确认则显示异常并阻止不安全重开，重开数据保留。当前本机试用不替代此验收，也不因兼容范围收敛而绕过既有真实数据和恢复现场保护。

## 1 默认使用前端与平台 SQL

优先采用 **构建好的前端 + 平台 SDK + 平台 SQLite / 附件**。表单、列表、搜索、统计和本地数据管理通常不需要应用自己的后端，不为这些功能额外引入 Node、数据库服务器或其他常驻服务。

平台以 Rust 提供本地服务和原生 SQLite；网页通过项目实际版本的 SDK 读写 SQL 和附件，不直接打开数据库文件，不用浏览器缓存替代业务主数据。React、TypeScript、Vite 是现有模板和构建工具，使用它们不意味着应用运行时需要自己的 Node 服务。

确需只能在后端使用的 SDK、私密 API Key 或服务端接口时，再选择 Node 服务类型。前端直连外部接口仍受平台声明、CSP 和服务方 CORS 限制；不能为了省掉后端把私人 Key 放进网页。应用调用 AI 优先采用服务商的 HTTP API，由适配代码处理实际协议，不默认要求用户安装 Claude Code 等开发工具，也不将不同服务商的接口一概当作兼容。

既有 project-v1 才有当前 SDK 的 SQL、附件和完整生命周期能力。独立 Node 源码槽没有自动获得同一套数据库接口；不能让 Node 直接打开平台 `main.sqlite` 或伪造 project ID。确需自有数据时使用该应用受管数据目录，并如实说明当前未接入完整备份、迁移等限制。

## 2 需要 Node 时，尽量只增加一个应用服务

首选 **静态前端 + 一个受管 Node 服务**，业务 SDK 尽量作为库放进这个服务。平台提供私有 Node，统一负责启动、停止、健康状态和窗口生命周期；作者实现业务、接口适配和完整依赖。不要把 Vite 开发服务器、`npm start`、自建守护程序或多服务启动脚本作为用户的运行入口。

应用不依赖终端的 PATH、全局 npm 包、作者机器路径、原开发服务或宿主未声明的环境变量。配置通过清单逐项声明，由平台表单保存并在启动时注入；用户不编辑 `.env`。每项写清中文名称、用途、必填／可选、默认值、填错影响及具体获取步骤。秘密值只交给平台配置入口，不随源码、网页或分享包交付。

尽量避免要求用户安装 Claude Code、Python、Rust 工具链、Docker、数据库服务器或额外 CLI。若业务确实离不开，必须在选方案时提前向用户说明，并在用户指南和开发说明中列出名称、版本／系统要求、用途、安装与认证准备、缺失影响和替代办法；不能等运行失败后才补充。

**提前声明不等于平台已经支持。** 当前没有通用外部 CLI、任意二进制或多服务编排的运行契约；不能仅因用户机器装了工具，就绕过受管入口调用它并声称标准兼容。外部在线 API、账号、Key、网络或付费额度属于使用前提，也要提前说明，但与本机软件安装要求分开写。

所有应用从“我的项目”进入同一种原生窗口。Node 在后台随业务窗口启动，关闭业务窗口收尾本应用受管进程；重复打开只聚焦。macOS 管理窗口 X 只隐藏并保留 Dock、业务窗口和服务，Dock／Reopen／重复启动恢复同一个管理窗口；菜单退出／Cmd+Q 才安全收尾全部，非 macOS 管理窗口 X 维持退出。配置缺失先显示详情弹窗的配置 tab，保存不启动。具体约束见[窗口与后端契约](app-window-runtime-contract.md)。

## 3 作者准备完整运行文件

交付目标是用户配置后直接打开，不在首次运行时补装依赖或编译源码。

| 交付内容 | 作者需要准备 |
| --- | --- |
| 前端 | 构建完成的 HTML、JavaScript、CSS，以及实际引用的图片、字体等资源；不能只交 React/TSX 源码或要求用户启动 Vite |
| Node 入口 | 能被平台指定 Node 直接执行的 JavaScript，适配当前受管协议；可以是 `.js` / `.mjs` 源码或打包产物，TypeScript 等先转换为受支持的 JavaScript |
| Node 依赖 | 将运行依赖预先打入产物，或携带可独立运行的完整依赖树；动态加载文件、模板、静态资源及必要许可证也随程序保留 |
| 开发资料 | 提供实际源码、锁文件、构建方式和版本信息时如实标注；源码可以作为开发资料附带，不能替代运行文件。既有开发项目仍保留完整源码、固定 SDK 和资料 |
| 用户资料 | 独立的用户使用／配置说明、开发说明，内容与实际清单及平台能力一致；不附真实 Key、账号 Cookie 或作者本机数据 |

优先纯 JavaScript 运行依赖，运行不依赖联网执行 `npm install` / `npm ci`。这只要求本地程序已准备好；AI、TTS、音乐等在线业务仍需其声明的网络服务。

含原生扩展、额外二进制或安装时编译步骤的依赖，不能假定作者的 `node_modules` 可以跨系统／CPU 直接复制。当前标准接入范围不因本文扩大；未有相应类型和目标系统实测前不接受为标准兼容包。Node 自带模块也按平台指定版本核实，不能假定“任意 Node 包都能用”。

正式自包含应用包应脱离作者源码路径运行，包含所需程序和依赖。2026-10-22 新增[Node 源码副本安装子集](node-managed-installation.md)：从已核验来源准备独立程序和生产依赖，再明确安装；运行不依赖作者目录。既有外部目录登记继续引用原路径，不自动迁移。通用应用包、分享和任意项目构建仍未交付，不手工搬登记目录来模拟安装。

## 4 内置 Node 不等于内置构建工具链

| 使用场景 | 当前实际能力 |
| --- | --- |
| 创建／打开已有起始网页及已构建 project-v1 | 不需要系统 Node、npm 或现场构建；本地数据能力由平台提供 |
| 启动已接入的 Node 服务 | 使用固定私有 Node，当前 macOS arm64 内部版为 `24.22.0`；不借系统 Node，应用依赖须已就绪 |
| 私有运行时与构建资源 | Mac 内部版提供固定 Node、许可证与校验元数据，并配套 npm 供已有 project-v1 构建入口使用；不附 pnpm、yarn 或通用原生编译器，应用启动不使用 npm 安装依赖 |
| 修改 project-v1 源码后构建 | 已有显式本机 Node 路径优先；没有显式选择时，有受管资源位置的环境默认使用配套私有 Node/npm，没有该位置的开发服务仍可自动探测。支持 Node `^22.12.0 || ^24.0.0`，以 `env doctor` 的实际路径、版本和可用性为准；平台构建任务可按锁文件执行 `npm ci` |
| 在用户端准备 Node 应用依赖 | 新安装候选可按 npm 锁文件准备生产依赖并跳过安装脚本；须直接可运行 JavaScript 及已有前端产物，不执行通用构建。旧登记、恢复和启动不运行 npm |

Node 后端仍须交付能直接运行的 JavaScript 和完整依赖，前端须带运行产物。构建工具选择不改变应用运行 Node；已有显式选择失效或受管资源缺失／损坏时明确报错，不自动换用其他工具。用户可修正本机路径，或以“恢复默认工具”／`env node clear` 清除显式选择；默认受管位置不等于可用性验证通过。

Node/npm 子步扩展已有 project-v1 构建的工具来源；后续独立 Git 2.56.0 子步接工具选择与诊断，系统 SSH 仅检查版本，认证保持未验证。现有 project-v1 已在每任务候选中安装依赖和构建，不复用原源码依赖；公开源码获取、本机源码保存、历史列表与新建定制分支已接入，另有 Node 安装候选的生产依赖准备。显式源码取回及中断处理独立提供；已有分支切换、认证流程和通用 Node 源码构建流程尚未接入。不能据此宣称技术计划第 2 项或第 6 项整体完成，也不能保证旧版本、断网或异机重建。构建结果、系统与启动方式的实测单独记录在[技术实施计划](technical-implementation-plan.md)，不复用旧运行时记录作新构建证据。

2026-10-22 候选构建补充：平台只复制 `sourceDir` 内普通源码，每次在私有候选执行锁定安装与构建。构建脚本须接受绝对 `--outDir`；内部 file/workspace 依赖可用，外部路径、源码符号链接和依赖根歧义拒绝。不要依赖项目根目录的数据库、Git 或其他文件。原源码及其 `node_modules` 保留，失败不发布；崩溃候选保留以便核查。这是工作目录与依赖准备隔离，不是系统权限沙箱。

以上私有运行时结果只针对当前实际验证的 Mac 内部版。Windows 是支持目标，尚未完成平台运行验收；不把 Mac 依赖或验证结果当作跨系统支持。内置 Node 也不是权限沙箱，只接入用户信任的代码。

## 5 应用说明中固定交代的环境信息

用户指南与开发说明分别按[文档分工](application-documentation.md)维护。推荐使用下表，按本应用实际情况填写；无要求写“无”，不能留空让用户猜测。

| 说明项 | 必须讲清楚 |
| --- | --- |
| 运行类型与理由 | 网页／Node；为什么平台前端与 SQL 已足够，或为什么确需 Node |
| 平台提供 | 实际可用的窗口、数据能力、私有 Node 及已验证平台版本；不将目标能力写成已支持 |
| 应用自带 | 前端产物、后端入口／依赖、资源；是否仍依赖原源码目录，源码是否可重构建 |
| 用户需另装软件 | 默认无；有则提前列名称、版本、用途、准备和缺失影响，说明平台是否已支持 |
| 在线服务与配置 | 服务名、账号／Key／地址等准备、用途、获取步骤、可能费用、离线影响；秘密只在平台表单填写 |
| 数据与验证 | 真实保存范围、已支持的备份／恢复方式，实测系统、首次启动、保存后重开及关窗退出结果和未验项 |

现有清单没有通用“外部软件自动安装”字段。当前先在两份说明中明确环境前提，网络／设备和配置只使用实际支持的结构化字段，不自行发明 `requiresNodeInstall`、shell 命令等字段期待平台执行。新增检测、安装预览或统一外部依赖检查需另按契约实现；写了说明不等于已有自动预检。
