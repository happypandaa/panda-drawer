## 目录声明

Node 清单可增加：

```json
{
  "development": {
    "sourceDir": ".",
    "build": { "kind": "none" },
    "outputDir": "."
  }
}
```

直接运行 JavaScript 的应用使用 `none`。旧清单未声明时保留这一兼容方式。需要编译时使用 `build: {"kind":"npm","script":"build"}`，`outputDir` 指向仓库内独立产物目录，例如 `release`。当前 `sourceDir` 必须是 `.`，根目录是唯一源码仓库；不支持多个源码根或子模块。`outputDir` 中必须包含完整运行 `local-app.json`、静态网页、Node 入口及恰好一套有效 npm 包和锁文件，不能只交前端片段。

源清单、源码、脚本、依赖声明和文档归同一 Git。实际数据库、附件、配置、密钥、依赖和缓存不纳入版本；`.env.example` 是允许保存的公开模板，作者仍须保证其中没有真实凭据。文件名检查不能识别任意源码中写死的秘密。

## 桌面流程

应用详情保留“概览／应用配置／运行状态”三个页签；概览中展开“开发与更新”后，提供打开源码、选择源码目录、构建并更新和 AI 接手说明。“源码版本”折叠区提供本机 Git 状态、初始化、保存、历史和创建分支。普通查看配置不请求开发信息或执行构建。Node 与网页项目沿用相同入口含义，不把 Node 项目伪装成 `project-v1`。

外部目录登记沿用原源码作为权威仓库。第一次明确展开开发信息、且清单摘要仍匹配时保存原声明，之后作者可修改源清单；不能在原声明已经丢失时猜测旧配置。受管应用可明确绑定同应用标识的外部源码目录。安装代次、来源候选和平台控制目录不能充当可编辑源码。目录身份或应用标识改变时拒绝操作，不静默改绑。

构建要求应用已停止，在固定数据根 `node-development-builds/<任务>/` 创建新现场。构建使用“源码版本”核对的同一文件范围，排除未跟踪的忽略文件、Git、依赖、配置与运行数据；不会在作者仓库安装依赖或生成产物。npm 构建使用选定开发 Node/npm，私有 HOME、缓存与空 npm 配置，先 `npm ci --ignore-scripts`，再只运行清单显式脚本，跳过生命周期钩子。没有注入已保存的真实应用配置。工作目录隔离不等于操作系统权限沙箱，只运行用户信任的作者代码。

构建前后核对源码、Git HEAD 与目录身份。成功产物成为不可变来源候选，记录原源码摘要与 Git 提交；存在未提交修改时，提交号只标识基线，内容以构建源码摘要为准。构建成功尚未更新应用，仍须通过安装候选核验并明确应用。

旧外部登记可经这个显式更新流程转为受管程序，保留同一实例 UUID、数据、配置和窗口尺寸。提交点原子切换程序登记，并保留原登记与源码关联；不会移动或删除原仓库。2026-10-26 用户确认的新版添加流程允许外部应用直接把原文件夹交给 AI，先关闭应用再修改，随后明确重新打开；不强制先分离运行副本。用户主动“构建并更新”时仍可完成分离。源码取回继续要求已经分离并停止，不因 AI 交接放宽恢复门禁。

AI 入口只复制说明并打开已验证 Codex 的未发送草稿，不自动发送需求。说明指向作者源码，不指向安装目录。

## 明确取回本机源码

“源码版本”中展开“取回已保存源码”，输入版本记录中的完整40位本机提交号，先预览文件，再确认取回。仅支持已分离运行副本、应用停止且服务已收尾、源码与暂存区干净的实例。目标必须是当前本机仓库中的提交，且 `local-app.json` 与当前声明逐字节相同；不执行远程下载、分支切换或清单迁移。

取回只改变允许的源码文件，结果是当前分支上的未保存修改。HEAD、分支、暂存区、已安装程序代次、数据库、附件、配置和密钥保持；不会自动提交或构建。目标若含受保护文件、会覆盖本机忽略文件或目录、超过任一中间状态的文件／目录项／字节／深度限额，预览会拒绝整次操作。执行前后重新核对目录、仓库与文件身份；请先停止外部编辑器和 Git 写入。

源码取回复用原子文件交换底层，在作者原 `.git/local-projects-node-restores/` 中保留本次操作日志与交换文件，未创建第二个 Git 仓库。第一次改变源码前，固定 Node 实例槽先持久记录操作指针和计划／文件现场摘要。中断后重新展开即可只读核对，必须明确选择“继续本次取回”或“撤回本次取回”；重开界面、重连或重启不会自动重试。恢复操作本身再次中断仍保留现场。

未完成或无法核对的现场会阻止该实例后续构建、源码改绑、安装更新、删除和新 Git 写入；即使外部移走 `.git`，固定实例指针仍维持门禁。取回期间的实例租约还会阻止启动；停止运行始终可用。发现第三方源码、仓库、日志或文件身份变化时停止并保全，不猜测覆盖。成功或撤回后保留原仓库操作证据，只有本次日志确认为终态才解除门禁；不会替其他操作清理证据。日志容量在发布前预留，容量不足时不改变源码。

本小步仅在 macOS 提供并验证原子取回。入口使用原生管理窗口的既有开发操作协调；暂未向独立 CLI／HTTP 暴露 Node 取回写入。此操作不是完整应用降级或业务数据恢复；若要运行取回后的代码，作者仍须检查、保存并明确构建更新。

## 范围与保留

- Git 使用隔离环境、临时 index、原始对象与提交树、分支引用比较后提交，禁用仓库钩子和外部过滤器；保存前必须匹配刚读取的源码摘要和 HEAD。已跟踪受保护文件、嵌套或不支持的仓库形式会阻止保存。
- 本机保存不等于远端备份。当前不提供通用私有仓库认证或远程 push/pull；公开 GitHub/Gitee 源码下载沿用现有获取入口，可留空使用默认分支或明确指定分支；CLI 为 `source acquire --url <URL> --branch <分支>`。不会把一次下载或本机提交描述成已同步。
- 更新仍要求相同应用标识、相同配置声明，且双方都声明完全相同的数据契约标识与版本；缺声明或不一致时拒绝。显式来源构建在执行 npm 前先核对这一门禁，安装和提交时再次核对。不自动迁移业务数据库。Node 数据库、附件、密钥不能从源码 Git 恢复。
- 删除继续使用当前[永久删除契约](application-deletion.md)：仅删除用户明确确认的实例受管内容，不进入系统或平台回收站；外部作者仓库、来源候选和独立构建/安装证据保留。开发操作租约会阻止启动、更新、改绑与删除，停止运行仍可使用。构建失败、取消或退出保留现场；工作区迁移等待操作租约，退出等待所属进程收尾。

实际测试记录随本次验证更新；自动测试不代替真实设备、付费 AI/语音调用、Windows 或系统权限验收。


本轮仅移植 Node 开发、构建、版本与更新能力，以及完整依赖资源保留和显式构建授权；未引入其他分支的系统废纸篓路线或旧备份体系变更。实际检查结果在完成执行后记录，不把其他分支的 Radio 重装或原生界面证据当成本轮验收。
