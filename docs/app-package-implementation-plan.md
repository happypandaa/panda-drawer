## 1 范围与执行原则

本文静态 v1 目标流程：用户取得已经构建的包目录，选择根部有 `local-app.json` 的目录 → 检测并查看范围/问题 → 明确确认 → 复制到受管工作区并登记独立实例 → 主动打开使用。源码可以没有，静态安装不需要 Node，不执行包内安装/构建/SQL/迁移脚本；原包移动、删除或 GitHub 不可访问不影响已安装实例。

当前仍只支持平台完整 ZIP 导入，不能用现有导入入口承接本计划；没有新增可调用的安装 CLI/HTTP 路由。本计划不包含自动克隆 GitHub、源码构建安装、直接下载 URL 安装、ZIP 自动解包、市场、自动更新、独立后端、跨机同步或秘密 key 代理。

未来 Node 包的机器启动声明不得由用户/AI Markdown 中的命令推断，也不能透过 v1 的 `extensions` 偷渡执行语义。其完整运行依赖须作为归档产物保护；Node 自写数据的停写/退出核验、维护/恢复/迁移/回收门禁先于开放安装，校验与恢复过程不运行应用代码、不自动启动。应用自有数据的所有权仍是新方案草案，不改现有项目 SQLite/附件规则。

Node 配置验收须覆盖清单生成受控表单、每项中文名/用途/独立获取步骤/必填/示例/默认/格式错误影响，以及普通用户无需 `.env` 或终端的操作。普通配置私有归档并在原实例恢复快照值、分享默认去掉本机值、秘密 OS 存储且任何项目 ZIP 不带秘密值或可用绑定、原实例同机恢复不回滚 Key、新 ID 重配，以及公开迁移/回收/卸载的凭据保护，均按[配置候选契约](node-app-configuration.md)分别落实后再开放真实凭据；不以文案交付冒充这些实现通过。

执行时遵循：

- 检测先行，先验收纯静态最小闭环，再扩展有表结构/初始资料的应用，最后做手动更新。
- 新类型的维护、备份与恢复能力必须先于公开安装开放；不能用虚构源码、npm 工程或构建成功记录绕过现有检查。
- 原项目、源码、固定 SDK、数据库、附件、维护、备份、回收站和恢复证据按基线保留；不借新格式自动升级、重新登记或清理旧资料。
- 每一小步形成完整、可审查的变更，相关检查通过后 commit、push；依赖未定或并行改动未完成时不混进同一提交。应用、DMG、凭据及本地测试证据不进 Git。
- 运行实现需后续授权。本轮只交付计划与状态同步，不因列出任务而提前实现接口或改 Schema 的候选语义。

## 4 AP1：检测与安全暂存

“只读检测”指原包和既有项目不变；任务、日志、私有暂存和报告可以写入明确的平台所有范围，不能称为整个过程零写盘。检测不执行网页或包内代码。

| 小步 | 实现内容 | 相关验收 |
| --- | --- | --- |
| AP1.1 清单解析与兼容 | 严格 UTF-8/重复键检查、Schema 对应结构、版本/能力/运行需求语义，保留原始清单字节 | 缺清单、选错层、未知字段/格式/API、无效 origin/设备、非空能力无 API；同时保留有效扩展元数据；无 PWA 普通网页正常进入下一步 |
| AP1.2 范围与暂存 | 解析声明路径/重叠/名称、链接/挂载/特殊文件；复制到私有候选，形成有序文件清单和摘要，前后复核 | 越界、软/硬链接、大小写/Unicode/目标系统名称碰撞、源变化、磁盘不足；只复制声明内容，原包 SHA 不变，不触及其他目录 |
| AP1.3 网页与数据预检 | 用语法分析区分导航/资源/JSON 块/可执行内容，复用实际 MIME/文本大小/CSP 依据；核对两类Markdown文件、独立性、编码/字节/引用边界，首阶段拒绝未开放数据模式 | 缺 JS/CSS/图片、根路径、TSX/开发模块、base、注释假标签、多页面/片段导航；缺失/超限/非法说明不伪装完整；动态内容未验证，有限正则不等于完整检测 |
| AP1.4 报告与单次确认计划 | 输出 passed/blocked/incomplete、实际范围/体积、来源/网络设备、未验证项；绑定候选摘要、实例、工作区与策略 | 计划失效、重启/迁移、候选篡改/策略变化、检测取消/超预算；过期报告不能确认，报告不隐瞒未纳入文件，不因读取失败显示零或通过 |

AP1 退出条件：可以通过明确入口只做检测，得到可复核范围和错误；确认安装仍关闭。确认资格绑定最后校验的受管副本，不在确认时重新盲读原目录。临时残留清理仅处理本操作拥有、状态允许的范围；未知目录、已提交实例和恢复证据不得混作暂存删除。

## 5 AP2：先建立新类型的保护基础

此阶段相对复杂，不能把“没有源码”描述为旧开发项目损坏。当前项目清单要求源码/构建字段，维护结束和复制/恢复会计算源码输入摘要，归档验证要求源码与文档，来源记录只认识已有构建类型。以下兼容要先用隔离的合成实例测试，再开放真实安装入口。

| 小步 | 实现内容 | 相关验收 |
| --- | --- | --- |
| AP2.1 类型、来源与启动识别 | 按 AP0 定稿引入已安装类型；区分原包摘要、当前程序摘要和可变业务数据；启动扫描/空间/接管理解来源与映射，AI入口引用开发说明，构建按类型限制 | 没源码无需 Node，不伪造 build task/Node 版本/matched；说明不伪造可开发能力；旧项目README/skill/SDK保持，未知/部分提交类型保守阻断 |
| AP2.2 维护、完整备份与恢复 | 按安装程序/来源检查进入和结束维护；归档保存当前程序、资料、当前 DB/附件及可移植来源；恢复不依赖原包或源码 | 无源码基线、维护跨重启、缺原包恢复、损坏库原现场保全、WAL/SHM 与代次；不复验一次性 seed 路径、不初始化、不重置版本 |
| AP2.3 ZIP 交换与生命周期兼容 | 完整 ZIP 导出/导入保留当前程序/数据与类型；复制当前实例为新 ID；删除/恢复保留类型和当前数据；已开放迁移/清理认识其受保护资料与来源 | 业务主键/UUID/附件保持，导入/复制不播种；回收原 ID 恢复且维护不解除；统计不重计初始资料；未开放系统功能继续拒绝而非隐式执行 |

AP2 退出条件：新类型的基线/维护、备份恢复及当前平台已经开放的生命周期操作在隔离测试通过，旧项目回归通过；所有不支持的新类型操作显式拒绝。不能只让新类型“能打开”却沿用一条必然因缺源码失败的保护路径。安全文件、身份与崩溃恢复不因初期功能少而延期。

## 6 AP3：最小安装闭环

| 小步 | 实现内容 | 相关验收 |
| --- | --- | --- |
| AP3.1 持久安装事务 | 接受精确计划、预留新实例 ID，写操作日志，准备空库/附件与安装程序，校验后发布目录和登记；定义提交点 | 同一操作查询/重试不重复创建或初始化；目标冲突不覆盖；提交前失败不暴露可运行半成品；响应未知先查询，不自动重发 |
| AP3.2 接口与真实 GUI | 接入CLI/HTTP及管理安装流程；用户说明在预览/详情展示，开发资料独立入口，查看不执行内容；首次打开由用户主动触发 | 用户仅凭使用说明完成配置/首次操作；选目录不是安装确认，blocked/incomplete 不可确认；接受前取消不建实例/接受后关UI不撤销；版本/位置真实；“另装一份”新ID |
| AP3.3 真实运行与中断对账 | 最终内部包装入新建可丢弃实例，断开原包、无 Node、无互联网、本地服务重启；重复 AP2 的真实保护链路 | 桌面/指定浏览器读取同一实例；程序/资料独立保留；正常退出重启与故障注入分别记录；提交前后状态明确且不重复播种 |

AP3 交付门槛：AP1、AP2 和上述三步均通过，再开放“纯静态应用安装内部版”；原数据保护审计通过，安装类型可备份和恢复。真实系统/GUI未验证不能以单元测试或 HTML 打开代替。应用运行仍依赖平台本地服务开启；无互联网可用不等于平台关闭仍可访问 SQLite。

取消和关窗按操作边界处理：选择/检测或尚未接受安装时取消，不创建正式实例；任务一旦接受，关闭界面不等于撤销安装。若后续另定运行中取消，只能在协议允许的安全提交前停止，并通过原任务/操作 ID 核对结果。提交后不因“取消”回滚或删除已提交实例，不重复初始化；用户随后要删除时另走公开回收站流程。

| 小步 | 实现内容 | 相关验收 |
| --- | --- | --- |
| AP5.1 更新协议与预检 | 确认应用 ID、版本/数据版本、目标实例、元数据保留、维护基线和程序提交/恢复规则；显示新增网络设备需求 | 同版本不同摘要、降级、错 app.id/实例、数据版本不符、已有维护/未解决恢复现场；默认不覆盖名字/图标，不自动合并数据 |
| AP5.2 更新事务、GUI 与异常恢复 | 暂存新程序，完成更新前受保护完整快照，持久提交程序及声明，保留当前业务数据，按已确认方式结束维护 | 提交前失败仍旧程序；提交后响应丢失可对账；不播种/不执行迁移；旧页面代次失效且草稿提示；完整恢复回到同一时点并保留恢复前现场 |

初始候选是只允许相同数据格式版本更新，精确版本判断、维护结束交互和内部发布记录须先确认。实例已有维护改动时，不能用更早基线冒充本次更新前快照。种子属于新实例初始化，不成为更新覆盖数据的来源；不提供一键降级或自动数据库迁移。更新成功不能只证明“页面新了”，还要核对当前 DB、附件、显示元数据、维护、来源和发布代。

## 9 AP6：实机交接、交付与系统范围

| 小步 | 内容 | 通过条件 |
| --- | --- | --- |
| AP6.1 桌面与浏览器矩阵 | 对所交付 AP 功能验证真实 GUI、资源、路由、运行需求、退出重连和离线本地功能 | 各实际系统/浏览器版本单独记录；需要设备才测试授权/拒绝与释放，静态包不为验收主动要求设备；未覆盖项明确列出 |
| AP6.2 作者到接收者交接 | 干净包经手动下载解压在另一台支持电脑安装；用户按使用说明操作，另一个AI按技术说明理解架构/数据和实际开发边界 | 无Node/原路径/开发者AI可用；无源码不伪报构建；两份说明与真实版本一致；保存/重启/恢复可用，不借此实现自动下载/登录 |
| AP6.3 实际安装包与保护审计 | 构建对应系统的内部应用/安装包，核对版本、签名状态、CLI/资源/Schema说明、安装内容和摘要；复核既有资料 | Mac 交付 `.app` 与 DMG，Windows 在对应工作线就绪后交其安装包；最终包真实启动/退出/重启及旧数据核对通过，限制与文件摘要入记录 |

AP6 不自动完成 M6 正式发行：Developer ID/公证、Windows 签名安装及最低系统和外部用户等原门槛仍适用。文档中的分享流程未执行前不能写“已完成跨机器交接”。没有真实验证的包只叫候选，不以构建成功代替验收。

Mac 可沿现有内部运行线实施和验证。Windows 10 22H2 x64、Windows 11 x64 分别验收，不能由 Mac 通过推导可用。Windows 的运行时/安全文件/SQL/附件门禁及 W3 保护能力仍是前置；首次安装开放前至少满足对应 W3.1–W3.6 的备份、维护、恢复、ZIP、复制和回收保护依赖。不在 W2 精简新样本版提前接管安装应用；迁移及永久清理继续受 W3.7/W3.8 约束，安装功能不能绕过它们。具体系统支持范围沿用[Windows 工作线](windows-support-plan.md)。

## 10 PWA：已确认可选，不阻塞基础安装

普通网页包无需 Web App Manifest 或 Service Worker 即可满足格式准入。PWA 的完整兼容不是 AP0–AP6 的完成条件，也不因用户确认“可选增强”而已实现。

若以后单独授权标准 PWA 模式，另做三项后续工作：

1. 明确浏览器安装 manifest、稳定启动入口、动态端口、项目与发布代 scope/缓存归属，保留平台清单分工。
2. 设计缓存更新/退出/恢复策略：不缓存凭据及敏感管理/业务响应，不跨项目拦截/清缓存，不自动重放 SQL/上传，不用缓存成功冒充服务端已保存。
3. 分系统与浏览器实测安装、更新、旧页面、清缓存、平台退出及重启。缓存界面不代表平台关闭后还能读写本机数据库。

在上述能力验收前，包包含 PWA 文件不等于被平台保证兼容；明确冲突仍按正常检测说明，不给普通网页加 PWA 必填。具体取舍与架构依据见[格式 v1 的 PWA 小节](project-and-app-format-v1.md#74-是否要求-pwa当前不设必填兼容仍待评估)。

## 11 统一失败矩阵与原数据保护

每一步仅验证与该变更有关的风险，跨阶段最终联调再组合检查；不要求文案修改重复全部故障测试。相关记录至少覆盖以下边界：

| 边界 | 预期与证据 |
| --- | --- |
| 清单/范围/数据明确不兼容 | blocked，展示具体字段/路径/当前与要求；原包及原项目不变 |
| 检测读取/超预算/磁盘不足/取消/源变化 | incomplete 或明确检测任务失败，失去确认资格；接受安装前取消不创建实例，不把未知当兼容通过 |
| 已接受安装后关窗/请求取消 | 关窗不撤销原任务；若支持安全提交前取消则按协议对账；已提交实例保留，查询原结果，不删除或重新初始化 |
| 任务已接受但未发布 | 私有候选及预留可识别，正常列表无可运行半成品；按日志安全收尾 |
| 目录已发布、登记尚未完成 | 重启依据操作 ID、目标身份、摘要和提交记录核对，不另建第二实例 |
| 提交完成但响应丢失 | 查询原操作得到真实结果，保留已提交实例，不谎报全未变化、不重播初始化 |
| 维护/备份/恢复中断 | 原基线与完整原现场受保护；不静默解除维护、不删 WAL/SHM，不让旧页面继续写 |
| 包、旧项目或工作区真实身份不符 | 保守拒绝并保留资料；不新增空根、不通过更改设备号记录绕过、不手工改设置迁移 |
| 同包多实例及业务数据变更 | 平台 ID 独立，业务主键/UUID保留；复制/恢复/更新不重新初始化 |

实现前记录现有受保护范围的文件清单/内容摘要和业务记录，使用 `AP 可丢弃 · <阶段> · <日期>` 的样本；阶段验收后复核旧源码、SDK、数据库、附件、维护、备份、回收和恢复证据。设置/缓存/本轮任务等正常控制变化也需精确归属，不能无限泛化豁免。检测候选、样本及安装程序的数据不能混进旧项目基线。

真实验证区分单元/模拟、合成文件、真实 CLI/HTTP、GUI、正常应用重启、进程故障和系统重启。用故障注入不能声称硬件断电完成；普通浏览器通过不代替桌面，Mac 通过不代替 Windows。现有开发数据不用来验证安装或更新，不因原包来自开发项目而直接拿其工作库作种子。
