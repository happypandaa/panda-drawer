## 1 首版能力范围

| 能力 | 确定范围 | 不应混淆的边界 |
| --- | --- | --- |
| 外部 HTTPS 数据请求 | 声明用途及目标 origin 后，由浏览器直接请求 | 对方必须满足 CORS，平台不自动绕过 |
| 外部图片与音视频 | 分别声明来源，可选使用 | 离线时不可用；需要长期保存时应明确导入附件 |
| 文件选择、拖入 | 用户选择后上传到本项目附件目录 | 不是任意系统目录读写权限 |
| 下载与另存文件 | 浏览器标准下载，桌面适配其下载交互 | 不依赖仅部分浏览器支持的文件选择 API |
| 音视频播放 | 支持实际环境可解码的格式 | 处理用户手势与自动播放限制 |
| 麦克风录音 | 首版支持，用户点击、授权、前台短录音、保存到本地 | 不自动提供转写、评分或离线语音识别 |
| 摄像头拍照 | 首版支持的可选项目能力，按需声明、请求并保存图片 | 不默认开启，不包含屏幕或系统声音录制 |
| 剪贴板 | 用户点击复制；粘贴优先浏览器 paste 事件 | 不承诺静默读取或持续监听 |
| 屏幕录制、系统声音、后台持续录音 | 后置 | 与麦克风录音是不同产品范围 |
| 浏览器语音识别 | 不作为首版稳定依赖 | 是否支持、是否联网及结果都不能用录音支持推导 |

这是首版开发范围，只有 macOS 15 最低版本、签名后的 Tauri 应用及选定普通浏览器分别验收通过后，才列入对用户发布的正式支持矩阵。普通浏览器首版验收 Safari 与 Chrome；不据 Web API 名称宣称所有浏览器版本都可用，准确版本与兼容性结果在发行测试中记录。

## 2 联网策略与声明

### 2.1 平台仍是本地服务

服务继续只监听 `127.0.0.1`。网页访问本地数据库与附件不需要互联网。运行时对外请求、npm 构建下载和平台检查更新是三种不同来源，项目的联网声明仅管理网页运行时需求，不冒充整个电脑的网络隔离。

默认模板把脚本、样式、字体和基础素材打进本地产物。外部脚本、远程模块、任意 iframe 暂不作为首版默认能力；第三方库通过构建依赖提供。公开接口调用失败时，项目应显示错误并保留已存数据，不阻塞无关本地功能，也不自动重放可能产生费用或写入的请求。

### 2.2 可选清单扩展

`project.json` 提供可选 `runtimeRequirements`，与平台实际提供的 `context.get().capabilities` 分开：前者是项目声明，后者是平台支持的接口能力，不是操作系统已授权证明。

以下为已确定的声明格式示例，不要求每个项目都声明这些能力：

```json
{
  "runtimeRequirements": {
    "network": {
      "connect": [
        {
          "origin": "https://api.example.com",
          "purpose": "查询公开词典",
          "dataSent": "用户提交查询的单词"
        }
      ],
      "images": [],
      "media": []
    },
    "devices": {
      "microphone": { "purpose": "录制孩子的跟读练习，仅保存在本地" },
      "camera": { "purpose": "拍摄练习照片，仅保存在本地" }
    }
  }
}
```

`runtimeRequirements`、其 `network`／`devices` 分组以及各能力成员均可省略。未声明网络分组或某个网络数组时，该项按空列表处理；本地平台请求和本地附件访问不需要列入外网来源。未声明 `microphone` 或 `camera` 表示项目没有声明相应设备需求；声明时提供非空 `purpose`，不使用布尔值表达系统已授权。`camera` 只用于本节范围内的拍照，不扩展为录像或屏幕捕获。默认本地模板可省略整个字段或保留空声明，录音／拍照模板再按用途添加成员。

`connect`、`images`、`media` 的每个网络条目统一包含 `origin`、`purpose` 和 `dataSent`，使用精确的 HTTPS origin，不含路径、用户名、密码、令牌或通配 `*`。每项写清用途和会发出的数据；公开资源请求也会向目标服务发送资源地址及常规请求信息，不能笼统写成“完全不发送数据”。若允许重定向，最终目标也必须符合策略。直接访问其他本机服务、局域网地址和明文 HTTP 不在默认首版范围。常规外部链接由明确用户点击打开；项目 WebView 不直接导航成外部网站并继续携带宿主权限。

声明是可移植配置，可随归档保存；不存授予状态或密钥。没有此字段时按只使用本地平台、未声明设备需求处理。首个模板需包含约定；以后不得给已经发布的 API v1 项目悄悄增加必填字段，变更遵守已有兼容政策。平台详情页显示“需要网络／麦克风”等说明和实际支持情况。

### 2.3 CSP、CORS 与权限不是一回事

本地 HTTP 服务统一给项目 HTML 返回 CSP：本地脚本与基础资源优先，`connect-src`、`img-src`、`media-src` 分别根据声明放行，录音预览需要的 `blob:` 等按实际用途配置。不能只写 `connect-src` 就声称已经控制所有对外资源；也不使用 `connect-src *` 解决调试问题。参见 [CSP connect-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src)。

CSP 允许请求，不代表目标服务允许网页读取响应。服务方仍需配置合适 CORS；不能把开放本地管理接口的 CORS 或向项目授予 Tauri HTTP 插件作为绕过方式。桌面和普通浏览器走相同 HTTP 服务策略。参见 [CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)。

网络和设备声明变更后提示重新加载，新的文档收到新策略；第一版不承诺可以瞬间撤销任意旧页面已发出的网络请求或已经获得的浏览器设备访问。必要时关闭项目页面或到系统设置撤销设备权限。

桌面已确定为管理窗口与独立项目 `WebviewWindow`，项目是顶层页面；同项目重复打开只聚焦，不重新加载。原生权限只给受信任的管理窗口，项目仍走 HTTP 与普通浏览器能力；外链和弹窗由宿主按主约定处理，不导航外部页面后继续携带宿主管理能力。

已有架构中各项目位于同一 origin 的不同路径。Cookie 路径、项目开关和 CSP 都不把恶意项目变成彼此隔离的应用；浏览器权限通常也不按 `/p/<id>/` 分开。端口改变会改变 origin，可能触发重新授权。平台应显示“项目声明需要什么”和“当前运行环境是否允许”，不伪造逐项目系统授权状态。参见 [同源定义](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)。

## 3 API 密钥：首版后置已确认

### 3.1 已确定的首版范围

第一版支持公开 API，带保密 API key 的调用后置。服务方明确设计为可公开的 publishable key 属于公开标识，不是平台替用户保管的秘密凭据；仍须遵守服务方的浏览器调用规则。公开接口也可能有配额和费用，项目文档写明服务依赖和失败处理。

需要保密的长期密钥不能写入项目源码、`project.json`、README、SQLite、浏览器存储或进入前端构建的环境变量。特别是 `VITE_*` 会被打包进客户端产物；单纯放进 `.env` 不会让前端调用具备保密能力。参见 [Vite 环境变量说明](https://vite.dev/guide/env-and-mode)。

平台备份不会自动识别和抹除 AI 私自写入任意文件的密钥。必须从保存位置上避免进入项目持久内容，不能用“导出时自动脱敏”的承诺补救任意嵌入。

已确认的本地录音、回放和历史保存能力不依赖密钥连接器；需要保密密钥的在线转写或发音评分不由首版平台提供。外部编码 AI 是否在线与项目自己调用云 API 是两回事。

### 3.2 后续连接器参考，不属于首版

若后续明确增加带密钥调用，建议只增加少量平台维护的 Rust 连接器，按明确供应商和操作开放，例如一个指定服务的转写功能。以下不是已批准的交付要求，流程参考为：

```text
项目网页 → SDK 中的连接器操作 → 本地 Rust 服务
                                    ↓
                             本机钥匙串读取凭据
                                    ↓
                             固定供应商 HTTPS API
```

用户在平台设置中输入密钥，Rust 使用 macOS Keychain 保存；项目只持有逻辑连接名称与用途，不获得读取明文密钥的 SDK 或 CLI。Keychain 用于保存密码和密钥，参见 [Apple Keychain Services](https://developer.apple.com/documentation/security/keychain-services)。

连接器必须限定供应商、HTTPS 目的地、方法、操作、可接受参数和附件范围；不能让项目任意传入 URL、Authorization 或重定向目标。密钥由服务端按固定规则附加，不发给网页。输入输出限制、取消、超时、供应商错误脱敏、流式响应和费用提示由平台负责。超时不代表服务方没有处理或计费，不能无条件自动重试。

对用户照片或录音的上传必须由具体功能触发，界面说明接收服务及用途；保存录音到本机不隐含上传授权。后续启用这一扩展时，先确定一个实际服务和一项操作，再设计精确接口，不先交付“任意 API 代理”。

凭据与本机绑定在工作区外管理，不随项目归档传播。导入重新绑定；复制生成的新项目默认没有密钥绑定；同机迁移可保留原绑定；回收站中的项目停用调用能力，恢复时重新核对绑定，永久清除不删除其他项目共享使用的凭据。项目恢复旧备份不会回退系统钥匙串。具体绑定存储和生命周期是启用该分支前必须补齐的协议。

这主要减少密钥随源码、网页、归档和日志传播，不声称对同一操作系统用户或获授权的本地编码 AI 形成绝对隔离。同源项目也不是恶意代码隔离边界；未来若运行不可信应用，需要另行更改 origin 与权限架构。

## 4 录音、拍照与持久保存

### 4.1 环境与授权

使用浏览器的 `getUserMedia` 和 `MediaRecorder`。`http://127.0.0.1` 可作为受信任本地来源使用需要安全上下文的 API，不必仅为录音要求用户安装自签 HTTPS 证书；仍要实际检查 `isSecureContext`、API、设备及授权结果。参见 [Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)。

桌面侧配置麦克风／摄像头用途说明，并核对签名与 Hardened Runtime 的设备 entitlement。网页授权和 macOS 对宿主的授权分别处理；普通浏览器使用它自己的系统授权，不能因为桌面允许就认为浏览器也允许。参见 [Tauri macOS 配置](https://v2.tauri.app/distribute/macos-application-bundle/)与 [Apple Audio Input Entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input)。

首次使用由用户点击触发，不在打开项目时弹一串权限申请。支持“拒绝”“设备不存在”“被占用”“宿主未授权”和“不支持”的可理解提示。标准录音组件及 AI 编写的页面应显示录制状态与停止按钮，并在可检测到页面退出、项目切换、进入维护或连接中断时停止录制、释放设备，明确提示未保存内容；不能承诺退出或崩溃后恢复。

独立窗口之间的失焦不自动等同于页面关闭或项目切换。标准组件在页面变为不可见、明确离开录制流程或收到上述停用状态时停止；关闭项目窗口销毁该页面并释放其设备，关闭管理窗口不结束其他仍打开项目的页面。明确退出平台关闭所有桌面项目窗口；普通浏览器仍由项目协作处理断线与设备释放。

这些停止行为是标准组件和项目的实现要求，平台不能在普通浏览器里强制停止任意项目自行调用的 `getUserMedia`。平台服务端可以保证维护中或旧文档代次的请求不能继续持久化；服务断开时写入不能当作成功。页面状态通知不替代这一写入检查。

### 4.2 格式与保存流程

不统一假设 `.webm`。运行时通过 `MediaRecorder.isTypeSupported()` 选择可用 MIME，并保存实际类型、扩展名、时长及大小；有能力探测仍需处理实际录制失败。WebKit 在 Safari 18.4 才增加部分 WebM 录制支持，不能据此覆盖最低 macOS 15.0 环境。参见 [MediaRecorder 格式探测](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)及 [WebKit 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)。

标准流程：录制 → 本地预听 → 用户选择保存 → `files.put()` 写入 `data/attachments/` → SQL 保存业务记录与附件逻辑路径。文件保存与 SQL 不是同一事务，项目处理失败重试和残留；两步成功后才显示完整业务记录“已保存”。不把临时 `blob:` URL 写入数据库当永久资源，也不把录音转成 Base64 长期塞进源码。

文件上传沿用主约定的暂存后发布规则：超限或明确失败不能破坏同路径原文件，未完成上传不展示成正式素材；结果未知时先检查，不盲目重放上传或 SQL。记录完成前仍按未完整保存处理。

首版限定为可配置上限的短录音；平台文件接口返回允许的大小，项目在录制前显示时长限制并在接近限制时停止。不要假设所有数据可无限积存在浏览器内存。长时、分片断点录制和转码后置；没有对应编码器时给明确格式提示，不暗中加入 FFmpeg 依赖。默认时长和文件大小的具体数值在资源限制方案中确定，不能将尚未确定数值理解为无限制。

拍照由明确点击触发摄像头预览，用户拍摄后可预览、重拍或保存；不自动连拍或保存所有视频帧。保存实际图片 MIME、大小及附件逻辑路径，业务关联仍由项目数据库维护。关闭拍照流程、切换项目或进入维护时按与录音相同的规则释放设备。设备不可用时仍可通过标准文件选择上传已有照片，不要求每个项目都启用摄像头。

照片与文档同样写入附件目录，项目数据库保存标题、所属活动或练习、时间和逻辑路径。空间页可按真实文件分类统计，但业务用途由项目说明维护。

## 5 文件、剪贴板与预览

上传以 `<input type="file">` 和拖放为基础，保存到平台后成为独立副本，原文件移动不会让项目失效。下载使用标准浏览器下载并验证 WKWebView 的保存交互；`showSaveFilePicker` 不作为跨环境必需依赖，参见 [兼容性说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)。

复制通过用户手势触发标准 Clipboard API，失败提供可选中文本；粘贴优先用户的粘贴动作。不能把 Chromium 的剪贴板权限查询模型照搬到 Safari，也不提供原生全局剪贴板监听。参见 [Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)。

通用附件预览优先支持常见图片、音频和视频；文档至少提供下载。HTML、脚本或不能安全隔离的格式不作为平台管理页直接执行。格式可预览与可以存储分开：无法预览的文档仍可完整保存并导出。

## 6 平台与 AI 分工及文档要求

平台提供环境适配、声明展示、HTTP 策略、文件持久化与状态错误；AI 编写录制按钮、业务流程、离线提示和记录关联。标准模板可提供录音辅助组件，建议使用而不强制项目 UI。普通网页继续不依赖 Tauri 专属插件。

每个项目的 README 应说明：需要联网的功能、目标服务和发送内容、离线仍可用的功能、设备用途、实际文件格式、附件保存与业务删除规则；不使用的能力明确写“无”。模板提供这些栏目，AI 按项目实际情况填写，并保持其内容与 `runtimeRequirements` 一致；不能把真实密钥写入示例。

本地短录音、拍照、文件与剪贴板、联网声明与 CSP 策略均已确定；带保密密钥的调用继续后置。准确的资源上限和浏览器版本验收记录仍需在相应方案与发行测试中补齐，不能因此把已确认的能力范围重新列为待选项。本文是开发契约，不是已有功能清单。


## 7 M5 实现与验收边界

模板自 `react-ts-vite-0.1.2` 提供独立 `app/src/lib/browser-tools.js` 和可选素材示例，当前模板为 `react-ts-vite-0.1.4`，固定 SDK 0.1.0 未改变。设备默认未声明，只有配置用途并由用户操作后才请求；正常运行模式为 `normal`。维护、忙碌、迁移、失效、离线、隐藏或离开会释放标准助手持有的设备，晚到权限结果也会释放。当前 60 秒、10 MiB 与服务上传上限取小值是内部测试保护，不是正式限额。明确保存示例才先写附件、后执行 SQL；附件已存而 SQL 失败会保留路径并提示，不自动重放。

macOS 包包含相机、麦克风用途说明与 hardened runtime 的 camera/audio-input 权利。宿主按本项目声明及就绪状态处理新权限请求；已有许可可能跳过回调，自行编写的项目代码也不受标准助手完全控制。运行声明变化提示明确重载，不自动丢弃草稿或承诺即时撤销全部旧授权。

桌面下载进入私有暂存，经非阻塞原生保存框选择位置后安全发布；不自动保存至 Downloads。完成文件内部上限为 256 MiB，未声称下载网络中途已限流。保存保护固定数据根、当前与已登记保留工作区及应用包，校验文件与父目录身份。外链当前由宿主原生确认后交默认浏览器，源页面不外部导航；程序请求也可能触发确认，尚无证明请求来自可信鼠标点击的原生桥接。

当前 18 项媒体助手模拟检查及 16 项组件回归通过，不能代替真实录音、拍照、拒绝权限、系统弹窗、Safari/Chrome 和 WKWebView 的设备验收。上述实测记录单独列明实际通过及未完成项；已有工具 URL 访问限制未被其他 UI 工具绕过，正式支持矩阵与最低系统实机仍待实际检查。
