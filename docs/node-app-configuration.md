## 1 用户看到“应用配置”

环境变量是应用启动时读取的一组设置。对用户而言，配置页只需说明“这个应用要连接哪个服务、使用哪个账号凭据和模型”；不用安装 Node、打开终端或编辑 `.env`。

建议入口为应用详情的“配置”。页面先显示中文名称、用途、必填标记、输入框和获取步骤；变量名放在折叠的技术信息中，供 AI 和开发者核对。

| 用户看到的字段示例 | 用途 | 获取说明应达到的程度 |
| --- | --- | --- |
| AI 服务地址 | 告诉应用向哪家服务发送 AI 请求 | 说明这是 API 基础地址，并非官网首页；作者写出所支持服务的文档/控制台位置、是否包含 `/v1`、应用如何拼接路径 |
| AI 访问密钥 | 让该服务识别用户的调用身份 | 作者写明账号准备、控制台入口、创建密钥、复制和粘贴步骤；说明是否需要开通 API 或额度，不能拿聊天网站登录密码代替 |
| AI 模型 | 指定该服务实际可用的模型 | 作者写明到哪里查模型 ID、填写 ID 而非宣传名称；平台不猜测服务商或自动选择可能产生费用的模型 |

用户流程建议为：打开配置 → 按字段旁的步骤取得地址/密钥 → 填写并保存 → 查看缺失或格式提示 → 打开应用，由平台后台启动并显示原生窗口。运行中修改则提示“已保存，下次启动生效”，提供明确的“重启并应用”；保存本身不重启、不发外部请求。

## 2 声明与实际值分开

应用作者在版本化的 `local-app.json` 中声明需要哪些配置，平台据此生成表单；用户填入的值由平台管理，不能写回作者清单或源目录。受管项目保留所用声明版本、来源和配置修订，具体内部格式在 NR0 冻结。

清单声明可以随应用分享。用户的 API Key、密码、令牌和音乐 Cookie 不是清单内容；普通地址、模型等用户值也不能自动变成所有接收者的默认配置。首期按应用实例独立配置，不自动共享账号或从用户电脑的现有环境、`.env` 和其他应用查找秘密值。

## 3 每个变量必须讲清楚

| 候选字段 | 规则 |
| --- | --- |
| `name` | 必填，实际注入的环境变量名；建议限制为 `[A-Z][A-Z0-9_]*`，跨系统大小写折叠后唯一 |
| `label` | 必填，普通用户能理解的中文名称，不能只重复技术变量名 |
| `type` | 必填，首期建议受控的 `string / url / integer / boolean / select`；不执行作者提供的校验脚本 |
| `required` | 必填，是否启动前必须具备有效值；可选字段说明不填写会影响什么 |
| `secret` | 必填，是否为秘密凭据；首期秘密字段限字符串，平台用密码输入，不读回保存值 |
| `description` | 必填，具体用途、向哪个服务提供什么内容、填写影响；不能只写“用于 AI” |
| `howToGet` | 必填，非空步骤数组；写到用户能够照做，或明确这是自行选择的配置、怎样选择。不能只有一个链接或“找管理员” |
| `placeholder` | 可选，非秘密字段可给虚构格式示例，秘密字段只给输入提示，不能带可用凭据 |
| `default` | 可选，仅允许非秘密值且符合类型；界面明确显示默认值。秘密字段禁止默认值 |
| `options` | 仅 `select` 使用，声明唯一值及易懂标签；不从远程动态执行代码生成 |
| `helpUrl` | 可选，准确的官方 HTTPS 帮助入口，用户主动打开；正文仍须有完整步骤 |
| `endpointField` | 秘密字段可引用同一声明中的 `url` 字段，表示凭据对应的服务地址；引用必须有效，平台据此提示地址变更后的重新确认 |

具体字段与表单预算在 NR0 定稿。检查包括声明版本、未知字段、重复名称、引用类型、默认值和选项一致性、说明是否存在及可读。结构检查只能发现说明缺失，不能证明获取步骤准确；NR7 需由未接触过项目的使用者照着完成一次配置。

平台保留系统/运行控制变量，不允许作者覆盖 `APP_*`、平台内部名称、`PATH`、`HOME`、`USERPROFILE`、临时目录、`NODE_OPTIONS`、`NODE_PATH`、动态加载相关变量等；完整保留表要在实现前固定并跨系统验证。不能通过变量注入 Node flags、加载器或平台管理凭据。秘密字段不得使用 `VITE_*` 等进入前端构建的方式。

字符串按字面值传递，不执行 shell，不展开 `$HOME`、变量引用、反引号或模板表达式。拒绝 NUL 及超限内容；密钥格式不擅自限定为 `sk-` 前缀，不静默截断、改写或“修正”秘密值。布尔和整数转换成稳定的环境字符串，保留显式 `false` 和 `0`。首期不支持注入显式空字符串；普通字段清空视为未设置，秘密空输入则保持原绑定，两者不能混用。

有效值的候选解析顺序固定如下；先解析，再检查类型和必填性，最后生成运行快照：

| 用户保存状态 | 有效值与启动规则 |
| --- | --- |
| 普通字段已填写 | 使用用户值并校验类型；`false`、`0` 不是缺失，非法值不保存 |
| 普通字段未设置或清空 | 有合法 `default` 就使用并注入默认值；否则必填项缺失、可选项不注入 |
| 只有空白的字符串输入 | 普通字段视为未设置；秘密字段拒绝纯空白替换，不自动裁剪其他秘密输入 |
| 秘密输入留空并选择保持 | 保留现有有效绑定；没有绑定则按未设置处理，秘密不存在默认值 |
| 明确移除秘密配置 | 解除本实例该字段的本机文件绑定；必填项变为缺失，可选项不注入；不清理旧系统条目或无关恢复现场 |
| `null` 或与类型不符的提交 | 非法提交，不当作保持、删除或默认值操作 |

必填项存在合法默认值可通过本地完整性检查；可选字段也会注入生效的默认值。默认值变化随声明更新作为有效配置变化处理，不能绕过修订和生效检查。缺必填可保存为未完成配置，但不得启动；这与非法类型拒绝保存分别报告。

URL 默认只接受 HTTPS，拒绝用户名/密码、查询串和片段中的凭据；是否允许明确回环 HTTP 以支持本机 AI，在字段能力和 NR0 中单列，不能悄悄放开任意明文 HTTP。地址末尾斜杠、路径和 API 版本由应用声明与实际代码一致处理，平台不擅自补 `/v1` 或替换域名。

## 4 配置状态、保存与生效

配置完整性和运行修订差异分开记录，且都独立于后端进程与健康状态：完整性候选为 `needs-configuration / configured`（需要配置／配置完整）；有旧实例运行且保存版本不同时，另显示 `pending-restart`（待重启）。没有运行实例时提示下次启动使用已保存配置。“配置完整”仅表示必填项和本地格式通过，不代表密钥有效、账号有余额或上游服务可达。

例如运行中移除必填 Key 后，可同时显示“需要配置，旧配置仍在运行”；不能因后端还在运行而标为配置完整，也不能重启到缺失值。已保存版本完整时才提供“重启并应用”，否则先引导补齐配置。

- 打开配置页只读声明、普通配置和秘密的“已设置/未设置”状态，不运行应用代码、不查询上游，也不自动填入别的应用的值。
- 配置草稿只在受信管理页中编辑，不能写浏览器持久存储。取消离开不保存；已修改未保存时提示，保存后清空秘密输入，普通读取不返回秘密明文。
- 秘密字段明确区分“保持原值、替换、移除本应用配置”。留空不能意外删除既有密钥；移除只解除该字段的本机文件绑定，保留必要中断／恢复证据，不读删旧系统凭据。提示哪些功能或下次启动会缺少配置；本机秘密文件的永久回收另定。
- 保存校验失败保持草稿并指出中文字段和可修正原因，错误不回显秘密。缺少必填项时允许作为未完成配置保存，但不得报告“已配置成功”或启动后端；普通可选项不能阻断无关功能。
- 保存使用配置修订检查防止两个窗口互相覆盖。成功表示普通值和秘密文件绑定已一致提交；部分写入失败不能半保存。秘密文件与普通配置的提交／中断恢复必须一起验证。
- 启动时核对当前声明和已保存修订，解析所需秘密，取一致快照后创建子进程；缺失、私有文件不可读、权限／归属不符或声明不兼容时，给出“去配置”入口，不用空值启动碰运气。
- 运行中保存新值不自动重启或热更新；显示已保存版本和运行中版本不同，由用户明确“重启并应用”。停止失败就保留异常/待重启，不启动第二实例，不承诺配置已生效。

修改与密钥关联的服务地址，必须提醒密钥将交给哪个目标，并重新确认/配置该地址的凭据；不能无提示把原密钥带到新目标。具体绑定按规范化地址还是更细范围判断，在 NR0 冻结。修改模型无需猜测或自动更换密钥。

备份/导出/复制等管理操作临时停服务后，只有保存修订与原运行快照一致、原凭据绑定仍有效且门禁允许时，才可恢复原服务。停机前已待重启、绑定有变化或无法安全复现同一快照时，保持停止并提示用户明确启动；不能借管理操作自动应用用户尚未确认生效的新值。

本机移除/替换凭据不等于在服务商撤销旧密钥；已经运行的 Node 仍可能持有旧环境值，直到确认停机。界面须说明当前与下次启动的差异，不能显示“已撤销远端密钥”。

## 5 秘密保存与进程注入

用户最新明确选择本机文件：秘密放在固定数据根下每个应用自己的 `node-apps/<实例ID>/configuration/credentials/`，目录权限 `0700`、秘密文件权限 `0600`；普通配置只保存修订和本槽秘密文件绑定。该槽不是作者源码目录、分享包或 Git，旧 project-v1 的格式和数据范围不变。这是以当前系统用户文件权限保护的明文存储，不是系统加密凭据库；同一用户权限的程序仍可能读取。私有文件不可用或权限／归属不符合要求时明确失败，不改存源码、SQLite、`.env`、浏览器或其他兜底路径。

此前建议使用 Keychain／系统凭据库的段落属于已被本次选择覆盖的历史方案，不作为当前 Node 槽的执行要求。不读、不迁移、不删除旧 Keychain 条目，不根据旧绑定自动取出秘密；需要用户在当前配置入口重新填写。Windows 文件权限与实际存储另按该平台工作线验收，不能以 POSIX 权限测试宣布 Windows 已支持。

用户在平台管理配置页输入时，该受信页面会短暂持有秘密明文并提交给 Rust；保存后只返回“已设置”状态，不提供读取保存明文的常规接口。应用业务网页、项目 SDK、日志、诊断复制、AI 接手说明和归档均不应获得秘密。平台内部控制令牌不属于用户配置，不能拿来代替或混入 API Key。

启动时 Rust 把当前应用声明且已校验的业务值注入**目标 Node 子进程创建时的环境**。不改系统环境、平台进程全局环境或其他应用环境；不通过命令行传秘密，不生成临时 `.env`，不执行 `npm` 或构建脚本。系统必要环境、平台保留变量与业务变量分开校验后合并，禁止覆盖。

Node 必须能读取注入的秘密才能调用服务。这能减少意外传播，不能向用户宣称应用自己读不到 Key、Node 被沙箱隔离，或对同一用户权限的本机程序/调试器绝对保密。受信应用不得打印环境、将 Key 返回网页或把 Key 写进业务库；其普通后代进程可能继承环境，应用不得把无关凭据传给额外子任务。

平台禁止记录完整创建环境、请求认证头或秘密值；诊断以变量名、状态和修订号为主。对已知值的日志脱敏仅是额外防线，不能保证抹除恶意代码变形输出或任意业务文件中的秘密。若第三方 SDK 自行持久化 Cookie 或凭据，必须在开放账号前适配独立秘密存储，不能仅靠导出时搜索/擦除补救。

## 6 备份、复制、恢复和更新

以下为新 Node 类型的建议生命周期，不重解释既有项目或修改已有归档；具体绑定与完整性校验在 NR0.2 冻结。

| 场景 | 普通配置 | 秘密值与有效绑定 |
| --- | --- | --- |
| 完整私有备份/原实例恢复 | 未来归档显式包含普通配置修订与声明；恢复按快照校验，可能重新提示配置 | 项目 ZIP 不含秘密值或可复用绑定；原实例同机恢复保留当前本机绑定，不回滚为旧 Key，并重新核对字段/目标是否仍匹配 |
| 分享应用包 | 携带声明、公开默认值及说明，不携带作者或用户的实际配置 | 不携带 |
| 完整 ZIP 导出/导入 | 普通配置可能随完整项目归档，导出明确显示包含本机配置；新实例按支持格式校验 | 不携带秘密值/有效绑定；导入实例重新填写，不从包内接受秘密引用 |
| 创建副本 | 普通配置可复制并提示核对服务地址 | 新应用身份不继承绑定，重新填写 |
| 同机工作区迁移 | 随受管数据迁移 | 仅走公开迁移流程，核对同一本机应用身份后保持本机绑定，不把秘密写入新旧工作区 |
| 回收站与卸载/重装 | 保留现有保护与恢复规则 | 移入回收站禁止运行；不借此自动清理凭据。恢复/重装重新核对身份及可用性，找不到绑定时重新填写 |
| 仅程序更新/切换声明，未做完整数据恢复 | 对新增必填项、改名、类型和默认变化做差异校验，不静默覆盖用户值；完整数据恢复仍按首行恢复普通配置快照后重验 | 不自动将秘密降为普通字段、不按新变量名猜测复用；服务目标或字段含义变化需用户重新确认 |

完整备份可能含业务隐私，“不包含 Key”不能描述为可公开分享。跨机导入、凭据丢失或本机秘密文件不可用时，给出重新配置指引；不承诺仅靠项目 ZIP 恢复账号。当前独立 Node 槽不在 project-v1 备份／导出中，未来新类型不能把 `configuration/credentials/` 一起打入分享或 Git。

保存配置、修改绑定和生命周期操作必须与项目/工作区门禁协调。维护、恢复、删除或迁移冻结期间，不允许旁路修改配置或改变即将使用的修订；恢复核对发现声明/地址与当前凭据不匹配时，保留现场、标记需配置，不自动启动。永久删除凭据的范围和共享引用检查另定，不把现有清理授权扩大到系统凭据。

## 7 校验与故障说明

首期“保存检查”仅做本地声明、类型、必填和存储校验，不能为了检查 Key 自动请求服务商。在线“测试连接”若后续提供，须由用户主动操作，说明目标、发送内容和是否可能计费；其最小请求、取消、超时和脱敏规则需单独定义，不执行清单中的任意测试代码，也不自动重试结果未知的付费请求。

| 情况 | 给用户的目标提示 |
| --- | --- |
| 未填地址或密钥 | “还需要填写 AI 服务地址／AI 访问密钥”，附字段获取步骤 |
| 地址格式不符 | “请填写此服务的 API 基础地址”，展示虚构正确格式，不回显带秘密的错误 URL |
| 本机秘密文件不可用或权限不符 | “暂时无法保存或读取密钥”，提示检查本应用私有目录与重新配置，不弹钥匙串授权，也不谎报服务商已拒绝密钥 |
| 服务商拒绝认证 | “服务未接受此密钥，请核对服务地址与账号凭据”，不直接断言欠费 |
| 模型不存在或无权限 | 核对模型 ID、账号可用范围，显示经脱敏的实际类别 |
| 上游超时或断网 | “目前无法连接服务”，保留配置；不据此把 Node 标成已停止 |
| 修改后仍在运行旧配置 | “新配置已保存，重启应用后生效”，显示可控的重启入口 |
