# 应用窗口与受管后端运行约束

状态：2026-10-20 用户明确确认的产品约束。适用于平台中的应用运行体验；实现和实际验收以当前交付记录为准。此前浏览器试跑记录保留为验证证据，不作为标准应用的默认打开方式。

## 统一项目入口与详情

网页类型和 Node 类型统一显示在 **我的项目** 列表，以独立的类型图标与中文文字区分；项目自己的图标继续保留。用户都从项目卡片进入，配置完整后在唯一原生应用窗口运行，不要求先找另一个“Node 应用”管理页。

- 卡片保留名称、图标、类型和必要状态；项目概览、配置、使用说明、获取方法及其他详细信息收在管理页面内的详情弹窗，不展开成另一整页或新的原生窗口。
- 详情使用带 tabs 的页面内 modal，沿用静态项目已有的详情分组和操作习惯。Node 所需配置在同一弹窗中呈现；尚未支持的备份、迁移等能力明确说明，不伪造为可用的静态项目功能。
- 必填配置不足时，“进入／打开应用”入口仍可点击，先打开详情弹窗的配置 tab，标明缺少的字段与获取步骤；不能只禁用按钮，让用户无法补配置。
- 保存只提交配置，不自动启动后端、自动打开应用或重启。保存后由用户明确打开；已有实例则按明确重启流程应用新快照。
- 这些是最新确认的交互要求，新增统一列表、tabs 和缺配置引导的实际验收需另记；不能用此前独立 Node 页的实测代替。

统一列表是展示与入口统一。Node 身份和存储仍为独立的本机源码槽，不移动目录，不合并或转换 project-v1，不借此获得其完整安装、备份、导出、回收或迁移能力。

## 1 一个应用，一个原生窗口

应用从平台打开，在平台提供的独立原生窗口内运行。网页是窗口承载的界面，本机 HTTP 地址只是内部传输，不要求用户另外打开浏览器或终端。

- 同一个应用实例最多有一个应用窗口。再次点击打开只显示并聚焦原窗口，保留页面与未保存内容，不新建窗口、不自动重载。
- 正在启动时再次打开，复用同一次启动和窗口准备，不再创建 Node 进程或第二个窗口。
- 应用不得通过 `window.open`、`target="_blank"`、弹出式网页、其他 WebView 或外部浏览器扩展自己的运行窗口。宿主必须拒绝新窗口请求，不能只依赖作者自觉。
- 业务表单、帮助和确认内容放在当前窗口内。不要用脚本 `alert`、`confirm`、`prompt` 作为业务弹窗或阻塞宿主流程。
- 文件选择、保存位置及系统权限提示继续服从平台已有的受控能力、用户操作和实际授权；这不授权业务应用创建第二个顶层窗口。
- 未授权的外部导航在宿主阻止，不让应用把当前窗口替换成任意网站。如何安全查看服务商的官方获取说明属于平台管理配置入口，不由业务应用自行弹窗实现。

“应用实例”按平台登记身份区分。同一源码被明确登记为不同实例时，其配置、数据、窗口和进程分别隔离；不能仅按显示名称或源码路径合并两个实例。现有 project-v1 ID 与独立 Node 源码槽 ID 不能互相冒用。

## 2 窗口驱动 Node 生命周期

| 用户动作或状态 | 标准行为 |
| --- | --- |
| 打开网页类型应用 | 打开或聚焦唯一原生窗口，不启动应用 Node 后端 |
| 打开已停止的 Node 应用 | 核对配置与运行条件，平台在后台启动本应用唯一 Node 进程；就绪后在原生窗口加载应用 |
| 必填配置缺失 | 卡片进入入口可点击，先打开详情配置 tab 并指出缺项；保存后仍需明确打开，不自动启动 |
| 来源失联或启动失败 | 显示可理解原因和详情／重试入口，不加载一个看似成功的空白应用，也不转到浏览器 |
| 再次打开正在启动或运行的应用 | 复用同一次启动；已有窗口只聚焦，不重启、不自动刷新 |
| 关闭应用窗口 | 撤销本应用页面会话、关闭代理与活动流，收尾本应用全部受管 Node 及可确认归属的普通子进程；不停止其他应用或用户独立启动的 Node |
| 启动过程中关闭窗口／取消打开 | 取消该次打开并清理已创建的受管进程；迟到的成功结果不能重新弹出窗口 |
| 保存配置 | 只保存新的配置修订，不因保存、选中应用或打开配置页就启动／重启应用 |
| 运行中明确“重启并应用配置” | 停止旧运行实例，再用同一应用的新配置快照启动并复用原窗口；不能同时运行两份后端 |
| 点击平台管理主窗口 X | 按用户最新要求进入正常退出流程，关闭全部业务窗口并收尾全部受管 Node 及其普通子进程；不再仅隐藏到托盘 |
| 菜单／快捷键正常退出整个平台 | 与管理主窗口 X 使用同一退出收尾路径，再退出；不通过宽泛的“杀全部 Node”清理 |
| 平台再次启动 | 不自行恢复应用窗口或后台业务；用户再次打开时再启动 |

应用窗口的关闭与明确“停止”应采用同一受管收尾路径。不能只因主 Node 退出、收到 `stopping` 或窗口消失就报告已停止；还须核对本应用受管进程组及普通后代已退出。正常握手、超时终止和进程归属确认由平台实现，收尾失败或无法确认时记录真实异常／未完成状态，保留现场并阻止不安全的重复启动，不拿旧数字 PID 猜测杀进程。

业务代码不得接管进程或通过脱离进程组让后端常驻。宿主硬崩溃、被强制杀死以及逃离受管进程组的后代不能被虚假保证全部自动清理；能力与实测边界必须明确。管理窗口隐藏托盘是旧版本行为及历史记录，已被本次“主窗口 X 正常退出”的要求覆盖。正常退出仍须遵守已接受的数据库、备份／恢复等操作收尾保护，不为关闭软件破坏数据或恢复现场。

后端异常时在当前应用窗口或平台管理页展示可恢复状态，撤销不可用入口；由用户明确重试，不进行无限自动拉起或静默丢弃页面草稿。外部 AI、音乐或 TTS 服务不可用，不应直接被解释为 Node 已退出。

## 3 作者与 AI 的职责

- 先声明 `static-web` 或 `node-service`，按当前已支持的格式和入口接入。运行类型来自清单，不取决于有没有填写 Key。
- Node 启动入口采用结构化清单和受管协议。不要让用户手动运行 npm、固定端口服务、Claude Code 或常驻脚本来完成应用启动。
- Key、地址、模型等需要用户提供的设置，在配置声明中逐项写明中文名称、用途、必填与否、默认值及获取步骤。秘密交给平台配置入口，不进入源码、网页、清单、`.env`、说明截图或日志。
- 用户最新明确不用 macOS Keychain：Node Key 保存在各应用自己的本机受管槽 `configuration/credentials/`，目录 `0700`、秘密文件 `0600`。这是当前用户文件权限保护的明文存储，不是系统加密库；本机槽与作者源码、分享包及 Git 分开。平台不读删旧 Keychain 条目，不把秘密文件交给 AI 或业务页面。
- 页面使用平台允许的同源接口；后端凭据和管理令牌留在宿主／后端，不交给业务页面。Node 只能获得自己这次启动的配置快照。
- 验证从平台原生应用窗口完成打开、重复打开、关闭、重开、配置生效、异常和数据保留。HTTP 或浏览器检查可以补充诊断，不能替代原生窗口验收。
- 保全已有源码、SDK、数据库、附件、维护状态、备份和恢复现场。固定开发标识 `dev.localprojects.platform.m0` 与数据根保持；工作区换位置只走公开迁移流程。

## 4 当前交付边界与文档关系

[本机 Node 配置与运行](node-native-configuration.md)说明当前独立源码槽、配置保存和运行接入。它不等于把 Node 应用纳入既有 project-v1 的完整安装、备份、导出、复制、回收站、更新或工作区迁移生命周期；未交付的入口不能由 AI 自行伪造。

本页记录用户已确认的窗口与启停约束；[Node 总体方案](node-app-runtime.md)、[启动协议](node-app-startup-spec.md)、[配置设计](node-app-configuration.md)的其他候选字段和公开格式仍按各自状态处理。[实施计划](node-app-implementation-plan.md)记录顺序，[实际验证记录](node-native-configuration.md#验证记录)记录做到什么，不以方案文字自动宣布实现。

平台交付给 AI 的入口维护在 `skills/local-projects-app/SKILL.md`，随 skill 携带的 `references/app-window-runtime.md` 提供不依赖平台源码的执行说明。旧项目自带 skill 和文档不随平台升级覆盖；需要接手旧项目时使用当前平台提供的补充说明并核对实际能力。
