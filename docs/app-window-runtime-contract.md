2026-10-23 删除补充：Node 直接删除必须先关闭对应业务窗口，原生管理入口重新核对目标及预览修订，并核实、停止遗留受管运行。确认后永久删除的范围按[删除契约](application-deletion.md)执行；外部引用目录保留，不进入平台或系统回收站。其他未交付的生命周期能力不因此开放。

状态：2026-10-20 用户明确确认的产品约束。适用于平台中的应用运行体验；实现和实际验收以当前交付记录为准。此前浏览器试跑记录保留为验证证据，不作为标准应用的默认打开方式。

同日最新关闭要求覆盖此前“管理主窗口 X 退出”的约定：macOS 管理窗口 X 只隐藏窗口并保留 Dock，已开的业务窗口和受管服务继续运行；Dock 点击、Reopen 事件或重复启动恢复同一个管理窗口。菜单“退出”／Cmd+Q 才执行整个平台的安全收尾。非 macOS 管理窗口 X 维持正常退出。历史实测按原版本保留，不能据此宣称新行为已经通过。

## 统一项目入口与详情

网页类型和 Node 类型统一显示在 **我的项目** 启动台，项目自己的图标继续保留，Node 使用绿色六边形角标；完整运行类型中文保留在右键菜单、详情及读屏说明中。用户都从项目卡片进入，配置完整后在唯一原生应用窗口运行，不要求先找另一个“Node 应用”管理页。

- 卡片只常显图标与单行名称，超宽名称省略，悬停可查看完整名称，读屏也保留完整名称；Node 绿色六边形角标继续显示。不设置三点按钮，右键或聚焦后使用 Shift+F10／ContextMenu 键打开详情菜单，保留键盘可达性。
- 配置、运行、维护和异常等状态收在右键菜单、详情及读屏说明中，不另占卡片下方的首页文本行。展示精简不改变进入门禁，也不把缺配置、维护或异常伪装为正常；项目概览、使用说明和其他详细信息仍在管理页面内的详情弹窗，不展开成另一整页或新的原生窗口。
- 详情使用带 tabs 的页面内 modal，沿用静态项目已有的详情分组和操作习惯。Node 所需配置在同一弹窗中呈现；尚未支持的备份、迁移等能力明确说明，不伪造为可用的静态项目功能。
- 必填配置不足时，“进入／打开应用”入口仍可点击，先打开详情弹窗的配置 tab，标明缺少的字段与获取步骤；不能只禁用按钮，让用户无法补配置。
- 保存只提交配置，不自动启动后端、自动打开应用或重启。保存后由用户明确打开；已有实例则按明确重启流程应用新快照。
- 这些是最新确认的交互要求，新增统一列表、tabs 和缺配置引导的实际验收需另记；不能用此前独立 Node 页的实测代替。

统一列表是展示与入口统一。Node 身份和存储仍为独立的本机源码槽，不移动目录，不合并或转换 project-v1，不借此获得其完整安装、备份、导出、回收或迁移能力。

## 1 一个应用，一个原生窗口

应用从平台打开，在平台提供的独立原生窗口内运行。网页是窗口承载的界面，本机 HTTP 地址只是内部传输，不要求用户另外打开浏览器或终端。

- 同一个应用实例最多有一个应用窗口。再次点击打开只显示并聚焦原窗口，保留页面与未保存内容，不新建窗口、不自动重载。
- 正在启动时再次打开，复用同一次启动和窗口准备，不再创建 Node 进程或第二个窗口。
- 应用不得通过 `window.open`、`target="_blank"`、弹出式网页、其他 WebView 或外部浏览器扩展自己的运行窗口。宿主必须拒绝新窗口请求，不能只依赖作者自觉。
- 业务表单、帮助和确认内容放在当前窗口内。不要用脚本 `alert`、`confirm`、`prompt` 作为业务弹窗或阻塞宿主流程。
- 文件选择、保存位置及系统权限提示继续服从平台已有的受控能力、用户操作和实际授权；这不授权业务应用创建第二个顶层窗口。
- 未授权的外部导航在宿主阻止，不让应用把当前窗口替换成任意网站。如何安全查看服务商的官方获取说明属于平台管理配置入口，不由业务应用自行弹窗实现。

“应用实例”按平台登记身份区分。同一来源可分别下载为独占实例；同一个可写源码目录不得跨项目登记。各实例的配置、数据、窗口、浏览器存储和进程分别隔离，不能按显示名称或复用的目录名合并身份。现有 project-v1 ID 与独立 Node 源码槽 ID 不能互相冒用。

## 项目浏览器存储

网页与 Node 的原生容器均按稳定项目 ID 分配独立 `data_store_identifier`，最低系统 macOS 15。复制／导入生成新身份及新 store；公开迁移保留原身份和 store。管理器使用另一全局 store 保存主题等平台偏好，不与项目共用。旧默认共享 store 在启动阶段清空并等待核验，期间 HTTP／CLI 与原生开窗均不得先行；不迁移旧会话。

删除前关闭本项目写入与窗口，收到真实 Destroyed 并经过主队列屏障、释放句柄后，再清所有网站数据并等回执、核对记录为空、删除 store、再次枚举确认标识消失。清网站数据这一步也避免系统删除标识后旧 Cookie 仍驻留内存。系统操作失败或超时保留当前清理凭据，不能先注销任务和归属再宣称成功。系统 store 标记在固定数据根的独立项目目录，寿命覆盖项目文件删除及 OS 回执；成功后不留标记或成功回执。

Node 后端使用 `APP_PORT=0`，本机代理也绑定动态端口。Cookie 不按端口隔离，随机端口可能复用；隔离来自项目 store。localStorage／IndexedDB 仍按 origin 划分，动态端口改变时不承诺自动延续到新 origin，但删除会清该项目 store 中所有 origin 的数据。平台项目入口只接受原生窗口；未在界面使用的默认浏览器项目启动分支已移除。用户自行复制内部 URL 到外部浏览器形成的状态由该浏览器管理，平台无法替它确认删除。

## 2 窗口驱动 Node 生命周期

| 用户动作或状态 | 标准行为 |
| --- | --- |
| 打开网页类型应用 | 打开或聚焦唯一原生窗口，不启动应用 Node 后端 |
| 打开已停止的 Node 应用 | 核对配置与运行条件，平台在后台启动本应用唯一 Node 进程；就绪后在原生窗口加载应用 |
| 必填配置缺失 | 卡片进入入口可点击，先打开详情配置 tab 并指出缺项；保存后仍需明确打开，不自动启动 |
| 来源失联或启动失败 | 显示可理解原因和详情／重试入口，不加载一个看似成功的空白应用，也不转到浏览器 |
| 再次打开正在启动或运行的应用 | 复用同一次启动；已有窗口只聚焦，不重启、不自动刷新 |
| 关闭应用窗口 | 撤销本应用页面会话、关闭代理与活动流，收尾本应用全部受管 Node 及可确认归属的普通子进程；不停止其他应用或用户独立启动的 Node |
| 启动过程中关闭窗口／取消打开 | 取消该次打开并清理已创建的受管进程；迟到的成功结果不能重新弹出窗口 |
| 保存配置 | 只保存新的配置修订，不因保存、选中应用或打开配置页就启动／重启应用 |
| 运行中明确“重启并应用配置” | 停止旧运行实例，再用同一应用的新配置快照启动并复用原窗口；不能同时运行两份后端 |
| macOS 点击平台管理窗口 X | 只隐藏管理窗口，平台和 Dock 保留；已开的业务窗口、受管 Node 及平台服务继续运行，不撤销它们的会话 |
| macOS 点击 Dock、收到 Reopen 或重复启动 | 恢复并聚焦同一个管理窗口，不重建管理页、不启动第二套平台服务，也不自动重开已关闭的业务窗口 |
| 非 macOS 点击平台管理窗口 X | 维持正常退出流程，安全关闭全部业务窗口并收尾全部受管 Node、普通子进程及平台服务 |
| 菜单“退出”／Cmd+Q 等正常退出整个平台 | 安全关闭全部业务窗口并收尾全部受管 Node、普通子进程及平台服务，再退出；不通过宽泛的“杀全部 Node”清理 |
| 平台再次启动 | 不自行恢复应用窗口或后台业务；用户再次打开时再启动 |

应用窗口的关闭与明确“停止”应采用同一受管收尾路径。不能只因主 Node 退出、收到 `stopping` 或窗口消失就报告已停止；还须核对本应用受管进程组及普通后代已退出。正常握手、超时终止和进程归属确认由平台实现，收尾失败或无法确认时记录真实异常／未完成状态，保留现场并阻止不安全的重复启动，不拿旧数字 PID 猜测杀进程。

项目删除（包括通过 CLI 提交）先撤销该项目的原生开窗凭证，并等待已受理的该项目开窗／重新加载操作退出。网页下载须收到引擎实际 `Finished`，已确认另存的复制也须完成，然后才能销毁窗口；未答复的旧保存对话框失效。销毁须等待同一窗口代次的实际 `Destroyed` 和随后主线程队列屏障，再释放捕获的窗口句柄、清理项目内存与磁盘。窗口从查询表消失、销毁请求返回成功或回调被丢弃均不作完成证明；未确认时保留现场并阻止删除。等待只占用该项目的操作锁，不以全局创建锁阻塞其他项目；迟到的旧开窗、关闭或销毁回调不能重新创建已删除项目的条目。普通网页关窗同样先等待本项目的下载与已确认另存复制完成；重复关闭合并处理，30 秒内未确认结束时保留页面并允许再次关闭，不伪造引擎完成回执。


业务代码不得接管进程或通过脱离进程组让后端常驻。宿主硬崩溃、被强制杀死以及逃离受管进程组的后代不能被虚假保证全部自动清理；能力与实测边界必须明确。macOS 管理窗口隐藏不触发受管收尾，也不等于最小化到托盘；明确退出及非 macOS 管理窗口关闭仍须遵守已接受的数据库、备份／恢复等操作收尾保护，不为关闭软件破坏数据或恢复现场。

后端异常时在当前应用窗口或平台管理页展示可恢复状态，撤销不可用入口；由用户明确重试，不进行无限自动拉起或静默丢弃页面草稿。外部 AI、音乐或 TTS 服务不可用，不应直接被解释为 Node 已退出。

## 应用窗口尺寸

2026-10-29 网页构建占用按[网页代次契约](web-build-generation-retention.md)执行：新建／重载窗口固定本次入口代，复用窗口不刷新草稿，只有真实 `Destroyed` 释放窗口占用；实际文件生产者另持短占用到读取结束。无来源现役网页使用固定控制根内有收据的短期 `view_…` 入口快照。迁移可撤销旧访问并排空读者，不能靠刷新或销毁草稿来冒充占用释放。

作者可为业务应用声明初始窗口内容区的逻辑宽高。它适用于 project-v1 根部 `project.json` 的可选顶层 `window`，以及当前内部 Node 源码槽 `local-app.json` 的同名顶层字段；Rust 对 project-v1 的透传字段存放在 `manifest.extra.window`，清单 JSON 不另嵌套一个 `extra`。该配置不改变平台管理窗口自己的默认或最小尺寸，也不开放网页原生窗口权限；有效 Node 清单的变更按[单目录运行规则](node-single-directory.md)在下次真正启动时接受。

清单中的可选片段如下，不是完整项目或应用清单：

```json
{
  "window": {
    "width": 960,
    "height": 640,
    "rememberSize": true
  }
}
```

- 整个 `window` 省略时，初始内容区为 **1080×780**，默认记忆尺寸。只要提供 `window` 对象，`width` 与 `height` 都必填，分别为 **1..32768** 的整数；`rememberSize` 可省略，默认 `true`，提供时必须为布尔值。不接受 `null`、缺失宽高、浮点数、越界数值或未知子字段。
- 宿主实际最小内容区为 **640×480**。初始值和记忆值都按当前显示器可用区收敛，并为原生窗口装饰留出空间；小于最小值的声明会升到最小值，过大值会收缩。可用区本身小于最小值时仍保留宿主最小值，不能承诺任何屏幕都完全容纳。记录的是内容区逻辑尺寸，不是屏幕物理像素或整窗外框尺寸。
- 没有可用本机记录时使用声明尺寸；有记录且 `rememberSize: true` 时，之后新开窗口优先使用该应用上次的普通窗口尺寸。设为 `false` 时每次新开都使用声明尺寸，不读取或更新其记忆值。再次打开已存在窗口仍只聚焦，不重置尺寸或重载页面；修改初始尺寸也不会强行改变正在打开的窗口。
- 宿主观察普通窗口的逻辑尺寸，在业务窗口正常关闭及平台明确退出时保存；不把最小化、最大化或全屏状态当作普通尺寸。该功能只记尺寸，不赋予网页调整宿主窗口、管理其他窗口或修改本机偏好文件的能力。

本机记忆按项目独占，分别保存在固定数据根 `web-project-ownership/<项目ID>/window-size.json` 与 `node-project-ownership/<实例UUID>/window-size.json`，独立于 `settings.json`、项目清单和业务数据库，不随分享包携带。网页项目按稳定 ID、Node 按注册 UUID 隔离，不按显示名或源码路径混用；公开工作区迁移保留同一项目身份，已有窗口仍只聚焦。每个项目按需读取自己的缓存，单个缓存损坏或无法安全读取只让该项目使用声明／默认尺寸，并停止对该缓存继续写入，不影响其他项目。

macOS 在普通窗口尺寸实际变化后的关窗／明确退出时原子保存。正常成功保存只保留当前偏好文件，不积累换出的旧副本；临时文件和外部冲突材料只留在该项目自己的控制目录。发现外部替换时保留冲突现场并停止该项目的后续写入，不能保证发布后的原路径仍是原内容。项目删除通过 core 同步清理入口撤销内存写许可、清除缓存与相关临时材料，原生尺寸绑定也随之失效；关闭事件、已克隆回调及迟到 flush 不能复活已删除项目的缓存。每次窗口绑定使用可撤销 generation，普通关闭后的旧绑定不能覆盖新窗口的记录。

本次使用新的项目独占格式，不读取、迁移或扫描清理旧 `app-window-sizes.json` 及 `.app-window-sizes-preserved-*`；用户另行重置固定数据根。缓存写入不会创建或接管缺失的项目归属目录。其他系统尚未启用该原子发布实现，不借此宣布新增运行平台支持。

project-v1 的非法 `window` 会记录诊断并回退默认窗口配置，不借展示偏好阻断原有项目。Node 清单的 `window` 严格解析，无效声明被拒绝。作者可在关闭应用窗口后修改有效 `local-app.json`，包括 `app.id`、版本、入口、配置和窗口声明；平台下次真正启动前重新检查并接受新摘要，平台实例 UUID、数据和删除归属不变。已有窗口仍只聚焦，记忆尺寸继续按上述规则优先；不能通过修改平台控制记录绕过清单或入口检查。平台不会主动改写作者源码或业务数据。

解析、尺寸计算、缓存隔离或损坏保留的自动回归只能证明对应逻辑。实际原生拖动缩放、关闭重开、屏幕／DPI 改变及最小化／最大化／全屏排除必须另记真实窗口验收；本文不宣称这些原生动作已通过。

## 3 作者与 AI 的职责

- 按[应用开发环境与交付要求](app-development-environment.md)选型，优先前端、平台 SDK 与 SQL；确需后端才用 Node，尽量单服务，提前说明用户环境前提。作者准备前端构建产物、后端入口和完整运行依赖；应用启动不执行 npm 安装或源码构建，独立开发工具仅接现有 project-v1 构建。
- 先声明 `static-web` 或 `node-service`，按当前已支持的格式和入口接入。运行类型来自清单，不取决于有没有填写 Key。
- Node 启动入口采用结构化清单和受管协议。不要让用户手动运行 npm、固定端口服务、Claude Code 或常驻脚本来完成应用启动。
- Key、地址、模型等需要用户提供的设置，在配置声明中逐项写明中文名称、用途、必填与否、默认值及获取步骤。秘密交给平台配置入口，不进入源码、网页、清单、`.env`、说明截图或日志。
- 用户最新明确不用 macOS Keychain：Node Key 保存在各应用自己的本机受管槽 `configuration/credentials/`，目录 `0700`、秘密文件 `0600`。这是当前用户文件权限保护的明文存储，不是系统加密库；本机槽与作者源码、分享包及 Git 分开。平台不读删旧 Keychain 条目，不把秘密文件交给 AI 或业务页面。
- 页面使用平台允许的同源接口；后端凭据和管理令牌留在宿主／后端，不交给业务页面。Node 只能获得自己这次启动的配置快照。
- 验证从平台原生应用窗口完成打开、重复打开、关闭、重开、配置生效、异常和数据保留。HTTP 或浏览器检查可以补充诊断，不能替代原生窗口验收。
- 普通业务改动保全已有源码、SDK、数据库、附件、维护状态、备份和恢复现场；2026-10-25 用户单独授权的[旧开发环境重置](development-identity-reset.md)覆盖本次旧受管资料的保留要求。固定开发标识为 `dev.happypandaa.pandadrawer`，不能借业务应用修改身份、清空资料或改数据目录。普通工作区换位置只走公开迁移流程。
