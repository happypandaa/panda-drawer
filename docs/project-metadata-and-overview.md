# 项目基本信息、概览与平台信息

状态：v0.2，已确认契约；M5 已实现并通过 CLI/API、坏库诊断及重启验证，完整 GUI 交互未实测

更新日期：2026-10-19

本文件确定项目名称、简介、图标、概览页以及它们的存储和更新规则。平台自身信息按[发行契约](release-and-updates.md)管理，空间数字按[空间契约](project-storage-and-assets.md)扫描；M5 已实现管理页面与服务入口，实际结果见 [M5 记录](m5-verification.md)；页面完整交互未因接口通过而视作通过。

外部应用包后续按[两类应用文档](application-documentation.md)分别提供用户使用/配置与AI技术/开发说明。现有 `description` 仍为纯文本，根README/skill的AI接管角色与当前元数据接口不变；本次只整理规范和示例，没有增加Markdown读取/渲染或改写旧项目文档。

## 1 信息存放在哪里

| 信息 | 唯一权威来源 | 便携与更新规则 |
| --- | --- | --- |
| 项目稳定 ID、名称、简介 | 项目根目录 `project.json` 的 `id`、`name`、`description` | 随项目保存；改展示名称不改 ID 或目录 |
| 项目图标 | `project.json.icon` 指定的项目内 PNG，标准位置 `meta/icon.png` | 随项目备份、导出和复制，不依赖外部图片网址 |
| 项目业务数据 | `data/main.sqlite` 及用户附件 | 不另建“项目名称表”作为平台信息来源 |
| 维护、任务、构建来源 | 已有工作区 `.platform/` 持久控制记录 | 沿用控制状态与生命周期规则，不放进业务表 |
| 项目空间数字 | Rust 对项目实际文件的扫描结果 | 缓存在 `workspace/.platform/cache/storage/projects/<projectId>.json`，可删除重建 |
| 工作区空间汇总 | 对当前工作区各范围的扫描及汇总 | 缓存在 `workspace/.platform/cache/storage/workspace.json`，不是数据登记簿 |
| 平台名称、图标、版本、应用标识 | 随安装包发布的配置与只读资源 | 发布时统一生成；不保存在任一项目中 |
| 平台程序体积 | 对实际运行 `.app` 根目录的扫描结果 | 缓存在固定 `appLocalDataDir/cache/storage/platform.json`，不随工作区迁移 |

平台可以缓存已读取的名称与图标以加快界面，但不能形成第二份可编辑的权威记录。第一版无需为基本信息增加平台数据库；重新启动或刷新后从项目文件重新读取。统计缓存的根身份、切换代次、时效与完整性字段以空间契约为准。

## 2 项目清单与图标

下例是清单中的基本信息片段；完整必填字段仍见[主约定](platform-development-contract.md)：

```json
{
  "id": "prj_english_01",
  "name": "孩子英语学习",
  "description": "管理单词、练习和学习记录",
  "icon": "meta/icon.png"
}
```

- `name` 必填，去除首尾空白后不得为空，按纯文本显示。允许不同项目同名，所有操作仍按稳定 ID 定位。
- `description` 可选，按纯文本显示；省略或空字符串表示没有简介。列表可截短，详情可查看完整内容，不执行 HTML 或 Markdown 中的活动内容。
- `icon` 可选，为项目根目录下 `meta/` 内的相对 PNG 文件路径。首版只接受可解码的静态 PNG，不接受远程 URL、绝对路径、`data:` URL、SVG、HTML 或动画图标；不跟随符号链接读取图标。
- 推荐正方形、512 × 512 像素的 PNG，可带透明背景；这是资源制作建议，不是强制尺寸。解码须有文件大小及像素数量边界，具体数值在实现参数中落实，不能把待确认的通用资源限额直接套作已定值。
- 没有图标时使用平台默认项目图标。图标路径不合规、文件缺失、格式或解码失败时使用默认图标并提示原因；这一装饰性字段的问题本身不阻止既有项目运行。其他清单错误仍按原有规则处理。

`meta/` 是平台展示用的持久项目资料，位于 `sourceDir`、`outputDir`、`data/` 和平台临时目录之外，不能互相包含。它计入“源码与项目资料”，但不属于构建输入。空间分类和构建输入分类用途不同，不能据此认为所有“源码与资料”都要打包。

网页内部的按钮图标、favicon 等仍放 `app/public/` 或其他被构建扫描覆盖的源码资源目录。如果网页要使用同样图案，由 AI 在源码中保存一份；平台不会把 `meta/` 公开为项目静态目录，也不会在构建时偷偷读取或复制它。源码与产物中确实存在的副本各计实际体积。

元数据和图标随项目持久保存；项目备份恢复后以快照内的值为准。副本使用独立图标文件，不能引用源项目的路径。统计缓存不随单项目归档保存，恢复、导入、复制和工作区根切换后重新核对并扫描。

## 3 平台页面

### 3.1 项目列表卡片

卡片显示图标、名称、简短简介、运行／维护状态及当前项目文件大小，附统计时效。没有扫描结果显示“尚未统计”，不是 0 B。卡片分别提供“打开项目”和“查看详情”：前者进入独立项目窗口，后者留在平台管理窗口。

同名项目可用位置或稳定 ID 区分。未构建项目仍能显示基本信息；数据库不可用也能查看清单、目录与空间。清单本身无法解析时显示“清单不可用”和目录标识；上次读到的信息如用于辅助展示须标为旧值，不自动用旧缓存修复或覆盖文件。

### 3.2 项目详情的概览页

| 区域 | 展示内容和操作 |
| --- | --- |
| 基本信息 | 图标、名称、简介；编辑基本信息、选择或移除图标 |
| 项目位置 | 稳定 ID、实际项目目录、README 入口；复制路径、打开目录、复制给 AI 的说明 |
| 当前状态 | 是否可打开、维护及恢复提示、相关活动任务；状态来源保持分开，不用一个“正常”掩盖未完成任务 |
| 构建情况 | 最近成功构建时间、源码匹配状态及检查时间；尚未构建或来源未知分别说明 |
| 运行需求 | 声明的联网来源、用途、发送内容、麦克风与摄像头用途；声明不等于已取得系统授权 |
| 空间摘要 | 当前项目大小与分类比例、统计时间和完整性；进入“空间与文件”或重新统计 |
| 维护入口 | 进入“备份与维护”，查看已有备份、维护和恢复状态 |

概览是平台提供的统一页面，不是项目 `dist/` 中的 HTML。显示概览不会启动项目脚本、执行 SQL 或为读取基本信息而打开数据库。读取目录和控制记录仍遵守恢复、迁移及文件访问边界。第一版不要求每个项目额外填写应用版本号，也不把最近构建时间冒充项目版本。

项目的名称和图标变化后，平台刷新列表、概览及桌面项目窗口的宿主标题，无需重载业务页面。网页自身写死的标题、logo 或业务文案由 AI 修改源码并构建；普通浏览器标签标题仍由网页负责。项目图标不代表为每个项目安装一个独立 macOS App 或更改平台 Dock 图标。

### 3.3 空间与文件页

沿用七类互斥顶层分类：源码与项目资料、网页产物、用户素材、数据库、开发依赖、缓存与日志、其他文件。源码固定素材为子项；`meta/` 归项目资料。当前项目占比的分母只含当前项目目录；备份、回收站和恢复现场另列，不混入此比例。

所有数值来自平台扫描。比例应与同一份扫描结果的分类字节一致；未统计或不完整时明确标注，不能拼成看似精确的 100%。缓存、重新统计、逻辑字节与磁盘实际占用的区别见空间契约。

## 4 如何修改基本信息

用户在概览编辑，平台写回同一份 `project.json` 和项目 `meta/`；外部 AI 也可直接编辑这些文件。README 用于解释用途和维护方法，不是平台名称或图标的另一份权威配置。UI 不重写 AI 编写的整份 README；AI 改名后应同步其标题和相关说明。

平台读取清单时返回不透明 `metadataRevision`，涵盖当前清单内容及当前图标的内容／有效性，并绑定当前服务实例、项目登记及根切换代次。恢复同 ID、迁移或重启后，即使文件内容相同，旧编辑表单也须重新读取。编辑提交须携带期望版本；平台重新读取，版本不同返回 HTTP 409 `METADATA_CHANGED`，让调用方重新读取并合并，不能以旧表单覆盖 AI 的新修改。文件监听用于刷新提示，实际读写仍重新校验。

平台只修改提交的 `name`、`description`、`icon`，保留清单其他字段；省略表示不改，`description: null` 或 `icon: null` 表示移除对应可选字段，`name` 不允许为空或 null。清单不可解析或版本不被支持时拒绝通过表单重写，保留原文件交给 AI 修复。

正常模式下改基本信息不要求先进入维护；若已经维护，必须提供当前 `maintenanceId` 且 `readyForChanges`。修改和图标导入使用同项目操作互斥，与构建发布、备份冻结、恢复、删除、复制快照及迁移等协调；项目忙或 `recoveryRequired` 时不得写入。它不自动结束维护或清除已有待构建要求。

选择图标由可信管理窗口的文件选择器取得文件，宿主校验后复制到 `meta/` 内独立的新 PNG 路径，例如 `meta/icon-<随机标识>.png`，再提交清单引用；AI 首次制作可用 `meta/icon.png`。新文件完整落盘后才原子替换清单，成功提交前保留旧引用和旧文件，失败不得留下指向半写文件的清单。移除图标只移除清单字段，不自动删除旧文件；未被引用的文件仍计入项目资料，不能猜测其已无用途。平台可清理本次尚未提交且能确定归属的临时文件。

外部 AI 直接写文件不受平台互斥锁约束，仍遵守单编辑者协作、完整写入后替换以及操作期间暂停编辑的约定。版本比较用于发现冲突，不声称能强制锁住任意外部工具，也不通过回滚整个清单覆盖随后发生的编辑。

只改基本信息、根 README 或 `meta/` 不触发构建，不需要 Node；这不豁免其他已修改源码的待构建要求。平台完成修改后使相关空间缓存过期，并重新读取展示信息。

## 5 服务和 AI 交接

正式管理接口在[本地服务契约](local-service-and-ai-tools.md)同步：

| 入口 | 返回或修改内容 |
| --- | --- |
| 项目列表 | ID、名称、简介、图标有效性、状态，以及带时效的当前空间摘要 |
| `project info` / `GET /api/v1/projects/{id}` | 清单、`metadataRevision`、`iconStatus`、基本信息问题、路径、文档、构建及维护状态；空间摘要引用扫描信息 |
| `project metadata set` / `PATCH /api/v1/projects/{id}/metadata` | 仅补丁修改名称、简介、图标引用；返回更新后的基本信息与新 revision |
| 现有 storage 接口 | 空间详细结果与扫描，不把字节数写进清单或业务库 |

补丁请求包含 `expectedRevision` 与至少一个可编辑字段；维护中另带 `maintenanceId`。`icon` 非空时，必须指向当前项目 `meta/` 内已存在、可读取并通过格式校验的 PNG；这个接口不接受机器任意路径或复制任意文件。UI 的文件选择与导入通过宿主受控模块，CLI 的 AI 可以先写好 PNG 再提交相对路径。读取时容忍坏图标以便使用原项目，不等于编辑接口允许保存一个新的无效图标引用。

图标读取和显示由平台受控管理模块完成，只读取清单指向且已校验的项目 PNG，按图片解码展示；不开放项目根静态服务，不把绝对路径当 Web URL，不把管理凭据附在图片 URL。普通项目 SDK 不新增跨项目读取、修改基本信息或修改平台品牌的权限。

`GET /api/v1/runtime` 的 `platform` 信息用于关于页面与管理诊断，字段包括当前安装版的 `name`、`identifier`、`version`、可选 `buildNumber`、`architecture`、实际 `installationPath`。公开 `/healthz` 继续仅返回原有最小信息，不因此公开机器路径。平台程序大小通过空间接口的 `platformProgram` 返回，与项目体积分别展示。

## 6 平台自身展示

平台设置提供“关于”和“空间总览”。关于展示当前安装的名称、图标、版本及架构，提供程序位置、程序体积及统计时间。当前内部开发版说明尚无正式更新通道；正式更新说明与检查更新入口在 M6 落实，最新发行版与当前安装版应分别显示。空间总览区分平台程序、当前工作区、本机其他已知数据位置，并解释各自包含什么。

平台程序名称、图标、版本与固定应用标识随发布生成，只从当前程序读取。它们不会被某个项目的 `project.json` 改写，普通用户也不通过关于页修改已签名安装包。正式品牌名称、图标图稿、首个发行版本及固定应用标识仍需发布前落实，本文件不替用户命名。

## 7 文档和实施验收

项目 README 至少说明基本信息的清单字段、实际图标路径或默认图标、平台概览与空间入口，以及元数据与网页素材的区别。创建时填入实际值；AI 修改后同步有关文字，不维护手写体积表。

实施时覆盖：无图标旧项目、同名项目、坏 PNG 与越界图标路径、无构建产物和坏库查看概览、UI 与 AI 编辑冲突、改名不改 ID、不刷新已有业务表单、换图标不重建、备份恢复图标、复制后文件独立、统计缓存丢失和根切换失效、默认工作区位于应用数据目录时去重、平台更新后读取新安装版信息。这里记录验收要求，不表示已经实现或运行这些测试。
