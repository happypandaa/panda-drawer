# 应用与项目的直接删除

确认日期：2026-10-23。本文为当前删除规则，取代早期“删除先移入回收站”的产品流程；旧回收站、备份和恢复记录继续保留并按原兼容入口处理。已有资料不会因规则变更被批量清理。

## 删除范围

| 对象 | 本次删除范围 | 明确保留 |
| --- | --- | --- |
| 平台新建、完整 ZIP 导入或复制的网页项目 | 选中实例的项目目录，包括源码、网页产物、数据库、附件及实例内文件 | 其他项目、外部 ZIP、历史备份、旧回收站、受保护恢复现场及必要历史记录 |
| 从 Git 或本机源码副本安装的 Node 应用 | 选中实例的登记、受管程序代次及私有 `configuration/`、`data/`、`cache/` | 原作者目录、独立来源记录／源码副本、安装及更新证据、`runs/` 恢复记录、删除回执和其他实例 |
| 通过外部目录引用登记的 Node 应用 | 平台登记及该实例私有 `configuration/`（含秘密）、`data/`、`cache/` | 外部引用的整个目录及其中源码、文件和数据；保留运行恢复记录与删除回执 |

新删除直接移除上述选定内容，**不进入平台回收站，也不进入操作系统废纸篓／回收站，无法从回收站撤销**。外部引用目录与平台私有数据的边界必须在确认前展示；不能把“移除引用”误写成删除外部目录，也不能只隐藏卡片而保留承诺删除的本机私有数据。

本次授权不包含清理其他实例、来源、安装失败现场、旧备份、旧回收项或未解决恢复证据。Node 删除回执保留在 `node-apps/.deletions/`，旧 `runs/` 及 `.installations/` 记录保留，不把整个槽和安装历史树当作可删目录。实例自己的当前配置与秘密随明确删除一起移除；既有系统 Keychain 条目不在当前文件槽删除范围内。独立来源副本若仍被其他流程引用，不能随安装实例一起删除。

## 确认与执行

删除前明确展示项目／应用名称、实例身份、实际目录、永久删除范围和保留范围，并提示无法撤销。只有用户明确确认后才执行；取消确认不改文件。对外部引用应用额外说明“外部目录保留，本机配置和数据将删除”。CLI 调用方同样应先核对目标与不可撤销后果，再明确调用 `project delete`。

执行前核对当前目标及目录身份、活动任务、业务窗口、数据库／文件句柄和受管进程状态。无法确认已停止写入、目标身份变化或存在未解决恢复现场时拒绝删除并保留诊断，不能靠跳过检查或按进程名清理来完成。外部 AI、编辑器和数据库工具须停止访问待删除范围；平台门禁不构成系统级沙箱。

删除完成后，原业务入口与旧会话失效，卡片从当前列表移除，并显示实际结果。部分失败或中断要报告剩余范围，保留必要的任务、日志与恢复证据；不能把部分删除说成成功，也不承诺已删除文件仍可恢复。结果未知时先核对原任务和现场，不自动重复删除。

## 管理入口

网页项目的当前管理入口为 `POST /api/v1/projects/{id}/deletions`，HTTP 请求须有当前 `expectedDocumentEpoch`，维护中另携带当前 `maintenanceId`。CLI 为 `project delete --project ID`；未在可选 JSON 中提供 `expectedDocumentEpoch` 时，CLI 先只读查询当前项目信息并取得 `documentEpoch`，再提交一次绑定该身份的删除。显式提供的值原样保留，过期时由服务拒绝；读取失败、字段缺失／类型错误时不提交删除，不在写入失败后重新绑定或重试。即使业务数据库损坏，也以平台可核对的登记身份为准，不猜测或省略绑定。

旧 `POST /api/v1/projects/{id}/trash` 拒绝新请求，不把旧客户端的可恢复删除变成永久删除。成功任务报告 `operationOutcome: "deleted"`、`restoreAvailable: false` 及历史备份保留；部分删除报告 `delete_incomplete` 与残留路径。

Node 仅通过原生管理命令删除：`node_app_delete_preview({appId})` 返回名称、实例 ID、`ownership`（`managed`／`external`）、`platformRoot`、`sourcePath`、`deletePaths`、`preservedPaths` 和 `expectedRevision`；确认后以 `node_app_delete({appId,input:{expectedRevision}})` 提交。提交重新核对预览修订，不接受客户端提供的任意目录。业务窗口必须先关闭，再核实和停止遗留受管运行；成功结果报告 `operationOutcome: "deleted"`、所有权与保留证据，必要时另报 `metadataCleanupPending`。未新增 Node HTTP／CLI 删除入口。

## 旧回收站兼容

早期版本已经移入 `.platform/trash/` 的内容仍按原 `trash list/info/restore/purge` 及历史清理流程查看、恢复或显式清除；恢复仍保留原 ID 并推进文档代次。旧回收项继续占用身份，直到按既有规则解决。新删除不再创建这些回收项，旧 API 的保留不表示新项目删除仍可撤销。

历史验证文档中的软删除、恢复和空间统计是当时的事实，继续原样保留，不改写为新删除行为，也不当作本次验收。自动回归、真实服务、原生确认与系统文件行为须按实际执行分别记录；本页不宣称已完成 Windows、原生或操作系统废纸篓验证。
