## 删除范围

| 对象 | 本次删除范围 | 明确保留 |
| --- | --- | --- |
| 平台新建、完整 ZIP 导入或复制的网页项目 | 选中实例的项目目录，包括源码、网页产物、数据库、附件及实例内文件 | 其他项目、外部 ZIP、历史备份、旧回收站、受保护恢复现场及必要历史记录 |
| 从 Git 或本机源码副本安装的 Node 应用 | 选中实例的登记、受管程序代次及私有 `configuration/`、`data/`、`cache/` | 原作者目录、独立来源记录／源码副本、安装及更新证据、`runs/` 恢复材料和其他实例 |
| 通过外部目录引用登记的 Node 应用 | 平台登记及该实例私有 `configuration/`（含秘密）、`data/`、`cache/` | 外部引用的整个目录及其中源码、文件和数据；保留已有运行恢复材料 |

新删除直接移除上述选定内容，**不进入平台回收站，也不进入操作系统废纸篓／回收站，无法从回收站撤销**。外部引用目录与平台私有数据的边界必须在确认前展示；不能把“移除引用”误写成删除外部目录，也不能只隐藏卡片而保留承诺删除的本机私有数据。

本次授权不包含清理其他实例、来源、安装失败现场、旧备份、旧回收项或未解决恢复证据。Node 不再创建独立删除回执或逐文件日志，当前登记中的待清理状态用于阻止部分删除后再次运行；旧 `runs/` 及 `.installations/` 登记保留，不把整个槽和安装历史树当作可删目录。实例自己的当前配置与秘密随明确删除一起移除；既有系统 Keychain 条目不在当前文件槽删除范围内。独立来源副本若仍被其他流程引用，不能随安装实例一起删除。

## 确认与执行

删除前明确展示项目／应用名称、实例身份、实际目录、永久删除范围和保留范围，并提示无法撤销。只有用户明确确认后才执行；取消确认不改文件。对外部引用应用额外说明“外部目录保留，本机配置和数据将删除”。CLI 调用方同样应先核对目标与不可撤销后果，再明确调用 `project delete`。

管理界面使用独立的“删除项目”弹窗。列表中的删除入口直接打开该弹窗；详情中的删除入口也打开独立弹窗，取消后保留原详情页签和已有草稿。勾选确认前不能提交；重新打开、重新核对范围、目标身份变化或出现活动任务／恢复门禁后，必须重新确认。Node 应用只读取删除预览，不为打开删除弹窗加载应用配置或密钥。

正在提交或已受理但尚未结束的删除任务，不能通过取消、关闭按钮、Esc 或背景关闭，也不能重复提交。名称或维护状态的刷新不会解除已受理任务的等待锁。只有同一项目目录、身份代次与服务实例的最终 `deleted` 结果，才移除对应卡片、关闭相应弹窗并提示成功；失败、部分删除或未知结果留在原处供核对，不自动重试。外部目录的保留规则及历史备份、恢复证据的边界不因此改变。

执行前核对当前目标及目录身份、活动任务、业务窗口、数据库／文件句柄和受管进程状态。无法确认已停止写入、目标身份变化或存在未解决恢复现场时拒绝删除并保留诊断，不能靠跳过检查或按进程名清理来完成。外部 AI、编辑器和数据库工具须停止访问待删除范围；平台门禁不构成系统级沙箱。

删除完成后，原业务入口与旧会话失效，卡片从当前列表移除，并显示实际结果。部分失败或中断要报告剩余范围，保留通用任务状态和未解决的源码／数据恢复材料；不能把部分删除说成成功，也不承诺已删除文件仍可恢复。结果未知时先核对原任务和现场，不自动重复删除。

## 管理入口

网页项目的当前管理入口为 `POST /api/v1/projects/{id}/deletions`，HTTP 请求须有当前 `expectedDocumentEpoch`，维护中另携带当前 `maintenanceId`。CLI 为 `project delete --project ID`；未在可选 JSON 中提供 `expectedDocumentEpoch` 时，CLI 先只读查询当前项目信息并取得 `documentEpoch`，再提交一次绑定该身份的删除。显式提供的值原样保留，过期时由服务拒绝；读取失败、字段缺失／类型错误时不提交删除，不在写入失败后重新绑定或重试。即使业务数据库损坏，也以平台可核对的登记身份为准，不猜测或省略绑定。

旧 `POST /api/v1/projects/{id}/trash` 拒绝新请求，不把旧客户端的可恢复删除变成永久删除。成功任务报告 `operationOutcome: "deleted"`、`restoreAvailable: false` 及历史备份保留；部分删除报告 `delete_incomplete` 与残留路径。

Node 仅通过原生管理命令删除：`node_app_delete_preview({appId})` 返回名称、实例 ID、`ownership`（`managed`／`external`）、`platformRoot`、`sourcePath`、`deletePaths`、`preservedPaths`、`expectedRevision` 和可空的 `blocker`；确认后以 `node_app_delete({appId,input:{expectedRevision}})` 提交。提交重新核对预览修订，不接受客户端提供的任意目录。业务窗口必须先关闭，再核实和停止遗留受管运行；成功结果报告 `operationOutcome: "deleted"`、所有权与保留证据，必要时另报 `metadataCleanupPending`。未新增 Node HTTP／CLI 删除入口。

## 2026-10-28 删除等待反馈

Node 删除范围读取及网页／Node 删除执行期间，弹窗切换为独立等待视图，显示旋转图标、项目名称和等待说明。只读范围核对保留取消与关闭入口，隐藏确认项；真正提交删除后隐藏确认内容与底部操作，并明确说明无需再次点击。网页删除按实际任务阶段展示提交、排队、停止写入、范围核对及文件删除，不估算百分比；任务详情可展开查看。提交后的等待继续禁止关闭和重复提交，不同时显示要求重新确认的通用门禁提示。等待标题接收焦点，状态播报位于 `aria-busy` 容器外，减少动态效果的系统设置会停止旋转动画。

取得最终结果后结束等待；失败、部分完成或结果不明确时恢复范围及实际诊断，仍需核对并重新确认后才能再提交。网页删除的两个状态观察入口同步已验证的最终结果，避免其中一次读取迟迟未返回时，另一次已确认结束却仍显示 loading。

Node 预览读取名称时只读取受限的普通声明文件，核对登记中的声明摘要后解析名称；声明异常时使用原有目录名回退。打开确认弹窗不再触发整个已安装程序及 `node_modules` 的逐文件哈希，仍保留修订、目录身份及保护门禁，也不读取私有配置或密钥。取消只读预览立即退出弹窗，迟到响应不能污染重新打开的范围或确认状态；已经提交的删除不会因此被取消。

后续原生窗口排查发现：确认删除被安全关闭门禁拒绝后，滚动区域仍停留在底部，顶部错误不可见，而勾选及提交已失效。因此错误改为固定在底部操作区并接收焦点；失败时隐藏失效的勾选／删除按钮，提供明确的重新核对与取消操作。重新核对仍需重新勾选，不自动再次删除。

2026-10-28 后续确认的[“停止并删除”第一阶段](stop-and-delete-phase1.md)覆盖上轮“存在遗留标记就一律拒绝”的规则。启动时核对所有实例：普通运行标记的创建时间早于本次系统开机时间时，按精确文件身份退役标记；本次开机内的完整 v2 标记核对 PID、PGID、进程启动时间、可执行文件及独立运行身份随机值，组内已无存活进程时可收尾，身份一致的遗留运行可停止后继续。未绑定完整身份的 v2 启动意图或无法核实的当前运行状态保持 `NODE_APP_RUN_RECOVERY_REQUIRED`／`not_deleted`，在按钮附近说明重启电脑后重新核对，不按旧 PID 猜测发送信号。

同日用户进一步确认：当前仍在开发阶段，**旧 v1 运行标记直接丢弃，不再要求兼容接管或重启电脑**。对可读取的普通 `active.json`，确认 JSON 的 `version` 为 `1` 后，仅按捕获的文件身份清理该标记；启动核对、停止及删除均不再因这类标记被拦住，也不会向其中的 PID 发送信号。丢弃标记是开发阶段明确接受的旧记录处理策略，不表示已经核实旧进程全部停止；项目文件与数据仍须经过正常删除确认才清理。损坏文件、不安全文件类型、v2 身份检查及未完成启动的门禁不因本条放宽。

删除执行依据该实例进程组是否已停止及平台自身已接纳工作的实际收尾结果；强制停止、协议报错及异常退出作为诊断，不再单独阻止删除。v1 不增加系统级端口或文件句柄扫描。此阶段不实施第二阶段的协调器、持久删除任务、同卷改名及崩溃续删，也不提前扩大第三阶段实际删除范围。

上轮原生 WebKit 可丢弃验证窗口使用同一前端组件及模拟拒绝响应，验证了滚动到底部后的等待、固定错误与重新核对；真实产品窗口只读观察了已有失败结果。当时管理界面 **513/513**（包含 Node 界面 **86/86**）、删除与运行门禁 Rust **26 项**、格式检查及前端构建通过。这些历史数字不代替第一阶段的新身份、开机时间及遗留运行验证，实际结果另记于第一阶段报告。删除回归均限可丢弃目录，未再次提交实际项目删除，也未进行真实永久删除或跨系统验收；既有 JavaScript chunk 超过 500 kB 的构建提示仍存在。

确认后会关闭应用窗口并停止该实例。任务在实例目录外先落盘，再逐目录同卷暂存和删除，登记也使用外部任务事务收尾。未移动任何目标时可申请放弃，安全退场后才报告已放弃且不自动启动；任何目录移动后不能放弃。失败显示剩余范围并重试原任务；重启恢复已确认任务，待删实例不回到普通可运行列表。v2 运行身份未知等独立门禁仍保留；旧 v1 标记按上文后续确认直接清理。此为内部删除事务，未恢复旧回收站或用户数据恢复能力。

本阶段沿用既有具体删除白名单及外部源码保护；完整实例槽、独立受管源码和共享引用的最终范围另按已确认归属规则接入，不能依据“暂存”扩大目标。
