# project-v1 的 Git 数据版本

本步骤补充项目根标准 Git 的主动数据保存；源码版本与数据版本的取回分别处理。Node 应用自有数据库没有统一快照契约，不纳入本步骤。数据库从 Git 取回到活库继续作为下一步，当前接口不会替换活库、附件、源码分支或应用程序。

用户明确选择“保存源码和数据”时，平台在项目自己的 Git 仓库中提交源码，以及 `version-data/database.sqlite`、`version-data/attachments/` 和 `version-data/snapshot.json`。这里仅存当前受跟踪快照，历史属于标准 Git；不新建 ZIP、不创建私有恢复仓库、不自动推送。普通“保存源码”继续保留当前已保存的数据子树，不重新读取活库，也不把当前业务数据偷偷纳入提交。

`snapshot.json` 记录格式版本、项目 ID、SDK API 版本、活库与附件的声明路径、数据库及每个附件的长度和 SHA-256，以及空附件目录。没有每次变化的生成时间；相同源码与相同数据不会生成空提交。Git 提交时间表示版本保存时间。当前状态报告只检查已有受跟踪快照，不宣称已经预览当前活库的全部改动。

## 支持边界

- 首期仅接受项目根的普通、已核验 Git 仓库。已有 `app/.git` 保持源码范围，明确提示不能纳管项目数据库；不搬 Git 根、不包第二层仓库、不复制私钥或改用户全局 Git 配置。祖先／多个／不安全仓库仍按原 Git 门禁处理。
- `version-data` 已有同名内容时，不凭名字认领。快照须属于同一项目与数据路径、内容和清单完全匹配，且当前 Git HEAD／索引跟踪同一组原始文件。缺失、损坏、外部改动或额外文件拒绝后续写入并保留现场。
- 只复制声明数据库的 SQLite 一致性文件及声明附件树。活库、WAL／SHM、平台配置、凭据、依赖、运行产物、控制日志和无关 `data/` 文件不进入 Git。数据库和用户附件仍可能包含个人资料；没有通用数据库脱敏或秘密识别承诺。
- 文件须为无硬链接的普通文件；拒绝符号链接、特殊文件、危险路径、大小写／Unicode 碰撞及 Git 控制文件名。出现不支持的附件时拒绝整个快照，不静默跳过后宣称完整。
- 内部预算独立于源码预算：单文件 256,000,000 字节，总数据 1 GiB，最多 10,000 个附件目录项；清单最多 8 MiB。源码与数据合并后的 Git 文件数还须不超过 10,000，路径输出和保存日志也须能被后续状态／恢复检查完整读取。这些是当前内部保护参数，超限停止、不截断，不是最终产品配额。

## 业务操作与候选

平台开发任务租约先阻止同项目的构建、Git 写入、删除及迁移并发。捕获数据时再设置短期冻结并取得项目排他写锁，等待已接受的 SQL、附件上传／删除／读取退出。等待超过 5 秒或收到取消时释放冻结，本次没有提交。SQL 和附件请求都经过同一业务读锁和页面身份检查。

排他锁与冻结作为同一个 `SnapshotLease` 移入执行快照的后台工作，不能因调用方 future 取消而提前释放。已有 SQLite worker 不需要为了只读一致性快照重开；直接复用 SQLite Backup API，将副本关闭为 DELETE journal mode，使副本不依赖 WAL／SHM。复制并复核完整附件树后释放业务锁，再执行 Git 对象和引用提交。普通业务可以继续使用，之后的新数据不自动进入刚刚捕获的版本。平台锁不阻止同一用户权限下的任意外部进程，外部数据库／文件编辑和 Git 写入须先停止；观察到变化时保留候选并拒绝发布。

## 提交与收尾恢复

Git 引用、索引和当前 `version-data` 目录不能在一个文件系统原子动作中提交。任务日志绑定项目、Git 目录、提交号、原索引、所持锁、候选和旧快照摘要；Git 引用提交后，完成索引与当前快照发布。提交前失败不改变当前受跟踪快照，提交后收尾失败准确报告 `committed` 并保留证据，不引导重做一个版本。

只读数据保存恢复状态独立于普通 Git 检查，普通检查被未完成索引锁或缺失快照阻挡时仍可核对。未完成或损坏的数据保存日志会阻止后续开发写入、删除、工作区迁移和相关历史清理，正常 SQL／附件业务继续可用。只有同一任务、新鲜日志摘要、仍为目标提交的 HEAD／分支、确认属于本任务的索引锁及已验证候选才允许“完成保存收尾”。此操作只完成已经提交的同一数据快照，或在 HEAD／原索引／自有索引锁都证明尚未提交时明确确认 `not_committed`，仅释放本任务自己的索引锁、终结日志并保留未提交候选。确认未提交的释放阶段也有持久检查点，可中断后再次核对。不改活库、不回退 Git、不删除外部锁、不自动推送。任何身份或内容变化均保留现场。

正常成功且完成持久确认后，逐个核验并清理本任务临时候选、源码复制、临时索引和被替换的上一份工作树快照，仅保留小日志。不会把这些副本累积为第二套数据历史。未知文件、无法确认归属或清理失败时保留并返回 `cleanupWarning`；不递归删除不明内容。失败、未完成和旧历史现场继续保护。

## 接口

- `POST /api/v1/projects/<id>/git/data-saves`：`expectedHead`（必填且可为 null）、`expectedSnapshot`、`message`、`author`。任务类型 `gitDataSave`。
- `GET /api/v1/projects/<id>/git/data-save-recovery`：`clear`／`pending`／`blocked`，逐项提供 `saveTaskId`、`phase`、`journalDigest`、`targetCommit`、`canFinalize`、问题。
- `POST /api/v1/projects/<id>/git/data-save-finalizations`：`saveTaskId` 与 `expectedJournalDigest`。任务类型 `gitDataSaveFinalize`，成功操作名 `save-data-finalize`。
- 现有 Git 状态的 `database.canSave` 只表示能力与门禁；不要求源码本身已有改动。`currentSavedSnapshot` 是当前受跟踪快照摘要，不能据此说当前业务数据已保存。

源码取回只比较和替换开发材料，跳过目标提交中的 `version-data`，不会增删、替换或启用任何数据快照，更不会覆盖活库和当前附件。

## 网页详情入口（2026-10-25）

原网页项目详情没有挂载已有的 Git／数据版本面板。现已在“概览”中加入默认收起的“源码与数据版本”，用户主动展开后才读取版本状态。它使用已有源码保存、主动数据保存及只读数据取回预览；本步不开放尚未完成的数据应用操作。

版本草稿、尚未返回的请求和源码取回任务加入详情的关闭保护；有草稿或这些操作时不能将该面板折叠消失。切换详情页保留草稿，请求等待或源码取回进行中禁止切页和关闭；版本操作期间协调元信息、空间、删除、交接及构建入口。已接受的普通 Git 保存任务会在平台继续执行，界面明确显示关闭面板不会停止任务。卸载后释放父页面的编辑状态。

128 项 DOM 检查通过（72 项页面交互、56 项 Git 面板），其中新增实际父组件挂载、延迟读取、折叠／切页草稿保持、关闭确认和未决初始化请求保护。TypeScript／Vite 构建通过，保留现有超过 500 kB 的构建体积提示。检查日志在本地忽略证据目录；此次尚未在重新打包后的原生窗口验证新入口，也未将模拟交互写成真实数据恢复成功。
