# 停止并删除：第二阶段第 3 批

本批将管理界面接到第 2 批的持久任务，不扩大删除范围。正常项目列表与删除任务列表分别加载；即使原实例登记已移动或普通列表为空，仍可从“删除未完成”任务区查看原任务。

## 交互

- `node_app_delete_submit` 返回受理快照；只有同一 task ID、实例 ID、确认修订、所有权及有效最终结果才触发删除成功。轮询和动作响应使用单调 journal 修订，旧响应不能覆盖重试、放弃或新弹窗。
- 显示等待具体操作、关闭／停止、暂存和删除阶段。不展示估算百分比，不通过请求超时或本地按钮状态推断完成。
- 失败在固定底部显示错误及剩余目标，提供“重试”；后台确认尚未移动目录时同时提供“放弃删除”。界面不自行推导是否可放弃。
- 执行中符合条件也可申请放弃。收到非终态 `abandonRequested` 时显示“正在放弃删除，等待安全收尾”，保持任务归属及关闭限制；收到实际 `abandoned` 后才刷新应用列表，不在前端伪造已停止。
- 已改名的任务不提供放弃。部分失败、仍有剩余目标或结果不明不能显示成功，也不会自动重新启动。
- 恢复任务直接读取持久快照，不重新读取可能已经移动的目录预览。失败时关闭只是关闭任务视图，不表示撤销删除。
- 放弃收尾自身失败时显示实际错误并可重试同一次放弃；worker 已退场而记录被隔离、暂不可重试时，仍显示错误并提供只读重新读取，不会永远停留在放弃进度，也不会把关闭视图当作放弃成功。
- 待删实例从普通项目卡片及空间列表隐藏；任务仍可单独查看。本机清理界面同时避让未结束删除任务。

本轮保留已确认的目录白名单、外部文件夹保护和共享恢复边界。原计划第三阶段的最终按钮文案及完整目录范围仍须按已确认的归属规则单独接入，不能把本批任务界面改动视为扩大范围。
