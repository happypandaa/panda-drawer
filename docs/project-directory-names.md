# 新项目的可读目录名

确认日期：2026-10-23。用户确认使用 npm `transliteration` 为新用户项目生成可读目录名，完整项目 ID 保持原语义，已有目录不改名。本轮只调整目录命名，不翻译管理界面，也不把项目名称或目录名当作身份。

## 适用范围

新建 project-v1、创建项目副本和完整 ZIP 导入时，新分配的用户项目根使用可读名字。显示名称仍按清单显示，完整 ID 仍保存在清单、登记和接口中；同名项目可以有不同完整 ID。以后修改显示名称不会自动改已经分配的目录。

已有项目目录、任务及控制目录、Node 私有安装槽保持原布局。用户选择的外部目录与空目录初始化位置不改名、不移动；平台不能因选中某个文件夹而接管其命名或覆盖内容。工作区位置变更继续使用公开迁移流程，不以本规则自动搬迁旧目录。

## 固定命名规则

原生命名函数 `readable_directory_name(display_name, full_id)` 只返回一个目录名分量，不读取目录、不创建路径，也不修改完整 ID：

1. 使用固定 `transliteration` 转写数据生成小写 ASCII 可读部分，只允许 `a-z`、`0-9` 和单个连字符，去掉首尾连字符。
2. 可读部分最多48个 ASCII 字节；没有可用文字时使用 `project`。Windows 的 `con`、`prn`、`aux`、`nul`、`com1`–`com9` 和 `lpt1`–`lpt9` 加 `project-` 前缀。
3. 添加连字符和完整 ID 的 SHA-256 前8位十六进制短码，形如 `ni-hao-shi-jie-1234abcd`。整个候选名最多57个 ASCII 字节。

中文等文字是**转写为读音形式**，不是语义翻译；例如中文词语不会自动变成对应英文词义。语言读音、多音字和未覆盖字符不能保证符合每个人的预期；目录可读只是辅助，应用名称与完整 ID 仍是查找和核对依据。

短码不是全局唯一性证明，不替代完整 ID。分配器必须以原子、不覆盖的方式取得新目录，不能把同名、短码碰撞或已有现场当作可复用目录；发生冲突时拒绝或另选安全目标，不能替换用户文件。前端或 CLI 不传入任意目标路径来绕过原生分配。

## 登记、迁移与中断兼容

新登记持久绑定完整 ID 与实际目录名。读取、构建、维护、空间统计和删除按此绑定定位；映射损坏或不一致时报告诊断并停止相关操作，不扫描其他可读目录来“认领”同 ID。缺少新绑定字段的旧登记继续核对原来的精确 ID 目录，不因升级重写或移动它。

复制／导入任务在发布前保存本次目标，重启不按后来修改的显示名称重新命名。旧操作日志缺少目录名时仍使用原 ID 目录；未完成恢复中，日志目标与当前绑定不一致时保留所有副本并要求核对，不把另一份同 ID 副本重新登记。创建或发布失败保留本次候选和必要记录，不以清理错误为由删除现场。

公开工作区迁移复制实际目录后，显式更新登记中的工作区路径，保持目录分量和完整 ID。旧回收项／已退役登记只重定向已核验的复制路径，不因此复活实例、改变原代次或重置文件身份；已登记实例的备份恢复和旧回收项恢复也不重算转写目录名。此兼容规则不提供新的任意目录收养入口。

## npm 来源与离线实现

开发依赖固定为 [`transliteration` 2.6.2](https://github.com/yf-hk/transliteration)，版本和下载完整性记录在 `package-lock.json`。包无运行依赖，使用 MIT 许可；生成数据旁保留上游许可全文 `LICENSE.transliteration.txt`。

本仓库**实际使用该 npm 包的公开 API 生成数据**：`scripts/generate-project-directory-names.mjs` 读取固定版本的字符映射，并从真实 `transliterate` 输出推导中文边界标记，同时用真实 `slugify` 生成对照样例。已提交数据由 Rust 原生函数离线消费，创建项目不启动 Node、不联网、不安装依赖，也不把转写库加入网页。

这不是每次命名都调用 npm JavaScript，也不是声称 Rust 对该库全部自定义配置、替换规则或语言行为完全等价。Rust 执行的是本页固定的安全命名策略；已提交的公共 API 对照样例核对其所覆盖的默认转写／分隔行为。

日常构建不重新生成映射。维护者修改固定版本时，运行 `npm run generate:project-directory-names`，审查映射、对照样例及许可变更；`npm run test:project-directory-names` 重新使用固定版本检查提交数据，`npm test` 先执行此检查。升级只影响之后分配的新目录，不迁移或重新计算已有目录名。
