# 多步骤导入与临时文件清理

确认日期：2026-10-26。用户在统一 Git 导入后进一步确认：清理过程文件也要进入进度；其他需要分步骤的导入使用同类弹窗。本页补充[Git 导入](git-app-import.md)、[本地目录接入](local-directory-onboarding.md)和完整 project-v1 ZIP 导入的交互规则，不扩大可安装应用类型或改变各自的身份、数据和目录所有权。

## 同一弹窗完成整条流程

表单、实际执行进度、必要确认、错误和最终结果留在同一个弹窗。开始后自动衔接可以自动完成的阶段，避免下载成功后还需用户寻找安装入口。仅执行项目构建脚本、空目录生成或目录预览添加等需要真实选择的步骤停下来等待明确操作。

| 入口 | 实际阶段 | 最后结果 |
| --- | --- | --- |
| 从 Git 导入应用 | 下载源码 → 检查兼容性 → 准备应用 → 安装应用 → 清理临时文件 | 清理完成后显示导入成功，再由用户打开或进入配置 |
| 导入完整项目 ZIP | 读取归档 → 检查内容 → 导入项目 → 清理临时文件 | 核对项目已登记且清理完成后显示导入成功，可查看项目或完成 |
| 添加本地应用 | 选择目录 → 检查项目 → 添加应用 → 完成 | 保留预览／空目录确认，添加成功后由用户打开、进入配置或完成 |

本地应用入口登记外部目录引用，没有下载副本或安装缓存，不添加虚假的清理阶段。空目录生成的起始文件属于用户选定目录，也不当作临时文件删除。独立来源记录与历史安装候选仍保留其明确恢复操作；不因展示方式统一就自动重放历史写入。

进度显示真实阶段和活动状态，拿不到准确百分比时不编造百分比。清理是完成前的实际工作；正在清理时不能先显示所有步骤已完成，也不能把未执行的准备、安装标成成功。必要确认、失败和待核对停在对应阶段。

## 成功、清理失败与结果未知

- 导入成功表示登记完成，而且该入口需要清理的本次临时材料已经处理完成。仅任务接受、下载或准备成功不能替代最终结果。
- 已登记但清理失败时，明确显示“应用／项目已添加，清理未完成”，提供“重试清理”；不把它说成未安装，也不让用户再导入一次。清理成功后进入正常成功页。
- 清理进行中禁用关闭和重复操作。失败／取消后明确清理、重试或更换来源时，也要显示清理的实际进度，等待清理结果后再关闭或开始下一次操作。
- 临时读不到任务或安装是否提交尚不确定时，先核对原任务和当前登记。确认前不重新安装，也不清除恢复依据；重开弹窗不自动执行历史安装。
- “去配置”只打开配置，即使重新读取时配置已经完整也不顺便启动应用。“打开应用”才授权打开；“查看项目”和“完成”不自动运行项目。

## 清理范围

Git 清理继续按 `source_import_cleanup({sourceTaskId})` 的本次来源和安装绑定执行。成功后保留正式源码及 Git、运行程序、数据和配置，失败后仅移除已停止且未被引用的本次材料。最小诊断和清理回执保留。

ZIP 弹窗提交 `project_import` 时明确使用 `cleanupTemporaryFiles: true`。该任务在登记后进入 `cleanup` 阶段，清理本次任务创建的临时根；原 ZIP、已登记项目及其数据库、附件、源码均保留。清理未完成时，通过原生管理命令 `project_import_cleanup({taskId})` 按任务和临时根身份重试，不接受任意清理路径。未明确启用这项清理的既有调用继续沿用原保留规则。

两种清理均先确认相关写入已经结束、范围归属和登记结果。ZIP 任务在自身的 `cleanup` 阶段处理本次临时根；显式重试则要求原导入任务已经结束。其他活动任务、未知提交、目录身份变化会阻止删除。清理失败不能靠关闭界面掩盖，也不能扩大到历史目录、其他导入、业务数据或外部原作者目录。
