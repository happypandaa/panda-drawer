# Node 应用配置声明 v1：实验规范与校验

更新日期：2026-10-20

用户要求将 radio 整理为平台标准应用，首先把应用所需的 Key、地址、语音配置及获取方式写清楚。本轮交付的是**可校验的配置声明和源码范例**；此页不负责运行与保存；后续独立本机槽的通用表单、私有秘密文件与注入见[当前接入](../node-native-configuration.md)，正式安装仍未交付。它不修改现行 project v1 或静态应用包 v1，不把实验格式当作已定稿的完整应用标准。

## 1 标准统一什么

应用作者在根部 `local-app.json` 的 `configuration` 对象声明“需要什么”，用户实际填写值由平台管理。应用声明可以分发，真实 Key 不写进清单、源码或说明。平台的长期秘密保存按[配置契约草案](../node-app-configuration.md)推进，本轮不生成明文配置文件来替代。

统一的是字段结构和运行规则，不要求所有应用都使用固定的 `AI_API_KEY` 或 `FISH_API_KEY` 名称。`name` 必须与该应用后端实际读取的环境变量一致；普通用户看中文 `label`、用途和获取步骤。业务后端负责调用具体服务，平台负责声明、配置与启停管理。

配置类型已经支持：

| 类型 | 适用内容 | 当前检查 |
| --- | --- | --- |
| `string` | 模型 ID、音色 ID、秘密 Key | 非秘密默认值不能空白；秘密字段禁止默认值 |
| `url` | 服务基础地址 | HTTPS，可解析且不含用户名/密码、查询或片段；不自动改域名或拼接 `/v1` |
| `integer` | 数量、预算 | i64 整数；业务上下限由应用检查，尚不支持清单 `min/max` |
| `boolean` | 开关 | `false` 是有效值，不当作缺失 |
| `select` | 固定型号或模式 | 选项值唯一、默认值属于选项；不能动态执行代码取得选项 |

每个字段的必填属性为 `name / label / type / required / secret / description / howToGet`；可选属性为 `placeholder / default / helpUrl / endpointField / options`。版本固定为 `configuration.version: 1`，最多 32 个字段；准确字节预算及保留变量表以 [Rust 读取器](../../crates/platform-node/src/node_app_manifest.rs) 为准。

`required` 表示**整个受管应用启动前必须有有效值**；有合法普通默认值即可满足。当前没有条件必填、功能分组、折叠高级设置、用户校验脚本或任意正则字段，不能在清单自行加属性假装平台已支持。

## 2 radio 的六项声明

radio 当前清单保留六项真实使用的变量，技术名称沿用已有代码，独立版的旧兼容读取继续保留。

| 用户看到的设置 | 实际变量 | 规则与默认 |
| --- | --- | --- |
| AI 服务地址 | `ANTHROPIC_BASE_URL` | 必需，预填 `https://api.deepseek.com/anthropic`；应用追加 `/v1/messages`，不能任填 OpenAI 格式地址 |
| AI API 密钥 | `ANTHROPIC_API_KEY` | 必需、秘密、没有默认值；帮助链接指向服务商密钥页面，并引用 AI 地址字段 |
| AI 模型 | `CLAUDE_MODEL` | 必需，预填已实测的 `deepseek-flash`；使用同一服务商的模型 ID |
| 语音生成密钥 | `FISH_API_KEY` | 可选、秘密、没有默认值；留空不调用 Fish，仍可用文字串词和音乐 |
| 主持人音色 ID | `FISH_REFERENCE_ID` | 可选；未设置时不提交音色参数，由服务处理，不保证账号有指定声音权限 |
| 语音生成模型 | `FISH_MODEL` | 可选，预填应用原默认 `s2.1-pro-free`，有明确选项及官方说明；不自动换型号 |

Fish 的实际地址固定为 `https://api.fish.audio/v1/tts`，已写进密钥用途说明。当前代码不读取 `FISH_BASE_URL`，因此不在表单声明一个无效地址。网易云采用同进程游客 SDK，不要求用户填写网易云 URL/Key，真实账号登录仍关闭。

radio 原清单里的接入模式、两套模型/认证/推理别名和预算等七项已从用户声明移除；不要求普通用户理解历史兼容配置。没有更改原 `.env`、真实业务数据或独立版启动配置。此前十三项清单的试验记录保留其原时点，不据此回填历史验证结果。

本轮选择 AI 版 radio 的启动语义：AI Key 未配置时，平台预检应阻止受管启动；Fish 未配置则仅缺语音。底层生命周期夹具仍能无 AI 值启动本地健康检查，这不能绕过正式启动前的配置要求。当前没有秘密保存入口，不能靠在清单写 Key 默认值通过预检。

## 3 开发者怎样检查

编辑辅助文件为 [configuration.schema.json](configuration.schema.json)，只对应 `configuration` 对象；[configuration.example.json](configuration.example.json) 是五种类型的虚构示例，不是可安装应用，也不提供真实服务。

Schema 检查版本、结构、类型和秘密默认值等规则；它无法代替重复 JSON 键、变量名/选项去重、URL 完整语义、跨字段地址引用、默认选项成员关系、UTF-8 字节预算和文件系统检查。Schema 的字符计数与数学整数规则也不代替 Rust 检查。不要给当前严格清单添加 `$schema` 等未支持属性；编辑器单独关联 Schema。

最终使用实验只读检查器，在平台仓库根执行：

```sh
node scripts/rust.mjs run --locked -p platform-core --example node_app_manifest_inspect -- --app /Users/ethan/dev/radio-bob
```

它只读取声明，检查网页入口、后端入口和已声明的两份说明是普通文件，再输出显式配置元数据与普通默认值。不启动 Node、不装依赖、不请求服务、不读取 `.env`、已有用户值或系统凭据，不登记项目或初始化工作区。

当前 radio 的检查结果为：六项声明、四个入口/说明文件通过，`configuration.status=needs-configuration`，`missingRequired=["ANTHROPIC_API_KEY"]`。这是基于作者默认值的预览，缺密钥不影响预览成功退出；正式启动解析则拒绝缺必填值。它不会从先前聊天、Shell 或其他应用补入真实密钥。

当前实验读取器允许省略文档声明，检查器会明确报告未声明；radio 已携带两份独立说明。文件检查不验证正文准确性、完整依赖或可安装性，也不证明网上服务可用。是否已保存用户配置和远端凭据有效性都不在本次检查范围。

## 4 成为正式应用还需哪些步骤

本轮已完成声明、radio 用户说明和开发说明的整理，以及只读检查。后续继续按 [NR 实施顺序](../node-app-implementation-plan.md)：准备完整运行依赖和前端代理适配；实现普通值保存、OS 秘密库及一致启动快照；接入配置表单、启停与类型图标；完成安装和数据生命周期保护后，才正式登记真实应用。

用户最终只需在平台填入自己的 AI Key，需要主持声音时再填 Fish Key；默认地址和模型已由作者声明。这个用户流程目前是交付目标，不能把本轮的开发检查器写成用户已可操作的配置界面。

## 5 本轮验证

2026-10-20：使用 JSON Schema Draft 2020-12 独立引擎核对 Schema；通用示例、radio 六项声明、大小写 HTTPS 和国际化域名共四个正例同时通过 Schema 与 Rust 检查器，十九个错误声明同时被拒。另三项 Schema 不能表达的错误（地址引用不存在、默认值不属于选项、变量名重复）由 Rust 正确拒绝。测试只使用人工值，未读真实凭据、未发业务请求。

radio 新增三个离线集成检查，验证声明的六项变量确实进入真实应用工厂的模拟 AI/Fish 请求、健康检查不触发外部调用、未配 Fish 时返回文字。使用包内 Node 运行全部 **46/46 通过**。核心清单的十项测试包含路径/文档、秘密不读取或输出、缺必填预览和默认值回归；完整核心库 **216 项通过、1 项默认忽略**，全 targets Clippy 和 rustfmt 通过。本轮未重跑被忽略的真实 Node 测试，也未发起真实 AI/Fish 请求；此前真实音乐和 DeepSeek 记录保持原时点。

原始证据与备份只在本机忽略目录 `.test-artifacts/node-radio-config-2026-10-20/` 保留，不携带到发行资源或 Git。Schema 检查引擎仅装在该试验目录，不新增平台运行依赖。radio 没有 Git 仓库，源码清单和说明改动保存在本机；平台只提交自己的检查器、规范与示例，不把 radio 应用源码或试验数据混入平台仓库。
