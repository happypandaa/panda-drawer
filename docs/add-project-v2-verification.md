## 本轮交付

- 首页与空列表并列“新建项目／添加本地项目／从 Git 添加”。Git 表单包含地址即时校验、源码位置、源码／应用／应用数据说明、高级选项和添加前的 AI 评估入口。
- Git 添加同一弹窗显示五步进度，可在下载／准备时后台继续并从任务回到原流程。构建前读取并核对本次实际脚本；明确同意后才执行。相同仓库先提示打开已有应用或另加空数据实例。
- 安装确认后，将完整 Git 源码另行复制发布到当前工作区 `project-sources/<仓库名或安全后缀>/`，绑定为开发源码；运行程序仍是独立的已准备版本。目录冲突不覆盖，重试复用同一发布记录及目录，用户后续源码修改保留。公开工作区迁移同时核对开发绑定与发布回执的新目录身份，外部作者目录不搬动。
- Git 已知失败自动调用本次任务的受保护清理；结果未知或进程未确认停止时保留现场，不能显示“文件已删除”。清理失败与源码发布失败分别重试，不重复安装。新的统一添加任务有独立本机记录，退出重开后核对原任务；只对已确认结束且归属明确的材料清理，已提交应用先核对并补齐源码发布。
- 本地选择采用三步进度，已有登记按路径及目录身份优先提示，不重复添加。界面提供四类结果、最多5个最近目录、重新检查差异、完整路径与后续动作；保留原有生成／登记修订门禁。选中后收紧目录区域，需处理结果获得焦点。
- 共享 AI 帮助覆盖添加前评估、添加失败、启动／更新失败。平台要求从维护文档生成随包正文，并附当前版本、目标、问题和可用诊断。失败按钮先复制说明，再提供全文预览；用户自行发送。网页 AI 可选有限公开材料摘录，文件逐项可取消；已验证 Codex 可打开未发送草稿。外部项目直接交给 AI 修改，不强制先分离运行程序；删除应用数据须先说明影响并取得用户明确同意。
- 启动／更新失败说明与原任务结果绑定；无法核对提交结果时不承诺旧版本未受影响。新的受管应用更新保留可核验的旧程序指针，只有旧程序完整、声明兼容、应用停止且无未解决操作时才显示“退回上一个版本”。退回只切程序登记，不回退数据、配置或源码，不自动启动。
- 设置显示真实项目目录并沿用工作区迁移；卸载前清理确认显示已读取的托管项目名称／路径与外部文件夹数量，实际删除仍由原生清理计划重新核对。

最近目录与上次地址属于按工作区区分的本机界面偏好，不作为登记、目录身份或兼容证据。高级源码检查／恢复入口继续保留，未变成待接入分组。

## 明确边界

- 静态检查不能证明真实协议、依赖、设备、系统权限或主要业务都可用；首次打开仍可能失败。不会因为Node程序在启动途中失败就承诺其数据从未被应用代码改变。
- 现有后端没有可核对的实时下载字节或准确剩余磁盘需求时，只显示真实阶段及等待信息，不虚构数字。Python／Java等分类使用有限工程证据，复杂项目交给AI进一步判断；不声称自动理解任意源码。
- 本轮没有用真实远程Git／在线npm完成整个添加与适配往返，没有实机执行程序退回、硬崩溃／断电、真实工作区迁移、卸载清理、跨平台或干净电脑验收。离线假npm验证的是安装登记、材料保留和收尾，不证明第三方依赖实际运行。
- 待用户同意的构建脚本不记忆长期授权；多应用目录不提供无法核对的自动根选择；无有效旧程序回执时不显示退回按钮。第一版不新增旧数据迁移、通用备份、私有仓库认证或自动向AI发送。

本轮日志和人工样本保存在忽略的 `.test-artifacts/`，不提交源码库；开发应用包同样不提交。
