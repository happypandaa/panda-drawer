# 删除应用与系统废纸篓

更新：2026-10-22。用户确认网页项目和 Node 应用均提供删除入口，取消新删除对平台内部回收站的依赖，改为调用 macOS 系统废纸篓。本文覆盖[原生命周期契约](project-lifecycle-and-workspace.md)中新删除的行为；旧回收项及其证据继续兼容，不自动迁移或清空。

## 删除范围

| 对象 | 移入系统废纸篓的完整目录 | 保留的独立资料 |
| --- | --- | --- |
| 网页项目 | 当前工作区 `projects/<projectId>/`，包括项目源码、SDK、`.git`、数据库及 WAL/SHM、附件、产物和项目内说明 | 工作区外或项目目录外的作者源码、历史备份、迁移副本、操作和恢复现场、外部导出文件 |
| Node 应用 | 固定数据根 `node-apps/<实例UUID>/`，包括受管程序代次与依赖、数据、配置及本机秘密文件、缓存和运行记录 | 旧 v1 登记引用的外部作者源码、独立来源副本、`.installations` 安装候选/现场和其他实例 |

范围由平台登记和固定目录决定，客户端不能提交任意路径。删除不会递归追随符号链接到外部目录。未解决恢复现场仍受保护，不为删除另行绕过。独立历史资料不因所属应用从列表消失而自动清除；已有范围清理按原有确认流程管理。

## 用户确认与 Git 提示

卡片菜单和详情均提供删除。确认界面只保留一个标题、应用名称和一组“取消／移入废纸篓”操作，默认显示完整应用及本机数据会移走、尚无远程 Git 同步的短提醒。完整目录、实际包含及保留资料放在默认关闭的“查看删除范围”中，可随时展开；用户明确勾选核对后才可提交。Node 另使用短期预览绑定实例、登记及目录身份，提交重新检查；不能拿旧预览删除替换后的目录。

删除确认不再叠在完整详情头部和操作按钮之下；正常 Node 详情也只显示一次应用名称。取消保留原配置草稿并恢复入口焦点，离开页签不抢走导航焦点；提交期间仍禁止重复操作和关闭。网页确认沿用相同短提醒和折叠范围。

界面必须说明：

- 当前只有本机 Git 初始化、保存源码版本、历史、分支和源码取回；远程推送、拉取和同步尚未交付。
- 保存到本机 Git 不等于已同步到远端；项目内 `.git` 也在本次移动范围内。未使用 Git、未提交或未推送的工作，应先自行另存或确认已有独立副本。
- 当前源码版本不包含活库、附件和本机配置，不能承诺从 Git 恢复这些资料。Node 外部源码和独立安装副本的归属另行说明，不能把源码仓库当成业务数据备份。
- 应用从列表移除后不提供平台内的一键恢复。文件找回与清空交给系统废纸篓；手动放回文件不承诺自动恢复平台登记或启动。

没有远端核验时只显示“未核实”，不把配置过 remote、本机有提交、工具可用或匿名远端检查成功视为已同步。

## 执行与故障

网页删除继续使用项目操作互斥、请求排空、数据库关闭、会话失效和身份注销。Node 删除要求业务窗口关闭、后台及受管后代确认退出，并与配置、启停和安装提交串行；正在准备安装时拒绝删除。独立旧安装现场继续保留，不因无关历史问题永久阻止健康应用删除。外部编辑器和工具仍需用户停止写入，平台互斥不等于系统沙箱。

原生调用使用 Foundation `NSFileManager.trashItemAtURL:resultingItemURL:error:`，由系统决定同卷废纸篓位置及重名处理。不拼接 `~/.Trash`，不借 Finder 自动化权限，不用 shell 删除，也不在失败时退化为永久清除。尚未实现相应原生能力的平台明确拒绝删除并保留文件。

调用前持久写入目录身份与意图，成功后记录系统返回位置并核对目标身份及原路径。返回未知或中断不自动重复删除；原目录消失本身不足以认定成功。任务、注销和最小回执保留在应用目录外，用于旧页面失效与故障核对，不构成另一份平台回收副本。

系统废纸篓由用户和系统管理，平台不保证文件永久保留。找回文件后需重新核对登记状态；Node 整槽放回原位置时可重新被扫描发现，但不自动启动。系统接口失败、停机无法确认、路径身份改变及预览失效均应准确呈现。

工作区只读响应中的 `projectDeletionMode: "system-trash"` 标记新删除语义，供验证脚本区分历史平台回收流程。它不赋予任意文件删除权限，也不承诺所有系统均已接入原生移动。
