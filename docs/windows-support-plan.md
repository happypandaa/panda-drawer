状态：v0.1，Windows 10 22H2 x64 与 Windows 11 x64 支持目标已确认；适配方案和 W1–W4 计划已整理，尚未实施、构建或实际验收

更新日期：2026-10-18

用户于 2026-10-18 确认两个 Windows 系统均作为产品支持目标，并要求先整理方案与里程碑、暂时不写代码。本轮只更新规划文档，不新增程序实现、安装包、CI 配置或测试样本。本文中的“建议”“待定”不因支持目标已确认而自动成为正式契约。

Windows 10 的系统安全维护与本产品兼容性分别记录。微软目前列明 Edge/WebView2 在 Windows 10 22H2 上至少更新至 2028 年 10 月；这不构成本产品的发行日期或维护期限承诺，也不替代系统补丁与 ESU 状态检查。W1 及每次发行前重新核对[微软生命周期](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-support-lifecycle)。

## 2 共用核心与平台适配边界

保持一套项目格式、SDK/API v1 和业务规则。Windows 10 与 Windows 11 共用 Windows 实现；只在已证实存在系统差异的地方增加兼容处理，不分别维护两套产品分支。

| 层次 | 共用部分 | Windows 适配任务 |
| --- | --- | --- |
| 管理与项目界面 | React、项目状态、任务和错误展示 | 窗口菜单、托盘、缩放、键盘交互与原生对话框 |
| 本地服务 | Axum、SQLite、SQL/事务、会话、文档代次、任务协议 | 系统目录、用户私有权限、单实例与本机发现文件保护 |
| 文件及持久操作 | 快照校验、恢复/迁移提交规则、清理预览与回执 | HANDLE、卷/文件身份、ACL、文件占用、重解析点、安全发布与持久化 |
| 项目构建 | 固定 SDK、输入摘要、失败保留旧产物、任务日志 | Node/npm 定位、PATH、带空格/中文路径、构建进程树停止与异常退出 |
| AI 交接 | 项目路径、schema、CLI 能力与接管 skill | 实际 `.exe` 位置、PowerShell 可执行示例、参数转义与环境诊断 |
| 桌面宿主与网页 | 管理/项目权限分隔、HTTP CSP、用途声明 | WebView2 管理页面来源识别、导航/下载/剪贴板和媒体许可回调 |
| 发行 | 版本、包内资源校验、兼容与数据保留规则 | Windows 资源布局、安装器、代码签名、运行中更新及卸载行为 |

建议建立小范围系统适配层，集中处理安全文件操作、进程、工具链发现、系统打开、目录与安装布局。不能通过关闭现有安全检查、为 Windows 返回假成功或到处补条件分支来达到可编译。

只读审查发现：文件、下载和历史清理使用 Unix 文件描述符与身份；构建发布的非 Mac 路径返回不支持；迁移检查要求 APFS；Node/npm 查找、进程组停止、`/usr/bin/open`、管理页面来源及打包脚本存在 Mac 专用逻辑。具体落点包括 `crates/platform-core/src/{files,paths,builds,environment,workspace,history_cleanup}.rs`、`apps/desktop/src-tauri/src/{main,browser_download}.rs` 与 `scripts/prepare-desktop.mjs`。这是移植清单，不表示已运行 Windows 证明这些修复有效。

### 2.1 文件、凭据与故障保护

- Windows 使用适合该系统的卷/文件身份和用户私有 ACL；Mac inode、POSIX mode 不直接当作 Windows 身份和权限。涉及控制文件格式演进时明确版本，保留旧状态并提供恢复证据。
- 处理保留名称、尾点/尾空格、大小写与 Unicode 冲突、长路径、ADS、盘符及路径别名；目录链接与 junction/reparse point 不可绕过项目边界。
- 预检后执行仍须核对对象身份，历史清理不能退化成对字符串路径递归删除。部分失败展示实际完成范围，保留重试/恢复所需回执。
- 构建、附件、恢复和迁移在文件被占用、杀进程、磁盘不足及目标失联时保持明确状态；不能丢旧产物、把坏库当空库、自动解除维护或重放未知结果的写入。
- 迁移提交后只认可新根，目标不可用不自动回源；所有历史清理继续使用范围预览、明确确认及既有保护规则。

Windows 的命名与文件替换规则以[微软命名说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)和[文件替换说明](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files)为依据。进程树管理可评估 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)，实际退出与子进程残留必须验证。

### 2.2 运行环境与浏览器

成品运行、新建预编译初始项目及已有产物读写无需 Node、Rust 或 Visual Studio 开发工具。系统 Node/npm 仅参与构建；沿用最低 Node 22.12.0、支持 22/24、推荐 24 LTS 的现有约定，W1 核对实际依赖组合及两版 Windows 的最低系统要求，不借移植擅自提高支持线。

WebView2 是桌面网页运行环境，不能用安装了 Edge 浏览器来代替运行环境检测。建议使用 Evergreen，并在缺失、版本不足、安装失败或被策略限制时提供可理解诊断；在线安装、离线运行环境安装、首次 npm 依赖下载是三个不同场景。依据为[微软分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。

媒体格式运行时探测；用途声明、网页许可和 Windows 系统隐私开关分别生效。桌面 WebView2、普通 Edge 与 Chrome 分别验证，不因都使用 Chromium 就合并结论。关闭窗口、隐藏页面、维护、拒绝、许可等待和晚到许可均核对设备释放与写入门槛。

## 3 项目交换与工作区迁移

跨系统先验证完整单项目 ZIP：Mac 导出 → Windows 导入 → 使用及修改 → Windows 导出 → Mac 导入。已有归档结构继续携带源码、固定 SDK 原字节、锁文件、清单/图标、当前产物、SQLite 一致性副本和附件；业务主键保持，原 ID 导入冲突时不覆盖，副本使用新项目 ID。

依赖在目标系统重新安装，不搬运行机器的 `node_modules`、构建缓存、管理令牌或绝对 CLI 路径。允许符合现有维护与来源规则的完整产物免 Node 打开，不能要求为了换系统一律重建；包含平台专用脚本的用户项目仍须实际构建验证。导入不运行脚本，不自动升级固定 SDK 或重写用户 README；重新生成的交接信息优先给当前机器实际路径与命令。

导入前预检目标系统不兼容名称和碰撞，失败保留原 ZIP 和现有项目，报告具体文件；不静默改名、覆盖或丢弃内容。

整工作区迁移仍指同一台电脑上的公开迁移流程。Mac 的 APFS 支持条件继续有效，Windows 对应文件系统和路径规则待 W1 确定、W3 验收。跨电脑整工作区格式、控制记录移植、实时同步和工作区合并不在现有契约中，不能用直接复制工作区控制树代替项目导入。

## 4 与 M0–M6 的关系

主里程碑仍为 M0–M6 共 7 个，不重编号，不把 Mac 历史结果改写成跨平台结果。W1–W4 是 Windows 的适配和验收工作线，映射既有能力与 M6 分平台发行门槛。

| Windows 阶段 | 对应主阶段 | 主要交付与退出条件 | 前置 | 当前状态 |
| --- | --- | --- | --- | --- |
| W1 系统适配与工程基础 | M0、M1 基础 | 确定待定支持边界；Windows 原生构建/CLI/内部包、系统适配基础、安全文件与凭据；两版系统实际启动，Mac 相关回归通过 | 本规划；后续开工指令及 Windows 环境落实 | 未开始 |
| W2 项目与外部 AI 完整流程 | M1、M2，提前探测 M5 | 创建、无 Node 打开、SQL/附件、AI 交接与构建、取消、重启保留；桌面与浏览器分别跑通，并提前探测真实媒体权限 | W1 | 未开始 |
| W3 生命周期、可移植与恢复 | M3、M4、历史清理 | 备份/恢复、双向 ZIP、复制、回收站、同机迁移、清理 GUI 和中断恢复，逐项证明受保护数据保留 | W2；安全基础不能延至本阶段才实现 | 未开始 |
| W4 浏览器、安装与发行验收 | M5、M6 Windows 门槛 | 两版系统的真实 WebView2/Edge/Chrome 矩阵、设备与断网恢复；签名安装、升级、卸载保留、非开发用户试用，交付可核验安装包 | W3；发行资源与签名条件落实 | 未开始 |

W1 → W2 → W3 → W4 为主要顺序。平台边界设计、测试设备准备和不依赖 Mac 未完成设备项的工作可独立推进；涉及共享数据格式或接口的修改统一协调。媒体可行性在 W2 提前探测，不能全部拖到发行前才发现不兼容。

本轮只完成规划整理，不视为 W1 开工或通过；不设置未实测的工期、完成比例或发行日期。任何 Windows 阶段都不授权使用现有 Mac 用户项目做破坏性测试。

### 4.1 W1：平台基础

1. 记录 Windows 10 22H2 x64、Windows 11 x64 的实际版本、补丁、用户权限、磁盘、WebView2、Node 和开发工具；核对 Rust/Tauri/依赖最低系统要求。
2. 确定第 6 节中阻塞实现的安装、磁盘、数据目录及凭据权限方案；产出系统适配边界与兼容控制格式说明。
3. 在 Windows 原生环境建立构建、检查与 CI，生成平台和 CLI 的 x64 内部包，修正 Mac 专用入口、来源校验及资源定位。CI 配置在正式进入实现后再写。
4. 两版 Windows 以普通用户实际启动，验证单实例、服务发现、管理/项目权限分隔、系统打开与正常退出；不依赖开发终端 PATH。
5. 安全文件访问、用户私有凭据和失败保留基础具备真实测试后再进入 W2；相关 Mac 回归同时通过。

Windows 原生编译、CI 或虚拟机适合构建与自动化，不能代替目标系统的设备和安装实测。Apple Silicon 上 Windows ARM 虚拟机中的 x64 模拟结果不能单独证明 x64 实机及驱动兼容。Tauri 建议优先使用 Windows 原生/虚拟机/CI 构建，见[Windows 安装器](https://v2.tauri.app/distribute/windows-installer/)。

### 4.2 W2：真实使用流程

两版系统分别使用明确命名的可丢弃项目，完成创建 → 直接打开初始应用 → 复制给 AI → 独立外部 AI 读取 skill/README/schema → 修改页面与数据 → 构建并等待 → 桌面与普通浏览器读写 → 关闭 AI、完整退出平台 → 重启复核。

补验无 Node/无网络时创建和使用已有产物；构建环境缺失有明确提示。构建失败、输入变化、取消、超时及退出保留旧产物，检查 npm 等子进程树无普通残留。覆盖中文、空格和带引号路径以及从桌面启动时的 Node/npm 发现，确认 PowerShell 交接命令可由无原对话上下文的 AI 使用。

提前在真实 WebView2 中探测文件保存、许可请求/拒绝和短录音拍照；记录不可用原因，不以模拟设备填补结论。

### 4.3 W3：数据与生命周期

- 备份恢复包含源码、SDK、图标、数据库和附件；正常/维护/未知来源状态均按原契约保留。
- Mac ↔ Windows 双向 ZIP 核对文件摘要、业务主键、附件、固定 SDK 和可用产物；验证原 ID 冲突、新 ID 副本及目标路径不兼容拒绝。
- 复制内容独立，删除/恢复使旧页面失效；永久清除只影响明确对象，现有备份和受保护恢复现场不被顺带删除。
- 通过公开入口同机迁移，覆盖复制、校验、提交前后中断及目标不可用；固定发现位置、凭据隔离、维护与代次符合契约。
- 真实 GUI 检查历史清理入口、范围与字节预览、保护原因、取消、明确确认、部分失败及完成结果。只永久清理本轮可丢弃样本的已审计范围。
- 使用受控故障覆盖占用文件、重解析点/对象替换、磁盘不足、拒绝访问及进程中断，逐项核对原项目、备份、回收项和恢复证据。受控中断不标作硬件断电实测。

### 4.4 W4：浏览器与发行

每个 Windows 系统分别记录桌面 WebView2、Edge、Chrome 的实际版本和结果：文件选择/拖入/下载、主动剪贴板、录音/拍照/回放/保存、权限允许与拒绝、许可等待与取消、系统隐私阻断、设备释放、关闭/隐藏/维护中断、物理断网后的本地保存与外网恢复。

正式发行还需：签名与实际安装包核对；WebView2 已装/缺失/版本不足和部署失败；首次及离线启动；无开发工具/无 Node 使用；旧版覆盖、运行中更新协调、持久维护及恢复日志保留；卸载默认保留数据、重装重新发现；非开发用户完成主流程。离线首次安装仅在明确采纳对应分发范围后纳入交付，不与离线使用混淆。

Windows 安装器与版本信息明确列出两个支持目标和 x64，附实际摘要及已知限制；代码签名不承诺消除所有 SmartScreen 或企业策略提示。Mac 发行继续独立核验 `.app` / DMG、Developer ID、公证、最低系统及设备，不能用 Windows 通过代替。

## 5 验收证据、开发数据与提交规则

每个阶段记录代码版本、系统构建号、CPU、文件系统、WebView2/浏览器/Node 版本、安装包身份与摘要、可丢弃项目 ID、操作步骤、预期/实际结果及未完成项。区分源码测试、CI、真实服务、GUI 和真实硬件；未执行、失败或工具不可达均不标通过。

Windows 使用独立测试数据与目标实例；保留现有 Mac 开发标识 `dev.localprojects.platform.m0`、固定数据根及当前工作区指向。不重建现有开发环境、不直接改迁移日志、不升级旧项目的源码、固定 SDK、锁文件或文档，不清除备份、维护、回收站及恢复证据。测试前后核对受保护范围，清理只用已确认的公共流程。

进入实施后，每个完整步骤通过相关检查即 commit、push；不混入未完成并行工作、凭据、生成的安装包或本地验证证据。文档规划提交与未来代码交付分别记录。本轮只提交文档，不生成或重新交付 `.app`、DMG 或 Windows 安装包。

## 6 实现前需要落实的选择与条件

| 事项 | 当前建议或问题 | 最晚落实阶段 |
| --- | --- | --- |
| 安装形式与权限 | NSIS、当前用户安装；是否需要额外企业或便携形式另定 | W1 |
| Windows 文件系统及位置 | 本机 NTFS；内置/直连外置盘、长路径、重解析点和同步目录检测边界 | W1 |
| 本机目录及权限 | 系统 API 获取用户本地应用数据目录；固定发现位置、私有 ACL、安装与数据分离 | W1 |
| WebView2 | Evergreen 与最低版本；在线引导及失败行为；是否另交离线安装包 | W1，W4 复核 |
| 支持矩阵与设备 | Win11 具体测试版本、两版 x64 测试环境、普通用户及真实摄像头/麦克风 | W1 建立，W2 提前探测，W4 完整验收 |
