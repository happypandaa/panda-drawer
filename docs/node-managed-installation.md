# Node 源码副本、安装与更新

更新：2026-10-22。本页描述本轮新增的内部安装子集；实际原生验收另见[三场景记录](three-scenario-verification.md)。既有[外部目录登记](node-native-configuration.md)继续兼容，不自动迁移或改写。分享与通用应用包下载不在本步范围。

## 从来源到应用

1. “添加 → 获取项目源码”可获取公开 GitHub/Gitee HTTPS 仓库，也可先检查本机目录，再明确“接入此目录的源码副本”。检查本身不复制。每次获取或接入创建独立来源记录，不覆盖作者目录，不登记应用，不执行项目代码。
2. “查看安装候选与准备安装”只接受已完成、摘要匹配且检测为 Node 服务源码的来源。准备在独立目录复制普通程序文件，使用选定的开发 Node/npm 执行 `npm ci --omit=dev --ignore-scripts`。不运行应用、不读写目标业务数据、不使用作者的 `node_modules`、`.env` 或 npm 凭据。
3. 准备成功表示材料已就绪。核验应用、来源和候选后，另行确认安装；程序进入新的随机实例槽。安装提交不启动应用，配置缺失仍须填写后才能打开。
4. 已安装应用详情中可明确选择更新来源。准备时记录旧程序代次、登记与配置修订；提交时必须仍一致、应用已停止且没有业务窗口或待清理进程。用户须正常关窗，平台不代替用户偷偷停止或重启。
5. 普通更新保留实例 UUID、数据、配置和窗口尺寸，只切换程序代次。再次明确打开时使用新版。更新只支持相同应用标识和完全相同的配置声明；不自动转换业务数据，也不能从清单证明新旧业务数据格式兼容。

准备和提交分别有持久任务。准备支持请求取消，必须等待最终状态；确认安装不提供伪装的“撤销提交”。成功、未提交、已提交但收尾异常及无法确认分别呈现；无法确认时先核验记录，不自动重复安装。关闭面板后可从保留记录继续核验候选，失败和中断现场保留。

## 当前可接受材料

源码必须带有效 `local-app.json`，声明静态网页和一个受管 Node 服务，后端入口为可直接执行的 JavaScript。根目录或声明的后端目录必须恰好有一组受支持的 `package.json` 和 npm v2/v3 锁文件。安装只准备生产依赖，不执行生命周期脚本或任意构建命令。

依赖声明限普通 registry 版本／范围；Git、file、workspace、别名、原生扩展、额外安装脚本及需要前置转译的材料不在这一子集。普通 HTTPS 锁定资源也必须通过输入和安装后内容校验。准备成功不能证明所有动态加载、外部服务或任意依赖运行兼容。应由可信作者先准备前端产物并在目标平台实际运行验证。

本机源码接入排除已知数据、附件、数据库文件、配置／凭据、Git 控制、依赖、备份、回收和缓存路径；project-v1 的声明输出目录也排除，Node 的 `public` 和运行 `dist` 保留。声明依赖于已排除目录时报告需要适配。未排除的符号链接、硬链接、特殊文件及路径碰撞拒绝接入。未知文件可能仍含私人内容，平台不承诺通用秘密识别或数据脱敏。

安装材料和候选具有内容与执行权限摘要；提交前重新校验。它们仍是当前用户权限下的可信本机代码，不是系统安全沙箱。应用运行时可使用自己的 `APP_DATA_DIR`，不得把保存数据写到不可变程序目录；平台不替 Node 接管业务数据库格式。

当前内部准备预算为10分钟，最终程序最多512MiB、50,000个文件、单文件64MiB。npm 运行期间另按元数据周期检查整个准备现场（包括缓存）：总逻辑大小1GiB、100,000个目录项、磁盘剩余至少64MiB；超限或无法核对时停止所属进程并保留现场。检查间隔至少250毫秒且须等待上一次扫描完成，不是操作系统硬配额，也不保证任意下载峰值都不越过阈值。这些数值尚非正式产品限额。

## 持久位置与兼容

| 位置 | 内容与生命周期 |
| --- | --- |
| 工作区 `.platform/sources/src_<UUID>/` | 来源记录及独立源码副本；参加公开工作区迁移 |
| 固定数据根 `node-apps/.installations/install_<UUID>/` | 安装准备、npm 缓存及提交日志；失败和中断保留 |
| 固定数据根 `node-apps/<UUID>/generations/<代次>/` | 已安装的独立程序及生产依赖；运行不再依赖作者或来源目录 |
| 同槽 `registration.json` | v2 受管登记及当前程序代次，原子写入为提交点 |
| 同槽 `data/`、`configuration/`、`cache/`、`runs/` | 沿用既有运行和配置规则；准备／切换程序不覆盖业务数据或配置 |

旧 v1 登记仍引用原外部目录，不被自动改成受管安装，不支持直接用此入口覆盖；可通过独立来源安装为新实例，旧槽继续保留。Node 槽不在 project-v1 的工作区迁移、ZIP 导出或回收范围内。没有公开删除安装现场的入口，本轮样本和残留须登记供后期处理。

## 管理入口与协调

本机接入另有 CLI `source capture --path /绝对路径 [--name 名称] --json` 和管理 HTTP `POST /api/v1/sources/captures`（`sourcePath`、可选 `name`）。结果为 `sourceCapture` 任务，仍通过原来源查询及取消接口观察。

安装使用原生管理命令 `node_install_prepare`、`node_install_candidate`、`node_install_list`、`node_install_issues`、`node_install_cancel`、`node_install_apply`，仅管理窗口可调用。没有可绕过原生窗口锁的 HTTP／CLI 提交入口。准备持来源租约，工作区迁移等待它；服务退出先通知停止准备，再等待已开始的迁移完成，并停止迁移后的服务状态。

执行成功与原生使用验证分别记录。自动测试只证明其覆盖的复制、依赖、提交、冲突和进程收尾边界，不代替真实原生配置、关窗、更新或硬崩溃验证。
