## 从来源到应用

本页的独立源码副本安装与[“添加本地应用”的目录流程](local-directory-onboarding.md)分开。后者对空目录先确认生成起始 Node 项目，对现有有效 Node 应用先预览再登记为外部引用，对其他目录只复制完整 AI 检查说明；不复制或自动适配该外部目录。已有目录检查不写 skill、安装依赖或启动服务；缺声明不证明一定能适配。只有进入下面的独立副本准备／安装流程才产生受管安装材料。

1. 普通入口为“添加 → 从 Git 导入应用”，接受公开 GitHub/Gitee HTTPS 仓库。在开始导入时说明下载、依赖准备及安装新实例，在同一界面串联下载、检测、准备、核验和提交；成功后可打开或进入必填配置。用户无需重新选择刚下载的来源和安装候选。详细交互及清理规则见[统一导入契约](git-app-import.md)。底层获取本身仍不登记应用、不执行代码。
2. 准备只接受已完成、摘要匹配且检测为 Node 服务源码的来源。声明 npm 构建时须另行明确同意，在隔离目录运行声明的脚本；普通准备请求不能隐式执行，可信已构建产物也不再次执行。更新在任何 npm 操作前核对应用、配置及数据声明。随后在独立目录复制程序，使用选定开发 Node/npm 执行 `npm ci --omit=dev --ignore-scripts`。不运行应用、不读写目标业务数据、不使用作者的 `node_modules`、`.env` 或 npm 凭据。
3. 准备成功表示材料已就绪，底层仍需重新核验来源、候选和应用身份后才能提交。统一新实例导入在开始时已明确授权，系统自动衔接最终提交；“源码记录与恢复”及现有更新入口仍逐步准备、核验和明确确认。程序进入新的随机实例槽，安装提交不启动应用，配置缺失须填写后才能打开。本机源码检查、独立副本接入和旧候选核对由“源码记录与恢复”保留；检查本身不复制，不覆盖作者目录。
4. 已安装应用详情中可明确选择更新来源。准备时记录旧程序代次、登记与配置修订；提交时必须仍一致、应用已停止且没有业务窗口或待清理进程。用户须正常关窗，平台不代替用户偷偷停止或重启。
5. 普通更新保留实例 UUID、数据、配置和窗口尺寸，只切换程序代次。再次明确打开时使用新版。更新要求相同应用标识、完全相同的配置声明，且新旧双方的数据契约标识及版本均已声明并完全一致；不自动转换业务数据。声明匹配是作者的兼容承诺，不能证明实际业务数据格式兼容。

准备和提交分别有持久任务。准备支持请求取消，必须等待最终状态；确认安装不提供伪装的“撤销提交”。成功、未提交、已提交但收尾异常及无法确认分别呈现；无法确认时先核验记录，不自动重复安装或清理依据。关闭面板后可从保留记录继续核验候选，重开不自动安装。新统一导入按本次任务清理已结束的临时材料：成功后保留正式源码，失败／取消可明确清理并关闭；清理失败展示残留及重试。既有独立来源、更新和未解决恢复依据继续保留，不批量套用新规则。

## 当前可接受材料

源码必须带有效 `local-app.json`，声明静态网页和一个受管 Node 服务，后端入口为可直接执行的 JavaScript。根目录或声明的后端目录必须恰好有一组受支持的 `package.json` 和 npm v2/v3 锁文件。安装阶段只准备生产依赖，不执行生命周期脚本或任意构建命令；声明式开发构建另走[明确构建流程](node-development-workflow.md)。

依赖声明限普通 registry 版本／范围；Git、file、workspace、别名及第三方 Node 原生扩展（`.node`，不区分大小写）不在这一子集。需要转译的源码须先经清单声明的显式构建流程准备。普通 HTTPS 锁定资源也必须通过输入和安装后内容校验。

安装完整保留 SDK 和跨系统依赖资源，不因包内带 `.exe`、`.dll`、`.so` 或 `.dylib` 就拒绝或裁剪。它们与普通文件一样参加内容、执行权限、路径、链接及空间预算校验。安装器不执行这些工具、不注册系统服务，依赖生命周期脚本仍关闭。携带文件不代表其执行或加载已受支持；额外服务、原生编译及目标系统兼容仍须单独验收。Node 是可信本机代码，并非沙箱，平台没有承诺拦截应用自行调用子进程。准备成功不能证明所有动态加载、外部服务或任意依赖运行兼容。

本机源码接入排除已知数据、附件、数据库文件、配置／凭据、Git 控制、依赖、备份、回收和缓存路径；project-v1 的声明输出目录也排除，Node 的 `public` 和运行 `dist` 保留。声明依赖于已排除目录时报告需要适配。未排除的符号链接、硬链接、特殊文件及路径碰撞拒绝接入。未知文件可能仍含私人内容，平台不承诺通用秘密识别或数据脱敏。

安装材料和候选具有内容与执行权限摘要；提交前重新校验。它们仍是当前用户权限下的可信本机代码，不是系统安全沙箱。应用运行时可使用自己的 `APP_DATA_DIR`，不得把保存数据写到不可变程序目录；平台不替 Node 接管业务数据库格式。

## 数据契约与旧声明

Node `formatVersion: 2` 清单可声明顶层 `dataContract: {"id":"org.example.notes-data","version":1}`，表示应用对 `APP_DATA_DIR` 中业务数据的读写格式承诺。`id` 为 1–128 个 ASCII 字母、数字、点、下划线或连字符，首位须为字母或数字；`version` 为 1–2147483647 的整数。字段一旦出现必须完整有效，不接受 `null` 或额外键。它独立于应用版本与配置声明版本，不适用于静态 v1 格式。

准备更新时在执行 npm 前检查；保留候选重新核验、提交前及原生提交锁内再次检查。双方都有声明但标识或版本不同，返回 `NODE_INSTALL_DATA_INCOMPATIBLE`；任一方未声明，返回 `NODE_INSTALL_DATA_COMPATIBILITY_UNKNOWN`。错误只提供新旧声明，不读取业务数据来推断格式，也没有强制更新、自动迁移或回滚入口。拒绝时旧程序、数据和配置保持原样，候选证据保留。

缺少字段的旧应用继续读取、打开和配置，不自动改写清单、登记或数据。新建独立实例仍允许未声明的旧材料，但其后普通更新会因无法核对数据契约而停止；相同应用标识和配置不能替代数据声明。不能直接编辑已安装清单补猜测版本，原有摘要门禁继续生效。历史已提交结果仍可读取，旧版留下的未提交候选必须通过现行检查。界面仅显示“数据声明匹配”或“未声明”，不称已验证数据格式。

当前内部准备预算为10分钟，最终程序最多512MiB、50,000个文件、单文件64MiB。npm 运行期间另按元数据周期检查整个准备现场（包括缓存）：总逻辑大小1GiB、100,000个目录项、磁盘剩余至少64MiB；超限或无法核对时停止所属进程并保留现场。检查间隔至少250毫秒且须等待上一次扫描完成，不是操作系统硬配额，也不保证任意下载峰值都不越过阈值。这些数值尚非正式产品限额。

## 持久位置与兼容

| 位置 | 内容与生命周期 |
| --- | --- |
| 工作区 `.platform/sources/src_<UUID>/` | 来源记录及独立源码副本；参加公开工作区迁移 |
| 固定数据根 `node-apps/.installations/install_<UUID>/` | 安装准备、npm 缓存及安装／提交状态；不另存npm输出日志，失败摘录随既有任务错误展示，失败和中断材料保留 |
| 固定数据根 `node-apps/<UUID>/generations/<代次>/` | 已安装的独立程序及生产依赖；运行不再依赖作者或来源目录 |
| 同槽 `registration.json` | v2 受管登记及当前程序代次，原子写入为提交点 |
| 同槽 `data/`、`configuration/`、`cache/`、`runs/` | 沿用既有运行和配置规则；准备／切换程序不覆盖业务数据或配置 |

旧 v1 登记仍引用原外部目录，不自动改写。原声明摘要仍匹配时，明确展开开发入口会保存原声明与源码身份；此后可经独立构建、核验候选和明确更新，切换为相同 UUID 的受管运行副本，原源码、数据、配置与窗口身份保留。原声明已失效时不猜测旧配置；缺数据契约的旧实例不能通过该流程绕过更新门禁。也可将独立来源安装为全新实例，原槽继续保留。Node 槽不在 project-v1 的工作区迁移、ZIP 导出或旧回收范围内。独立安装准备、失败及更新证据不随删除应用一起清理；新统一导入只提供本次任务的受保护临时材料清理，不提供任意目录删除入口。2026-10-26 起，已结束的安装现场、被替换的旧程序版本和不再被引用的源码副本可在“历史资料”中逐项核对后显式清理，规则见[历史清理](history-cleanup.md#可清理的历史资料2026-10-26)；当前程序、未结束的安装和仍被引用的源码不会列为可清理。

## 直接删除实例

2026-10-23 用户确认：受管安装确认后直接永久删除选中实例的登记、程序代次、业务数据、本机配置和秘密、缓存，不进入平台或系统回收站。独立来源记录／源码副本、安装／更新证据、其他实例、旧备份和旧回收／恢复现场继续保留。对于旧外部目录引用，只移除平台登记和私有配置／数据／缓存，引用的整个外部目录保持原样。旧 `runs/` 恢复记录及 `node-apps/.deletions/` 删除回执继续保留，不递归清空整个槽。详见[删除契约](application-deletion.md)。

删除前展示名称、实例 ID、所有权、实际删除及保留路径并提示不可撤销，用户须先关闭业务窗口。原生 `node_app_delete_preview({appId})` 返回当前 `expectedRevision`，确认后 `node_app_delete({appId,input:{expectedRevision}})` 再核对修订与运行状态；停不下的受管进程、尚未关闭的业务窗口或身份不符会阻止删除；最终安装提交与删除共用原生操作锁，已删除实例的旧更新候选不能重新登记它。取消不改变文件，部分失败保留诊断及残留范围，不能报告已完整删除。没有新增 Node HTTP／CLI 删除入口。

## 管理入口与协调

本机接入另有 CLI `source capture --path /绝对路径 [--name 名称] --json` 和管理 HTTP `POST /api/v1/sources/captures`（`sourcePath`、可选 `name`）。结果为 `sourceCapture` 任务，仍通过原来源查询及取消接口观察。

安装使用原生管理命令 `node_install_prepare`、`node_install_candidate`、`node_install_list`、`node_install_issues`、`node_install_cancel`、`node_install_apply`，仅管理窗口可调用。没有可绕过原生窗口锁的 HTTP／CLI 提交入口。准备持来源租约，工作区迁移等待它；服务退出先通知停止准备，再等待已开始的迁移完成，并停止迁移后的服务状态。

执行成功与原生使用验证分别记录。自动测试只证明其覆盖的复制、依赖、提交、冲突和进程收尾边界，不代替真实原生配置、关窗、更新或硬崩溃验证。
