## 独立 AI 与桌面/浏览器交接

第一会话已完成：使用 Codex 桌面中的独立上下文代理，仅获得平台生成的交接文本与业务需求，禁止读取或修改平台源码。它通过已打包的原生 CLI 操作项目，并使用 CUA 后台 IAB 调试网页。这是实际代理工具调用验收；没有把手工测试 fixture 冒充 AI 生成结果，也没有宣称验证了独立 Codex CLI 或 Claude Code 客户端。

项目为 `prj_723e8302b59a4ea5a3c9ff1adc2daa66`（“M2 英语学习 · AI 交接验证”）。首个构建 `task_21d72169d89947b681c087b575b8df37` 已成功，实际使用固定 SDK 0.1.0 和平台 CLI，数据库由空库创建业务 words 表。后续修订构建为 `task_19d52443fa234f389b26625ad9339eed`，同样成功。

第一会话验证了 browser-grape/葡萄 的真实表单保存与整页刷新、中文搜索、掌握状态持久化、大小写重复拒绝，以及新版通知保留未提交草稿。IAB 在带确认的刷新操作中自动化通道超时，此额外确认对话框用例未记为通过；新浏览器入口能够打开最终页面。项目文档已记载此限制。

桌面独立窗口读到了 browser-grape，并保存 desktop-pear/梨。返回管理窗口后重复打开，仍保留 unsaved-desktop 输入，未创建第二个窗口。完整退出后 CLI 确认服务离线；用最终包重新启动后，两条记录及原始 3 条演示记录均在。构建边界项目中无 Node 时写入的记录也仍在。通过平台的“在浏览器打开”入口，普通 Chrome 显示同一份 5 条数据。
