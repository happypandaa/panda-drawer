| 版本管理 | 当前尚未集成 Git；后续按已确认技术计划接入标准 Git，未交付版本操作、数据库 Git 保存／取回或自动数据库迁移 |

第一版以单机个人使用、自行创建的项目为目标。跨设备同步、多人协作、第三方应用市场、定时任务及平台内置 AI 对话不在本约定范围内。用户应用的受管 Node 后端已作为新增方向确认，现有静态 v1 契约不自动获得后端执行能力。应用作者负责 AI 等联网业务的 SDK、接口适配和配置说明；当前独立本机槽已接私有 Node、配置表单、本机私有秘密文件与启动注入，完整安装、归档及生命周期仍未交付。秘密不交给项目网页，目标 Node 后端读取自身注入值；受管本机进程不是沙箱，不将安装或运行用户代码描述成恶意应用隔离。

桌面框架为 Tauri 2，本地服务使用 Rust，数据库使用原生 SQLite。Mac 原首发方案继续有效，新增 Windows 10 22H2 x64 和 Windows 11 x64 支持工作线；各平台发布前分别验证最低支持系统与目标设备，框架可编译范围不自动扩大产品支持范围。平台共享业务、SDK 和项目格式，系统文件、进程、工具链及桌面集成分别适配；具体路线见[Windows 规划](windows-support-plan.md)。

平台常驻运行能力由原生程序提供；project-v1 构建使用服务选定的受管或显式本机 Node/npm。不安装系统 Node 也能创建并打开带初始应用的新项目，以及浏览和操作已有静态网页的项目。当前 Mac 内部 Node 槽使用私有运行时，不要求用户另装 Node，但作者仍须事先准备程序与依赖，不代表标准安装及跨系统交付已完成。Tauri 使用系统 WebView，平台无需随应用分发完整浏览器引擎，详见 [Tauri 架构说明](https://v2.tauri.app/concept/architecture/)。需要分别验证桌面 WebView 与实际承诺的浏览器兼容性，标准应用入口为唯一原生窗口，不能用浏览器测试替代桌面测试。

## 2 平台、项目和外部 AI 的职责

| 参与方 | 负责的内容 |
| --- | --- |
| 平台 | 创建和识别项目、提供本地网页服务、管理 SQLite 和附件、提供 SDK 与 AI 工具、探测构建环境并管理任务和日志、备份恢复、运行需求展示及统一空间管理 |
| 项目 | 页面、交互、业务规则、数据模型、对平台接口的调用，以及项目文档 |
| 外部 AI | 阅读文档和实际表结构、修改源码和数据、调用构建、查看错误、通过浏览器验证、同步维护说明 |

用户点击项目后，平台提供构建后的 HTML、JavaScript 和 CSS。网页运行项目逻辑，通过 SDK 实时查询数据库或保存数据；外部 AI 不参与每一次点击。

项目网页使用浏览器能力和平台 SDK，不直接依赖 Node 文件系统、Tauri IPC 或其他桌面专属接口。这样同一份产物才能同时在桌面窗口和普通浏览器中运行。项目的业务主数据不存入浏览器私有数据库；浏览器存储可以保存可丢弃的界面偏好或缓存。

本地服务随软件启动。按2026-10-20同日最新要求，macOS 平台管理窗口 X 只隐藏管理窗口并保留 Dock，已开的业务窗口、受管 Node 和平台服务继续运行；这覆盖此前“主窗口 X 退出”的要求。菜单“退出”／Cmd+Q 才安全结束活动操作、关闭全部业务窗口并收尾全部受管 Node、普通后代与平台服务；非 macOS 管理窗口 X 维持该正常退出流程。单独关闭业务窗口只释放该页面并收尾本应用后端，不停止其他应用或独立 Node。清理未完成或归属不明不得假报成功；硬崩溃、强制结束和逃离受管组后代不作绝对清理保证。旧浏览器诊断页不随平台退出关闭，须检测断开；标准应用仍从唯一原生窗口打开。

软件仍运行时，macOS 点击 Dock、收到 Reopen 事件或重复启动须恢复并聚焦同一个管理窗口，保留管理页状态，不创建第二套窗口或平台服务，也不自动重开已关闭的业务窗口。隐藏管理窗口不等于退出，也不撤销业务会话；当前关闭契约见[窗口与后端约束](app-window-runtime-contract.md#2-窗口驱动-node-生命周期)，旧版本实测仍保留原结果。

### 2.1 桌面窗口与浏览器

管理窗口承载项目列表、空间与文件、备份、维护和设置；项目以独立 `WebviewWindow` 中的顶层网页加载本地 HTTP 入口。每个项目 ID 至多一个桌面项目窗口，重复点击或并发打开请求均复用并聚焦已有窗口，不重载、不覆盖未提交表单。不同项目可以同时打开；普通浏览器的标签不参加桌面窗口去重。

新窗口通过一次性入口建立项目会话。复用窗口仍核对项目状态；会话过期、旧文档代次、维护、删除或工作区迁移时展示相应状态，不能把聚焦当成恢复访问。需要重新连接或重载时由用户明确触发，使用新入口；保留窗口容器不等于允许旧 JavaScript 继续操作。删除的项目不能再打开业务入口；恢复同 ID 后仍执行代次检查。

关闭项目窗口释放该页面及设备；关闭前的未保存内容提示由项目实现，平台不能推断任意表单，也不能保证强制退出或崩溃后找回内存内容。窗口失焦不等于关闭；标准录音/拍照组件在页面变为不可见或发生明确切换时停止设备并提示未保存内容，不把每次失焦都当作切换。首版不增加多项目标签系统或自动恢复全部项目窗口。

业务窗口的可选顶层 `window` 初始尺寸及本机普通尺寸记忆按[尺寸契约](app-window-runtime-contract.md#应用窗口尺寸)处理，默认 1080×780，最小 640×480；它不调整管理窗口或开放网页原生权限。固定数据根缓存与工作区设置、项目业务数据分开，已登记 Node 的整份声明摘要门禁保持，不借尺寸字段修改旧来源或增加声明更新入口。

管理窗口和项目窗口使用独立的窗口标签及权限配置。项目窗口不获平台管理命令权限；所有自定义原生命令及插件权限都必须在宿主侧核对调用来源，不能仅隐藏前端对象。宿主处理顶层导航及 `target=_blank`／`window.open`：用户主动打开的外部 HTTP(S) 链接交给系统浏览器，项目窗口内仅保留本项目及平台连接流程所需导航，拒绝任意原生协议跳转；项目不能借导航或新窗口取得管理权限。普通浏览器直接打开项目顶层网页，首版没有浏览器管理后台。此边界不把同 origin 项目变成恶意代码安全沙箱，参见 [Tauri capabilities](https://v2.tauri.app/security/capabilities/)。

## 3 工作区与项目目录

程序安装目录与用户工作区分开。当前安装目录保存平台程序、平台 CLI、SDK、模板源码、预编译初始网页和 AI 接管 skill，以及相互独立的 `node-runtime` 应用运行资源和 `development-node` 开发资源。Mac arm64 内部版对开发工具校验固定发行声明、完整文件树及权限；这些程序资源不作为用户数据或依赖缓存目录。用户应用后端及依赖的交付、可写数据位置与生命周期仍按新增草案落实，不把用户业务写入平台安装资源。工作区保存用户项目及其依赖。软件升级不得覆盖用户项目。Mac 默认工作区为 `appLocalDataDir/workspace`，通常位于 `~/Library/Application Support/<bundle-id>/workspace/`；通过系统目录 API 解析实际位置，并提供打开目录和迁移位置的入口。

工作区位置、显式本机 Node 选择、服务发现信息和本机管理凭据保存在固定的用户应用数据目录中。它们是本机运行配置，不属于项目导出内容；工作区移动后，CLI 仍从固定位置发现服务。

迁移自身的日志与任务记录固定保存在 `appLocalDataDir/migrations/<taskId>/`，不放进正在迁移的工作区；先校验并安置最终目标，再持久更新 `workspaceRoot`。提交后目标不可用时等待恢复目标访问，不自动回退到旧副本。

以下为工作区的标准布局；项目名称与 ID 为示例，默认工作区的具体系统路径按已确认的发行方案执行。

### 3.1 文件的归属与生命周期

| 路径 | 归属与处理方式 |
| --- | --- |
| `project.json`、`README.md`、`docs/` | 项目持久文件，随项目导出；平台说明由平台按接口版本提供 |
| `AGENTS.md`、`CLAUDE.md`、`.agents/skills/local-projects-app/` | 项目持久交接资料，随备份、导出和复制保存；不随平台更新自动覆盖 |
| `meta/` | 项目图标等平台展示资料，随项目备份与导出；计入源码与资料，不作为构建输入 |
| `app/` | AI 编辑的项目源码和依赖声明 |
| `app/vendor/` | 项目持有的固定版本 SDK 发布包，属于持久源码材料，随备份和导出保存 |
| `app/node_modules/` | 可重建依赖，不作为项目的唯一依赖来源；通常不随项目导出 |
| `dist/` | 构建生成，可以整体替换；不要手工修改它作为长期维护方式 |
| `data/` | 持续保存，不得因构建、清理缓存、刷新网页或升级平台而清空 |
| 项目内 `.platform/` | 项目构建临时产物和日志，不放唯一的用户数据；运行中由平台管理清理 |
| 工作区 `.platform/` | 持久控制状态、操作日志、恢复现场及缓存；只能分类清理，未完成维护与受保护现场不得当缓存删除 |

网页固定图标、内置示例图片等随代码发布的资源放在 `app/public/`。平台列表用的项目图标放在 `meta/`，由清单引用；两个用途需要同一图案时各自保存文件。用户上传的图片、音频、文档放在 `data/attachments/`。

项目基本信息以清单及图标文件为准，不另存在业务数据库。平台提供卡片与统一概览，可编辑名称、简介和图标；UI 写回同一份项目文件，外部 AI 也可编辑。图标缺失或无效使用默认图标并提示，尚未构建或坏库仍可查看概览；详细字段、冲突检查和更新规则见基本信息契约。

项目统计缓存位于工作区 `.platform/cache/storage/`，可重建、不进入单项目备份；程序体积缓存固定在 `appLocalDataDir/cache/storage/platform.json`。缓存不作为文件删除或恢复依据，根切换后失效。平台实际 `.app`、当前工作区与其他已知本机位置按不重叠范围展示；关于页读取安装包的名称、图标与版本，详见发行及空间契约。

项目列表展示当前项目文件大小，统一“空间与文件”页按已确认口径展开：源码与资料（固定素材为子项）、当前网页产物、用户素材、SQLite 及 WAL/SHM、工程依赖、可清缓存与日志、其他文件。每路径只计一次；关联备份、回收站与恢复现场另列归属，固定素材不再次累加。数字为逻辑文件字节及文件数，显示统计时间、过期和不完整状态，不保证等于实际释放磁盘量。

附件页支持分页、筛选、大小排序、基础预览和下载，不自动分析业务引用或批量清除用户素材。缓存清理只处理已识别的工程依赖根与可清缓存/日志，禁止把源码、SDK、当前产物、用户附件、数据库伴随文件、受保护现场或未知文件作为缓存删除；细则见空间管理契约。

项目目录使用稳定 ID，不随展示名称改变。平台扫描 `projects/` 下的项目清单发现项目，并通过清单校验识别是否可运行。标准新建流程同时安装初始网页，完成后可直接打开。合法的旧项目或导入项目可能从未有过网页产物，应显示为“尚未构建”，不能因此删除其数据或忽略已有源码；已经登记的产物意外缺失则报告异常。

AI 可以直接编辑项目目录。复制已有项目用于建立新项目时，应生成新 ID；移动工作区或导入同一个项目时保留原 ID。发现重复 ID 时报告冲突，不自动覆盖已有项目。

导入、导出、复制、删除、回收站和迁移的完整流程按[已确认生命周期契约](project-lifecycle-and-workspace.md)执行。活跃项目、回收站和未完成操作占用 ID，历史备份本身不阻止重导入；同 ID 恢复或重新登记推进文档代次，不能复活旧标签。当前直接删除遵守[删除契约](application-deletion.md)，不创建新回收项；旧回收项继续保留原维护状态，恢复／永久清除仅处理明确选中的旧项，不连带删除历史备份。

### 3.2 路径规则

项目清单内的文件路径一律相对项目根目录，采用 `/` 分隔。不得写入机器绝对路径、当前端口或访问凭据。

解析路径时需要检查实际目标，包括符号链接，防止路径意外越出项目根目录。源码目录和产物目录互不包含，也不能包含持久数据区域 `data/`，或位于其中。数据库文件与附件目录分别管理，可以共用 `data/` 父目录，但数据库文件不能放进附件目录。网页服务只提供指定的网页资源及受控附件接口，不把整个项目根目录作为静态目录公开。

项目根 `meta/` 为独立持久资料目录，与源码、产物、数据及平台临时目录互不包含；图标仅允许其中的相对 PNG 路径，不跟随符号链接。服务不把 `meta/` 作为网页资源根公开。

## 4 project.json 约定

推荐的完整示例：

```json
{
  "manifestVersion": 1,
  "id": "prj_english_01",
  "name": "孩子英语学习",
  "description": "管理单词、练习和学习记录",
  "icon": "meta/icon.png",
  "sdkApiVersion": 1,
  "sourceDir": "app",
  "outputDir": "dist",
  "entry": "dist/index.html",
  "database": "data/main.sqlite",
  "attachmentsDir": "data/attachments",
  "build": {
    "script": "build"
  },
  "docs": {
    "readme": "README.md",
    "database": "docs/database.md",
    "platform": "docs/platform.md"
  },
  "runtimeRequirements": {
    "network": {
      "connect": [],
      "images": [],
      "media": []
    },
    "devices": {}
  }
}
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `manifestVersion` | 是 | 清单格式版本，与应用内容版本、Git 版本无关 |
| `id` | 是 | 项目稳定标识；1 至 64 个字符，以小写字母开头，只使用小写字母、数字、下划线或连字符；建议以 `prj_` 开头 |
| `name` | 是 | 用户看到的纯文本项目名称，去除首尾空白后非空；可修改、可同名，不改变 ID |
| `description` | 否 | 纯文本简介；省略或空字符串表示没有简介 |
| `icon` | 否 | `meta/` 内本地静态 PNG 的相对路径，通常 `meta/icon.png`；无图标或无效时展示默认图标和相应提示 |
| `sdkApiVersion` | 是 | 项目要求的 SDK 接口主版本，首版为 `1` |
| `sourceDir` | 是 | 工程目录，标准模板为 `app` |
| `outputDir` | 是 | 当前网页产物目录，标准模板为 `dist` |
| `entry` | 是 | 网页入口，相对项目根目录，必须位于 `outputDir` 内 |
| `database` | 是 | SQLite 文件路径，必须位于项目根目录下的 `data/` 内 |
| `attachmentsDir` | 是 | 附件根目录，必须位于项目根目录下的 `data/` 内 |
| `build.script` | 是 | `sourceDir/package.json` 中的脚本名称，不是任意拼接的 shell 命令 |
| `docs.*` | 是 | 项目阅读入口、数据库说明、匹配版本的平台说明 |
| `runtimeRequirements` | 否 | 项目运行需求；省略时默认本地平台、未声明外网及设备需求，格式见下文 |

标准创建流程生成全部必填字段。第一版先使用标准路径布局；自定义布局按相同规则校验，不需要为每个路径提供设置界面。

`icon` 是可选兼容扩展，旧项目省略仍有效；默认图标属于平台资源，不必复制到每个项目。名称、简介、图标及 `meta/` 不计入构建输入；若网页需要这些内容作为固定资源，应由 AI 明确放进源码并构建。平台编辑按基本信息契约校验 revision、保留其他清单字段；不因更改展示信息升级清单主版本或 SDK。

平台拒绝无法理解的清单主版本或 SDK 主版本，并返回可读错误。`sdkApiVersion` 指接口主版本，不等于 npm 包版本；当前内部 SDK 包为 `@local-projects/sdk 0.1.0`，以本地 tarball 分发，没有发布到公共 npm registry。可识别但尚未构建的项目，与清单格式错误的项目应显示不同状态。

数据库已登记但文件意外缺失时，应报告缺失，不静默新建一个空库覆盖用户对原数据的预期。只有明确的新建项目流程负责初始化数据库。

### 4.1 运行需求声明

`runtimeRequirements.network` 的 `connect`、`images`、`media` 均为可选数组，缺省为空。每个条目包含精确 HTTPS `origin`、非空用途 `purpose` 和发送内容说明 `dataSent`；不含路径、凭据或通配符，本地平台与本地附件无需列入外网条目。

`runtimeRequirements.devices` 可声明 `microphone` 或 `camera`，各项包含非空 `purpose`，`camera` 仅表示拍照。所有分组和成员可省略；它们表示需求，不是系统授权。完整示例和 CSP 规则按[运行能力契约](project-capabilities-and-secrets.md)执行。声明随项目保存与导出，操作系统授权和密钥不写进清单。

网页、桌面通过同一 HTTP 服务取得资源策略；公开接口仍遵循 CORS。默认脚本、字体等随产物提供，不开放任意远程脚本、项目网页自行嵌入的任意外部 iframe 或通用代理。桌面使用独立顶层项目窗口。网络/设备声明变化后提示重载，不承诺瞬间撤销旧页面已有请求或权限。同源项目路径不构成恶意代码隔离。

## 5 网页 SDK 约定

### 5.1 连接与项目上下文

平台提供可用于普通浏览器的 SDK。SDK 通过运行时上下文获得当前项目 ID、本地服务入口及会话状态；项目代码不得写死端口、机器路径或长期凭据。SDK 采用第 5.6 节的本地版本包分发，当前内部包名为 `@local-projects/sdk`，正式发行命名尚待冻结；HTTP 布局见已确认的接口文档。模板和 `docs/platform.md` 必须给出实际导入方式。

网页默认绑定当前项目，不需要每次传入数据库文件路径。外部 AI 管理工具通过显式项目 ID 选择目标。项目 ID 是定位信息，不单独充当认证凭据。管理工具的跨项目能力不直接暴露给普通项目页面。

本地服务默认只监听本机地址，并校验访问会话及请求来源。同一站点下的不同项目路径不等于浏览器安全隔离；第一版按用户信任的自建项目设计，不承诺运行不可信第三方代码。若后续需要该能力，应另行设计独立 origin 和权限边界。

### 5.2 最小接口

下表方法已在内部 SDK `0.1.0` 实现，实际导入为 `import { platform, PlatformError } from "@local-projects/sdk"`。除订阅返回取消函数外，方法均异步返回结果；失败以统一的 `PlatformError` 表示。完整签名及错误处理见 [SDK 说明](../packages/sdk/README.md)与随项目复制的 `docs/platform.md`。

| 接口 | 输入与结果 | 说明 |
| --- | --- | --- |
| `context.get()` | 返回项目 ID、名称、SDK 接口版本和 `capabilities` 能力列表 | 获取当前运行上下文，检测可选能力 |
| `db.execute({ sql, params })` | 返回 `SqlResult` | 执行一条 SQL，支持查询、数据写入和表结构调整 |
| `db.transaction({ statements })` | 返回按顺序排列的 `SqlResult` | 一次提交多条语句，任一步失败全部回滚 |
| `db.schema()` | 返回表、列、约束、索引和视图信息 | 读取实际数据库结构 |
| `db.subscribe(listener)` | 返回取消订阅函数 | 收到变化通知后，由页面重新查询 |
| `files.put({ path, content, overwrite })` | 返回 `FileInfo` | 保存 Blob 或字节内容；默认不覆盖同路径文件 |
| `files.get(path)` | 返回 Blob | 读取附件内容 |
| `files.list(prefix)` | 返回 `FileInfo` 列表 | 列出指定逻辑路径前缀下的附件 |
| `files.remove(path)` | 返回完成状态 | 删除附件 |
| `files.url(path)` | 返回当前会话可用的访问 URL | 用于图片、音频或下载展示 |

`FileInfo` 至少包括逻辑路径、文件大小、媒体类型和修改时间。逻辑路径相对 `attachmentsDir`，例如 `audio/practice-001.webm`。数据库保存稳定的逻辑路径，不保存临时访问 URL。

录音文件后缀仅是示例；录音与拍照使用浏览器 API、实际格式检测和用户授权，不要求新增原生媒体 SDK。文件上限由 `context.get().limits.fileUploadMaxBytes` 返回当前正整数的字节值，SDK 在上传前可检查，服务仍须执行限制；数值在实施验证中锁定，不能省略后被理解为无限制。运行需求可在上下文的 `runtimeRequirements` 中读取，它与平台接口 `capabilities`、浏览器设备检测和系统授权分别解释。

上下文还提供当前项目的维护、暂时忙碌及重载提示。服务在提供入口 HTML 时附上 `documentEpoch`，SDK 在该文档内固定持有；业务请求携带该代次，结束维护后旧代次不能继续操作。身份验证仍使用项目会话；读取新上下文不允许旧文档静默换用新代次。此要求从首个 SDK/API v1 实现起包含，详见已确认的备份维护方案。

### 5.3 SQL、结果与事务

`SqlResult` 至少包含列描述数组 `columns`、对象数组 `rows`，以及适用时的 `changes` 和 `lastInsertRowid`。写语句带 `RETURNING` 时，也可以返回结果行；DDL 成功时结果行可以为空。查询同名列时应使用别名，以免对象形式的结果行发生字段覆盖。

SQL 值使用参数绑定；用户输入不得直接拼接到 SQL 中。第一版至少支持位置参数 `?`。SDK 接受空值、字符串、有限数值、`bigint`、布尔值和字节内容；布尔值按 `0/1` 写入，读取时仍返回数值。结果中的安全整数使用 `number`，超过 JavaScript 安全整数范围的整数使用 `bigint`，字节内容使用 `Uint8Array`。超过 SQLite 有符号 64 位整数范围的整数参数返回错误，禁止静默截断或四舍五入。日期、单位和枚举的业务约定写入数据库文档。

每次 `execute` 接受一条语句，并在返回成功前完成该请求的提交。多条需要共同成功的操作使用 `transaction`，每项均包含 `sql` 和 `params`。平台在同一数据库连接上依次执行、统一提交或回滚。事务控制由平台管理，接口不接受让调用方通过多个请求执行 `BEGIN`、`COMMIT`、`ROLLBACK` 或 `SAVEPOINT` 等事务控制语句。发生执行或提交错误后，平台清理事务状态再归还连接，不能假设任何 SQLite 错误都会自动回滚整个事务，详见 [SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)。第一版不支持在语句之间运行任意 JavaScript 回调；关联 ID 可由应用预先生成后作为参数传入。

事务之外才能执行的维护语句单独调用。SQL 的数据和结构操作保持开放，但数据库目标由平台绑定；涉及打开其他数据库文件、加载扩展或写出系统路径的管理能力不默认通过网页接口开放。外部 AI 仍可使用本机数据库工具处理工程需要的维护操作。

SDK 和管理 SQL 均不能改写平台管理连接的外键、日志、同步、忙等待等配置，或绕过平台的事务和数据库绑定。请求违反这些不变量时返回明确错误；业务 DDL/DML 不因此收缩为预设 CRUD。外部工具维护后，平台重新接管时核对并恢复约定配置，无法满足则报告诊断。

平台创建的数据库连接统一开启外键约束。AI 使用外部 SQLite 工具直接连接时，也应为该连接启用外键约束；平台不能替外部连接设置这一选项。数据一致性由 SQL 约束、事务和项目业务代码共同保证；平台不替项目推断业务规则。

### 5.4 数据变化与刷新

查询读取当前已提交的数据。平台 SDK 或 AI 工具成功提交写入后，发送项目级“数据可能已变化”通知，订阅者重新查询；事务回滚不发送成功变更通知。这里只约定项目级失效通知，不提供逐行同步或跨设备同步。

连接中断后恢复、页面重新获得焦点或错过通知时，SDK 先核对会话及项目状态，正常且文档代次有效时重新查询。维护中显示提示，收到 `PROJECT_RELOAD_REQUIRED` 时要求重新加载，不重放旧请求。第一版不承诺通知持久化和精确一次投递。

AI 绕过平台直接用 SQLite 工具写入时，数据仍然属于同一份数据库，但第一版不承诺立即推送通知。AI 可调用项目刷新工具，页面也应支持刷新；后续可以补充数据库变化检测。业务数据更新不需要重新构建网页，只有页面代码变化才需要构建。

### 5.5 附件与错误

附件路径不能包含绝对路径或越界访问；平台统一解析到当前项目的附件目录。文件操作和 SQL 事务不是同一个原子事务。项目应处理“文件已上传但数据库记录保存失败”等中间状态，必要时清理孤立文件。

单文件上传先写入同一文件系统上的平台暂存区，完成尺寸及内容校验后才发布到附件路径；未完成文件不作为正式附件列出或读取。`overwrite` 默认 `false`，同路径冲突不覆盖；显式覆盖失败保留原完整文件，不能先截断原文件再接收上传。最终发布前复查项目模式、文档代次和目标冲突；活动上传与备份、恢复、删除及迁移的排空规则一致。暂存残留由平台识别清理，不扫描用户文件猜测临时附件。请求结果未知时先查询，不自动重放上传；这些保证不把文件与 SQL 合并成一个事务。

`PlatformError` 至少包含 `code`、`message`、`details` 和 `retryable`。错误代码应区分平台未启动、项目不存在、接口版本不兼容、SQL 错误、数据库忙、附件不存在和路径无效。项目页面显示可理解的错误；具体 SQL 或构建错误供 AI 调试。

### 5.6 SDK 分发与升级

此方案已确认。平台安装包携带带版本的 SDK 发布包，创建项目时复制到 `sourceDir/vendor/`，标准路径为 `app/vendor/`。项目通过相对本地 tarball 依赖使用它，并由 `package-lock.json` 锁定；不依赖平台安装目录的绝对路径，不在运行时注入最新 SDK。npm 支持本地 tarball 包来源，见[npm 包引用规则](https://docs.npmjs.com/cli/v11/using-npm/package-spec/)。

SDK 发布包包含浏览器代码、类型声明和匹配版本说明，尽量不引入外部运行时依赖。构建时 SDK 进入网页产物，现有静态网页正常运行不需要 Node 或 npm 包目录；新增 Node 后端应用另按运行时规范执行。该包必须随源码备份、导出和复制，不得仅保存在可清理的工具缓存中。其他第三方依赖仍按第 7 节下载和缓存，不能因此宣称首次构建全部离线可用。

SDK 升级是明确的项目修改：取得目标版本包，更新相对依赖、锁文件和 `docs/platform.md`，再构建和验证。不得以覆盖同名发布包内容的方式悄悄改变已锁定版本。M2 的安装资源为 `sdk/releases/local-projects-sdk-0.1.0.tgz`，项目持有 `app/vendor/local-projects-sdk-0.1.0.tgz`；依赖为 `file:vendor/local-projects-sdk-0.1.0.tgz`。包包含 ES module、类型声明和匹配说明，无外部运行时依赖。

### 5.7 平台与旧项目兼容

此政策已确认。平台软件版本、SDK 包版本、接口主版本和模板版本分开记录：平台软件版本由运行服务报告，SDK 包版本由包元数据与锁文件记录，`project.json.sdkApiVersion` 表示接口主版本；创建时将模板来源版本记入平台生成的项目说明。不要把 SDK 包版本或模板版本当成数据库 schema 版本。

平台后续更新在 API v1 内保持向后兼容。旧项目无需仅因平台更新而重建；平台更新不自动改写已有项目的源码、SDK 发布包、锁文件、业务数据库或说明文档。新模板和初始网页仅用于新建项目，旧项目采纳模板变化由 AI 明确修改。此规则也适用于 M1 阶段创建的项目：升级到 M2 不自动补写模板、SDK、锁文件、README、AGENTS.md、CLAUDE.md 或项目 skill；旧产物无来源记录时标为 `unknown`，仍可使用。没有产物的合法旧项目不会自动被初始应用覆盖。

同主版本的新增可选能力通过 `context.get().capabilities` 检测；能力列表使用文档化的稳定字符串标识，未知标识可忽略，缺少所需能力时返回明确的不支持错误。SDK 不因主版本相同就假设所有新增功能都存在，也不能把缺失能力静默当作成功。具体能力标识与实际实现同步写入 `docs/platform.md`。

不支持的接口主版本按第 4 节报告不兼容，不自动改表或升级项目。将来引入 API v2 时另定 v1 的兼容期限；第一版不承诺永久维护任意历史版本。

移动或导入项目后，只更新平台生成的本机交接信息，例如 CLI 绝对路径；不覆盖业务说明或把项目的平台说明自动换成最新版本。平台自身设置格式的升级不等于项目业务数据库迁移。

## 6 外部 AI 的工具入口

外部 AI 直接读写源码和文档，不要求所有文件编辑都经过平台工具。已确定第一版提供原生 Rust CLI，MCP 后置并复用相同服务能力；命令、服务发现和输入输出格式见[已确认的工具接口方案](local-service-and-ai-tools.md)。平台至少提供以下管理能力。

| 能力 | 最少返回内容 |
| --- | --- |
| 创建、列出和查看项目 | 项目 ID、状态、目录、文档入口 |
| 查看与修改项目基本信息 | 名称、简介、图标状态和 revision；按期望 revision 修改并报告冲突 |
| 查看数据库结构 | 实际 schema，而非只读取文档 |
| 执行 SQL 和事务 | 结果行、写入结果或结构化错误 |
| 构建项目 | 构建任务 ID、最终状态、日志位置、成功时的浏览器地址 |
| 查看日志 | 构建错误、平台请求错误和关联任务信息 |
| 获取浏览器入口 | 当前可用的本地 URL，不要求 AI 自己猜端口 |
| 请求数据刷新 | 通知已打开的项目重新查询 |
| 备份和恢复项目 | 备份标识、包含内容、执行状态 |
| 列出和查看备份 | 时间、大小、校验结果、保护原因及内容说明 |
| 进入、查询和结束维护 | 维护 ID、准备状态、基线备份、关联任务及失败原因 |
| 导出、导入和复制 | 任务 ID、目标项目 ID、归档或结果位置；原 ID 与副本语义明确 |
| 直接删除及旧回收站管理 | 当前删除不可撤销、返回任务与实际范围；旧回收站 ID 仅用于旧项恢复／永久清除 |
| 工作区查看和迁移 | 当前位置、迁移任务、源目标位置与提交状态 |
| 项目与工作区空间 | 分类字节数、数量、统计时效、关联历史、保护原因；重新扫描返回任务 ID |
| 素材列表与缓存清理 | 分页附件信息；明确清理类别及实际结果，不接受任意路径递归删除 |

CLI 结果默认支持机器可读格式。命令执行成功与任务最终成功必须区分：如果构建仍在进行，返回任务 ID 和查询方式；退出或请求被接受不等于构建完成。最终结果包括 `ok`、`projectId`、相应数据或错误。

SQL 值在 CLI JSON 及 SDK 传输中使用无损编码：需要 `bigint` 的值表示为 `{ "$int64": "十进制字符串" }`，字节表示为 `{ "$bytes": "Base64字符串" }`。`$int64` 仅在 SQL 值及明确声明采用该编码的空间统计字节数字段解释，`$bytes` 仅在 SQL 值的位置解释，不对任意对象递归猜测标签。SDK 解码为对应 JavaScript 类型，CLI 保留带标签的 JSON，不把普通字符串自动猜测成整数，也不直接序列化原生 `bigint`。

已确定的构建调用形式为，实际可执行文件名仍待命名：

```text
platform project build --project prj_english_01 --json
```

`platform` 只是占位名称。正式创建项目时，平台应在 README 中填入可以实际调用的命令或可执行文件路径。项目构建要求系统已安装受支持的 Node 和可用的 npm；平台负责探测，并提供选择路径及缺失时的安装指引。用户不需要全局安装 Vite、React 或 TypeScript。

### 6.1 AI 接管 skill 与文档入口

仓库 `skills/local-projects-app/SKILL.md` 维护业务项目接管流程，随平台安装包分发；标准创建流程将整套 skill 复制到项目 `.agents/skills/local-projects-app/`，README、AGENTS.md 和 CLAUDE.md 提供简短入口。skill 应要求先确定实际项目根、项目 ID、当前 CLI 和接口版本，再阅读 README、数据库说明及实际 schema；随后按用户任务修改源码或数据，等待平台构建最终结果，验证网页并更新交接说明。数据独立于构建保存，构建失败不回滚 AI 已执行的数据修改。

`project handoff`／“复制给 AI”提供项目、README、skill 和 CLI 的绝对路径。skill 是普通可读项目文件，不要求所有 AI 工具采用相同发现机制，也不自动安装到全局 AI 配置。已有项目存在自带 skill 时优先引用；没有时只读引用安装包后备 skill，不在读取交接信息时创建文件或覆盖项目说明。旧项目仍以其自带 SDK、锁文件、匹配平台说明与实际接口为准，不能因后备 skill 更新而静默升级项目。

skill 和当前生成文档只描述已可调用的功能，备份维护及 M4 生命周期/迁移按当前 CLI 提供，不把历史管理讨论稿或 M5 管理接口当作已有命令。更新资源只用于新项目和安装包后备说明，不改已有项目文件。skill 服务于用户的具体业务项目，不要求 AI 修改平台软件源码。

“复制给 AI 的说明”应至少包含：项目根目录、README 与 skill 入口、平台工具入口、项目 ID、获取当前浏览器地址的方法。用户可一并说明本次需求。不要假设所有 AI 都自动读取某个特定命名的指令文件；AGENTS.md 和 CLAUDE.md 只提供同一套说明的入口，显式交接路径仍需保留。

## 7 构建和加载流程

### 7.1 构建环境

project-v1 构建向 AI 提供统一的服务端编排入口。当前 Mac arm64 内部版另外携带固定的受管开发 Node 24.22.0／npm 11.19.1；应用后端使用的 `node-runtime` 与此分开。平台提供模板、SDK 和依赖声明；Vite、React、TypeScript 等作为项目本地依赖安装，不要求全局安装。开发 Node 不承担平台 HTTP 或数据库服务，构建环境不可用不阻止已有静态网页和数据使用。

最低 Node 版本和推荐版本已确认。第一版按以下版本政策执行，模板落地时需在最低支持版本和推荐版本上完成构建验证。

| 项目 | 约定 |
| --- | --- |
| 最低 Node 版本 | 22.12.0 |
| 受管开发版本 | 固定 Node 24.22.0／npm 11.19.1；升级须另行准备并验证发行资源 |
| 推荐本机 Node 版本 | Node 24 LTS；仅在用户明确选择时使用本机版本 |
| 首版支持分支 | Node 22 的 22.12.0 及以上版本，以及 Node 24.x；对应范围为 `^22.12.0` 或 `^24.0.0` |
| 其他主版本 | 不因为版本号较大就自动纳入支持；后续 LTS 经验证再扩展支持范围 |
| 包管理器 | 与所选 Node 配套的 npm；受管版本固定为 11.19.1，使用 `package-lock.json` |
| 默认构建工具 | 建议 Vite 8；模板固定实际验证过的版本及依赖组合 |

截至 2026-10-14，Node 22 和 Node 24 属于 LTS，Node 20 已结束支持；版本状态参见 [Node 发布列表](https://nodejs.org/en/about/previous-releases)。Vite 8 的 Node 基础要求为 20.19+ 或 22.12+，产品采用仍受支持的 Node 22.12 作为最低起点，并以 Node 24 LTS 为推荐环境；模板依赖若要求更高版本，需显式调整要求，不能静默放宽检测，参见 [Vite 8 Node 支持说明](https://vite.dev/blog/announcing-vite8#node-js-support)。

开发工具选择与诊断遵守以下约定：

1. 已有 `toolchain.json` v1 显式 Node 路径优先，失联或探测失败即报告错误，不改选受管或其他本机工具。没有显式选择且服务带安装资源时默认使用 `development-node`；缺失或校验失败也不回退本机。只有不带安装资源的开发／测试服务保留 nvm、Volta、常见安装位置与 PATH 探测。
2. 同时检查 Node/npm 版本及实际路径。受管工具先在阻塞工作线程校验源码中固定的发行声明和完整文件树，再执行版本探测；拒绝链接、硬链接、特殊文件及增加、缺失、改变的内容。设置、`env doctor` 和构建日志显示真实结果。
3. npm 的 JavaScript 入口由选定的 Node 执行，不把普通 shell shim 当作 JavaScript。受管构建 PATH 只包含所选工具目录与系统工具目录；不修改全局 PATH、shell 配置或 npm 配置。显式选择保存在固定数据根，不写入可移植的 `project.json`。
4. 清除显式选择表示恢复服务默认值：带资源时恢复受管工具，无资源开发服务恢复检测。当前选择不可用时仅阻止构建，并显示诊断和修复／重新选择入口；不悄悄安装或升级本机 Node。

M2 原系统探测的实测保留在 [M2 记录](m2-verification.md)，不改写为受管工具已验收。当前选择语义及开发验证入口见[开发说明](development.md#7-m2-sdk模板与构建)。CLI 离线时仍报告构建环境未读取，不将终端 PATH 的结果冒充桌面服务环境。受管开发工具当前仅覆盖 Mac arm64；不据此宣称 Windows、任意旧项目重建、Git 或 Node 源码槽构建已经完成。

依赖修改时同步更新 `package.json` 和锁文件。首次构建或需要重建依赖时，按锁文件使用 `npm ci`；它要求锁文件与依赖声明一致，且会重建项目依赖目录，见 [npm ci 文档](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。仅修改页面源码、依赖状态未变化时可以复用已安装依赖。AI 主动新增依赖时先完成依赖和锁文件更新，再进行构建，不以每次自动升级替代锁定版本。

依赖保存在项目内，缓存由平台安排在工作区内，供构建进程使用。首次下载依赖或新增依赖可能需要联网；已有依赖完整时可以离线构建。平台不承诺所有项目首次构建都离线可用。

构建工具与项目运行分开。新项目的欢迎应用在平台打包时预编译，创建过程只校验和复制匹配的源码与产物，不执行依赖安装或构建。创建并打开初始应用、打开已有成功构建的静态项目，均不需要 Node、npm、Vite 开发服务器、联网或 AI 客户端。平台网页服务和数据库服务仍需运行。用户修改源码后执行构建时，仍须通过所选开发工具校验并满足项目依赖要求；新增 Node 后端类型的运行和依赖交付另按草案落实。

### 7.2 标准流程

1. 用户创建项目后即可打开初始应用。AI 接管时阅读项目 skill、README、匹配版本的平台说明和实际表结构，修改 `app/` 中的源码，并同步更新有关文档。
2. AI 调用项目构建工具。平台取得项目任务互斥，校验清单、依赖声明、路径及服务选定的 Node/npm 环境，创建任务；在安装依赖之前记录本次输入摘要，再按需准备依赖。
3. 依赖准备后复核输入未变，再在 `sourceDir` 下执行 `build.script`。当前标准模板脚本为 `tsc --noEmit && vite build`，平台向脚本传入 `--outDir <本次临时输出目录的绝对路径>`。自定义构建脚本也必须接受并遵守这一参数，只把产物写入指定目录；不能直接清空当前 `dist/`。平台拒绝未遵守输出契约的产物，并由标准模板避免这一错误；这里不承诺隔离任意脚本的系统文件权限。构建及 npm 生命周期脚本是以当前用户权限运行的普通本机代码，不是沙盒；脚本禁止启动后台服务或脱离构建进程组的子进程。平台清理普通进程组，不能据此声称恶意脚本无权访问其他本机文件。
4. 构建产物先写入 `.platform/builds/<任务ID>/dist/`。该目录是可清理的中间产物，不能承载业务数据库或附件。
5. 脚本退出成功后，平台检查网页入口和基础资源完整性，并在发布前重新计算输入摘要；输入变化或无法完成核对时任务失败，不发布临时产物。脚本退出成功不等于任务成功，也不代表所有业务逻辑正确。
6. 平台将完整新产物切换为当前 `outputDir`，连同其来源记录持久提交。切换期间的请求不能看到一半旧文件、一半新文件。M2 将每代完整资源保存在项目 `.platform/artifacts/{buildId}/dist/`，保留当前 `dist/` 副本，并用工作区 `.platform/project-state/builds/` 下的发布日志与来源记录协调提交；来源记录是提交点。异常重启核对产物与来源匹配，不能给旧网页套上新构建记录。
7. 平台返回最终状态、日志和浏览器地址。已经打开的页面收到更新提示后可重新加载，避免静默刷新丢失尚未提交的表单内容。
8. AI 打开浏览器，验证主要页面、真实查询和写入流程，发现问题后继续修改和构建。

每个项目同一时间只进行一个构建；重复请求返回 `PROJECT_BUSY`，不为同项目累积构建队列。构建开始后，AI 应等待本次结果再继续编辑用于构建的源码，以免同一产物混入前后两次修改。

M2 首版采用单编辑者协作，输入检测规则见第 7.4 节；候选源码隔离与后续本机 Git 能力按各自已确认合同增补，不提供多 AI 文件锁。摘要不能检测所有外部写入，不替代构建期间停止编辑和外部 Git 操作的要求。

构建的 Git 冲突门禁只在项目根、源码范围或祖先发现相关 `.git` 标记时启用；没有相关标记的普通项目不读取 Git 工具选择、不执行 Git，也不新增 Git 构建依赖。当前支持项目根或 `sourceDir` 根的单个普通 `.git` 目录；祖先、嵌套、多个仓库、gitfile／链接、共享索引或不能安全核对的特殊配置返回 `BUILD_GIT_CHECK_UNAVAILABLE`，保持现场并说明需要处理。显式 Git 选择失效时不改用其他工具；现阶段读取使用已验证的 Git 2.54.0／2.56.0。

检测覆盖该仓库整个索引，包含 `docs/` 等构建输入摘要以外的冲突。未结束的 merge／rebase／cherry-pick／revert／bisect／sequencer 返回 `BUILD_GIT_OPERATION_IN_PROGRESS`；索引仍有未合并阶段记录返回 `BUILD_GIT_CONFLICT`。普通未提交修改、正常暂存和未跟踪源码不因此禁止构建。检查沿用隔离的 Git 环境，只在私有临时仓库读取索引副本，不运行用户 hook、filter、fsmonitor 或凭据程序，不写原仓库、索引和配置，不自动完成或撤销 Git 操作。

门禁在依赖安装之前执行，并在产物发布之前复核；仓库标记、索引或配置改变返回 `BUILD_GIT_STATE_CHANGED`，出现进行中操作或冲突则返回对应错误，无法核对则失败，不发布候选产物。检查仍不替代停止外部编辑／Git 操作，也不声称外部写入具有原子隔离。门禁只约束构建，不阻止继续打开既有产物、查询数据库或读取附件；原有数据和旧产物保护规则不变。

构建失败或产物检查失败时，保留当前网页产物，返回错误及日志。标准新项目的首次用户构建失败时继续保留初始应用；只有原本没有任何产物的合法旧项目才继续为“尚未构建”。若 AI 已经执行了不兼容的表结构变更，保留旧产物并不保证旧页面仍能正确工作；这类调整应保持新旧页面所需的数据兼容，或在暂停项目使用期间完成。保留旧代产物用于完成切换和处理旧页面资源请求，初始应用也使用不可变代；属于运行机制，不构成 Git 或用户可选的多版本管理。M2 暂时保留全部已生成代及发布现场，不自动按数量或时间删除；正式保留策略和空间清理规则仍待确定。入口 HTML 不应长期缓存；资源切换后旧页面的资源加载失败需要能够提示刷新。Vite 的生产构建和资源路径行为可参见[官方构建文档](https://vite.dev/guide/build.html)。

### 7.3 网页路径、预览和数据

平台返回的地址是唯一可信入口，示例形式为 `http://127.0.0.1:<端口>/p/<项目ID>/`。端口及具体路由由平台管理，不写入源码或数据库。

标准模板使用相对资源基址 `./`。M2 服务给入口 HTML 注入 `/p/{id}/_builds/{buildId}/` 基址，旧文档继续使用对应不可变代的资源，新入口使用当前发布代；SDK 仍从项目路由取得上下文，不能把构建代路径当作数据库或附件 API 根。第一版建议使用 hash 路由，例如 `#/practice`，避免依赖额外的深层页面路由回退。其他路由方式需要符合平台的静态资源服务规则。

本版“预览”指通过浏览器打开当前网页（初始应用或成功发布的用户构建），与桌面使用同一份正式数据。不隐含独立测试数据库、草稿发布系统或自动覆盖正式数据的功能。需要验证破坏性的表结构变更时，应先备份，或另建项目副本进行验证；测试数据由 AI 明确区分并清理。

构建只生成和替换网页资源，不自动建表、改表、导入测试数据或重置数据库。AI 的数据库操作是独立步骤；表结构调整后，应同步更新有关代码和数据库说明。第一版不自动编排代码和数据库的一体化迁移，也不承诺代码回退能够恢复数据。

### 7.4 构建输入、来源与显示状态

输入摘要使用版本化规则：对相对路径、文件内容及规范化的构建配置计算 SHA-256，不能只比较修改时间或文件大小。首版范围如下：

| 纳入 | 排除或单独处理 |
| --- | --- |
| `sourceDir` 中的源码、固定素材、构建配置、`package.json`、锁文件、本地 SDK/vendor 包和构建所用环境文件 | 已识别的 `node_modules`、工具缓存、工程版本控制内部目录、平台临时产物；不得将未识别源码当缓存排除 |
| 清单中的 `manifestVersion`、`sdkApiVersion`、`sourceDir`、`outputDir`、`entry`、`build` | 项目 ID、名称、说明、图标引用、文档入口及生成的本机交接路径不参与；不能直接散列整个清单或根 README |
| 构建直接读取的项目材料必须位于纳入扫描的源码范围 | 数据库、附件、当前产物、根目录业务说明和 `meta/` 不作构建输入；若页面导入某份说明或图标，应复制到源码范围并纳入检测 |

`runtimeRequirements` 由服务在运行时读取并生成资源策略，变更走状态提示和重载，不单独触发源码重建。项目身份与服务地址从运行时上下文读取，不在构建时固化；因此复制新 ID、改名和移动工作区不必重建可复用产物。

开始摘要在 `npm ci` 之前生成，执行构建脚本前及脚本退出、产物检查完成后的发布前分别复核；安装脚本或构建脚本改写纳入范围的文件，同样按输入变化失败，不重设基准，生成中间文件应放临时目录。扫描读取失败或文件集变化也不得当作相同。任务沿用 `failed`，输入变化使用 `BUILD_INPUT_CHANGED`；核对失败返回可读阶段和原因，均保留旧产物。检测不提供原子快照：期间改动又还原、最后检查后的外部编辑、任意外部环境及手改依赖可能无法由摘要完整证明一致性。

本机成功构建记录保存在工作区 `.platform/project-state/`，至少包含完成时间、摘要规则版本、输入摘要、产物内容摘要及实际 Node/npm/SDK 版本；本机任务 ID 仅供查日志。来源与当前产物关联，不依赖任务日志永久保留。归档在 `backup.json` 的可选 `buildProvenance` 中携带可移植来源信息，另保留已知待构建要求；导入恢复后重建本机记录，不伪造一个本机成功任务。旧归档无记录时标为来源未知，不因缺少摘要就认定已验证网页无效或强制安装 Node。

初始应用使用独立的模板来源记录：`origin: bundledTemplate`、模板版本、平台打包时的源码与产物摘要，以及安装到本项目后的输入基线。创建时核对匹配，不伪造用户成功构建任务，也不把平台打包工具版本说成用户的 Node/npm 环境。初始来源可同样检查源码为 `matched`、`modified` 或 `unknown`；用户首次成功构建后，当前来源切换为 `projectBuild` 和真实本机构建记录。

管理窗口与 `project info` 显示当前初始来源或最近成功构建及 `buildInfo.sourceState`：`unbuilt`（从未构建且无产物）、`matched`（最近检查输入匹配）、`modified`（源码与当前产物不同）、`unknown`（来源缺失或无法核对），附 `checkedAt`、过期标记与原因。已登记产物意外丢失或校验失败另报异常，不能伪装成新项目尚未构建。`matched` 只表达扫描时的结果，不证明可重复构建或业务正确。检测在构建前后、查看项目详情/状态及维护结束检查时执行；文件监听只用于标记过期，不能作为一致性的唯一依据。耗时扫描期间保留上次结果并明确标为过期，不以零变化冒充已核对。

发现差异时展示“源码有修改，当前网页仍为已发布版本”，并区分初始应用与用户构建来源。这些是展示状态，不替代任务状态或 `ready`／`maintenance`；正常模式下仍可使用旧产物。结束维护前的必需构建要求另行保留：维护期间编辑构建输入、或归档已知有未完成构建，不能因建立新基线、导入、复制或来源未知而清除。维护开始及结束使用同一输入范围比对，纯 README 或业务说明更新不强制重建；恢复例外与未知归档检查按备份维护契约处理。

合法的 `unbuilt` 项目是例外：本就没有已发布产物时，包括导入、复制或恢复得到的这种状态，其他维护检查通过后可以回到 `ready + unbuilt`。待构建信息继续保留，不能标为成功或开放业务网页。已登记产物意外丢失、损坏，或原先可运行的项目不能借此绕过检查。

### 7.5 M2 已落实的字段与实施边界

当前模板版本为 `react-ts-vite-0.1.4`，固定 React 19.3.1、TypeScript 5.9.3、Vite 8.3.4。初始页只展示连接和使用引导，不创建业务表或样例数据；平台包携带匹配的预编译网页，新建后立即可打开。本地基础组件位于 `app/src/components/ui.tsx`，主题在 `app/src/theme.css`，使用黑白灰风格；扩展建议 shadcn/ui，不强制组件选择，也不把基础组件称为已安装 shadcn/ui。

本机构建来源 schema 为 `1`，包含 `buildId`、`taskId`、`completedAt`（Unix 毫秒）、`digestRuleVersion: 1`、`inputDigest`、`artifactDigest`、`node`／`npm` 的路径与版本、可选 `sdkVersion`、`entryRelative`。`buildInfo` 含 `sourceState`、`checkedAt`（Unix 毫秒）、`stale`、`reason`；用户构建附 `origin: projectBuild` 和 `provenance`。初始应用附 `origin: bundledTemplate`、`templateVersion` 和 `starter`，记录保存在项目 `.platform/starter.json`，代 ID 为 `starter_…`，没有任务 ID 或虚构成功日志。新项目的正常初始状态为 `ready`、`sourceState: matched`。M3 在 `backup.json.buildProvenance` 中携带两类来源的可移植字段；恢复后生成新的本地资源代，保留原 origin，不伪造成功任务，不依赖被排除的原项目 `.platform/`。M4 导入和复制复用该可移植来源，实际结果见 [M4 记录](m4-verification.md)。

当前只实现任务与输入扫描，不以文件监听代替核对；管理列表/详情、构建前后读取实际状态。已发布项目的新构建不会自动刷新已有页面，SDK 的 `project.updated` 供页面显示明确重载入口。没有来源记录的旧产物按未知处理，已有来源而产物损坏则报告异常。

构建全局并发、等待队列、超时、日志截断与 SQL/上传预算仍为内部测试参数，见[开发说明](development.md)。任务和旧代产物没有自动过期清理；正式保留值未定。构建只负责网页及来源提交，不自动回滚 AI 独立执行的数据变更，完整备份和维护的 M3 实际范围见 [M3 验证记录](m3-verification.md)。M2 实际全流程结果见 [M2 验证记录](m2-verification.md)，初始应用与 skill 的新增验证单列于[补充记录](starter-skill-verification.md)。

## 10 数据保留、备份和恢复

第一版提供整项目备份和恢复，不要求 Git。备份至少包含清单、`meta/` 图标与资料、README、业务文档、源码、本地 SDK 发布包和锁文件、当前网页产物、数据库一致性副本及附件；不依赖构建缓存、日志或 `node_modules` 才能恢复。

本节与[备份与维护状态方案](backup-and-maintenance.md)均已确认。具体归档、保留策略、持久维护、页面代次、接口和异常恢复按该方案执行。

平台应使用 SQLite 支持的备份方式创建数据库副本。活动数据库不能仅复制 `main.sqlite` 就宣称完整备份，WAL 中可能仍有已提交内容。参见 [SQLite Backup API](https://www.sqlite.org/backup.html) 和 [WAL 说明](https://www.sqlite.org/wal.html)。

整项目快照需要在复制期间协调项目数据、附件及源码的修改；平台暂时阻止自身写入，并要求外部 AI 暂停直接写入后再执行。无法控制其他进程任意写文件时，不宣称获得全项目原子快照。

普通备份在制作不可变暂存副本期间冻结业务 SQL 和附件操作，副本完成后解冻并继续压缩校验，不改变持久维护模式。AI 维护则持久保存，等待基线归档成功后才允许管理修改；失败或重启不会自动开放业务网页。结束维护检查完成后推进文档代次，旧页面必须重新加载。

恢复时暂停当前项目读写，等待操作结束，关闭平台数据库连接，并确认外部数据库工具已经停止访问。校验备份完整性、保留替换前的完整项目副本后，恢复清单、源码、文档、网页产物、数据库和附件，使其回到同一个备份时点；不能把“整项目恢复”实现成只恢复数据库和附件。数据库恢复必须正确处理原库的 WAL、SHM 等伴随文件，不能将旧伴随文件与新数据库混用。无法取得独占维护状态时报告忙碌，不强行替换。完成后重新打开连接，要求旧页面重新加载恢复后的网页，再查询数据；仅刷新数据不能消除旧代码与恢复后结构的不一致。SQLite 对使用中的数据库文件替换有明确限制，参见[文件替换与损坏说明](https://www.sqlite.org/howtocorrupt.html)。

恢复数据库意味着回到备份时点，后续记录可能不再包含其中，界面必须清楚展示这一含义。

恢复前原库损坏时，保留完整目录及伴随文件作为原现场，不强求先生成有效 SQLite 归档。恢复成功后仍处于维护，已验证的恢复来源可作为可用恢复基线；明确结束维护后才开放网页。程序中断时依据工作区级操作日志和实际目录判断已回退、已恢复或待处理，不自动重放恢复请求。

平台升级和项目重新构建都不得删除业务数据。删除项目是单独的用户操作，不以“清理缓存”或“构建失败”为由触发。

项目归档携带 `snapshotState` 和已知待构建提示，不携带本机维护 ID。维护或未知状态的归档导入后重新建立本机维护与基线，新基线不能消除未完成的构建要求。完整工作区迁移则保留全部控制历史、回收站、备份和恢复现场，不能复用单项目导出的排除规则。

迁移提交后，在目标工作区为活跃登记项目单调推进文档代次并持久记录，再开放业务入口；保留历史值和维护模式，不从零重置。这样同浏览器的新会话也不能让迁移前的旧文档继续写入。

## 11 第一版验证标准

使用“孩子英语学习”完成一次完整验证：

1. 用户创建项目，得到可直接打开的初始应用、匹配源码、独立空库、README、skill 和给 AI 的交接说明；在没有可用 Node 的受控环境验证创建及打开，初始来源真实且没有伪造成功任务。
2. AI 从 skill 和项目文档理解平台，读取实际数据库结构，建立业务表并导入单词。
3. AI 编写网页，调用平台构建，拿到浏览器地址和日志。
4. 浏览器和桌面可以查询同一份单词和学习记录；一次写入在另一端重新查询后可见。
5. 关闭外部 AI，用户仍能答题、保存结果、重新打开并看到记录。
6. AI 修改页面重新构建，原有数据和附件保留；首次用户构建故意失败保留初始应用，后续失败保留上次网页；成功发布后已打开的旧初始页仍能读取同代资源。
7. 换另一个 AI，仅凭项目目录、文档和工具入口继续修改。
8. 完成一次项目备份和恢复，核对数据库、附件和网页均可用。
9. 在真实桌面签名包与普通浏览器分别完成录音、拍照、回放和保存；拒绝权限或进入维护时提示正确，已保存内容可重新打开。
10. 核对运行声明与网络策略、公开接口失败时的本地功能，以及源码/产物/用户素材等空间分类；只清理允许的依赖或缓存后，项目数据、素材和当前网页保持可用。
11. 构建期间改动输入，任务失败且旧产物与来源不变；只改数据库、附件或根 README 不误判构建输入。复制改 ID、恢复旧归档与迁移后来源显示符合实际。
12. 同项目重复打开复用且不丢表单，多项目各自运行；业务关窗收尾本应用 Node 与普通后代。macOS 管理窗口 X 只隐藏，业务窗口及服务继续运行；Dock／Reopen／重复启动恢复同一个管理窗口。菜单退出／Cmd+Q 与非 macOS 管理窗口 X 才安全退出全部受管应用。失败与归属不明保留真实状态，独立 Node 不动；旧代次仍要求明确重载，项目不能调用管理原生命令。
13. 改名称、简介和图标不改变 ID、不重建、不重载业务表单；基本信息编辑冲突被报告，备份恢复与复制保留正确图标。没有图标、没有产物或数据库不可用仍可查看平台概览。
14. 核对已安装平台信息、实际程序路径与程序体积；默认工作区和固定应用数据目录不重复加总，统计缓存失效后明确显示时效或未知。
