## 1 两个独立入口

| 文档 | 推荐位置 | 外部包字段 | 阅读者与入口 |
| --- | --- | --- | --- |
| 用户使用说明 | `docs/USER_GUIDE.md` | `documentation.readme` | 普通用户；安装预览和应用详情的“使用说明” |
| AI / 开发说明 | `docs/DEVELOPMENT.md` | `documentation.development` | AI、开发维护者；“开发资料／给 AI 的说明” |
| 数据业务说明 | `docs/data.md` | `documentation.data` | AI / 数据维护者；表、字段及初始资料说明，seed 候选仍有独立条件 |

前两份说明分别保存为 UTF-8 Markdown 文件，推荐 `.md`，也接受 `.markdown`。路径由清单声明，不要求固定文件名，不自动搜索或猜测。复用现有字段，不新增另一套 `userReadme`、`aiReadme` 配置；名称、版本、图标和短简介仍以清单为准。

两类说明指向不同文件，不能用同一路径或路径别名充当两份文档；这一关系由文件/语义检查验证，普通JSON Schema不能比较两个字段所指的实际文件身份。

用户所说的应用“说明文件”应区分机器清单与阅读资料：未来 Node 的启动入口、版本要求和生命周期协议放在版本化的结构化清单中；Markdown 可以解释约定，但平台不解析其中的 shell 命令、代码块或自然语言来执行启动，也不以 `package.json.scripts.start` 代替声明。未来字段仍是草案，不是现有清单的可用扩展。

```json
{
  "documentation": {
    "readme": "docs/USER_GUIDE.md",
    "development": "docs/DEVELOPMENT.md"
  }
}
```

这是外部包清单片段，不是完整清单；完整实例见[最小示例](project-format-v1/examples/minimal-app/local-app.json)。Schema 对声明的两种说明路径检查 Markdown 后缀及基本路径结构；真实文件、编码和内容另查。

本次确认的是两类文档的内容和入口分工。当前目标 Schema 的 optional 和 seed 数据说明条件保持，不擅自将所有包都新增为两份必填；是否每个包强制携带、附源码时是否额外强制开发说明，在 AP0.1 定稿。新写示例同时提供两份，避免继续把技术交接和用户操作混在一个文件里。

## 2 给用户看的使用与配置说明

用户不需要读懂源码、SQL、npm 或平台实现才能完成日常使用。说明至少覆盖：

- **用途和主要功能**：解决什么问题、适合谁、主要页面各做什么。
- **项目类型**：与受控运行声明一致地说明“网页项目（`static-web`）”或“Node 服务项目（`node-service`）”，解释后者有由平台管理的后端。平台类型图标/文字由固定映射生成，使用说明不覆盖标签，也不拿作者项目图标代替类型图标。
- **开始使用**：首次打开需要准备什么，如何完成一个最常见任务，初始资料是什么。
- **日常操作**：新增、查看、修改、删除、导入或导出等实际提供的功能；操作成功与失败如何判断。
- **配置方法**：在哪里配置；每项提供中文名、用途、必填/可选、虚构示例、默认值（无默认也说明）、格式限制及填错/缺失的影响。无配置就明确写“不需要配置”，不省略让用户猜测。
- **网络和设备**：哪些功能需要联网、请求什么服务/发送什么内容；麦克风/摄像头的用途与授权入口。未使用时写无，离线/拒绝时如何继续。
- **数据与帮助**：保存在哪里、关闭后是否保留、如何通过平台备份恢复；常见错误、已知限制和恢复后的变化。

只记录已经存在的界面和可操作配置；目标示例或尚未完成的功能明确标注，不编造安装按钮、配置页或承诺自动保存。普通使用不应要求改表、替换数据库、安装 Node 或理解 AI 的开发步骤。

类型与状态分开说明：停止的 Node 仍显示 Node 服务项目；启动中、健康、需要配置、维护及恢复提示分别表达，网页项目不显示“Node 已停止”。类型图标旁有中文标签，无需悬停即可辨识，灰度与读屏可用；卡片、详情和检测预览共用映射，只在既有平台管理界面展示，普通浏览器仍只承载业务网页。类型图形与具体布局尚待实施验证，不把文档描述写成已有界面。

普通配置与秘密凭据分开，普通配置也不默认公开给业务网页。说明不要求把秘密 key、管理令牌或会话写进清单、前端程序资料、项目库或 Markdown，也不把尚未实现的配置能力描述成当前已支持。配置示例使用虚构值，不携带私人数据和开发者机器路径。

Node 配置的每个变量还必须给出独立可读的获取步骤：在哪个服务注册/登录、到哪个页面创建或查找、复制什么内容、回到哪个表单项填写；无需获取时明确说明可以直接填写。官方入口可作为辅助链接，但不能只写“见链接”或“自行获取”。机器清单中的受控字段生成配置表单，Markdown 补充解释且与清单一致；实际值与声明分开。用户在界面填写，不编辑 `.env`、输入终端命令或理解环境变量的技术含义。

候选存储与生命周期策略是：普通值保存为本实例的受管私有数据，纳入新类型私有完整归档并在原实例恢复快照值，分享默认去掉本机配置值；秘密值交由 OS 凭据库，不写 `.env`、源码、项目库或日志，任何项目 ZIP 均不携带秘密值或可直接使用的绑定。同机原实例恢复保留当前凭据绑定、不回滚 Key，复制/导入新 ID 重新填写。管理表单在用户输入时短暂接触明文，保存后仅返回是否已配置，不读回展示，不提供给业务网页或 AI。具体同机迁移及凭据保留规则见[配置契约草案](node-app-configuration.md)，需先定稿再实现；用户配置与平台控制令牌始终分开。

## 3 给 AI / 开发者看的技术与开发说明

技术说明可以引用用户指南描述业务，但开发者应能从独立入口完成接手，至少包含：

- **项目定位与架构**：程序由哪些模块组成、各自职责，网页、平台服务、SQLite 和附件怎样协作。
- **运行类型依据**：解释清单及平台受管映射；不执行项目脚本、不按 `package.json` 或文档猜类型。旧合法 v1 以既有静态语义识别，不补写字段；未知类型显示不支持并禁止运行。运行类型与 AP 的有无源码/开发或安装身份分开。
- **目录与关键入口**：实际源码/产物位置、主要模块和依赖；哪些文件可编辑、哪些是平台管理资料。
- **开发环境与构建**：实际提供的源码、工具链和锁文件、SDK/API 版本、构建/发布方式。只有真实可用时才列命令和平台构建入口。
- **配置声明与交付**：逐项说明机器清单字段、中文用途、获取步骤、校验、缺失/错误影响及实际值的归属；普通值、秘密值和平台控制凭据分别处理，不附真实值或要求用户维护 `.env`。
- **数据契约**：业务表、主键/UUID、关系、单位、枚举、附件逻辑路径；链接数据说明，修改前核对真实结构。
- **维护与验证**：改表或恢复前的基线/维护流程、任务查询、受影响功能的验证、草稿与旧文档处理、重启后的保留。
- **限制与交接**：源码是否附带、来源是否验证、已知问题、尚未完成的功能、后续接手线索。

源码可选的包也可以提供技术说明，但必须写清“仅有预构建运行产物，未附可重构建工程”。不能因有一份开发说明就宣称可构建或来源 matched，不能伪造 npm/Node/构建记录。附带 source 也只是资料，转为受管开发型仍走后续明确流程。

查看技术说明不等于授权执行其中的命令或修改数据。项目业务文档作为待核对资料读取，实际平台状态、schema、来源和用户授权优先；外部包不能通过文档改写平台身份、工作区设置或跳过维护/恢复保护。

未来 Node 应用的技术说明还应解释与机器清单一致的入口、完整运行产物/依赖、就绪与停止协议、数据路径和已验证的系统范围；用户指南则说明界面中的启动、停止、状态及故障处理，不要求用户安装 Node 或执行终端命令。自有数据的所有权规则仍须定稿；不能因提供了说明就宣称已接入一致性备份。备份/维护/恢复/迁移/移入回收站前的后端停写和退出核验、运行依赖随归档保存、导入恢复不执行代码及不自动启动，都需要平台实现和独立验收。

## 4 短简介、正文与渲染限制

| 内容 | 规则与状态 |
| --- | --- |
| `app.description` | 外部包的纯文本短简介，最多 2000 个字符，适合列表与概览；不把整份 Markdown 塞进 JSON |
| 用户和开发说明正文 | UTF-8 Markdown，两个文件独立维护；正文单文件字节上限尚未定稿 |
| 64 KiB | 仅为之前提出的建议，未确认，不写进 Schema 或当作已执行上限 |
| 基础排版 | 目标支持标题、段落、列表、表格、代码文本和受控链接；查看时不执行 HTML、脚本或命令 |
| 图片/附件/外链 | 具体资源声明、相对链接、图片读取预算和外链行为在 AP0/AP1 定稿；不默认加载远程资源或公开源码/数据目录 |

正文要有受控读取和渲染预算，但具体字节数、行数/嵌套等参数仍是候选。超限、缺失、不可读、非法编码的诊断方式应明确定义，不能静默截断后把检查标为完整通过，也不能将读取失败当作没有说明。

Schema 只验证路径结构及后缀，不能证明文件字节、Markdown 内容、安全渲染或文字正确。安装预览显示用户指南；开发资料用独立入口查看，不作为网页脚本或自动配置执行。两份文档都不是项目静态服务根，管理页展示须走受控读取和 Markdown 渲染；这部分尚未实现。
