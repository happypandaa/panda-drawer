## 2. 支持边界与建议技术选择

### 2.1 沿用已经确认的边界

- 首个完整应用闭环采用[Radio 类兼容基线](app-development-environment.md#首版兼容基线radio-类应用)：静态前端与平台 SQL，或静态前端、一个受管 Node 服务、同进程 SDK 和外部 HTTP 服务。任意语言、多服务、Docker、通用 CLI、任意原生依赖和现场编译不自动纳入。
- 成品携带构建好的前端和完整后端运行文件。登记、安装、恢复和启动不隐式执行 npm 安装、构建脚本、SQL 或包内 shell 脚本。
- Node 继续采用一个应用一个原生窗口、一个受管后端，重复打开只聚焦；业务关窗收尾对应服务及普通后代。macOS 管理窗口 X 隐藏，菜单退出/Cmd+Q 才收尾全部，按[现行窗口契约](app-window-runtime-contract.md)执行。
- 现有项目、源码、SDK、数据库、附件、维护状态、备份、回收与恢复证据全部保全。固定开发身份和数据根不变，工作区变更走公开迁移。
- Node 秘密沿用本槽私有文件及现行权限约定，不擅自切回 Keychain。作者源码、Git、公开分享、日志不得携带本机秘密；备份和恢复的凭据边界须单独定稿。

### 2.2 建议在对应步骤定稿的选择

| 事项 | 建议方案 | 定稿位置 |
| --- | --- | --- |
| 内置 Git | 随平台分发固定版本的私有 Git 可执行工具及必要 HTTPS 配套，以绝对路径调用；不要求用户配置系统 Git | T04，验证体积、许可证、签名和目标系统后确定具体资源 |
| Git 首期范围 | GitHub/Gitee 公开 HTTPS 仓库；支持明确 branch/tag/commit，记录最终 commit；本地查看改动、保存源码版本和上游比较 | T06、T19、T22；私库/SSH/LFS/子模块自动获取后置 |
| 下载来源 | 仓库源码用 Git；源码快照、标准应用包和 Release 附件用 HTTPS；分别识别、共同进入检测 | T06–T08；GitHub/Gitee 的页面/API 分别实现与验收 |
| 私有开发环境 | 开发用 Node/npm 与日常运行用 Node 分开管理，固定版本、完整性和许可证；先支持现有模板和受支持纯 JS Node 样本 | T09–T10；具体版本、脚本策略与缓存预算待验证 |
| 源码与实例关系 | 来源记录、可编辑源码、候选产物、当前运行版本、实例数据、私有配置分开；开发工作不覆盖正在运行的文件 | T02、T10、T18；不直接重排旧项目目录 |
| 更新范围 | 先做用户触发、相同数据格式的应用更新；保存一致恢复点后切换程序，失败可恢复 | T20–T21；数据结构迁移协议后续明确，不能自动执行任意迁移脚本 |
| 分享默认值 | 干净成品包；源码和示例数据分别选择，个人业务数据默认不带，秘密始终排除 | T23；现有完整备份 ZIP 保留独立用途 |
| 首轮远程操作 | 先完成下载与本地导出；用户可自行上传分享包或使用既有仓库地址 | T25–T26 才扩展账号、私库与直接发布，不阻塞首个四场景闭环 |

候选目录与受控环境不能称为代码沙箱。下载和静态检查不运行作者代码；构建、预览和正式运行会执行应用代码，需清楚展示来源及执行动作，沿用受信任应用边界。

       网页：T08 + T11 + T14 → T15 安装 → T17 数据初始化 → T20 更新

图展示主依赖；表格中的前置条件是执行依据。分号后的“Node 另需”“附源码另需”等是按功能选择增加的门槛，不要求网页路线等待全部 Node 能力。并行开发可使用可丢弃样本；尚未满足前置条件的功能不对真实项目开放。

**最先推进**：T01–T03 固定共同规则，随后并行推进 Git 获取 T04–T08、开发构建 T09–T10，以及新类型保护 T11–T14。成品安装不依赖 Git 或私有 npm；Git 获取的工程试验也不需要等 Node 正式安装。

### B. Git、链接获取与检查

| 步骤 | 前置 | 做什么、解决什么问题 | 通过条件 |
| --- | --- | --- | --- |
| T04 私有 Git 分发与执行器 | T02、T03 | 打包固定 Git、HTTPS 所需配套、许可证和摘要；隔离系统/全局配置、模板、hooks、credential/askpass、filters、外部协议和继承环境；参数列表调用；首次只操作平台创建的独立仓库 | 无系统 Git 的目标 Mac 可使用；缺失/损坏/错架构明确失败，不静默回退 PATH；恶意本机配置不触发外部命令；取消只收尾所属任务；Windows 实际开放另等 T29/T30 |
| T05 Git 状态保护 | T04、T11 | 定义并实现版本化源码恢复快照：提交与引用、本地未推送历史、index、工作树、未跟踪文件、stash 和恢复证据；明确忽略文件、reflog/不可达对象和外部对象依赖的保留范围。补齐备份、复制、恢复和回收 | 离线恢复到新样本，提交/分支/tag、暂存与未暂存差异、未跟踪文件逐项相符；未推送内容不丢；旧备份仍可读；附件中同名 `.git` 不被误删；不执行恢复出的 hooks/config；无法覆盖的状态在操作前阻止或明确保全 |
| T06 仓库源码获取 | T03、T04、T05、T08 | 接 GitHub/Gitee 公开 HTTPS URL，解析仓库及明确版本，下载到任务候选后保存为受管源码；记录原地址、请求 ref、最终 commit 和完整性。检测 LFS、子模块、浅历史/缺对象及不支持布局 | 两个平台各真实验收公开仓库；branch/tag/commit 固定正确；404、私库、限流、超时分开；ref 后续移动不改变已取得源码；下载不运行脚本；不支持特性不能虚报“已准备好”；原目录与同名项目不被覆盖 |
| T07 成品/源码归档 HTTPS 获取 | T03 | 实现受管下载、重定向/来源规则、长度与摘要、部分下载处理；分别适配成品直链、GitHub/Gitee Release 附件和源码归档，避免把所有链接都当 Git | 断流/取消不发布完整文件；重试不重复安装；超预算/目标变化拒绝；下载摘要可追踪；普通源码 ZIP 不进入备份恢复；已支持的每类服务链接有实际样本，未验证的页面/API 不宣称支持 |
| T08 统一只读检测 | T02、T03 | 本地文件、下载包和源码共用检测器；安全解压、路径/链接/大小限制、清单与兼容性、入口/依赖/文档/数据检查；生成绑定内容摘要的报告与下一步 | 可安装成品、需要构建源码、需要 AI 适配、不支持、检测未完成分别返回；检测不执行代码；ZIP 穿越/链接逃逸/名称碰撞/损坏清单拒绝；内容变更令旧计划失效；检查报告解释具体缺项 |

映射：AP1.1–1.4；T04–T07 的工具、来源和 Git 状态属于新增模块，原 AP/NR 计划没有完整覆盖。T05 在 T11 后落地，T04/T08 可先行；内部获取试验允许只产生隔离候选，公开保存受管源码须通过 T05。

Git 恢复快照不能只做 `git bundle --all`：bundle 不包含完整工作树、index 等本地状态。首版不以依赖网络的 partial clone 作为唯一受保护副本；如做下载优化，必须在宣称离线可恢复前补齐对象或明确拒绝该能力。受保护证据和可激活配置分开保存，完整归档策略在 T05 定稿。[Git bundle 官方文档](https://git-scm.com/docs/git-bundle)

### C. 私有开发环境和候选构建

| 步骤 | 前置 | 做什么、解决什么问题 | 通过条件 |
| --- | --- | --- | --- |

| T10 候选依赖与构建 | T08、T09、T11；真实 Node 项目另需 T13 | 复用现有锁文件、输入摘要、日志、产物检查和失败保留机制，转为候选工作副本/依赖目录；先网页模板，再受支持 Node。记录工具/锁文件/目标系统/输入输出摘要；准备与应用结果和启停、备份、更新互斥 | 无系统开发环境可完成模板修改构建；Node 样本可产出完整可运行文件；锁不匹配、网络/脚本失败、取消、源码变化均不覆盖当前产物或依赖；构建产物重新过 T08；运行时无需 npm 补装；T13 前只验证可丢弃 Node 候选副本 |

映射：复用 M2 构建；私有 npm 是新增开发工作，不能将当前 NR1 私有运行时验收当作已完成。T10 与网页保护 T11 接合后开放，受管 Git 源码另受 T05 保护。

现有 `npm ci` 会在执行目录重建依赖，不能直接用于正在运行的 Node 源码槽。`ignore-scripts` 也不能把显式执行的 `npm run` 变成静态操作。T10 需要明确依赖来源、安装脚本与构建脚本策略，并基于最终固定 npm 版本验收；首次联网安装和缓存齐备后的离线构建分别记录。[npm ci 官方文档](https://docs.npmjs.com/cli/v11/commands/npm-ci/)

| 获取别人的项目 | 成品包本地/HTTPS 安装；GitHub/Gitee 源码获取后分别验证可构建、需适配和不支持三类 → 必要配置 → 使用 | 两个平台真实公开仓库样本；明确成品与源码区别；无作者目录依赖；安装不隐式执行构建；错误有可执行下一步 |
| 分享自己的项目 | 选择已验证版本 → 预览内容 → 导出干净包，可选源码/示例 → 另一电脑接收 → 填自己的配置 → 使用/重开/恢复 | 包内容清单、测试秘密排除、两个实例数据隔离、接收电脑与系统记录；不能只在作者电脑导入一次 |
| 修改与定制 | 配置修改；有源码时保留原版 → AI 定制 → 构建验证 → 一致恢复点 → 更新；再取一个上游更新和冲突样本 | 原数据和附件保留、来源关系可查、冲突不动当前运行版、失败一致恢复；Git 源码回退与业务数据恢复分别验证 |

### 6.2 共用故障与边界

| 范围 | 必测内容 |
| --- | --- |
| 来源与包检查 | 错链接/私库/限流/断网、恶意或损坏 ZIP、路径逃逸与名称碰撞、LFS 指针/子模块/缺对象、摘要变化、未知格式、不兼容系统与运行时 |
| 任务与提交 | 重复提交/迟到响应、取消、磁盘不足、源文件变化、文件占用、各持久提交点硬中断和重启对账；不重放结果未知的写入 |
| 数据与秘密 | SQL/附件完整性、备份恢复与维护代次、未推送及未提交源码、配置修订、日志/包秘密排除、复制/异机恢复绑定、不删除既有恢复证据 |
| 运行与窗口 | 同应用唯一窗口/后端、不同实例隔离、业务关窗、管理窗口隐藏、菜单退出、Dock/Reopen、宿主硬崩溃和进程身份复用；按具体系统真实验收 |
| 构建与兼容 | 无系统 Git/Node/npm、完整依赖交付、首次在线与缓存后离线、错误工具版本/架构、原生模块目标、旧 SDK/项目/备份兼容 |
| 真实环境 | macOS 最低支持版本与目标新版本、两版 Windows 分开；WebKit/WebView2/普通浏览器和物理录音拍照分别记录；外部服务是否真实调用、付费及联网前提准确列明 |

每步形成记录：代码版本、目标系统/架构、样本、动作、期望/实际、故障注入位置、恢复结果、尚未验证范围。模拟测试只证明模拟范围；不能用假媒体或静态检查替代真实设备和新电脑交接。

## 7. 实施落点与协作规则

| 模块 | 主要落点与原则 |
| --- | --- |
| 对象、类型和来源 | `projects.rs`、`metadata.rs`、清单及 Schema；兼容旧格式，不把运行类型与是否有源码混为一谈 |
| 受管工具和构建 | `environment.rs`、`builds.rs`、`resources.rs`、`scripts/prepare-desktop.mjs` 与资源打包脚本；建议 Git 执行器独立成模块 |
| 获取、检测、安装 | 建议新增独立获取/包检测/安装事务模块；`tasks.rs`、`service.rs`、CLI 与桌面只接统一接口，不各自实现一套状态机 |
| Node | 复用 `node_apps.rs`、`node_app_manifest.rs`、`node_app_configuration.rs`、`node_runtime_trial.rs`、`node_app_proxy.rs`、桌面 `node_windows.rs`；补齐已缺能力，不重做已验子集 |
| 数据与恢复 | `backups.rs`、`maintenance.rs`、`lifecycle.rs`、`workspace.rs`、`history_cleanup.rs`；按类型扩展，保留旧归档与现场身份检查 |
| 系统与发行 | `platform_support.rs`、`platform-preflight`、`file_identity.rs`、`paths.rs`、进程层及桌面打包；按能力开放，不用假成功绕过 Windows 门禁 |
| 作者与用户说明 | `docs/`、项目模板和随包 skill references；反映当前真实能力，不覆盖已有业务项目自己的 SDK、skill 或说明 |

每个实现子步骤先明确契约和退出条件，再写代码并执行相应检查；通过后只提交该完整步骤并推送远端。并行未完成内容、秘密、生成应用/DMG、真实数据及本地试验证据不混入提交。复杂格式或跨模块保护不能为了凑单次提交而省略恢复路径。

## 8. 技术依据与后续复核
