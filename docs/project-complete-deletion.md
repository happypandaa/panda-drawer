# 项目完整删除：独占归属与四批实施

确认日期：2026-10-28。用户确认：完全不兼容旧项目；不开发旧残留清理或迁移计划，现存 Radio 等残留由用户清空开发数据根处理。项目内容不跨项目共享，不做引用计数或删除时其他实例引用扫描。平台管理的可编辑源码（包含 Git、未提交修改与 AI 改动）随项目全部删除，不保留副本。

保留项限平台自带 Node 运行时及工具链、Git 环境、平台全局 settings／lock／runtime／migrations 和容器目录。用户补充确认：外部原始目录仍保留；平台下载或创建的源码全部删除。外部目录关联的实例私有内容和平台归属记录仍清除；外部 `.git` 内由平台创建的源码恢复材料也清除，普通 Git 版本、源码及用户文件保留。

用户另行确认：今后由平台导出的外部 ZIP 也归原项目所有，随项目删除。导出发布前登记最终路径及文件身份，删除按已登记身份处理；不追溯旧导出，不根据历史结果中的路径收养文件。原始导入 ZIP 保留。为落实目标路径独占，导出要求新文件名，不再覆盖现有文件或复用已占有的路径（同项目也需新文件名）。

## 分批与验收边界

1. Node 完整删除：受理时持久记录独占归属；停止实际写入者后，删除整个实例目录、平台源码、来源副本、安装／构建现场和相关任务，清磁盘及内存。成功不留删除任务；UUID 不复用，目标全部不存在时重试幂等成功。
2. 网页项目对齐：整项目及目录外登记、构建、维护和任务一起删；重导入永远生成新身份，旧会话不能访问新实例。
3. 其他残留：窗口尺寸及旧缓存副本、空间缓存、最近目录、任务中心。
4. 所有项目使用独立 WebView data_store_identifier（macOS 最低15）；销毁窗口后删除对应store并等系统完成。旧共享存储不兼容，切换时清空。核对Node动态端口与按项目存储隔离。

第4批完成前不宣称“无痕删除”。每批完成后检查、提交、推送并报告。所有删除回归仅操作明确命名的临时项目；不执行真实开发数据根重置，也不清已有Radio目录。

## 第1批

实现范围：

- 新增 `node-project-ownership/<实例 UUID>/ownership.json` 活归属索引。下载受理即分配 UUID；后续源码候选、安装候选、构建现场（含 npm 缓存）、任务与 onboarding 恢复记录只归该实例。来源不能再用于创建另一个实例或更新别的实例。
- 本地外部原目录只建立独占占有记录，不进入删除目标；拒绝同目录和父子目录跨实例登记。空目录“生成并添加”在写入前分配 UUID 并记录根目录身份，登记沿用该 UUID，生成源码随项目删除。
- 新 v3 删除任务在受理时绑定实例与归属索引身份，停止并等待实际写入者结束，移动任何目标前刷新同一索引内的最终独占材料。整实例槽、平台源码、来源／安装／构建／任务材料全部删除。每个目标在所在卷内暂存，保留目录身份、替换、链接和挂载边界保护。
- 删除成功后清磁盘与内存记录，不保存成功删除任务。当前等待者可收到最终结果；回执丢失时，只有实例槽、归属和未完成删除均已不存在才返回 `alreadyAbsent`，不会重新创建旧 UUID。
- 正常公开工作区迁移会复制工作区并保留旧副本；新迁移把旧工作区内本项目的精确材料路径及身份记入同一归属，删除时一并清除。迁移全局日志保留。工作区内普通外部原目录的原件仍保留，其新位置复制品归同一实例独占；生成项目的登记、绑定和占有记录一起迁移。存在待处理 Node 源码恢复时拒绝迁移，不为旧恢复 journal 改写绝对路径。迁移后删除读取当前运行时的工作区与任务管理器，避免清理旧 registry 而遗漏新记录。该机制不扫描、收养或清理未知旧数据。
- 登记发布前失败回滚新实例槽；外部源码的占有记录和归属也清除，原目录不动。生成完成但登记尚待核对时保留同 UUID 的活恢复流程；生成中失败仅回滚本次确实创建的文件，不覆盖并发外部修改。

追加交叉审查修正：源码恢复的两个同卷平台材料根（`.git/local-projects-node-restores`、`.git/local-projects-node-restore-preparing`）也在创建前登记归属，删除只清这些精确受管目录，外部源码和普通 Git 文件保留。删除等待实际恢复写入者结束，不再要求先处理待恢复记录。安装准备和 onboarding 的操作许可必须覆盖最终 journal／任务写入，避免进程 scope 提前结束后删完又重建材料。源码发布在 rename 前绑定 payload 身份，拒绝重名外部目录，不在失败后收编它；发布中断也能直接按既有归属删除。

移除的旧兼容与保留行为：

- Node 删除 journal v1/v2、旧 `legacyIrreversible` 及独立 registration 捕获／恢复事务；删除仅服务该事务的 `node_deletion_registration_tests.rs`。
- `.deletions/<id>.json` 与 `removalPending` 旧标记读兼容；不新增旧任务升级或清理入口。
- v1 运行标记自动丢弃与 `LegacyDiscardable`，以及详情读取时补写外部源码绑定的懒升级。未知标记不再被视为可以操作进程的凭据。
- 导入完成记录转存 `onboarding/imports/completed` 的行为；新记录按任务独立存放，完成清理后直接移除。
- 删除后保留实例运行恢复目录、安装历史和成功删除任务的行为。

验证：`cargo test --locked --workspace` 全组 1,016 通过、57 按原规则忽略；另实际执行真实 Git 恢复组 10/10（含 12 种逐文件中断恢复矩阵）、待恢复迁移门禁／删除解除 1/1，以及真实 Node/npm/Git 的构建、更新、运行、恢复、外部项目删除整链 1/1。前端 `npm run test:ui` 514/514，TypeScript/Vite 构建、全 workspace 严格 Clippy、格式及差异检查通过。回归期间修正两处测试夹具 PID 就绪文件的非原子发布竞态，未减弱进程清理断言。

所有删除只用临时项目；未执行真实 Radio 或已有开发数据清理。卸载前全量清理同样读取当期归属索引与当前删除 journal，纳入平台生成目录、迁移复制品及外部暂存的受管材料。网页生命周期资料、窗口尺寸与空间缓存、WebView 系统存储分别属于后续批次；此处不宣称“无痕删除”。

## 第2批

实现范围：

- 网页项目受理时建立 `web-project-ownership/<项目 ID>/ownership.json`。完整删除覆盖项目根、目录外登记／构建状态／维护与恢复材料、npm 缓存、相关任务及公开迁移保留的本项目副本。先排空实际写入者，再删材料、身份、任务和归属；成功不保存删除任务。坏业务数据库、坏维护 JSON 和静态恢复记录不再迫使保留项目。
- 增加只读删除范围预览。界面与 CLI 使用同一私有登记身份，不依赖业务数据库正常；有替换对象、离线卷或范围读取失败时不提交删除。尾段失败、成功回执丢失与目标全缺均按本项目及任务类型核对，不重新创建旧身份。
- ZIP 导入与复制一律分配新 UUID，副本不共享可写源码、数据库、附件、任务或恢复材料。清除旧身份时同时撤销 Session、Ticket 和上传缓存；身份校验与缓存插入和注销使用同一登记锁，避免旧请求在删除成功后重建缓存。
- 新导出的外部 ZIP 纳入原项目独占归属与预览，发布前绑定暂存文件身份，使用新文件名。文件名占有考虑父目录身份、Unicode 和大小写别名；平台项目之间不能嵌套占用来源与导出目标。原始导入 ZIP、外部原工程和其他独立项目保留。
- 为受管子进程增加持久写入标记：正式标记同步发布后才 spawn，只在实际进程组与输出 IO 闭合后移除。Drop、任务 Interrupted 或重启平台均不能当作已停写。当前 OS 启动会话的遗留标记阻止删除、迁移与卸载；使用内核启动会话 UUID 核对真正 OS 重启后才可退休旧标记，不按旧 PID 猜测杀进程。
- 已知材料缺失还须核对原卷仍可见；外置盘或旧工作区离线不能当成已删除。平台全局工具配置不能依赖项目内部 Node/npm/Git 或指向这些对象的软链接，避免删除一个项目破坏其他项目的工具。

移除的旧兼容与保留行为：原 ID 导入选项、旧目录按清单发现／读取时懒登记、retired 身份墓碑与旧 session generation、旧 `trashed` 页面状态和“删除后保留历史备份／任务”的当前行为。历史日期报告只证明当时版本，不转化为旧数据清理功能。

主要文件：`lifecycle.rs`、`web_project_ownership.rs`、`web_project_cleanup.rs`、`web_export_claims.rs`、`web_file_deletion.rs`、`projects.rs`、`builds.rs`、`service.rs`、`local_cleanup.rs`、`platform-cli/src/main.rs`；前端 `ArchiveImportPanel.tsx`、`ProjectDeleteDialog.tsx`、`ProjectExportDialog.tsx`、`App.tsx`；`durable_writer.rs`、`owned_process.rs` 与 Node/Web 进程 scope；`project_tool_boundary.rs`、Node/npm/Git 工具选择边界；同步更新相关测试和删除／生命周期／开发说明。

最终验证：`cargo test --locked --workspace` 全组 1,081 通过、57 按原规则忽略；前端 520/520、TypeScript/Vite 构建、全 workspace 全目标严格 Clippy、格式和差异检查通过，7 份变更文档的 160 个本地链接无缺失。新增文件安全组覆盖 10 个已绑定持久边界逐一重开续删，导出专项覆盖 7 种归属／路径／迁移情况；卸载组 22/22 通过，包括原址替换与失败保留归属后重新预览。真实临时宿主 SIGKILL 后已观察到孤儿继续写入，删除门禁拒绝；OS 重启退役只用不同内核启动会话夹具验证，失联卷用错误卷身份夹具验证，未重启电脑或拔真实磁盘。

已验证的安全拒绝边界：同卷文件暂存目录创建后、目录身份尚未持久化前崩溃，会保留删除计划和精确路径并阻止继续，不自动认领同名目录；成功路径与其余已绑定边界不留计划、暂存或 claim。此状态会明确报告失败，不当作删除成功。

未删除真实开发项目、原始输入或已有外部导出。窗口尺寸、空间缓存及原生 WebView 存储属于第3／4批，当前仍不宣称“无痕删除”。

## 后续两批已确认的代码缺口

- 窗口尺寸目前共用 `app-window-sizes.json`，每次交换还会留下完整旧缓存副本；需改成项目独占，并撤销已克隆的晚窗口事件写入。旧全局文件不迁移、不另加旧残留扫描，由用户重置开发数据。
- 最近目录和上次仓库地址目前写管理界面的 localStorage；后台来源会话及任务中心需要按项目的实际任务 ID 失效。Node 来源任务的 `TaskRecord.projectId` 为 null，不能仅按该字段过滤。CLI／HTTP 删除也必须触发同一清理通知，不能依赖前端删除按钮的回调。
- 空间汇总及项目扫描缓存需要清除磁盘和内存，并防止删除前开始的扫描晚发布。
- 当前 Web／Node 业务 WebView 共用默认系统存储。Node 后端与代理均使用动态端口，不能凭端口随机分配认为浏览器内容已隔离。第4批采用稳定项目身份的独立 store，销毁窗口后等待 WebKit 删除完成再确认不存在；旧默认共享 store 单独清空并核验。
- 网页应用浏览器下载的暂存目前位于全局 `runtime/native-downloads`，只持平台总 IO 许可，缺项目级写入归属；删除项目后旧保存对话框仍可能发布文件。需迁入项目归属、撤销未开始的保存并等待真实 Finished／复制收尾，缺 Finished 不能以关闭窗口代替。附件另存已有项目读锁保护，不能混作相同缺口。业务下载／附件交付到外部后的归属边界正在单独向用户确认；平台内暂存和未完成写入均属于本轮必须清理的范围。
