# 项目完整删除：独占归属与四批实施

确认日期：2026-10-28。用户确认：完全不兼容旧项目；不开发旧残留清理或迁移计划，现存 Radio 等残留由用户清空开发数据根处理。项目内容不跨项目共享，不做引用计数或删除时其他实例引用扫描。平台管理的可编辑源码（包含 Git、未提交修改与 AI 改动）随项目全部删除，不保留副本。

保留项限平台自带 Node 运行时及工具链、Git 环境、平台全局 settings／lock／runtime／migrations 和容器目录。用户补充确认：外部原始目录仍保留；平台下载或创建的源码全部删除。外部目录关联的实例私有内容和平台归属记录仍清除；外部 `.git` 内由平台创建的源码恢复材料也清除，普通 Git 版本、源码及用户文件保留。

## 分批与验收边界

1. Node 完整删除：受理时持久记录独占归属；停止实际写入者后，删除整个实例目录、平台源码、来源副本、安装／构建现场和相关任务，清磁盘及内存。成功不留删除任务；UUID 不复用，目标全部不存在时重试幂等成功。
2. 网页项目对齐：整项目及目录外登记、构建、维护和任务一起删；重导入永远生成新身份，旧会话不能访问新实例。
3. 其他残留：窗口尺寸及旧缓存副本、空间缓存、最近目录、任务中心。
4. 所有项目使用独立 WebView data_store_identifier（macOS 最低15）；销毁窗口后删除对应store并等系统完成。旧共享存储不兼容，切换时清空。核对Node动态端口与按项目存储隔离。

第4批完成前不宣称“无痕删除”。每批完成后检查、提交、推送并报告。所有删除回归仅操作明确命名的临时项目；不执行真实开发数据根重置，也不清已有Radio目录。

## 第1批

实现范围：

- 新增 `node-project-ownership/<实例 UUID>/ownership.json` 活归属索引。下载受理即分配 UUID；后续源码候选、安装候选、构建现场（含 npm 缓存）、任务与 onboarding 恢复记录只归该实例。来源不能再用于创建另一个实例或更新别的实例。
- 本地外部原目录只建立独占占有记录，不进入删除目标；拒绝同目录和父子目录跨实例登记。空目录“生成并添加”在写入前分配 UUID 并记录根目录身份，登记沿用该 UUID，生成源码随项目删除。
- 新 v3 删除任务在受理时绑定实例与归属索引身份，停止并等待实际写入者结束，移动任何目标前刷新同一索引内的最终独占材料。整实例槽、平台源码、来源／安装／构建／任务材料全部删除。每个目标在所在卷内暂存，保留目录身份、替换、链接和挂载边界保护。
- 删除成功后清磁盘与内存记录，不保存成功删除任务。当前等待者可收到最终结果；回执丢失时，只有实例槽、归属和未完成删除均已不存在才返回 `alreadyAbsent`，不会重新创建旧 UUID。
- 正常公开工作区迁移会复制工作区并保留旧副本；新迁移把旧工作区内本项目的精确材料路径及身份记入同一归属，删除时一并清除。迁移全局日志保留。工作区内普通外部原目录的原件仍保留，其新位置复制品归同一实例独占；生成项目的登记、绑定和占有记录一起迁移。存在待处理 Node 源码恢复时拒绝迁移，不为旧恢复 journal 改写绝对路径。迁移后删除读取当前运行时的工作区与任务管理器，避免清理旧 registry 而遗漏新记录。该机制不扫描、收养或清理未知旧数据。
- 登记发布前失败回滚新实例槽；外部源码的占有记录和归属也清除，原目录不动。生成完成但登记尚待核对时保留同 UUID 的活恢复流程；生成中失败仅回滚本次确实创建的文件，不覆盖并发外部修改。

追加交叉审查修正：源码恢复的两个同卷平台材料根（`.git/local-projects-node-restores`、`.git/local-projects-node-restore-preparing`）也在创建前登记归属，删除只清这些精确受管目录，外部源码和普通 Git 文件保留。删除等待实际恢复写入者结束，不再要求先处理待恢复记录。安装准备和 onboarding 的操作许可必须覆盖最终 journal／任务写入，避免进程 scope 提前结束后删完又重建材料。源码发布在 rename 前绑定 payload 身份，拒绝重名外部目录，不在失败后收编它；发布中断也能直接按既有归属删除。

移除的旧兼容与保留行为：

- Node 删除 journal v1/v2、旧 `legacyIrreversible` 及独立 registration 捕获／恢复事务；删除仅服务该事务的 `node_deletion_registration_tests.rs`。
- `.deletions/<id>.json` 与 `removalPending` 旧标记读兼容；不新增旧任务升级或清理入口。
- v1 运行标记自动丢弃与 `LegacyDiscardable`，以及详情读取时补写外部源码绑定的懒升级。未知标记不再被视为可以操作进程的凭据。
- 导入完成记录转存 `onboarding/imports/completed` 的行为；新记录按任务独立存放，完成清理后直接移除。
- 删除后保留实例运行恢复目录、安装历史和成功删除任务的行为。

验证：`cargo test --locked --workspace` 全组 1,016 通过、57 按原规则忽略；另实际执行真实 Git 恢复组 10/10（含 12 种逐文件中断恢复矩阵）、待恢复迁移门禁／删除解除 1/1，以及真实 Node/npm/Git 的构建、更新、运行、恢复、外部项目删除整链 1/1。前端 `npm run test:ui` 514/514，TypeScript/Vite 构建、全 workspace 严格 Clippy、格式及差异检查通过。回归期间修正两处测试夹具 PID 就绪文件的非原子发布竞态，未减弱进程清理断言。

所有删除只用临时项目；未执行真实 Radio 或已有开发数据清理。卸载前全量清理同样读取当期归属索引与当前删除 journal，纳入平台生成目录、迁移复制品及外部暂存的受管材料。网页生命周期资料、窗口尺寸与空间缓存、WebView 系统存储分别属于后续批次；此处不宣称“无痕删除”。
