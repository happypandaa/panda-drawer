# 给 AI 关联正确的项目目录

AI 要修改你的应用，需要访问这台电脑上的项目文件。最可靠的路径来自熊猫抽屉当前项目详情提供的接手说明。

## 先取到这次的路径

打开要修改的网页项目详情，点击上方常显的「复制提示词」。展开后可以看到「本次项目目录」与完整说明，也可以在「概览 → 应用位置」核对目录。

选择这一整个项目根目录。它通常包含：

```text
你的项目/
├── project.json
├── README.md
├── AGENTS.md
├── .agents/skills/local-projects-app/SKILL.md
├── docs/
└── app/                 应用源码
```

只选择 `app/` 可能漏掉接手说明与平台约定。选择熊猫抽屉本身的开发仓库，则会把 AI 带到另一份工程。复制项目、导入项目或迁移工作区后，都重新取得一次接手说明。

## Codex

1. 在项目详情点击「在 Codex 打开」。Codex 需要已安装在本机。
2. 平台会复制说明，并请求在新任务草稿中打开该项目目录。
3. 在草稿中粘贴完整说明，追加你的需求，核对后发送。

如果没有成功打开，就手动启动 Codex，在本地项目的文件夹选择入口中关联上面那一整个目录，再创建任务并粘贴说明。不同版本的界面可能不同，关键是实际工作目录与「本次项目目录」一致。

Codex 的文件夹与项目行为可参考 [OpenAI 官方说明](https://learn.chatgpt.com/docs/projects)。熊猫抽屉的一键入口只准备草稿，不会自动发送需求。

## WorkBuddy

1. 在熊猫抽屉点击「复制提示词」。
2. 打开 WorkBuddy 的本机任务或工作空间，通过其文件夹选择入口，关联「本次项目目录」。
3. 粘贴完整说明和你的需求，要求先读 `README.md`、`AGENTS.md` 和说明中给出的 skill 文件。
4. 让它先复述正在操作的项目目录，确认后再改。

关联本地文件夹与上传一份文件副本用途不同：这次要修改的是该目录里的实际源码。如果 AI 不能读取目录，先检查当前任务的文件权限与关联位置。

WorkBuddy 的具体入口以安装版本为准；可参考 [官方任务说明](https://www.codebuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)。目前熊猫抽屉没有 WorkBuddy 一键集成，本站也没有将其完整接手流程标为实机验收通过。

## 第一条消息可以这样写

先粘贴平台给出的完整接手说明，再追加：

```text
请先确认你能读取这次项目目录，阅读 README.md、AGENTS.md
和接手说明中指定的 skill。告诉我当前项目是什么、数据怎么保存。
随后帮我完成这个需求：……
保留已有数据，使用项目提供的平台接口；完成后构建并说明如何验证。
```

## Node 应用的目录要单独核对

以上结构对应网页项目。Radio 这类 Node 应用还区分开发源码、来源副本、已安装程序和运行数据。安装目录不能直接当成可编辑源码。先按 [应用类型与文件](/wiki/app-types/) 核对，再将自己的开发源码目录交给 AI。
