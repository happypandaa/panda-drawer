# 应用类型与文件

在使用前先认清应用类型，选择合适的安装与修改方式。

## 网页项目

适合便笺、清单、表单和本地信息管理。默认模板使用 React、TypeScript 和 Vite，业务网页通过项目自带的固定 SDK 读写平台 SQLite 和附件。

新项目有现成欢迎页，创建和打开时不需要现场安装依赖。修改源码后，通过详情上方的「构建更新」生成新程序。应用运行时不需要 Vite 开发服务器。

详情分为「概览」「空间与文件」「更多操作」。在「更多操作」点击「导出 ZIP」，先阅读弹窗说明，再选择位置并导出；同名文件需要另行确认替换。把完整 ZIP 按默认方式导入，可建立独立新身份的副本；详情不再提供直接创建副本的按钮。完整 ZIP 会包含业务数据和附件，分享前要核对内容。

## Node 服务应用

适合确实需要服务端接口、私密 API Key 或后端 SDK 的应用，例如 Radio Bob。平台使用自己的 Node 运行时管理一个应用服务，应用需要准备好可运行的 JavaScript、前端产物和依赖。

当前支持的源码安装先准备独立运行材料，再明确安装。平台不会把任意仓库自动改造成可运行应用，也不会在启动时临时安装依赖。

应用在独立原生窗口打开，后台服务随这个窗口启动和停止。所需配置在平台表单里填写，保存配置后仍需明确打开应用。

## 四类文件，各有用途

| 文件类别 | 做什么 | 修改时注意 |
| --- | --- | --- |
| 开发源码 | AI 和你编辑的程序与说明 | 给 AI 关联自己的开发项目目录 |
| 运行程序 | 构建或安装后实际执行的文件 | 通过平台发布，不直接修改受管产物 |
| 业务数据与附件 | 你录入的内容与素材 | 通过应用和受支持的平台接口读写 |
| 应用配置 | 地址、模型、API Key 等 | 在配置表单填写，秘密值不提交到源码 |

网页项目的 Git 版本由 AI 通过项目工具核对和保存，普通详情不展示完整 Git 面板。当前平台 Git 保存只包含源码与开发资料，不等于数据库和附件备份。取回旧源码也不会自动回滚业务数据。

Node 应用的数据规则以该应用和平台实际接入范围为准，不能套用网页项目的 ZIP、复制和迁移能力。已安装程序代次目录也不等于可编辑、可重建的开发源码。
