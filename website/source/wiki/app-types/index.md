# 应用类型与文件

每个应用对应一个项目文件夹，根目录的 `panda.json` 说明名称、运行方式和入口。网页和 Node 使用同一套清单格式，源码与运行文件都在这个目录中。

## 网页应用

适合便笺、清单、表单和本地信息管理。可以是普通 HTML，也可以是 React 等工具生成的页面，不强制使用某一种前端框架。

需要平台数据库和附件能力时，应用可以声明启用网页 SDK。数据库与附件按实际使用创建；普通网页不会因为被添加就自动生成数据库。

已准备好的网页可以直接打开，不需要启动 Vite 开发服务器。声明了构建的项目，在详情提供「准备应用」入口：先关闭应用窗口，运行声明的构建，完成后重新打开。

构建直接修改原项目里的文件，不保存旧运行副本。失败后应查看日志、让 AI 修复，再重试，不能假定旧网页仍然完好。

## 带 Node 服务的应用

适合需要后端接口、私密 API Key 或服务端 SDK 的应用。平台使用配套 Node 运行时启动后端，并在独立窗口显示页面。

应用的前后端入口须提前准备好，并符合平台的启动协议。从 Git 添加时，平台准备受支持的生产依赖，不执行仓库安装脚本；本地目录添加不安装依赖，启动也不会临时构建。需要额外准备时，以作者说明和实际检查结果为准。

关闭业务窗口会停止对应的后台服务。修改后端后通常需要关窗再打开；修改配置后，按界面明确重启或重新打开。

## 文件与配置放在哪里

| 内容 | 保存位置与用途 |
| --- | --- |
| 源码、Git 与运行文件 | 同一个项目文件夹；让 AI 编辑这个完整目录 |
| 数据库和文件附件 | 项目 `data/`；启用网页数据能力后按需创建，Node 按应用约定使用 |
| 配置与 API Key | 平台保存的本机私有配置，不写进作者清单和源码 |
| localStorage、IndexedDB、Cookie | 应用窗口的独立浏览器存储，与项目文件数据分开 |

网页配置不承载秘密密钥；需要私密 Key 的应用应通过后端使用。文件权限保护的本机配置不能当作系统加密密钥库。

## 修改、保存与分享

版本和备份由你与 AI 使用项目自己的 Git、备份方式管理。平台不再提供项目 ZIP 导入导出、复制、源码或数据版本取回；一次 Git 提交是否包含数据，要检查这个项目的实际保存范围。

想从他人的应用开始，优先使用作者提供的仓库地址。想分享自己的修改，可以让 AI 整理可交付的源码和说明，核对许可、个人内容与密钥后再分享。

## 删除时先看目录归属

用户选择的本机文件夹，包括在空目录生成的项目，删除应用时保留整个文件夹、Git 和 `data/`。平台新建或从 Git 下载的目录归平台管理，删除应用时整根删除。

两种方式都会清除该实例的平台配置、Key、日志、缓存、任务和浏览器数据。浏览器数据不会因为本地项目文件夹保留而一起保留。操作不可撤销，删除前以界面列出的范围为准。

格式细节可看[当前清单 Schema](https://github.com/happypandaa/panda-drawer/blob/develop/schemas/panda.schema.json)。
