想做一个便笺本、阅读清单，或者只适合自己习惯的小工具，可以先在熊猫小抽屉里建一个项目，再让 AI 帮你完成页面和功能。熊猫小抽屉负责保存项目、提供数据能力和打开应用，Codex 或 WorkBuddy 负责根据你的需求修改文件。

这篇教程从一个新的网页项目开始。先准备好当前 macOS 内部开发版熊猫小抽屉，以及能访问本机文件的 Codex 或 WorkBuddy。制作和修改时需要 AI；完成后的本地功能由应用自己运行。

## 1. 建立第一个项目

打开熊猫小抽屉，在“我的项目”点击“新建项目”，填上名称，例如“我的便笺”，再点击“创建项目”。

新项目已经包含一个可以打开的初始应用，以及源码、独立数据库和开发说明。你可以先点“进入应用”看一眼，再回到项目详情，让 AI 把它改成你需要的样子。创建和打开初始应用不要求你先安装系统 Node，也不需要输入构建命令。

先做一个小而明确的功能更容易检查：例如“写便笺并保存”，完成后再添加搜索、标签和排序。

## 2. 找到应该交给 AI 的文件夹

项目详情提供“概览”“空间与文件”“更多操作”三个页签，上方常显“复制提示词”“在 Codex 打开”和“构建更新”。点击“复制提示词”，接手说明会给出本次项目的真实目录、阅读入口和开发操作方法；长说明可以展开核对。

**关联说明里的整个“本次项目目录”。** 不要只选择里面的 `app` 文件夹，也不要选择熊猫小抽屉自身的源码仓库。标准项目大致是这样：

```text
你的项目目录/
├── project.json       项目信息和路径声明
├── README.md          项目说明
├── AGENTS.md          AI 阅读入口
├── .agents/skills/    项目随附的接手说明
├── docs/              数据库和平台使用说明
├── app/               要修改的页面源码
├── dist/              平台发布的网页
└── data/              数据库和用户附件
```

目录名称可能不同，以当前接手说明和项目清单为准。选择整个项目根目录，AI 才能同时读到业务说明、源码和使用规则。更详细的对照见 [AI 应该关联哪个文件夹](/wiki/ai-workspace/)。

## 3. 在 Codex 中接手

在项目详情点击“在 Codex 打开”。Codex 需要已经安装在这台电脑上。

熊猫小抽屉会复制接手说明，并请求 Codex 在这个项目目录中打开新任务草稿。接下来由你完成三件事：

1. 核对 Codex 使用的是说明中的项目目录。
2. 将刚复制的完整说明粘贴到新任务。
3. 在后面写上自己的需求，然后发送。

这个按钮不会自动发送任务。如果未能打开 Codex，手动打开 Codex，选择完整项目目录，再复制详情里保留的说明全文即可。Codex 中按文件夹组织工作的方式，也可参阅它的 [Projects 说明](https://learn.chatgpt.com/docs/projects)。

## 4. 在 WorkBuddy 中接手

如果使用 WorkBuddy，点击“复制提示词”，然后在 WorkBuddy 的项目或文件夹入口，选择说明中的完整项目目录。不同版本的入口名称可能变化，重点是让当前任务可以读取和修改这个本机文件夹。

把接手说明粘贴到任务里，再补充需求。只上传几份聊天附件，不能替代对本机项目文件夹的访问；也不能让 AI 持续修改原项目。

你可以要求 WorkBuddy 先读取根目录的 `README.md`、`project.json` 和 `.agents/skills/local-projects-app/SKILL.md`，再按照接手说明继续。不要假设它会自动发现所有项目规则。WorkBuddy 的任务入口可参考 [官方任务栏说明](https://www.codebuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)。

## 5. 把需求说清楚

接手说明解决“这是哪个项目、怎么开发”，你的补充解决“要做什么”。可以把下面这段放在完整接手说明之后：

```text
我想把这个项目做成一个自己的便笺应用。

请先阅读本项目的接手说明、README、项目清单和数据库说明，
确认当前工作目录就是这次交接的业务项目根目录。

第一版需要：
1. 新增、编辑和删除便笺。
2. 每条便笺有标题、正文和更新时间。
3. 按标题和正文搜索，并显示没有结果时的提示。
4. 保存失败时保留正在输入的内容，告诉我具体原因。
5. 关闭应用再打开，仍能看到已保存的便笺。

保留项目中已有的内容，通过平台提供的接口保存数据。
请同步更新项目说明和数据库说明，通过平台构建，
最后告诉我实际完成了什么、如何检查、还有什么没有验证。
```

不需要先指定一大串技术。普通的表单、清单和本地数据功能可以从现有网页模板开始；涉及在线服务、账号或 API Key 时，再让 AI 先说明额外准备和实现方式。不要把秘密密钥放进网页源码或聊天里的示例配置。

## 6. 构建，然后打开新版

AI 修改的是源码，已经打开的应用窗口还可能显示旧网页。修改完成后，需要通过熊猫小抽屉的构建流程发布新版。

AI 可以使用接手说明提供的实际平台工具；你也可以回到项目详情点击“构建更新”。等待任务结束，查看结果和日志。首次构建可能需要联网下载依赖。

构建成功后，先保存或另存应用窗口中的未提交内容，再在“概览 → 详细运行信息”点击“重新加载项目窗口”，确认“已处理草稿，重新加载”。单纯再次进入项目可能只是聚焦原来的窗口，不会刷新页面。

构建失败时，先把错误交给正在处理这个项目的 AI。原来可用的网页会保留；不过，已经成功提交的数据库修改不会因为构建失败自动撤销。

## 7. 检查自己的实际使用流程

在熊猫小抽屉的应用窗口里新增一条便笺，编辑它，搜索其中的文字，再关闭窗口重新打开，检查内容是否保留。错误提示、空列表和未保存输入也值得试一次。

确认功能可用后，可以让 AI 核对当前 Git 状态、保存一个本机版本，并报告实际提交结果。没有仓库时，让它先说明初始化范围；保存时明确作者和版本说明。普通应用详情不再提供源码版本列表和提交表单。

当前平台的 Git 保存范围是源码和开发文档，数据库、附件及运行网页没有纳入这次提交，也不会自动推送远端。保存 Git 版本不能当作整份业务数据的备份或回滚。需要完整归档时，在“更多操作”点击“导出 ZIP”，阅读说明后选择位置；归档包含业务数据和用户文件，分享前请核对个人内容。同名文件需要另外确认替换。

以后想继续修改，不必重建项目。从同一个项目详情重新复制接手说明，关联同一个当前项目目录，再描述下一项改动即可。想以别人的项目为起点，继续看 [复制应用，再改成自己的](/tutorials/remix-an-app/)。

## 遇到问题时

**AI 说找不到文件。** 核对关联的是完整项目根目录，并确认它确实能访问本机文件。工作区迁移后，要从熊猫小抽屉重新复制接手说明，重新选择新目录。

**平台工具提示连接受限。** 先确认熊猫小抽屉仍在运行，再检查 AI 当前会话对本机服务的访问权限。保留已完成的修改和具体错误，不要通过删除连接记录、重建项目或直接修改数据库来绕过问题。

**AI 完成了，页面还是旧的。** 检查构建是否最终成功，再处理草稿并明确重新加载。直接运行源码目录里的构建命令，不等于已经通过平台发布。

**详情提示有操作需要处理。** 点击“查看并处理”，先核对旧维护、恢复或未完成源码取回的状态。只有检查允许的操作才能明确继续、撤回或结束维护；源码处理前需停止外部编辑。状态无法确认或操作失败时保留现场和日志，再交给 AI 检查。重新打开窗口不会自动结束维护，普通源码修改不要求先创建 ZIP 基线。
