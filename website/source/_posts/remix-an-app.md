看到接近自己需求的应用，可以先用起来，再让自己的 AI 修改页面和功能。开始前先读作者说明，确认使用前提与许可。

本教程对应当前 `panda.json` 版本。早期的完整项目 ZIP 导入导出、平台复制和版本取回入口已移除。

## 1. 先看你拿到的是什么

| 手上的内容 | 当前起点 |
| --- | --- |
| GitHub 或 Gitee 公开仓库链接 | 「添加应用」粘贴地址，或「从 Git 添加」 |
| 电脑上已有的应用文件夹 | 「本机文件夹」检查并添加原目录 |
| 旧版项目归档或普通源码 ZIP | 先在自己的目录中检查内容，让 AI 适配当前格式，再添加文件夹 |
| 已经在抽屉里的应用 | 直接从该应用详情交接给 AI，修改当前项目 |

想保留原应用另做一份时，先让 AI 说明新目录、清单、配置和数据的处理方式。不要复制平台的私有登记，或假定再次添加同一个目录就会得到独立副本。

[应用列表与各自前提 →](/apps/)

## 2. 从链接或本机文件夹添加

有作者提供的公开仓库地址时，在「添加应用」粘贴地址并开始，按检查结果完成准备。需要执行网页构建时，先核对来源与说明，再明确确认。

使用本机文件夹时，选择包含 `panda.json` 的整个项目目录。平台直接使用原文件，不会建立另一份运行源码；添加本身也不安装依赖。

检查提示不兼容、需要配置或缺少入口时，保留说明，先处理问题。公开源码并不保证当前版本可以直接运行，不要把“下载完成”当成应用已经可用。

添加成功后，填写所需配置，再打开试一次。当前应用清单会说明需要哪些账号、Key 和在线服务。

## 3. 核对当前目录和数据

从要修改的应用详情取得当前 AI 交接，不沿用作者电脑上的路径或另一份应用的提示词。

```text
你正在修改的项目/
├── panda.json          名称、运行方式和入口
├── README.md           作者说明
├── …                   当前源码与运行文件
└── data/               该目录的文件数据（如有）
```

源码、Git 与运行文件共用这个目录。浏览器存储和平台私有配置单独保存；源码里带了什么业务数据，需要实际检查。

如果已有重要内容，先让 AI 核对保存方式、做好合适的备份，再修改。当前平台没有数据版本取回，不要依赖一个不存在的回滚按钮。

## 4. 交给 Codex、WorkBuddy 或自己的 AI

macOS 在应用详情选择工具后，使用「用 XX 改」。核对工具中的项目文件夹与提示词，再发送。Codex 和 WorkBuddy 都可以从这里接手；不同工具的预填与粘贴方式以界面提示为准。

Windows 当前通过复制提示词，手动在工具中选择项目文件夹。自动打开失败时也使用这条路径。

AI 先读懂应用，再在同一对话里告诉它要改什么。仅上传几份源码文件，不能代替对本机实际目录的读写权限。

[详细交接步骤 →](/wiki/ai-workspace/)

## 5. 先改一项看得见的功能

例如，在便笺应用上增加标签：

```text
我要修改的是本次交接的应用，请先核对目录，
阅读 panda.json、README 和指定的开发说明。
了解现有功能，不要从头重建。

请增加标签筛选：
1. 每条便笺可以设置一个标签。
2. 没有标签的旧便笺仍能正常打开和编辑。
3. 搜索和标签筛选可以同时使用，并能清除筛选。
4. 保存失败时保留输入，显示具体错误。

先检查实际数据结构，保留已有数据和附件。
修改前说明保存范围；完成后按项目要求准备或重启，
告诉我怎么检查旧内容与新功能，以及哪些部分尚未验证。
```

版本管理由你与 AI 使用项目自己的 Git 处理。确认当前仓库和提交范围，避免把密钥、个人内容或无关文件加入分享材料。

## 6. 准备、打开并检查

需要构建的网页，先保存草稿、关闭业务窗口，再在详情点击「准备应用」，成功后重新打开。Node 后端修改后要重新启动；静态页面按项目说明重新打开即可。

构建在原目录执行，失败可能留下已经改动的文件，不保证原程序保持可用。保留日志让 AI 修复，不用反复添加新项目掩盖错误。

至少走一次完整流程：打开原有记录、使用新功能、新增内容、关闭再打开。确认旧内容可读、新内容可保存，再继续下一项修改。

## 删除练习应用之前

从 Git 下载或由平台新建的项目，删除时会整根删除源码、Git 和数据。用户选择的本机目录会保留，但平台配置和浏览器存储仍会清除。先核对确认窗口，不需要删除时可以直接关闭应用。
