看到一个接近自己需求的应用，可以先取得一份独立副本，再让 AI 修改页面和功能。这样容易保留一个可用的起点，也方便比较改动。

这篇教程的主线是熊猫小抽屉的网页项目：导入完整项目 ZIP，或先导出自己的已有项目，再作为新副本导入。公开仓库使用“从 Git 导入应用”，平台会连续完成受支持应用的下载、检查和安装；不符合当前格式的仓库仍需先适配。

## 1. 先看你拿到的是什么

| 你手上的内容 | 从哪里开始 |
| --- | --- |
| 作者通过熊猫小抽屉导出的完整项目 ZIP | “添加 → 导入项目” |
| 已经在自己抽屉里的网页项目 | 详情“更多操作 → 导出 ZIP”，再作为新副本导入 |
| GitHub 或 Gitee 公开仓库链接 | “添加 → 从 Git 导入应用” |
| 已下载到本机的源码文件夹 | “从 Git 导入应用 → 源码记录与恢复 → 检查本机源码目录” |

普通仓库下载得到的 ZIP，不一定是熊猫小抽屉的完整项目归档。不要直接把它当成“导入完整项目”需要的文件。

取得他人的代码时，先查看作者的说明和许可，确认可以按自己的用途修改。如果只是想先体验一个应用，可以先看 [Radio 的介绍与安装方法](/apps/radio/)。

## 2. 从完整项目 ZIP 建立副本

打开熊猫小抽屉，在“我的项目”点击“添加 → 导入项目”，选择完整项目 ZIP。

导入方式默认 **“作为新副本导入”**，可以填写自己的副本名称，再点击“校验并导入”。等待任务最终完成，在项目列表找到新副本。

每次普通导入都生成新的项目 ID，即使再次导入同一份 ZIP，也可形成独立副本。源码、数据库和附件各自独立，之后修改它不会影响原项目。如果明确选择“恢复原项目 ID”，平台会保留归档身份；该 ID 已在项目列表、旧回收站或未完成操作中占用时会拒绝覆盖。为了以别人的应用为起点，使用默认新副本即可。

完整项目归档会包含源码、网页、数据和附件。它不是自动清空数据或脱敏后的模板，接收和分享前都应核对其中的实际内容。维护中的归档导入后仍会保持维护，需完成相应检查才能继续。

### 项目已经在自己的抽屉里

打开原项目详情，在“更多操作”点击“导出 ZIP”。弹窗会说明包含源码、当前应用文件、数据库和用户文件，不含 Git 历史、开发依赖、缓存和平台历史备份。核对实际业务数据后，点击“选择位置并导出”；同名文件须另行确认替换。

等待导出任务最终成功，再按上面的“作为新副本导入”流程导入这个 ZIP，为副本填写自己的名称。详情不再提供直接创建独立副本的按钮，已有应用和旧副本仍保留。

不要在 Finder 里直接复制工作区文件夹来替代这一步。平台需要为副本建立正确的新身份。

## 3. 从新副本取得当前目录

新副本创建后，进入它的详情，重新点击“复制提示词”。不要沿用原项目的接手文字、项目 ID 或目录。详情分为“概览”“空间与文件”“更多操作”，复制和开发按钮在上方常显。

标准网页项目的文件大致分为：

```text
新副本的项目目录/
├── project.json       新副本的项目信息
├── README.md          业务说明
├── .agents/skills/    AI 接手规则
├── docs/              数据库与平台文档
├── app/               可以继续修改的页面源码
├── dist/              通过平台构建更新的网页
└── data/              这个副本自己的数据和附件
```

AI 应关联接手说明中的**完整项目根目录**，不能只选 `app/`、运行网页目录或原作者的文件夹。复制不会随意改写作者写在文档里的文字，所以旧 README 中出现旧路径时，以本次新取得的交接为准。也可以对照 [AI 应该关联哪个文件夹](/wiki/ai-workspace/)。

## 4. 用 Codex 修改副本

在新副本详情点击“在 Codex 打开”。核对打开的是新副本的目录，把完整接手说明粘贴到任务草稿，再追加要修改的功能并发送。

这个入口只准备目录和说明，不会自动提交任务。如果未能打开，手动在 Codex 中选择交接显示的项目目录，粘贴全文后继续。关于 Codex 的文件夹项目，可参阅 [官方 Projects 说明](https://learn.chatgpt.com/docs/projects)。

不要因为原项目名字和副本名字相近，就跳过目录核对。让 AI 在开始前确认本次项目 ID、实际目录及项目说明，是避免改错应用最直接的方法。

## 5. 用 WorkBuddy 修改副本

在新副本详情点击“复制提示词”。到 WorkBuddy 的项目或文件夹入口，手动选择交接里的完整项目目录，再把接手全文和需求粘贴进当前任务。

不同版本的具体入口名称可能变化，可以参照 [WorkBuddy 官方任务栏说明](https://www.codebuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)。需要确认的是：当前任务真的能够读写新副本所在的本机文件夹。只把源码文件作为聊天附件上传，不等于已经关联可以持续修改的项目。

要求它先读项目 `README.md`、`project.json` 及 `.agents/skills/local-projects-app/SKILL.md`，再根据新交接继续；不要依赖自动发现，也不要继续编辑原作者目录。

## 6. 先保存起点，再提出具体改动

可以先让 AI 核对 Git 范围、保存一个初始版本，再开始修改；需要分支时让 AI 说明当前状态和操作结果。普通详情不再显示源码版本、提交或分支表单，版本管理由 AI 通过项目工具处理。导出 ZIP 不包含原应用的 Git 历史，不能假定新导入副本已有原仓库的提交和分支。

把下面这段追加在完整接手说明后，按你的应用调整：

```text
我要修改的是这次交接的新副本，请先核对项目 ID 和实际目录。
先阅读已有 README、清单、数据库说明和 AI 接手规则，
了解当前功能，不要从头重建，也不要改动原项目。

我想在现有便笺应用上增加：
1. 每条便笺可设置一个标签，列表可按标签筛选。
2. 保留原有便笺，没有标签的旧内容仍能正常显示和编辑。
3. 搜索与标签筛选可以同时使用，并提供清除筛选入口。
4. 保存失败时保留当前输入，清楚显示错误。

请保留已有源码、数据和附件，先查看实际表结构再调整。
同步更新项目说明和数据库说明，通过平台构建，
告诉我如何检查新功能，以及哪些检查尚未完成。
```

先改一项可以看得见的功能，更容易发现问题。不要让 AI 为了“整理项目”删除数据、替换项目自带 SDK，或手工覆盖运行网页。

当前平台的 Git 保存只包含本机源码和开发资料，不包含业务数据库、附件及运行产物，也不会自动推送到原作者仓库。让 AI 取回旧源码同样不表示数据库会一起回到旧状态。详情若提示有未完成操作，先通过“查看并处理”重新核对，明确处理后再继续开发；失败时保留现场和日志。

## 7. 构建、重载，检查旧数据和新功能

让 AI 按交接通过平台构建，或回到详情点击“构建更新”。查看最终结果，成功后处理窗口里的未保存内容，再在“概览 → 详细运行信息”点击“重新加载项目窗口”并确认。

至少检查一次完整流程：打开原有记录、使用新功能、新增一条内容、关闭应用并重新打开。旧数据能读，新内容能保留，才说明这个改动对你的实际使用有效。

构建失败时保留错误交给 AI 处理，原来可用的程序会继续保留。不要反复导入或再创建副本来掩盖失败；这样只会多出几个需要核对的项目。

## 如果拿到的是公开仓库

“添加 → 从 Git 导入应用”支持 GitHub、Gitee 的公开 HTTPS 仓库。填写地址，点击“导入应用”，在同一界面查看下载源码、检查兼容性、准备应用和完成导入的阶段。分支和备注名称可以在高级选项中填写。私有仓库和 SSH 尚不属于这个入口的支持范围。

对于符合当前 Node 服务子集的项目，平台会自动衔接准备和安装，无需重新选择刚下载的源码。确实需要执行作者声明的构建脚本时，会先说明并等待同意。最终显示“导入成功”表示应用已经加入列表；需要配置时进入配置，填齐后再明确打开。下载完成和构建通过都不能代替这个结果。

如果仓库缺少受支持的声明或需要适配，结果会说明不能直接导入及原因。可以进入源码检查流程交给 AI 继续评估，或“清理并关闭”。失败、取消和重试的清理只处理这一次导入的临时材料，保留已有应用、正式源码、数据和配置。清理失败会另行显示原因，不把关闭页面当作已删干净。安装结果需要核对时，先检查原候选，勿重复导入。

本机源码从“源码记录与恢复”先“检查本机源码目录”，再明确“接入此目录的源码副本”。检查本身不会复制；接入会创建独立来源副本，并展示排除范围，原目录保持不变。它按已知路径排除数据、凭据和依赖等内容，不能保证识别任意文件里的私人信息。这个高级入口也保留旧来源及安装候选的核对操作。

本段对应 2026-10-26 确认的新流程，需使用包含该改动的新构建。新流程的真实原生验收另记；旧包仍可能展示分步获取和安装界面。当前不承诺把任意公开仓库自动适配成应用。

已安装的受管程序目录不是已核实的开发源码目录。继续定制应在自己的开发源码中进行，再取得新的来源候选，通过应用详情准备更新。Node 自有数据也不能直接套用本文网页项目的 ZIP、复制和迁移流程。

## 遇到问题时

**导入提示项目身份冲突。** 如果是要建立自己的副本，确认选择了“作为新副本导入”；不要删除原项目来给同 ID 导入腾位置。当前删除确认后直接永久执行，不进入平台或系统回收站。

**试做的副本不需要了。** 打开副本详情，核对名称、项目 ID、实际目录和删除范围后再确认。删除会移除这个副本的源码、网页及自己的数据库／附件，无法从回收站撤销；原项目、旧备份及恢复记录不随它一起删除。外部目录引用的 Node 应用另按确认页提示，只删平台登记和私有配置／数据，原外部文件夹保留。

**AI 修改后，原项目也变了。** 先停止继续修改，核对 AI 当前关联的目录是不是新副本，从新副本详情重新取得交接。不要用相似的项目名称代替路径核对。

**仓库不能直接导入。** 先查看结果中的格式或依赖原因。需要适配时从源码检查入口交给 AI 评估；不需要继续时清理本次临时材料。只有“导入成功”才表示已加入应用列表，首次打开仍可能需要填写配置。

**重载后数据不见了。** 先确认打开的是哪一个项目及其 ID，并保留现场和日志。源码版本不会自动恢复数据库，不要让 AI 重建空库覆盖原内容。
